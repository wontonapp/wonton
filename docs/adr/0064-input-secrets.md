# ADR-0064 用户填写的密钥：清单声明，装时在原生表单里填，核心保管，不回显

- 状态：已接受（2026-11-08，主人在“商店加工具和技能区”里批了这一块）

## 背景

插件密钥（规范的“插件密钥”一节）只有两种：核心生成（`generate`）和插件运行中生成、交给核心保管（`collect`），都不经过用户。
可是多数 MCP 服务器和不少应用要用户自己的 API key（模型服务商、搜索、地图、云盘），没有地方填，装上也用不了。
插件只能让用户进它自己的网页去填，或者干脆写进说明里，让用户自己改环境变量，而这在 Wonton 里做不到。

同类做法：
- MCP 官方注册表的 `server.json` 给环境变量标 `isSecret`、`isRequired` 和说明；
- Docker MCP Catalog 的 `config.secrets` 写名字、环境变量和说明，由 Docker Desktop 的表单填进它的密钥库；
- Umbrel、Runtipi 让应用在安装表单里填字段。

## 决策

### 清单

```yaml
x-wonton:
  secrets:
    brave_key:
      input:
        title: {zh: Brave 搜索 API 密钥, en: Brave Search API key}
        description: {zh: 免费额度每月 2000 次, en: Free tier has 2,000 queries a month}   # 可不写
        url: https://api-dashboard.search.brave.com/app/keys                              # 去哪里拿，可不写
        required: true                                                                    # 默认 true
```

- `input` 是第三种，和 `generate`、`collect` 三选一。
- 填的值以 `WONTON_SECRET_<名字大写>` 注入，和另两种一样。可选项没填时注入空串，插件照常能引用。
- `title`、`description` 照清单其他可翻译文字的写法。`url` 只接受 `https://`。
- 规范版本 0.8。

### 什么时候填

**必填项缺了，插件照样装、照样升级，状态是“待配置”。**

- **主人在 App 里装**：安装预览列出要填的项，确认页用原生表单填，和确认一起提交。没填的必填项不拦安装，装好后插件是“待配置”。
- **Bot 经 MCP 装**：确认卡片（ADR-0016、ADR-0033）列出要填的项。主人在 App 里点开卡片，用原生表单填，随回答经核心的接口提交。
  值不进 Matrix，不进聊天记录，Bot 也拿不到。MCP 的安装工具不收密钥参数，Bot 不能替主人填。
- **升级新增必填项**：升级确认页（或卡片）同样列出。填过的项沿用，不再问；没填的照常升级，升级后是“待配置”。
- **装好以后**：详情页列出每一项“已填写”或“未填写”，可以改；可选项可以清空。改了以后，核心重建引用这个变量的服务，让新值生效。
  Bot 服务重建时沿用原 Matrix 身份，访问令牌从旧容器读回，不为更新密钥重新登录。

### 待配置时

- 状态是 `needs_configuration`（壳不认识的版本落到“其他”）。这是核心按“必填项还没填”算出来的，不另存：填齐那一刻就没了。
- 详情页列出缺哪几项，就是上面“装好以后”的那个列表，标记“未填写”。
- 这个插件的 MCP 工具在总线上不列出来，调用回失败，类别 `not_ready`，写明缺哪几项密钥；`wonton__list_plugins` 的 `tools_error` 同样写着。
  上游要凭据时，带着空头去连也只会被拒，不如直接说清楚。
- 网页入口照常：应用自己会报缺密钥，核心不挡。
- 填齐后核心按改密钥的现有逻辑重建引用它的服务，状态回到 `running`。`mcp.headers` 引用了填过的项时，连接上的请求头同时换成新值（见下）。
- 容器自己起不来、健康检查不过时仍然算“异常”：那比“待配置”更要紧。

`mcp.headers` 可以引用用户填写的密钥（如 `Authorization: Bearer {secret:token}`），引用的是没填的必填项时同上：
装得上，插件待配置，MCP 未就绪。引用的是没填的可选项时请求头先不带它，插件照常运行。引用没声明的密钥仍然是
`invalid_input`。

### 保管和显示

- 存进核心的密钥库（核心数据目录下，文件权限 0600，插件容器访问不到）。卸载时随“保留数据”一起保留或删除，和另两种一样。
- **任何接口都不返回填过的值**，包括主人自己：只给“已填写”和最后修改时间。审计和日志只记哪一项改了，不记值。
- 原生表单用系统的密码输入框，输入时不显示明文，不进键盘的学习和自动填充（iOS `isSecureTextEntry`、Android `textPassword`）。
  要看清自己输入的内容，用输入框自带的显示按钮，只在本机显示。
- 只有主人能填、能改（家人和好友不能，路由按 `owner_only`，同 ADR-0045）。

## 理由

- 装的时候就把表单递到主人眼前：多数情况下当场就填好了，碰不到“待配置”。不让缺一项就整单失败，是因为密钥常常要去别的网站申请，
  安装卡在一半等主人拿密钥，比先装上更烦；Bot 发起的安装也常常是“先装上、密钥等主人有空再给”。
- “待配置”由“必填项有没有填”算出来，不另存状态：核心里没有第二处真相，填完就消失，核心重启也照旧。
- 卡片的回答本来就走核心的 HTTP 接口，不经过 Matrix，所以 Bot 发起的安装也能让主人在原生表单里填，明文不经过聊天。
- 不回显，因为这些值是用户在别的服务那里的凭据：泄露的代价在 Wonton 之外，回显带来的方便（核对一下）不值这个风险。
  核对用输入框自带的显示按钮。填错了，插件会自己报鉴权错误，重新填一次就行。
- 字段和 MCP 注册表的 `server.json` 对得上（`isSecret`、`isRequired`、说明）：以后把注册表里的 MCP 服务器翻译成 Wonton 插件，这一块可以直接映射。

## 代价与风险

- 有一个“装上了但用不了”的中间状态：主人得自己回详情页填，Bot 装完后总要再提醒一句。壳要显示这个状态，不然主人只看到插件坏了。
- MCP 调用在待配置时一定失败；MCP 服务本身能用的部分（不认凭据的只读工具）这时也被挡住，等填齐再来。
- 核心不验证填的值对不对。填错时是插件自己报错，详情页看不出来，要靠插件把鉴权错误显示清楚。
- 改一个值要重建服务，正在进行的任务会断。
- 每个 Bot 各用一份密钥的写法（比如每个 Bot 一个账号）这次不做；声明在 Bot 服务上也是整个插件共用一份。

## 没选的做法

- **缺必填项就整单失败**（原先的做法）：密钥要去别的网站申请时，安装卡住、要重来一次；Bot 发起的安装还得等主人腾出手。
- **没填之前把插件停下**：多一个状态，还得决定什么时候算该停、停多久。容器照跑不影响谁，等填了就恢复。
- **Bot 在聊天里收主人的密钥再传给核心**：明文会留在 Matrix 的房间历史里，Bot 和它的模型服务商都看得到。
- **主人可以看自己填过的值**：主人设备被借用或截屏时就泄露了，而且核心得一直能解出明文给 App，多一条泄露路径。
- **核心替插件验证密钥（调一次对方的接口）**：每个服务的验法不一样，核心不该认识具体的服务（ADR-0015）。
