# ADR-0127 插件定为四种形态，技能随包；装前列组件清单，工具可逐个放行，装的是什么就跑什么

- 状态：已接受（2026-11-27，主人照插件生态调研的推荐定，见“主人已定”）
- 取代：[ADR-0066](0066-plugin-forms.md) 第 3 节“工具清单漂移”和“主人已定”第 3 条（远端 MCP 改了工具照旧放行）；
  [ADR-0080](0080-static-web-plugins.md) 第 7 节里 `link` 的 `minimal` 档位；[ADR-0017](0017-plugin-ecosystem-and-store.md)
  “镜像的固定”里社区插件只写标签时的做法
- 补充：[ADR-0024](0024-confirmation-scope.md) 的“始终允许”（加逐个工具的粒度）；[ADR-0031](0031-plugin-sources.md)
  预览里“镜像来自……”的提示并入组件清单

## 背景

[ADR-0066](0066-plugin-forms.md) 和 [ADR-0080](0080-static-web-plugins.md) 已经在容器之外加了远端 MCP、技能、静态网页和
外部网页，但都是逐个加的：哪些算形态、哪些不算，装的时候主人能看到什么，各篇各写一段。2026-11-20 主人提了四个方向
（容器加托管、共享轻运行器、核心认形态、混合），要先看别人怎么做再定。

插件生态调研（2026-11-26，只读源码和官方文档，外加本机实测）看了九个：

- 家用服务器：Home Assistant 的 add-on、Umbrel、CasaOS。全是“一个应用一组容器”，没有一家跑别人的脚本。
  差别在权限怎么声明、装前怎么同意、安全分由谁算：Home Assistant 由 Supervisor 按清单算分，作者填不了；
  Umbrel 让用户点选目录；CasaOS 只信 compose，没有权限模型。
- Agent 应用：Cindy、DeepSeek Harness（dsh）、Claude Code、OpenWebUI、LobeChat。插件代码跑在应用进程里或以用户权限跑，
  没有容器隔离，于是用三样东西补信任：
  - 装前列出会装什么：Claude Code 的“Will install”，Cindy 的安装回执和扩权批准；
  - 来源固定：Claude Code 社区目录固定提交，dsh 固定版本或提交；
  - 逐个工具介入：LobeChat 每个工具可设 `humanIntervention`，市场装的 MCP 要人工批准，OAuth 没连上不算装好。
- 共同的缺口：没有一家在不起容器的轻形态上同时做到平台下发的 CSP、OAuth 回调固定、逐个工具确认和可复现的安装。

Wonton 已有的对照：

- 容器隔离加声明权限（[ADR-0036](0036-plugin-privileges.md)）比进程内插件的底子强。
- 安全档位已经由核心按清单算（ADR-0080 第 7 节）。
- 插件包按提交和摘要装（ADR-0017、ADR-0031）。

缺的三样：

- 预览里的东西是散的：权限一张表，镜像、未审核、远端主机各是一条提示，技能和工具没有列。
- 放宽只能整插件给：“始终允许”放行的是插件现在和以后的全部工具（ADR-0024）。
- 只写标签的镜像，主人确认时看不到装的是哪个镜像。远端 MCP 的服务器不升版本就能改工具，没有任何一步让主人看到。

## 决策

### 1. 四种形态，技能是随包的负载

| 形态（`runtime`） | 服务器上谁执行 | 详见 |
| --- | --- | --- |
| `compose` | 核心起的容器 | ADR-0006、ADR-0036 |
| `static_web` | 静态托管插件（托管形态），可带 `web_storage` 数据 | ADR-0080 |
| `remote_mcp` | 远端服务器，经远程 MCP 连接器插件接上总线 | ADR-0066 第 3 节和“补充” |
| `link` | 没有，只存一个地址，App 内浏览器打开 | ADR-0080 第 5 节 |

- **技能不是形态。** 技能是给 Agent 读的文件，服务器上没有任何东西为它运行。前三种形态的包都可以带 `skills/`，
  怎么存、挂给哪些 Bot 照 ADR-0066 第 4、5 节。只带技能、别的什么都没有的包，`runtime` 写 `skills`，意思是“没有运行的部分”；
  App 不把它当成一种形态来介绍，在组件清单里列它的技能（第 2 节）。
- **`link` 是书签，不是插件权限体系里的一员。** 它没有权限、没有通道、不进组件清单，也不给安全档位：档位说的是插件在这台
  服务器上能拿到什么，外部网页什么都拿不到，Wonton 也管不了它做什么，给它“最低”会让人以为它被衡量过。App 在显示档位的
  地方写它的主机名。
- **不做的：** 共享轻运行器（要跑脚本的，Agent 在自己的容器里跑）、定时任务和 webhook，照 ADR-0080 第 1 节，
  有真实消费方时另写 ADR。
- **先后：** 静态网页和远端 MCP 先，静态网页的数据存储紧接，照 ADR-0080 的“主人已定”第 3、9 条。

### 2. 装前的组件清单

预览（`InstallPreview`）多一份核心算出的组件清单，写明这个包装上以后服务器上会多出什么、会连到哪里。主人确认前看的就是它。

| 组 | 列什么 | 从哪来 |
| --- | --- | --- |
| 来源 | 来源、提交、插件包摘要 | 已有（ADR-0017、ADR-0031） |
| 镜像 | 每个服务的镜像、仓库主机、摘要；只写了标签的也写核心解析出的摘要（第 4 节） | 清单，加预览时解析 |
| 工具 | 名字和效果：只读、会改数据、会删东西、没标注 | 不用鉴权的远端 MCP：预览时连接器探到的定义；其余见下 |
| 技能 | 名字、一句说明、带不带脚本、给哪些 Bot | 包里的 `skills/`，范围照 ADR-0066 第 5 节 |
| 连到哪里 | 远端 MCP 的主机；静态页 `connect` 的来源（从主人的设备连）；容器声明了 `network.egress` 时写“能连任何地址”；局域网端口 | 清单 |
| 碰哪些目录 | 共享文件夹、宿主路径、设备、静态页的数据存储，各自只读还是读写 | 清单的权限 |

- **一项只出现一次。** 清单是按组排的视图，不是第二份数据：权限行（`PermissionLine`）仍是授予的单位，属于“连到哪里”“碰哪些目录”
  的那些按组显示在这里，不在别处再写一遍。ADR-0031 的“镜像来自……”、ADR-0017 的“镜像没有按摘要固定”和 `remote` 里的主机，
  都并进这份清单，不再是单独的提示。
- **不知道的照实写。** 容器插件的工具要等容器跑起来才列得出（ADR-0024 的“始终允许”）。预览的工具组写“装好跑起来后列出”，
  装好后详情页列出；升级照 ADR-0024 在结果里列出新增的工具。要密钥或 OAuth 的远端 MCP 在主人填好密钥、授权之前也列不出工具，
  同样写明，装好后在安装结果里列出。不从清单里收作者自报的工具列表：作者说了不算，核心核实不了。
- **升级是同一份清单的对比：** 每组标出新增、变了、去掉的项。取代 ADR-0066 第 6 节里“列出新增的工具、技能、密钥”的分散写法。
- **Bot 经卡片装的（ADR-0033）**，卡片上是同一份清单。
- **协议：** 组是枚举，App 收到不认识的组不显示（AGENTS.md 的“兼容”）。组里的文字由壳按类别写（ADR-0043）。

### 3. 工具可以逐个放行

ADR-0024 的判定顺序不变，“始终允许”多一种粒度：

| 始终允许 | 放行什么 | 以后新加的工具 |
| --- | --- | --- |
| 整个插件（已有） | 这个 Bot 调这个插件的全部工具 | 算在内（ADR-0024，主人 2026-11-03 定） |
| 选中的工具（新） | 这个 Bot 调主人点了名的那几个工具 | 不算，照旧每次问 |

- 默认两者都关，每次问。主人在插件设置的工具列表里按 Bot 勾选；Bot 资料页显示同一份数据（ADR-0066 第 5 节的两处开关）。
- “每次都问的三类”（ADR-0024）勾不进去，设置接口回 400，同标成只读的规则。
- 名单按工具名记；远端 MCP 的工具改了定义时按第 5 节处理。
- 卡片上的按钮不变（“允许”“30 分钟内都允许”“拒绝”）。长期放行只在设置里给，那里写着风险。
- 看不看得到工具仍按插件给哪些 Bot（ADR-0066 第 5 节），不按工具。

### 4. 装的是什么就跑什么

每种形态都把主人确认的东西固定下来，之后不会悄悄换：

| 形态 | 固定什么 |
| --- | --- |
| `compose` | 插件包摘要和提交（已有），加每个镜像的摘要 |
| `static_web`、只带技能的包 | 插件包摘要和提交（已有） |
| `remote_mcp` | 服务器的代码固定不了，固定装时看到的工具定义（第 5 节） |
| `link` | 只有地址，什么都不固定 |

**只写标签的镜像在预览时解析成摘要：**

- 核心经 Docker 守护进程查标签当前指向的摘要（多架构镜像取清单列表的摘要），走和拉镜像同一条路：直连或 ADR-0074 的加速名单。
  核心不另开出网的路。
- 摘要写进组件清单，绑进预览的 `plan`。安装按 `名字:标签@摘要` 拉取和运行，安装记录逐个服务记下摘要。重建、恢复（ADR-0105）
  用记下的摘要，本地镜像没了就按摘要重拉，不按标签。
- 查不到就停下：标签不存在是 `not_found`，连不上仓库是 `source_unavailable`（ADR-0031 的类别）。不装一个主人没看到摘要的镜像。
- `pull_policy: never` 用本机已有的镜像，写镜像 ID，标“本机镜像”。
- 官方索引照旧要求清单里直接写摘要（ADR-0017），收录时检查。
- 升级预览逐个服务写旧摘要和新摘要。

### 5. 远端 MCP 的工具改了，要主人看过才吃放宽

远端服务器不升版本就能加工具、改说明和参数（ADR-0066 第 3 节）。容器插件的工具面跟着镜像摘要走，变了一定经过一次升级确认；
远端 MCP 没有这一步，所以补一步：

- **装时记下定义。** 每个工具的名字、说明、`inputSchema` 和注解，规范化后各记一个摘要。记的是预览给主人看的那一份
  （ADR-0066“补充”的 `/_wonton/probe` 返回完整定义，不只返回名字），绑进 `plan`；装的时候探到的和它不一样，不一样的那几个
  一装好就算变过。预览时列不出的（要密钥或 OAuth），记装好时探到的那份，并在安装结果里列出。
- **变了的工具退回每次问。** 运行中出现的新工具，或定义和记下的不一样的工具，在主人看过之前：
  - 照常出现在 `tools/list` 里，Bot 能用，调用照常判定；
  - 判定时不认它自己标的 `readOnlyHint`，也不吃主人标的只读、始终允许（两种粒度）、一律允许和放行时段，每次发卡片；
  - 卡片上写“这个工具在装好后变过”。
  - 去掉的工具直接消失，不用看。
- **主人看过，放宽照旧。** 详情页列出变化（新加、说明变了、参数变了、注解变了），主人点“看过了”，核心按现在的定义更新记录，
  放宽照旧生效。
- **危险模式照旧压过这一切**（ADR-0091）：主人开了危险模式的 Bot，不因为工具变过而发卡片。
- 只管 `remote_mcp`。容器插件运行中的工具变化照 ADR-0024 处理，不改。

### 6. 安全档位

照 ADR-0080 第 7 节，由核心按清单算，作者填不了。只改一处：`link` 不给档位（第 1 节）。档位显示在组件清单的顶上，
和来源标签并排，不合成一个分数。

## 理由

- **形态按“服务器上谁执行”分：** 这样每种形态要什么隔离、谁兜底一目了然。技能谁都不执行，归成形态反而要给它找一个执行者；
  当负载，它就跟着包的预览、范围和卸载走，不用另起一套。
- **`link` 不给档位：** 调研里家用服务器给的分数都是“这个应用能拿到什么”。外部网页拿不到东西，也不受约束，打分说明不了任何事，
  还可能让人放心点开。
- **组件清单而不是更多提示：** Claude Code 的“Will install”、Home Assistant 的权限页都是一份按类排的清单。散落的提示越加越多，
  主人看不出哪些是装上以后真的会有的。清单只排已有的数据，权限的授予方式不变。
- **逐个工具放行：** 整插件放行对浏览器这类插件太宽（ADR-0024 的“代价与风险”已经写了 `browser_evaluate`）。LobeChat 按工具设介入，
  Wonton 的确认本来就逐次发，缺的只是只放行几个工具的长期开关。新工具不进名单：点名的意思就是只有这几个。
- **镜像在预览时解析：** 只写标签时，“预览时看到的”和“拉下来的”之间标签可能被移动；摘要绑进 `plan` 后，主人确认的就是跑起来的，
  和插件包摘要的做法一致（ADR-0017）。顺带，所有镜像都按摘要拉，ADR-0074 的加速名单对社区插件也能用上。
- **远端 MCP 固定工具定义：** 服务器换工具（MCP 社区说的 rug pull）不经过任何升级，是这个形态独有的口子；放宽是主人对当时那份工具给的，
  不该自动延到他没见过的工具上。变了的工具照常能用，只是回到每次问，Bot 的任务不会因此断掉。
- **和 ADR-0015 的关系：**
  - 执行仍在可替换的插件里：静态托管插件、远程 MCP 连接器。核心多做的是读包、算清单、记摘要和定义、按记录判定，都是安装和授权，
    属于核心的职责。
  - 第 5 节按形态区别对待：核心认的是“这个形态的工具面没有被包摘要固定”，不是某个具体插件或服务器。
  - 张力在连接器的接口变宽了：probe 要交出完整的工具定义，不只是名字。这仍是 MCP 的 `tools/list` 原样转交，换一个连接器只要它能回
    标准的工具定义。
  - 镜像解析经 Docker Engine API，是 Compose 之下现成的标准接口，不引入新组件。

## 代价与风险

- 预览要多查一次镜像仓库。仓库慢或连不上时，预览比现在慢，或者直接报错装不上；以前只写标签的插件在拉镜像那步才失败，现在提前到预览。
- 只写标签的社区插件装上以后不再跟标签走：作者在同一个标签上推了修复，主人要等插件发新版本才拿得到。这是“装的是什么就跑什么”的代价。
- 远端 MCP 改一个工具的说明，主人就要去详情页点一次“看过了”，之前那个工具每次都问。服务器改得勤时会烦。
- 定义比较按规范化后的摘要：服务器只改了 JSON 的字段顺序不会算变化，但说明里改一个字就算。
- 容器插件的工具在预览时列不出来，组件清单在这一组上不完整，只能照实写。
- 逐个工具的名单按名字记：容器插件升级后，同名工具换了意思，名单照样放行。容器的升级要经主人确认，确认页列出已放行的 Bot（ADR-0024），风险写在那里。
- “整个插件”的始终允许仍然覆盖以后新加的工具（ADR-0024 主人已定），只对容器插件和看过变化以后的远端 MCP 生效。

## 没选的做法

- **共享轻运行器、核心认形态：** 前者主人 2026-11-11 已否（ADR-0080）；后者让核心自己执行各种形态，违反 ADR-0015。
- **技能单独算一种运行形态：** 服务器上没有东西运行，算成形态就要给它找一个执行者或一种状态，App 也要为它多一种详情页。
- **`link` 给 `minimal` 档位（ADR-0080 原来的做法）：** 见“理由”。
- **清单里由作者声明工具列表，预览时显示：** 作者声明的不一定是跑起来的；核心核实不了，显示出来等于替作者背书。
- **卡片上加“以后这个工具都允许”：** 卡片多一个按钮，长期放行会在一次快速点击里给出去；长期放行放在写着风险的设置里。
- **按工具决定 Bot 看不看得到：** 看得到不等于调得了（确认在卡片上），按工具隐藏只增加设置项，ADR-0066 第 5 节按插件给就够了。
- **只写标签的镜像拉下来以后再固定：** 能做到“之后不变”，做不到“主人确认的就是装的”，安装页也显示不了摘要。
- **只写标签的镜像拒装：** 社区插件大多只写标签，一刀切会让大部分社区插件装不上；解析成摘要同样达到固定的目的。
- **远端 MCP 的工具变了就藏起来，看过才出现：** Bot 正在做的事会因为服务器改了一个说明而断掉；回到每次问已经够了。
- **所有形态都固定工具定义：** 容器的工具面已经由镜像摘要固定，再固定一次只多出 ADR-0024 已经否掉的“改一个字就要重标”。
- **安全档位把带脚本的技能算进去：** 技能的脚本由 Bot 在自己的容器里跑，能拿到什么取决于 Bot，不取决于这个包；预览上醒目写
  “带可执行的脚本”（ADR-0066 第 4 节）。

## 主人已定（2026-11-27）

主人看完插件生态调研，照它的推荐定：

1. 插件除容器外还有三种形态：远端 MCP、静态网页（配每插件一小块存储：WebDAV 子集，每插件 64 MiB、单文件 8 MiB、`If-Match`）、
   技能（当包里的负载，装前展示清单）。外部链接只当书签：App 内浏览器打开，没有通道。
2. 不做共享运行器；定时任务和 webhook 先不做。
3. 补三件事：安装前的组件清单（技能、工具、域名、目录）；逐个工具确认和 Bot 的放行名单；镜像摘要和提交固定，平台算安全档位。
   调研里这一条写明“远端 MCP 的工具在装时就固定，新增工具要重新确认”，第 5 节照它做，推翻 ADR-0066 主人 2026-11-08 定的
   “远端 MCP 改了工具照旧放行”。
4. 先做静态网页和远端 MCP，再做静态网页的存储。
