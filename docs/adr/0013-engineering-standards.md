# ADR-0013 工程规范

- 状态：已接受（2026-10-28）

## 背景

旧仓库的问题：超过 1000 行的单文件 99 个（最大 5418 行），代码约 51 万行、测试约 27 万行，其中有
大量过拟合测试；过时文档和按日期的计划堆积；远端分支上百个；13 个仓库跨仓发版，近期 mono 有四成多的
提交在钉 BOM 或修发版机制。结构巡检脚本只报告不阻断，没能阻止文件膨胀。

## 决策

- **单仓库**：核心和 App 的代码在 `wonton` 一个仓库里，不跨仓发版和钉 BOM。插件各在自己的仓库（ADR-0017）。全新 git 历史，不导入旧仓库历史。
- **体量有门禁**：文件和函数的上限由 CI 检查，超过就失败。
- **测试以行为为主**，不写文案断言，不设覆盖率门槛。
- **文档少而准**，文档和代码在同一个 PR 里更新。
- **主干开发**，发布打 tag。
- **主要由 AI 编程代理实现**，按里程碑验收，彼此解耦的任务并行开发。

具体的数字和规则只写在 [AGENTS.md](../../AGENTS.md)。

## 理由

规则要能被机器检查，才能在多 Agent 并行开发时守住；单仓库消除了跨仓发版的大部分事故来源。
