# ADR-0013 工程规范

- 状态：已接受（2026-10-28）

## 背景

旧仓库的问题：超过 1000 行的单文件 99 个（最大 5418 行），代码约 51 万行、测试约 27 万行，其中有
大量过拟合测试；过时文档和按日期的计划堆积；远端分支上百个；13 个仓库跨仓发版，近期 mono 有四成多的
提交在钉 BOM 或修发版机制。结构巡检脚本只报告不阻断，没能阻止文件膨胀。

## 决策

- **单仓库**：所有代码在 `wonton` 一个仓库里，不再跨仓发版和钉 BOM。全新 git 历史，不导入旧仓库历史。
- **体量门禁**：源码文件 ≤ 800 行、函数 ≤ 100 行，CI 直接失败。文件行数由 `scripts/check-file-size.sh`
  检查，函数长度由各语言 linter 检查；例外写进 `.size-allowlist`，带原因和到期日。
- **测试**：核心行为测试为主，契约测试覆盖核心 API 和插件清单，每个里程碑一条端到端冒烟脚本；
  不写快照和文案断言，不设覆盖率门槛。
- **文档**：少而准，只维护 README、AGENTS.md、GOAL、ARCHITECTURE、插件规范和 ADR；文档和代码在同一个
  PR 里更新；不写进度报告和按日期的笔记。
- **分支**：主干开发，只有 `main`；一个 issue 一个分支一个 PR，squash 合并后自动删分支；发布打 tag。
- **人力模式**：主要由 AI 编程代理实现，按里程碑验收。彼此解耦的任务由多个 Agent 在各自的 worktree
  里并行开发，测完提 PR；跨模块接口先单独合并。

细则见仓库根目录的 [AGENTS.md](../../AGENTS.md)。

## 理由

规则要能被机器检查，才能在多 Agent 并行开发时守住；单仓库消除了跨仓发版的大部分事故来源。
