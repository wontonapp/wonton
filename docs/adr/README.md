# 架构决策记录（ADR）

每篇记录一个重大决策：背景、决策、理由、代价与待验证项。

- 推翻旧决策时新写一篇，新篇的状态行写“取代：…”，旧篇的状态行写“…已被 ADR-xxxx 取代”，被取代的段落就地标出或者删掉。
- 单纯扩展现有决策就在原篇加一节，状态行写明日期和来源 ADR（如“… 2026-11-12 补充（ADR-0098）”）；推翻才新写一篇。
- 状态只写在各篇的状态行。
- 验证结论写进对应 ADR 的“验证结果”一节，太长的单独成文，文件名用同一个编号（`NNNN-verification.md`），一级标题
  “# ADR-NNNN 的验证”。
- 编号和主题只写在各篇的文件名和一级标题“# ADR-NNNN 主题”里，这里不再手写目录表（几个 PR 同时往表尾加一行，回回冲突）。
  看全表运行 `python3 scripts/adr-index.py`。lint 用 `--check` 查文件名和标题的编号一致、编号不和已有的重复。
- 实施计划（PR 拆分顺序、要同步的文档、要写的测试）放 issue，不写进 ADR。

## 新能力检查单

每个新能力（新的插件间能力、新的运行形态、新的外部接口）的 ADR 写清三件：

- 契约（优先开放标准）；
- 至少一个提供方；
- 至少一个真实消费方。

外加一条能证明“换提供方时消费方不用改”的契约测试；样板见
[`model_gateway_contract`](../../crates/wonton-core/src/plugin/tests/model_gateway_contract/)。
