# ADR-0010 存储与 NAS 能力

- 状态：已接受（2026-10-28）；私人空间由 [ADR-0045](0045-family-members.md) 定

## 背景

NAS 是产品的基础能力。旧方案自研了媒体目录、语义索引（asset-indexer，约 2.4 万行 Rust）和
U 盘同步（Go）。新方案原则是不造轮子：预置插件的同类功能优先用成熟的开源方案。

## 决策

- **存储卷**：安装时选择一个或多个宿主目录作为存储卷，群晖的 `/volume1` 这类路径也可以。
- **共享文件夹**：核心划分共享文件夹（照片、文档、视频、音乐、下载等）和每个家人的私人空间；
  插件的内部数据放在各自的应用数据目录。
- **按需授权**：插件按清单申请共享文件夹的读或写权限，主人确认后才挂载进容器。
- **App 内的文件**：在 App 里看共享文件夹做成文件插件，可以固定到底栏（ADR-0033），核心不做原生浏览页（主人 2026-11-04 定）。Bot 和 App 按编号共用文件见 ADR-0020。
- **相册**：Immich 插件，加一个 MCP 适配器让 Agent 能按内容搜照片。
- **文件检索**：MVP 用文件搜索插件（`geraldpeng6/wonton-plugin-files`，限定在已授权的文件夹，实现见 ADR-0020）加 Paperless-ngx（文档的 OCR 与全文检索）。不另做语义索引插件：Agent 经各应用自带的检索去找（如 Immich 按内容搜照片），主人 2026-11-06 定。
- **音乐**：Navidrome 插件，在 App 里用它的网页放（GOAL 的 M2 第 2 项）。
- **不搬旧代码**：旧 asset-indexer、usb-sync 不迁移；U 盘自动导入在 M2 选型现成方案。

## 理由

- 共享文件夹加按需授权，让插件之间有清晰的权限边界，也让 SMB、同步等插件只看到用户文件。
- Immich、Paperless-ngx、Navidrome 都是各自领域最成熟的开源项目，作为独立容器运行不影响我们的许可证。

## 代价与风险

- 依赖第三方项目的升级节奏和数据格式，升级前要在官方目录里测试。
- 没有跨应用的语义检索：按意思找只在自带检索的应用里能用。
