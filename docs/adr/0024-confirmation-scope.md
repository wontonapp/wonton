# ADR-0024 确认的授权粒度：放宽、撤销和主人亲自操作

- 状态：已接受（2026-11-03）。取舍由主人确认（见“已定”）。补充 ADR-0016。判定的第 1 步已被 [ADR-0027](0027-bot-save-file.md) 和 [ADR-0033](0033-plugin-tabs.md) 取代：Bot 更新自己写的插件，权限没变宽时不发卡片；家人和有 Bot 联系人的 Bot 怎么放宽由 [ADR-0045](0045-family-members.md) 定；非归属人发起的轮次不放宽，见 [ADR-0083](0083-bot-contacts-and-group-chat.md)。2026-11-12 主人加了“每次都问的三类”（见该节），“没选的做法”里排除 `destructiveHint` 的那条随之改写

## 背景

ADR-0016 规定：插件工具只要没标 `readOnlyHint: true`，Bot 每调用一次，核心就给主人发一张确认卡片。用下来有三个问题：

- 浏览器插件（Playwright MCP）的 25 个工具里有 18 个敏感。Bot 每点一下网页，主人都要点一次“允许”，长任务和无人值守的任务做不了。
- 社区写的 MCP 普遍不标注解，“读未读文章”这类只读操作也要确认（miniflux）。
- 开发环境没有配对设备，批准不了卡片，会改数据的工具走不完端到端测试（browser、memos）。

主人定了四个方向（2026-11-03）：卡片上可以一次放行一段时间；插件设置里可以“始终允许”；主人可以把工具标成只读；主人亲自操作时不问。
主人原本选的是卡片上“这次任务都允许”。核心分辨不出任务什么时候结束，主人同意改成这里的做法：按钮写“30 分钟内都允许”。
不变的：安装、卸载每次确认；确认由核心发、核心验证，Agent 放宽不了；每次放宽和放宽期间的每次调用都写审计。

这里的取舍按 [ADR-0011](0011-security-model.md) 的“安全只做必要的”。

## 决策

### 几种放宽

“我来操作”是第二批，其余是第一批，分开实现、分开上线。

| 做法 | 主人在哪里做 | 范围 | 多久 | 什么时候失效 |
| --- | --- | --- | --- | --- |
| 30 分钟内都允许 | 确认卡片 | 这个 Bot 调这个插件，它的所有连接 | 30 分钟，不续期 | 到期、主人点“停止”、核心重启 |
| 始终允许 | 插件设置 | 这个 Bot 调这个插件 | 长期，存盘 | 主人关掉；Bot 或插件被删 |
| 一律允许 | Bot 所在插件的设置 | 这个 Bot 调所有插件 | 长期，存盘，默认关 | 主人关掉；Bot 被删 |
| 标成只读 | 插件设置 | 这个工具，所有 Bot | 长期，存盘 | 主人取消；插件被卸载 |
| 我来操作（第二批） | 插件网页的原生标题栏 | 这个插件，所有 Bot | 主人操作期间 | 见“我来操作” |

“这个 Bot”是总线认出的调用方：一个插件一个 Bot 时是插件 ID，一个插件多个 Bot 后是各自的令牌（ADR-0016）。

### 一次调用怎么判定

按顺序，先命中的算数。最高级插件的工具和“每次都问的三类”（见下一节）不看第 2、4 步：每次一张卡片，卡片上没有“30 分钟内都允许”。最高级的详见 [ADR-0036](0036-plugin-privileges.md) 的“Bot 来装、更新和调工具”。

1. **核心自己的工具**（`wonton__*`）：敏感的每次发卡片，不看下面任何一条。卡片上没有“30 分钟内都允许”，设置接口也不接受它们。
2. **不敏感**：插件标了 `readOnlyHint: true`，或者主人标了只读。直接放行。
3. **主人正在操作这个插件**（第二批）：先停住，等操作结束再往下判定（见“我来操作”）。
4. **一律允许、始终允许，或者在放行时段内**：放行，不发卡片。时段是否有效在把调用发给插件之前判定，“停止”只拦后面的调用，已经发给插件的不撤回。
5. **其余**：发卡片（ADR-0016）。

插件清单没有任何字段能免确认，`readOnlyHint` 也不能由清单代填。清单或 Bot 的工具白名单（ADR-0006）只决定工具看不看得到、调不调得了，只能收紧。列出来的工具照样按上面判定。

放宽只改变核心要不要问，不改 `tools/list` 交给 Agent 的注解。

没发卡片的调用（第 2、4 步）和只读调用走同一条路：Agent 取消或断开时，取消传给插件；结果只回给 Agent 并写审计。发了卡片的调用不跟着 Agent 走（ADR-0016）。没发卡片的调用结果不确定时（超时、连接断了），只有 Agent 看到 `app.wonton/failure`，审计里同样记下。

### 每次都问的三类

主人定（2026-11-12）：Agent 或 Bot 删东西、装应用、把东西开放到外面之前，每次都先发卡片，主人点了才做。记笔记、搜索这类照旧按上面判定。起因是盲测里 AI 没问就删了一条笔记、装了 Samba，还建议把记账应用开放到公网。

| 哪类 | 怎么认出来 |
| --- | --- |
| 删东西 | 插件工具明确标了 `destructiveHint: true`、没标 `readOnlyHint: true`；核心的卸载 |
| 装应用 | 核心的 `wonton__install_plugin`，两种来源都算 |
| 开放到外面 | 插件把端口开到局域网或宿主网络（`network.lan`、`network.host`）只能在安装时声明，所以就是装应用那张卡片 |

和放宽怎么叠：这三类不吃任何放宽。一律允许、始终允许、放行时段、主人标的只读都跳不过卡片；卡片上不给“30 分钟内都允许”，别的卡片打开的时段也不放行等着的这类卡片。主人要的是“每次先问”，留一个更宽的按钮，一次点击就放掉了之后所有的删除。插件设置里，这类工具照常显示“要问”，设置接口拒绝把它标成只读（400 `invalid_input`），免得设置里显示一个不生效的标记。

只认明确标了的 `destructiveHint`：规范里不标时默认算真，按默认值算，不标注解的社区工具就全要每次问，放宽形同虚设（见“没选的做法”）。没标的工具照旧按上面的判定。

管不到的：

- Agent 不经核心、直接在自己容器里动的文件（比如 Agent 自己执行 `rm`）总线看不到。这类走 Agent 自己的权限确认（ADR-0035），选项由 Agent 给，“总是允许”是 Agent 自己记的，核心拦不住。
- 插件没标 `destructiveHint` 的删除工具，核心认不出，按普通会改数据的工具判定。让主人自己把工具标成“会删东西”留作后续，要先改插件设置页。
- 插件自己的工具把服务开放到外面（比如隧道类插件的“开一个公网地址”），没有对应的 MCP 注解，核心认不出。装这类插件时卡片上列着它的权限。
- Bot 更新自己写的插件、权限没变宽时不发卡片（ADR-0027），这不算装应用；权限变宽了照常发卡片。

### 30 分钟内都允许

- **卡片。** 插件工具的卡片有三个按钮：“允许”“30 分钟内都允许”“拒绝”。回答是 `{"answer": "allow_window"}`，时长由核心决定，请求里带不了。其他卡片的 `choices` 里没有这一项，回答它得到 400 `invalid_input`。
- **生效。** 点了之后，这次调用照常执行，时段从点的那一刻开始算。这个 Bot 在等这个插件确认的其他卡片一起放行，不管发自它的哪条连接，卡片各自更新：反正它们晚一秒发来也会放行。
- **按时间，不续期。** 核心看不到“任务”的边界（见“没选的做法”），按钮如实写时长。调用不会延长时段，否则 Bot 一直调就永不到期。到期后的下一次调用发新卡片，主人可以再放行一段；时段内已经发给插件的调用不受影响。默认 30 分钟，`WONTON_CONFIRMATION_WINDOW_SECS` 可以改。
- **不看连接。** 时段对这个 Bot 的所有连接都有效。连接断开、Bot 重启都不影响时段，结束只看三件事：到期、主人点“停止”、核心重启。
- **显示和撤销。** 时段的状态放在打开它的那张卡片上（`ConfirmationCard.window`：到期时间、“停止”按钮、结束后的说明），不另发通知。卡片只在时段开始和结束时编辑，每次调用不编辑。结束时写明放行了多少次。主人点“停止”请求 `DELETE /_wonton/confirmations/{id}/window`。插件设置里也列出生效中的时段，也能停。
- **只在内存里生效。** 核心重启后所有时段失效，回到逐次确认。卡片要如实：时段打开时把这张卡片和它的消息标识写进 `core/confirmation-windows.json`，结束时删掉（写不进去只记错误日志，时段照常打开：这个文件只管改旧卡片）；核心启动后把里面剩下的卡片编辑成“核心重启，已结束”，写审计（放行次数不明），改成功才删。判定只看内存，不读这个文件。核心停着、Matrix 还没好的那段时间，卡片还显示着时段：App 点“停止”连不上就如实报连接错误，得到 404 就显示已结束。
- **不认识的按钮。** 核心和 App 分开升级时，`allow_window` 对旧 App 是不认识的按钮：不显示，别的按钮照常能点（AGENTS.md 的“兼容”）。

### 始终允许

插件设置里按 Bot 列开关，默认关，旁边写明风险：这个 Bot 用这个插件的工具不再问，包括会改数据的。打开时不再弹确认。只有一个 Bot 时就是一个开关。

新装的 Bot 不继承。Bot 或插件被删、被卸载（保留数据也算）时一起清掉，重装后要重新打开。插件升级时保留，升级确认页列出“已对哪些 Bot 始终允许”，主人在那一步可以关。

新增的工具也算在内。工具要等新版本跑起来才知道，确认页只能写明这一点；升级前核心记下旧版本的工具名，新版本跑起来后比较，升级的结果里列出这次新增的工具。比不了时（旧版本当时列不出工具）如实说比不了。

### 一律允许

这个 Bot 用所有插件的工具都不再问，以后装的插件也算。开关在 Bot 所在插件的设置里，默认关，旁边写明风险：提示注入能让它不经确认改数据、删东西、往外发内容。打开时不再弹确认。

用法和 Claude Code 的“一律允许”一样：要长时间无人值守、跨好几个插件时，主人知道风险，自己打开。安装、卸载和核心其他敏感工具仍然发卡片（判定的第 1 步）。

升级时不因它另外提示，风险已经写在开关旁边。

### 标成只读

主人在插件设置的工具列表里标。这是对工具的判断，和谁调用无关，所以对所有 Bot 生效。

标记跟着工具名走。插件卸载时一起清掉。

插件自己标了只读的工具，主人在这里改不了：这里只放宽。会删东西的工具也标不了（见“每次都问的三类”）。

### 我来操作（第二批）

主人在插件网页上的点击直接到插件，不经过总线，本来就不弹卡片。要定的是这期间 Bot 同时发来的调用。

- **信号。** App 的原生标题栏上有“我来操作”，只有声明了 `mcp` 的插件才显示。点了以后客户端核心请求 `PUT /_wonton/api/plugins/{id}/takeover`，每 10 秒续一次，30 秒没续就失效。按钮是原生壳画的，请求由客户端核心发，插件网页碰不到。
- **结束。** 点“交还”；离开这个网页；App 进后台或者锁屏；隧道断了或者 App 被杀（续不上）；设备被吊销；插件停止或被卸载。几台设备同时操作时，最后一台结束才算结束。连不上时下一轮再试，到下一轮就要超过 30 秒了就不再试，核心明确拒绝的也不再试：ViewModel 显示“已交还，连接断了”或者拒绝的原因，不假装还在操作。
- **Bot 的调用先停住。** 敏感调用既不发卡片也不执行，等操作结束后回到判定的第 4 步：始终允许或者放行时段内的直接执行，其余发卡片。只读工具照常执行，Bot 能继续看页面。
  - 停住的调用不发卡片，不占防刷屏的上限（ADR-0016），另有上限：每个调用方 16 个。超过时返回 `isError: true`，`app.wonton/failure` 是 `owner_operating`，明确没有执行。
  - 最多等 `WONTON_CONFIRMATION_TTL_SECS`（10 分钟），到了同样返回 `owner_operating`。
  - Agent 这期间断开，调用直接作废：没有卡片，主人没答应过。
  - 交还后这些调用一起回到判定：要发卡片的受防刷屏的上限约束，超过的照 ADR-0016 直接拒绝。
  - 这段等待和卡片的等待各算各的，最长 20 分钟，Agent 的工具超时要覆盖两段，短了只是这次调用失败，重试即可。
- 局域网浏览器没有原生壳，发不了这个信号，Bot 的调用照常判定。

### 谁能放宽

放宽的接口和管理接口（ADR-0017）是同一道门：经隧道的已配对设备或主人令牌，经隧道的还要不是网页发起的。Cookie 会话不算。Agent 和插件都在插件网络里，没有隧道身份也没有主人令牌，插件网页经 WebView 也发不了。放宽只属于主人：家人（M2）的 Bot 另行设计。

| 接口 | 作用 |
| --- | --- |
| `POST /_wonton/confirmations/{id}` | 回答卡片，插件工具的卡片多一种 `allow_window`；也接受主人令牌，所有卡片都算，包括安装、卸载（见“开发环境”）。Agent 自己的权限卡片（ADR-0035）带 `choice_id`，不进这里的判定顺序，也没有 `allow_window` |
| `DELETE /_wonton/confirmations/{id}/window` | 停止放行时段 |
| `GET /_wonton/api/confirmations` | 正在等回答的卡片 |
| `GET /_wonton/api/plugins/{id}/tool-policy` | 工具列表和各自的状态、始终允许、这个插件里各个 Bot 的一律允许、生效中的时段；插件没运行时带 `tools_error` |
| `PUT`、`DELETE /_wonton/api/plugins/{id}/tool-policy/always/{caller}` | 始终允许 |
| `PUT`、`DELETE /_wonton/api/plugins/{id}/tool-policy/allow-all/{caller}` | 一律允许，`{id}` 是 Bot 所在的插件 |
| `PUT`、`DELETE /_wonton/api/plugins/{id}/tool-policy/read-only/{tool}` | 标成只读 |
| `PUT`、`DELETE /_wonton/api/plugins/{id}/takeover` | 开始或续约、结束“我来操作”（第二批） |

一律允许、始终允许和只读标记存在核心数据目录的 `core/plugins/tool-policy/policy.json`（权限 0600，插件访问不到）。文件读不出来时当作没有任何放宽：记错误日志，设置里如实显示，不覆盖这个文件。这时设置接口的写请求返回 503 `policy_unavailable`，不写文件。

### 审计

`core/audit.jsonl` 里：

- 每次调用多一个 `basis`：`card`、`plugin_read_only`、`owner_read_only`、`allow_all`、`always`、`window`（带卡片 ID）。先停住过的再带 `held_ms`。
- 放宽本身各写一行：打开和结束时段（放行次数、结束原因）、一律允许和始终允许的开关、只读标记的增删、“我来操作”的开始和结束，都带上是哪台设备或主人令牌。
- 写不进去时只记错误日志，不拦调用，也不拦放宽：审计坏了不该让主人用不了工具。

### 开发环境

`POST /_wonton/confirmations/{id}` 也接受主人令牌，所有卡片都算，包括安装、卸载；`GET /_wonton/api/confirmations` 列出等回答的卡片。模板仓库的 `scripts/dev.sh approve [--watch]` 用它们批准，端到端测试开着 `--watch` 就能走完会改数据的工具。

核心里没有开发模式开关，正式安装也是这样。主人令牌在服务器上，本来就能直接装卸插件、加设备（ADR-0009、ADR-0017），批准卡片没有多给权力。卡片照样发、照样写审计，开发环境走的就是正式的路。

## 理由

- 放宽都由主人经核心的接口做，判定只在总线一处，提示注入能让 Agent 发起调用，打开不了放宽。
- 放行时段和始终允许绑定 Bot 和插件，放宽一个插件不会扩散到别处；要跨插件的，主人明确打开一律允许。
- 操作期间停住而不是放行：主人接手最常见的场景是自己输密码，这时放行等于让 Bot 不经确认就能在页面上跑 JavaScript（Playwright MCP 的 `browser_evaluate`）。停住同样不弹卡片，还免得 Bot 和主人抢同一个页面。

## 没选的做法

- **按“任务”放行。** MCP 没有任务的概念。让 Agent 报告任务结束，等于让不可信的一方决定放宽多久；用 ACP 会话或房间划分，核心就要为某类 Agent 特殊处理（ADR-0015）。
- **把 MCP 会话当成任务。** 它是标准接口里的边界，但和任务不是一回事：Hermes 的会话跟着进程，和有没有任务无关（见“验证结果”）。
- **打开时段的那条连接断了就提前收回。** 实测它只抓得到 Bot 崩溃或重启，抓不到任务结束（见“验证结果”）；代价是 Bot 重启后无人值守的任务要多等一张卡片，网关还要盯 GET 流。主人先定了要，看过实测后删掉。
- **调用一次续一次期。** Bot 一直调就永不到期，主人以为的 30 分钟变成无限长。需要长时间运行的用“始终允许”。
- **空闲一段时间结束，再加硬上限**（比如空闲 10 分钟结束，最长 2 小时）。活跃的长任务不用中途再问，是固定时长之外公平的选择。没选是因为主人点的时候说不清到什么时候结束，Bot 隔一会调一次就能撑到上限，卡片只能写“最长”。
- **按 `destructiveHint` 的默认值排除放宽。** MCP 规范里这个注解默认算真：不标注解的社区工具全会被排除，等于没有放宽。所以“每次都问的三类”只认明确标了 `true` 的。
- **按参数定规则**（比如只允许某个域名）。参数的语义只有插件懂，核心不判断语义（ADR-0016），主人也写不准规则。
- **插件在清单里声明免确认。** 插件自己说了不算，这是主人定的。
- **网关看到主人的流量就算在操作。** 分不清看和点：后台开着的 WebSocket、页面脚本的轮询都算流量，插件还能靠自己的页面维持这个状态。
- **插件告诉核心“主人在操作”。** 同样是插件自证。
- **打开插件网页就算在操作。** 浏览器插件的主要用法就是开着网页看 Bot 干活，一打开 Bot 就停了。
- **开发模式的自动批准开关**（环境变量）。正式环境设错一个变量就关掉了确认，也测不到真正的卡片流程。
- **开发环境模拟一台配对设备。** 要在每个插件的测试里跑 iroh 客户端，只为证明一个主人令牌本来就能证明的事。
- **时段存盘。** 主人定了核心重启就回到逐次确认，不用处理重启后继续放行的各种情况。
- **只读标记绑定工具定义**（说明或参数一变就失效，要主人重标）。能防社区 MCP 在运行中换工具内容，但工具说明改一个字主人就要再点一次，只为加固。
- **审计写不进去就退回发卡片。** 能保证没人看过的调用都有记录，但磁盘满了无人值守的任务就全停在卡片上。
- **运行中新增的工具在设置里标出来。** 要多记一份工具名、多看一个标记，主人要看随时能看工具列表。
- **“我来操作”上线前提醒主人输密码前先点“停止”。** 每张放行卡片都多一条字。风险写在下面的“代价与风险”。
- **打开放宽时再弹一次确认。** 开关旁边写明风险就够了。
- **以后做自动升级时（ADR-0012、ADR-0017），开了始终允许或一律允许的插件不能静默升级。** 新版本的工具也算在放宽内，这个风险已经写在开关旁边，不再拦一次。

## 代价与风险

- 放宽之后主人看不到每次调用，事后只能查审计文件。始终允许尤其如此，App 里没有查看审计的页面。
- 放行时段和始终允许的范围是整个插件：放行“浏览器”就是放行它的 `browser_evaluate`。这是主人定的范围。
- 插件自己标的 `readOnlyHint` 照旧算数，社区插件可能标错（ADR-0016），MCP 规范也提醒注解来自不可信的服务器时不能据此做决定。主人这里只能放宽，收紧不了。
- 操作期间只读工具照常：Bot 能截图、读页面快照，输入框里的内容能不能被读到取决于网页和工具。主人输密码时不能假定 Bot 完全看不到屏幕。
- 操作期间 Bot 的调用停着，主人要记得交还。离开网页、App 进后台就自动结束，停太久 Bot 收到明确的错误。
- 自己输密码时没点“我来操作”，或者在局域网浏览器里，放行时段、始终允许和一律允许照常生效，Bot 能不经确认在页面上跑脚本。要防就先点“停止”或者关掉开关。
- 一律允许打开后，提示注入能让 Bot 不经确认动所有插件的数据。这是开关默认关的原因。
- 审计写不进去时调用照常执行，只有错误日志：这段时间的调用可能没有记录。
- 社区 MCP 在运行中改了工具内容、加了工具，只读标记、始终允许和一律允许照样生效，主人不会收到提示。
- 时段不看连接：任务做完了，或者 Bot 崩溃、重启了，放行还在，要到 30 分钟才结束。主人想提前收回就点“停止”。
- `Answer` 多一个取值、`ConfirmationCard` 多一个字段，是跨端接口，先单独提接口的 PR（AGENTS.md）。
- “删东西”靠插件自己标 `destructiveHint`：标错或不标的插件，删除照样能被放宽放行。注解来自不可信的服务器，这里只用它收紧，不用它放宽。

## 验证结果

2026-11-03 在开发机上实测：Hermes v0.22.5（MCP Python SDK 2.3.0），核心 309b210（rmcp 3.8.0），开发环境，Hermes 和核心之间是明文 HTTP，在两侧抓包。

| 情况 | 看到的 |
| --- | --- |
| 启动，没有任何对话 | `initialize`（2025-11-25）建一个会话，开着一条 GET 流 |
| 空闲 7 分钟 | 还是这个会话、这条流，每 180 秒一次 `ping` |
| `docker restart`（SIGTERM） | 立刻 `DELETE`，核心立刻结束会话 |
| SIGKILL | GET 流立刻断开，没有 `DELETE`；核心的会话等到上次 `ping` 之后 5 分钟才结束，这期间 rmcp 没有日志；Hermes 起来后建新会话 |
| 断网 30 秒 | TCP 重传后接着用，还是这个会话、这条流，核心看不出断过 |
| 核心重启 | Hermes 到下一次 `ping`（这次 83 秒后）才建新会话 |

结论：Hermes 的连接一直挂着，一个进程一个会话（`tools/mcp_tool.py` 的 `_servers`），寿命跟进程，不跟任务。所以连接断开抓的只是 Bot 崩溃或重启，这是不做“连接断了提前收回”的依据。

没测：真实对话里的工具调用（开发环境没有模型的 key）、断网超过 30 秒、其他 Agent。

## 已定（主人 2026-11-03 确认）

1. **放行时段的按钮写“30 分钟内都允许”，固定 30 分钟，对这个 Bot 的所有连接都有效。** 结束只看三件事：到期、主人点“停止”、核心重启。主人原本选的“这次任务都允许”核心做不到（见“背景”）。实测连接断开抓不到任务结束（见“验证结果”），所以不看连接。无人值守的长任务用“始终允许”。
2. **“我来操作”放到第二批，另开 PR。** 第一批不含它。第二批按这里的设计：点按钮才算在操作，期间 Bot 的调用先停住。
3. **放行时段和始终允许只对单个 Bot，新 Bot 不继承。** 标只读说的是工具本身，对所有 Bot。
4. **升级时保留始终允许。** 升级确认页列出它，并写明新增的工具也算在内；新增了哪些，升级后在结果里列出（见“始终允许”）。以后做自动升级，开了放宽的插件不另外拦。
5. **主人令牌可以批准卡片，正式安装也一样，不做开发模式开关。**
6. **安全只做必要的（ADR-0011）。** 按这条删掉了只为加固、要主人多点一下或多看一条提醒的做法（见“没选的做法”），加了默认关的“一律允许”。
