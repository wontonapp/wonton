# ADR-0081 用户自己电脑上的 Agent：电脑只当远端 ACP 运行时，桥和令牌留在服务器

- 状态：已接受（2026-11-11，三处取舍主人定，见“主人已定”）
- 延伸 [ADR-0061](0061-agent-runtime-and-frontends.md)：运行时的 Agent 进程可以在服务器外。
  [ADR-0011](0011-security-model.md)、[ADR-0036](0036-plugin-privileges.md) 的“Agent 拿不到宿主 shell”只管服务器宿主，用户电脑按本篇

## 背景

用户的 Mac、Windows 上常常已经装好、登录好 Codex、Claude Code，订阅和项目都在那台电脑上。在云吞里用，只能在服务器容器里
再登录一次（ADR-0035），还碰不到电脑上的项目。这些 Agent 也要能当私人 Bot，并和 issue #8 的电脑被控端、Electron 桌面端
合成一个程序设计。

这和现有安全原则正面冲突：ADR-0011、ADR-0036 写着 Agent 只在容器里跑、拿不到宿主 shell；电脑上的 Agent 天然有这个用户的
全部文件、终端和已登录的账号，谁能指挥这个 Bot，谁就能在这台电脑上执行命令。服务器宿主的规矩不改；“自己的电脑”是新的一类，
默认关，靠第 5、6 节约束。

## 决策

### 1. 组件，每个只做一件事

| 组件 | 在哪 | 只做什么 | 不做什么 |
| --- | --- | --- | --- |
| 连接程序（桌面端安装包里的独立进程） | 用户电脑 | 按本机设置起一个 Agent 的 ACP 进程，把它的 stdio 接到经隧道的一条 WebSocket；常驻显示哪个 Bot 在跑，能停止 | 不说 Matrix，不拿 Matrix 令牌，不回答权限请求，不跑服务器指定的命令 |
| 本机 Agent 插件（`wonton-agents` 的一个子目录，ADR-0079） | 服务器容器 | 每个 Bot 一个 ACP 网关（ADR-0061 第 2 节，上游是连接程序）和一个桥（ADR-0035） | 不带任何 Agent 程序，没有官方登录 |
| 核心 | 服务器 | 配对和吊销“Agent 主机”设备；把它的连接转给绑定的 Bot 的网关；发确认卡片、审计；给出在线状态 | 不认识任何一家 Agent |

Matrix 令牌、加密存储、恢复密钥只在服务器的桥里（ADR-0035 的隔离不变），电脑上只有它自己的隧道身份。

### 2. 接口和注册

- **契约是 ACP over WebSocket**，照 ADR-0061 第 1 节一帧一条 JSON-RPC，跑在 iroh 隧道上（ADR-0004）。电脑在 NAT 后面，所以由电脑拨出；
  连上后服务器一侧是 ACP 客户端，电脑一侧是 ACP Agent。核心按隧道身份认出电脑、归谁、绑定哪个 Bot，转发给它的网关。
  一个 Bot 同时只接一条连接，新连接顶掉旧的。
- **“Agent 主机”设备只有这一条路**：不能登录 Matrix、不能进管理接口、不能回答卡片，别的一律 403 `permission_denied`。
- **提供方和消费方**：本机 Agent 插件声明 `provides: {agent_acp: …}`，和容器里的运行时一样被前端选用；第一个消费方是它自己的桥（云吞聊天），
  编排器等前端经核心同样能用。一台电脑上的一个 Agent 是一个 Bot（ADR-0045 的一个插件多个 Bot）。插件清单不随 Agent 变，
  也不分发任何 Agent，不违反 ADR-0079 第 5 节。
- **契约测试**：同一组 ACP 会话脚本（新建、续聊、权限请求、取消、断线）分别对容器运行时和经隧道的远端运行时跑，桥和网关不用改。
- **起什么由电脑本地定**：安装包内置支持的 Agent 名单（命令、最严参数、关掉“总是允许”的参数），每家的事实和
  `wonton-agents/agents/<id>/` 共用来源。服务器只能在名单里选，不能下发命令行。连接程序把 `cwd` 固定为主人选的工作文件夹，
  清空 `mcpServers`（stdio 条目等于在电脑上起任意命令），不声明 `fs`、`terminal`。

### 3. 配对和身份

照手机的做法用一次性配对码（ADR-0009），码的类型是“Agent 主机”：在已配对的设备上出码，在电脑的连接程序里粘贴或扫码，
码短时有效、归出码的人（ADR-0045）。这个身份和同一台电脑上桌面端的客户端设备是两把钥匙。

Bot 归配对它的人，是他的私人 Bot，只认这一个人：联系人也不算（ADR-0045“私人 Bot 听联系人”在这里不适用），不进群。

### 4. 离线如实显示

核心把“电脑连着没有、最后在线于何时”放进 `bots/activity`（ADR-0044），客户端合成 `offline`，壳写“<电脑名> 离线，最后在线于 X”。
电脑离线时桥在服务器上当场回一句“电脑离线”，不排队，电脑醒来也不补跑。断线时等着的卡片作废，已开始的工具调用报“不确定”。
连接程序不阻止电脑睡眠。

### 5. 权限和确认

做法参考了 Claude Code、Codex、Zed、Happy、Raft、Cursor、Tailscale、RustDesk 的公开文档和代码（见文末出处）。

- **默认每一步都确认。** 卡片三个按钮：“允许这一次”“这次对话里同类都允许”“拒绝”。网关丢掉 ACP 的 `allow_always`、`reject_always`，
  回给 Agent 的永远是“允许这一次”：Claude Code、Codex 的“总是允许”会写进电脑上的规则文件，以后不经云吞也生效 [CC1][CX3]。
  ADR-0024 的“30 分钟内都允许”“一律允许”对这类 Bot 不提供。不学开了沙箱就不再逐步问 [H6]，也不学全自动 [R1][CU1]。
- **“同类”**：网关按 ACP 工具调用的 `kind` 和参数算类别，写在按钮上。读、搜、改：目标都在工作文件夹里；命令：同一个程序加第一个子命令
  （如 `git status`），复合命令逐段比；抓网页：同一个域名。删除、移动和算不出类别的，每次都问。
  放行表记在核心内存里，按（Bot、ACP 会话、类别）查；网关只送一个不透明的类别键，核心不认识 ACP。不存盘，
  会话结束、电脑断线、吊销或重启时失效；聊天页能逐条或全部“停止放行”。放行那一下和之后每次按放行通过的调用都写审计，带原卡片编号。
- **一条关不掉的底线**：网关对执行类工具的参数查一份内置名单（递归删除家目录或根目录、读写 `~/.ssh` 和钥匙串、改 shell 启动文件），
  命中直接拒绝，放行过的类别也越不过 [Z2][CC1]。这是尽力而为的匹配，不是沙箱。
- **有沙箱就用**：名单给每家写上它最严的参数，比如 Codex 的 `read-only` 或 `workspace-write`（默认断网）[CX1]、Claude Code 的手动确认加沙箱 [CC2]。
  **沙箱不全的 Agent 也支持**，选它时醒目提示它能做什么，兜底靠每步确认、底线拒绝和工作文件夹：没沙箱的提示“它能改你电脑上的任何文件”；
  dsh 有沙箱（macOS 上是 Seatbelt，Windows 上是受限令牌），但只管文件、不管网络 [DSH1]，提示“它能把读得到的东西发到网上”。
  工作文件夹只是起点，不是围栏，提示里照实写。
- **电脑上也能点确认，不专门防“Agent 替你点同意”。** 电脑上的 Agent 能读这个用户的文件、能操作屏幕，
  **理论上能在同一台电脑上替你点同意**，或借桌面端的设备身份答卡。靠得住的防法只有“确认放在另一台设备”或“物理动作加服务器验签”，
  都要牺牲体验，先不做。只做低成本加固，不当安全保证：我们自己的屏幕操作工具（#8 被控端等）不操作 Wonton 的窗口；
  桌面端打开 Electron fuses（关 `runAsNode`、`nodeCliInspect`，开 asar 完整性校验）；Agent 主机身份不能答卡。
- **工作模式只许名单里那一个**（ADR-0061 第 2 节），聊天里换不了。审计在核心照 ADR-0016 记，连接程序在电脑上另记一份。

### 6. 怎么开、怎么关

- **开**，三道都默认关：主人在服务器设置里打开“允许电脑上的 Agent 当 Bot”（家人能给自己的电脑配，开关只有主人能动）；
  装本机 Agent 插件，走 ADR-0036 最高一级提示；每台电脑配对前再提示一次：这个 Bot 能在这台电脑上读写文件、执行命令、用你登录的账号，
  网页和文件里夹带的指令也可能让它这样做。
- **关**，任一处立刻生效 [T1][RD2]：电脑托盘里“停止”结束 Agent，“断开这台电脑”删掉本机身份；在 App 里吊销这台电脑，核心立刻断开、
  等着的卡片作废；关掉服务器上的总开关，所有电脑一起断开。

### 7. 和 #8 远程桌面、桌面端合成一个程序

一个安装包（Electron 桌面端，Mac 先做），三个角色各自一个进程、一个隧道身份、一个开关：客户端（普通设备，和手机一样）；
本机 Agent 连接（Agent 主机，只有第 2 节那条路）；被控端（#8，另写 ADR，只有画面和输入）。
Agent 由单独签名的连接程序拉起，不经被控端：macOS 按“负责进程”把屏幕录制、辅助功能授权传给子进程。
连接程序是客户端组件，“服务端只支持 Linux + Docker”不变；它也不是 ADR-0062 的宿主辅助程序。

## 威胁和取舍

| 威胁 | 约束 | 剩下的风险 |
| --- | --- | --- |
| 网页、文件、别的 Bot 里的诱导指令 | 每步确认、底线、沙箱、只认电脑主人 | 主人没看清就点了同意 |
| Agent 替自己点“同意” | Agent 主机身份不能答卡；丢掉 `allow_always`；我们的屏幕工具不碰 Wonton 窗口；Electron fuses | **在同一台电脑上点桌面端的按钮或借它的身份答卡，挡不住** |
| 借已放行的类别夹带危险操作 | 类别窄、复合命令逐段比、底线先查、会话结束失效 | 放行了 `npm run`、`python` 这类宽前缀后能做的事很多 |
| Agent 读走 Bot 的 Matrix 令牌 | 令牌只在服务器 | 无 |
| 服务器指定在电脑上跑什么 | 命令、参数、文件夹由电脑本地定；`mcpServers` 清空 | 服务器被攻破时能发消息、答卡片，让 Agent 在已有权限内干活 |
| 家人、联系人、群里的人指挥它 | 只认一个人，不进群 | 无 |
| 没沙箱或沙箱不管网络的 Agent（如 dsh） | 醒目提示、每步确认、底线 | 同意过的命令能碰全盘、能出网 |
| 电脑上用户自己配的 MCP、技能 | 不归我们管，提示写明 | Agent 照用 |

## 考虑过的做法

- **桥也放到电脑上，直接登录 Matrix**（Happy、Raft 的形态）：少一跳，但令牌和密钥落在电脑上，Agent 读得到。
- **电脑配成普通设备**：这台电脑的连接就能答卡、装插件。
- **网关放在连接程序里**：网关守的规矩落在 Agent 能改的机器上。
- **确认只能在另一台设备上点**：防得住同机自批，但手机不在手边时 Bot 只能等。
- **每次确认刷脸或按指纹、服务器验签**：模拟键鼠过不了，但每步都要物理动作，平台实现多。
- **只支持沙箱同时管文件和网络的 Agent**：更稳，但 dsh 这类（沙箱不管网络）用不了。
- **不逐步确认，靠沙箱**（Raft、Cursor 后台 Agent）；**往终端发按键**（Alma，拿不到结构化的权限请求）。
- **不做，在容器里再登录一次**：仍是开关关着时的路径。

## 主人已定（2026-11-11）

1. 确认在电脑上也能点，不专门防同机自批，不做只在手机批，也不做刷脸或签名；常规加固照做，风险照实写。
2. 卡片上有“这次对话里同类都允许”，对话结束失效，不写进 Agent 自己的设置；命中底线的照样拒。
3. 没沙箱的 Agent 也支持，选它时醒目提示。

## 代价与待验证项

- 依赖 ADR-0061 第 6 节的核心转发和网关拆分，以及 ADR-0045 的一个插件多个 Bot。
- 底线靠匹配参数，换个写法能绕过，只挡失手不挡攻击。以后要防同机自批，另加“只在另一台设备答”或验签的开关。
- 待实测：各家 ACP 适配器经隧道的延迟和断线后 `session/load`；macOS 子进程继承屏幕录制、辅助功能授权的实际行为；
  各家“关掉总是允许”的参数是否被适配器认；Electron fuses 对自动更新的影响。
