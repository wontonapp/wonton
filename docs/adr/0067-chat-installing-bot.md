# ADR-0067 装 Agent 插件时聊天列表有一行占位：阶段和类别由核心给，装好由私聊替换

- 状态：已接受（2026-11-08）

## 背景

网络慢时一个 Agent 插件要装几十分钟（#724：beta.5 上装了 45 分钟）。这段时间 Bot 账号还没建、私聊还不在房间里，
聊天列表只显示“还没有聊天”，看不出它在装。安装失败的同一个现象：插件回滚了，列表里什么都没有。

聊天列表是主人打开 App 的第一屏，Agent 的入口就在那里。装的时候这里空着，和“没装任何 Agent”分不开。

## 决策

### 单独一行数组

`ChatViewModel.installing_bots: Vec<BotInstallRow>`，显示在 `rooms` 上面。不往 `rooms` 里塞假行：`RoomRow` 以
`room_id` 为身份，打开、已读、预览、排序都按它对 Matrix 房间；装的时候还没有房间，假行会在每处都要特判。

一行一个插件，只给清单声明了 Bot 的插件：装之前由预览的 `has_bot` 知道，装起来以后 `InstalledPlugin.chat` 也是这个意思。
失败时插件已经从列表里回滚掉，只有预览还记着，所以 `has_bot` 加在 `InstallPreview` 上。装好、Bot 的私聊出现在 `rooms` 里以后，
客户端核心把这一行撤掉，由私聊那一行接替，不并排显示。升级时私聊本来就在，安装行留在上面直到升级结束。

### 行里是什么

| 字段 | 用途 |
| --- | --- |
| `plugin_id` | 找到插件；壳按它取插件网页入口、图标缓存和“去插件页” |
| `title`、`icon` | 行本身：插件名和图标，没有图标时壳画占位图 |
| `operation` | `install` 或 `upgrade`，壳据此选“正在安装”“正在升级”和失败的说法 |
| `source` | 重试用的安装来源，原样交给预览接口 |
| `state` | 下面的三种 |

`BotInstallState`：

- `Running { progress }`：`progress` 是 `InstallProgress { stage, percent }`。`stage` 取核心的安装阶段
  （`InstallStage`：拉镜像、准备、启动、等 Bot 就绪），不认识的落到 `Other`；`percent` 只在这类阶段算得出来时给
  （拉镜像有字节数），0 到 100，壳格式化。
- `Failed { reason, message }`：`reason` 是核心已有的 `PluginFailure`（传输不可用、上游出错、权限缺失……），壳按类别
  写人话、决定能做什么，给重试；`message` 是详情，默认收起。
- `Uncertain { message }`：说不清做到哪一步（连接断了、家里的服务器一直没回应），可能还在装。壳不显示重试，引导看插件列表。

### 重试走已有的安装流程

重试不加新的执行路径：壳拿 `source` 调 `preview_install`，主人看过确认页（权限可能变了）再发 `InstallPlugin`；
升级用 `preview_upgrade` 加 `UpgradePlugin`。这样重试和第一次安装是同一条路，插件包变了照样得到 `Changed` 和重新确认。
来源不知道时 `source` 为空，壳不给重试，引导回插件页。

`InstallPreview` 加 `has_bot: bool`，`InstalledPlugin` 加 `install_progress: Option<InstallProgress>`：正在装、正在升级时家里的服务器报阶段和进度，其余
为空。客户端核心从它和安装任务合成聊天列表的行，壳不认核心以外的东西。

### 第二步包括核心上报

客户端核心合成这些行只是其中一半。核心要在这条部署路径上真报阶段：拉镜像之前报 `pulling_images`，建网络和卷、
准备数据目录、代 Bot 登录时报 `preparing`，启动容器时报 `starting`，等健康检查和 Bot 上线时报 `waiting_for_bot`。
只做客户端合成的话，核心永远给不出阶段，每一行都只能落到 `Other`，等于没做。

## 理由

- **占位和房间分开**：一行在装、一行能聊，职责不同。合并成一个类型，打开的页面、已读、排序都要为假房间开分支。
- **阶段和类别由核心给**：安装是核心在做，只有它知道拉到第几个镜像、卡在哪。文字写在壳里，四种语言的目录各自维护
  （ADR-0043）。
- **失败给重试、不给自动重试**：安装会拉镜像、建网络，失败原因多半要主人动手（权限、磁盘、代理），自动重试会把真正
  的原因盖住。
- **详情默认收起**：列表一行放不下 Docker 的原话和超时秒数；要排查的主人自己展开。

## 考虑过的做法

- **往 `rooms` 里放假 `RoomRow`**：见上，身份字段和排序都要特判；而且假行会被推送、已读、预览的代码当成真房间。
- **只显示一句“正在安装 Agent”**：多装两个时看不出是哪个，也不知道卡在哪一步。
- **核心写整句文字进 ViewModel**：和 ADR-0043 冲突，两端的语言、复数都要在核心里重做一遍。
- **失败后自动重试**：连接这类原因可以，权限、磁盘不行；分开两套反而多一道状态。先统一由主人点。

## 代价

- 聊天列表多了第二种行，两端各要一套理由、阶段和三种状态的样式，还要处理整行不可点（成功前）、点击只展开详情。
- 阶段要核心在部署的每一步上报，部署路径上要带一个可写的进度；漏报的阶段显示成 `Other`，看起来比实际笼统。
- 安装任务在客户端核心的内存里：App 重启后失败的行不再出现，只在插件列表里看到它没装。要留住得另存，先不做。
