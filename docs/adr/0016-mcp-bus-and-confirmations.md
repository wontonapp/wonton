# ADR-0016 MCP 总线与敏感操作的确认

- 状态：已接受（2026-10-29）。确认卡片发在哪个房间、长什么样、等多久，以及 Bot 能装哪些插件，由主人确认（见“已定”）。由 ADR-0024 补充两件事：主人可以放宽插件工具的确认，安装、卸载仍逐次确认；主人令牌也能回答卡片，包括安装、卸载的卡片。“Bot 能装哪些插件”已被 [ADR-0033](0033-plugin-tabs.md) 取代。多步卡片的提议见 [ADR-0038](0038-multi-step-cards.md)；总线按 Bot 认调用方、卡片发给 Bot 的归属人由 [ADR-0045](0045-family-members.md) 定

## 背景

M1 验收第 6、7 项：对 Bot 说“帮我装某个应用”，Bot 在聊天里发确认按钮，主人确认后完成安装并回报结果；
Bot 能在已授权的文件夹里查找文件，并通过 MCP 在 Immich 里按内容搜照片。

已经定下的：MCP 总线用官方 Rust SDK rmcp 在核心里做最小聚合（ADR-0006）；改变系统状态的操作走核心的 MCP
工具，敏感操作由核心给主人发确认，主人点了才执行，并写审计日志（ADR-0011）；核心不为某个 Agent 特殊处理
（ADR-0015）。这里定下接口：插件怎样声明工具、Agent 怎样接入、怎样授权，以及确认怎样发、怎样验证。

## 决策

### MCP 总线

- **一个入口。** 核心在插件网络里有别名 `mcp.wonton.internal`，和 `matrix.wonton.internal`、
  `models.wonton.internal` 一样。申请了 `tools` 权限的插件得到 `WONTON_MCP_URL`
  （`http://mcp.wonton.internal:<网关端口>/mcp`），以 Streamable HTTP 连上来，看到的是一个 MCP 服务器：核心自己的
  工具，加上所有在运行的插件声明的工具。插件装上、卸掉、恢复运行时，工具列表随之变化，核心给连着的客户端发
  `notifications/tools/list_changed`。
- **授权。** 按来源地址认出请求来自哪个插件网络（`plugin::sources`，同模型网关和 Bot 的 Matrix 入口）。不在插件
  网络里的请求得到 403 `unauthenticated`，没申请 `tools` 的插件得到 403 `permission_denied`。M1 只有主人的私人
  Bot，申请了 `tools` 的插件看到全部工具；按 Bot 的白名单放行（ADR-0006）等 M2 一个插件多个 Bot 时再加，那时
  每个 Bot 另发一个令牌来区分。
- **插件声明工具**（插件规范的 `mcp` 字段：`service`、`port`、`path`、`transport: streamable-http`）。核心经插件
  网络连这个服务（同网页入口），插件的 MCP 服务只对核心可见。工具在总线上叫 `<slug>__<工具名>`，比如
  `app-wonton-files__search_files`：slug 里没有下划线，按第一个 `__` 拆开就能找回插件。只说 stdio 的 MCP 服务器在插件
  镜像里自带一个转成 Streamable HTTP 的桥（如 supergateway）。核心连插件用 `initialize` 握手（MCP 2025-11-25）：
  插件的 MCP 服务大多还不支持 2026-07-28 的无会话请求，supergateway 4.2.1 收到 `server/discover` 就断开、不回应
  （实测）。Agent 连总线时两种都行。
- **核心自己的工具**，前缀 `wonton__`（插件 ID 至少两段，slug 里一定有 `-`，不会和它重名）：
  - `wonton__list_plugins`：已装的插件和状态；
  - `wonton__search_catalog`：在官方索引里按关键词找插件；
  - `wonton__install_plugin`：按官方索引里的 ID 安装，敏感；
  - `wonton__uninstall_plugin`：卸载，可以要求删除数据，敏感；
  - `wonton__view_file`、`wonton__share_file`：看预览、发给主人，不敏感，见 ADR-0020。
- **哪些工具敏感**：核心的安装、卸载；插件的工具里没有标 `readOnlyHint: true` 的（MCP 的工具注解）。敏感的调用
  不直接执行，先走下面的确认。注解由插件声明，核心不判断语义：插件把会改数据的工具标成只读，等于在自己的数据上
  不设防，审核目录时把关。
- **审计**：每次 `tools/call` 写一行 JSON 到核心数据目录的 `core/audit.jsonl`：时间、调用方插件、工具、参数、
  决定（放行、拒绝、主人确认、主人拒绝、过期）和结果。
- **工具结果是不可信输入**（ADR-0011）：插件返回的内容原样交给 Agent，总线不解释、不据此做决定。文件引用是例外，见
  ADR-0020。

### 敏感操作的确认

确认由核心发出、由核心验证，Agent 只能发起，没法替主人说“同意”。

1. **发起。** 敏感调用到了总线，核心先做不需要确认就能做的检查（插件在不在目录里、清单合不合法、已经装了没有），
   通不过直接返回错误。然后生成一次性的确认：128 位随机 ID，记下调用方、动作和它的全部内容（安装时是插件包和它
   声明的全部权限）、到期时间，给主人发一张确认卡片。工具调用一直等着，直到主人决定或者过期。
2. **卡片。** 核心用自己的账号（`@wonton-core:<server_name>`）在主人的房间里发一条 `m.room.message`
   （`msgtype: m.text`）：`body` 是给其他客户端看的纯文本，结构化内容放在 `app.wonton.confirmation` 字段
   （类型见 `wonton-protocol` 的 `confirmation` 模块）：ID、状态、标题、说明行（高权限、删除数据这类醒目显示）、
   按钮和到期时间。不用 `m.notice`：Matrix 的默认推送规则（`.m.rule.suppress_notices`）不通知它，主人锁屏时就不知道有卡片在等；
   状态变化的编辑由 `.m.rule.suppress_edits` 挡住，不会再响。文字由核心写好，App 原样渲染。状态变了（确认、拒绝、过期、执行完）核心就编辑这条消息
   （`m.replace`），卡片原地更新。Matrix 客户端不理跨房间的编辑，所以编辑只发在卡片所在的房间；那个房间不能用了（主人退出过），就在当前的房间重发一张完整的，之后的更新跟着新的；当前也没有能用的房间时如实记错误，编辑不建房间。App 只认核心账号发的卡片：Bot 在自己的房间里发同样结构的内容，App 当普通消息
   显示，不出按钮。期限过了卡片还没被编辑（核心重启后等着的确认就没了），App 自己把它显示成过期。
3. **回答。** 主人点按钮，App 经隧道请求 `POST <核心地址>/_wonton/confirmations/{id}`，请求体
   `{"answer": "approve"}` 或 `{"answer": "reject"}`，同方向的按钮有多个时再带 `choice_id`（ADR-0035）。只接受经隧道的已配对设备和主人令牌（ADR-0024），核心域名上的跨站修改拦截照常
   （ADR-0011），所以插件网页借 WebView 发不了。插件网络里来的请求没有隧道身份，也没有主人令牌，Agent 就算拿到 ID 也答不了；
   卡片发在 Bot 不在的房间里，Agent 也看不到 ID。每张卡片只能回答一次；回答过期的、已经回答过的得到 409。
   核心和 App 分开升级（ADR-0012）：App 不显示不认识的按钮，别的按钮照常能点；核心收到不认识的回答返回 400 `invalid_input`，绝不当成同意。
4. **执行。** 主人确认后，核心照卡片上展示的那份内容执行：插件包在发卡片时就固定下来，授予的权限就是卡片上列出的
   全部权限，之后目录更新了也不影响这一次。主人拒绝或者过期，工具返回错误（`isError: true`），说明是主人没确认
   还是过期了。
5. **结果。** 执行完，工具调用把结果返回给 Agent（装好了：插件的名字、网页地址；失败：按原因分类的错误），由
   Bot 回报主人；核心同时把卡片更新成最终状态。Agent 等不到结果就断开了（比如它自己的超时），确认照样有效到过期，
   主人确认后照样执行，结果在卡片上。
   核心不主动断开等确认的调用：MCP 会话的空闲期限比卡片的有效期长（rmcp 默认的 300 秒会在等确认时把调用切断）。
   发给插件之后没等到结果（到期、连接断了）时，卡片标“结果不确定”（`uncertain`），不标“失败”：副作用可能已经发生。
6. **防刷屏。** 同一个插件同时等待确认的请求有上限，超过的直接拒绝。

### 文件搜索插件（`geraldpeng6/wonton-plugin-files`）

> 下面“用现成的 rust-mcp-filesystem”“没有自己写”已被 [ADR-0020](0020-file-service.md) 取代：它的工具不返回 `resource_link`，Bot 找得到文件发不出来，所以这个插件是自己写的。

一个小插件，按 ADR-0015 只做一件事：在已授权的共享文件夹里找文件、读文件，经 MCP 提供给 Agent。它按清单申请
共享文件夹的读权限（`storage.share.<名称>:read`），这些文件夹只读挂进容器，它看不到别的。核心只路由和授权，文件
搜索不写进核心。

- 用现成的 rust-mcp-filesystem（MIT）：默认只读，能关掉写工具（`--disable-tools`），工具带 `readOnlyHint`，
  除了按文件名找还能按内容找。它只说 stdio，镜像里用 supergateway（MIT）转成 Streamable HTTP。
- 没选官方的 MCP 文件系统服务（ADR-0010 原来写的）：它不能关掉写工具，只读挂载时 `write_file` 这类工具每次都要
  弹确认、确认了又写不进去；它也不能按内容搜。同样只说 stdio。
- 没有自己写：两个现成组件拼起来就够用，不造轮子。桥不稳定时再考虑用 rmcp 写一个只读的小服务（约 200 行）。

Immich 按内容搜照片等 Immich 插件进了目录再做：Immich 插件自己声明 `mcp`（插件规范的示例就是这样），核心不用改。

### Hermes

Hermes 是第一个用这份合同的 Agent：插件包申请 `tools`，`gateway` 服务的环境变量加上 `WONTON_MCP_URL`，
`config.yaml` 的 `mcp_servers.wonton` 指向它。确认要等主人，Hermes 默认的工具超时（MCP 调用 300 秒、工具调用
420 秒）在它自己的 `config.yaml` 里按确认的等待时间调大。调用等确认时 Bot 说不了话，所以 Matrix 的中间消息改为
打开（M0-4 时是关的，见 ADR-0008）：安装、卸载工具的说明要求模型调用前先告诉主人去 Wonton 私聊里确认，这句话先发
出去。这些都是 Hermes 插件包里的配置，核心不为它特殊处理。

## 理由

- 一个入口、按来源地址授权，和模型网关、Bot 的 Matrix 入口同一套做法；Agent 不用知道装了哪些插件，配置只写一次。
- 确认由核心发、核心验证，回答绑定已配对设备的隧道身份：提示注入能让 Agent 发起请求，但越不过主人。
- 卡片的文字由核心写，App 只渲染：确认的内容只有一份事实源，换客户端也不用重写一遍。

## 代价与风险

- 敏感调用在等确认时一直占着一个 HTTP 请求，要求 Agent 的工具超时比确认的等待时间长。MCP 2026-07-28 的 Tasks
  扩展能让调用先返回、确认后再完成，Hermes v0.22.5 的 MCP 客户端还不支持，支持的 Agent 多起来再改。
- 工具名带插件前缀，有的模型接口限制函数名 64 个字符；插件 ID 太长时 Agent 那边可能要截断。

## 已定（主人 2026-10-29 确认）

四处产品取舍都按推荐：

1. **卡片发在独立的“Wonton”私聊里。** 核心建一个和主人的私聊，核心账号的显示名也是 Wonton（通知的标题用它），核心发给主人的东西都在这里：装卸确认和结果，以后的
   插件通知、升级。核心没有端到端加密设备，这个房间不加密（服务器就在主人家里）。主人退出过这个私聊，核心就新建一个，自己退出旧的、从 `m.direct` 去掉，不越积越多。Bot 在自己的私聊里告诉主人去
   Wonton 里确认。没选的是发在 Bot 的私聊里：最自然，但要核心作为第三个成员加入每个加密的 Bot 私聊，并在核心里跑
   一个带加密的 Matrix 客户端（设备密钥、加密存储，App 还要信任核心的设备）。
2. **卡片的样式。** 标题如“Hermes 想安装 Grafana”，下面是说明、版本、来源和要授予的权限（高权限醒目，文字和 App 的
   安装确认页一致），按钮“安装”“不装”；卸载写明保不保留数据，删数据醒目显示“不可恢复”，按钮“卸载”“取消”。执行后
   卡片原地更新成结果。只有已配对设备上的 Wonton App 能点，别的客户端只看到纯文本。
3. **等 10 分钟。** 没回答就过期，Agent 收到“主人没有确认”（`WONTON_CONFIRMATION_TTL_SECS` 可以改）。
4. **Bot 能装什么：** 已被 [ADR-0033](0033-plugin-tabs.md) 的“确认”取代。

主人 2026-11-04 又定了一处：

5. **App 自己提示有卡片在等。** 主人在和 Bot 聊天时，卡片在别的房间，Bot 等回答时也说不了话，看起来像卡住了。模型调用前说的那句话没有保证，插件自己声明的工具也没有这句要求，所以客户端核心不管打开着哪个房间，都一直订阅和核心账号的私聊，把等回答的卡片放进 ViewModel。两端在任何页面顶上显示提示条，点了去卡片所在的房间，主人就在那个房间时不显示。这样不用改核心和协议，换 Agent、换模型也有效。没选的是打开 Hermes 的工具进度：省事，但只对 Hermes 有效，还不告诉主人去哪确认。模型那句话继续留着。

   通知也跟着改：点通知进消息所在的房间；卡片每张一条通知，这台设备知道它结束了就撤下，到期由系统撤下。卡片的编辑不推送，所以 App 被杀时主人在另一台设备上答了，这边的通知要等到期或打开 App 才撤。

   安装这类卡片变成“执行完了”后，App 补取一次已装列表，卡片上的“打开”“放到底栏”两个按钮凭它显示，不用先去“应用”页。算“这个会话里见过”的是：亲眼见过卡片等回答，或这台设备回答过它——卡片和结果可能落在同一批同步里，光靠看会漏。启动时翻回来的历史结果不补取，那时连上后的取列表本来就是新的。

最初的插件目录是开发镜像里的一个本地目录（`WONTON_CATALOG`），后来换成官方索引（ADR-0017）：Bot 能找到的只有
官方索引里审核过的插件，社区插件和上传的插件包只能由主人在 App 里装。开发镜像和冒烟测试用本地的索引目录
（`WONTON_STORE_INDEX`）。
