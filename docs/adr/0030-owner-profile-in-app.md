# ADR-0030 显示名和邮箱在 App 里填

- 状态：已接受（2026-11-04），“什么时候填”里配对后单独弹资料页的做法已被 ADR-0034 取代；邮箱不再交给插件，插件拿到的是内部邮箱（ADR-0056）
- 取代 ADR-0022 的“显示名和邮箱可以改”一节，和“邮箱和时区不兜底”里配邮箱的办法

## 背景

ADR-0022 让主人改 `.env` 再执行 `install.sh` 来配显示名和邮箱。一行命令装完的主机默认没有邮箱，于是用户在应用商店里装 Open WebUI 时，看到的是“在安装目录的 .env 里写上 WONTON_OWNER_EMAIL，再执行一次 install.sh”。普通用户看不懂，手机上也做不到。

## 决策

- **资料存在核心里。** 显示名和邮箱和用户名一起记在 `<数据目录>/core/owner.json`，原子写入，随数据目录备份和恢复。`WONTON_OWNER_EMAIL`、`WONTON_OWNER_DISPLAY_NAME` 不再存在。用户名仍按 ADR-0022 固定，App 里只读。
- **接口。** `GET`、`PUT /_wonton/api/owner-profile`（`wonton-protocol` 的 `OwnerProfile`、`OwnerProfileUpdate`），鉴权同插件管理接口：主人令牌，或者经隧道的已配对设备，且不是别的网页发起的。规则只在核心写一处，不合规则回 400 `invalid_input`，原因由 App 原样显示。
- **名字必填，邮箱选填。** 邮箱留空不报错，填了才查格式（主人 2026-11-06 定：不装要邮箱的应用的人用不着它）。填过以后只能改，不能清空：邮箱清掉后，要邮箱的插件重建时会失败，这个状态没有用处。
- **显示名也是聊天里的名字。** App 保存资料后，把主人 Matrix 账号的显示名设成同一个，Agent 和聊天里看到的就是它，不是用户名。
- **没填时。** 没有邮箱（ADR-0022 不兜底的规则不变）；OIDC 的 `name` 和代登录的 `{name}` 用用户名，不再是写死的 `Owner`。
- **改了就生效。** OIDC 声明和代登录的请求头每次都从记录里取，下一次登录就是新值。容器里的 `WONTON_OWNER_EMAIL` 仍是建容器时的快照，核心不因此重建插件。
- **缺资料不算“装不了”。** 预览放在 `InstallPreview.missing_profile`，不放 `blocked`：`blocked` 是这台主机上装不了，这里填了就能装。App 在安装页显示这句话和“填写资料”按钮，填完重新预览。真的走到安装时是错误类别 `owner_profile_incomplete`（409），和 `unsupported` 分开。
- **Bot 发起的安装** 在发确认卡片之前就查，不让用户确认完才失败。
- **什么时候填。** 首次填写并入新用户引导（ADR-0034）；要用资料时安装页还会提示，设置页里随时能改。

## 理由

- 手机是用户唯一的入口，配置要在 App 里能做完。
- 记录和用户名放一个文件：一个人的身份只有一份，恢复数据时一起回来。
- 核心写一份规则，App 不用抄：两端和核心的校验不会不一致，新规则也不用发 App。

## 没选的做法

- **留着 `.env` 当初值。** 两个来源要定谁优先，改了 `.env` 又要解释为什么不生效。绿地阶段不留。
- **配对后必须填完才能用。** 不装要身份的应用的人用不着，邮箱也不该成为用聊天的门槛。
- **改了邮箱就重建用到它的插件。** 重启用户正在用的应用，换来的只是建容器时用一次的值；应用按 `sub` 认人（ADR-0022）。
- **验证邮箱能收信。** 家里的服务器不一定发得了信，只挡明显不是邮箱的值。
- **把填过的状态放在 `blocked` 文案里让 App 认。** 靠文案判断要不要显示按钮，改一句话就坏。

## 代价与风险

- 应用里已有账号的资料是否跟着变，看插件怎么接：Open WebUI 在每次登录时更新，其他应用要用户在应用里改。
- 主人在引导里跳过填资料、又从不装要身份的应用时，`name` 一直是用户名 `owner`。应用里看到的不是真名，但不影响使用。
