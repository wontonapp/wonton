# ADR-0051 好友和插件共享：把自己服务器上的插件临时开放给好友

- 状态：已接受（2026-11-06）

## 背景

主人想把自己服务器上的某个插件给朋友用，比如自己写的多人贪吃蛇，以自己的服务器当服务器，经云吞的 iroh 网络分发到每个人的 App 上。

- 朋友可以没有服务器，只有云吞 App。
- 不是家人：家人在主人的服务器上有账号和私人空间（ADR-0045）。好友什么都没有，只能用被开放给他的插件网页。
- 按插件授权、按人或按群授权，可以设到期，收回后立刻断开。

这和跨服务器聊天（ADR-0050）是同一件事的两面：有服务器的好友能和你互相联邦聊天，没有服务器的好友只能用你开放的插件。两种好友用同一套“加好友”。

## 别人怎么做

| 产品 | 外人的身份 | 应用怎么认人 | 收回以后 |
| --- | --- | --- | --- |
| Tailscale 节点分享 | 要 Tailscale 账号 | `tailscale serve` 注入 `Tailscale-User-Login`、`-Name`、`-Profile-Pic` 头 | 移除设备立即断；只改 ACL 时，已建的 TCP 不断（issue #859） |
| ZeroTier | 本地生成的节点身份，不注册账号，管理员逐个授权 | 只有 IP，没有用户 | 控制面立即拒，数据面路由滞留到断开（issue #2223） |
| Plex Friends | 对方的 Plex 账号 | 每个账号一份权限和历史 | 删好友不收回库的访问，要另外移除；正在播的流播完为止 |
| Jellyfin、Emby | 服务器上建本地用户 | 用户令牌 | 禁用用户，现有连接立即踢掉 |
| Home Assistant | 每人一个用户 | OAuth2；WebSocket 按用户 | 撤令牌时回调主动关 WebSocket |
| Nextcloud | 联邦共享要对方服务器上的账号；链接分享不要账号 | 联邦 ID，或匿名 | 每个请求校验，下一个请求就失效；已开始的下载传完 |
| Cloudflare Access | 邮箱收一次性 PIN | 签名的 JWT，`email` 在声明里 | 旧令牌 20–30 秒内失效 |
| Syncthing、Briar | 设备密钥，扫码互加 | 设备 ID | 删掉即断。introducer 会让删掉的设备被重新加回，官方警告过 |

（2026-11-06 查，出处见调研笔记 share-survey。）

借鉴的几条：
- 收回要两件事一起做：每个请求都校验授权，并主动拆掉已有的长连接。缺一件就会出事：Plex 播完为止，ZeroTier 路由滞留，只在握手时验证的 WebSocket 撤销后不断。
- 关系和授权分开记，但删好友要一个动作清干净。Plex 删了好友还能看库，就是两处状态没一起收。
- 信任不自动传播：好友不能再邀请好友（Syncthing introducer 的教训）。
- 应用要的是稳定、不复用的 ID 加上显示名和头像；显示名会变，不能当主键。
- 纯设备密钥的身份，丢了手机就没了，对方只看到“永久离线”。我们的身份锚在主人这边：丢了就删掉重加。
- Funnel、分享链接那种“没装客户端也能用”，靠公网入口加单独的凭据，和这里的 App 加 iroh 是两条路，这次不做。

## 决策

### 身份

- **好友的身份是他 App 的一把密钥**，不建账号系统：
  - 每个 App 安装生成一把好友身份密钥（iroh 的 Ed25519），它的公钥就是好友 ID。
  - 这把密钥和连自家服务器的设备密钥分开，好友 ID 就不会暴露他连了哪台服务器。
  - 显示名和头像由好友自己填，随好友码一起给，主人那边可以改备注。
- **一人多台设备**：第一版一台设备一个好友，同一个人换手机就重新加。以后要合并时，再让旧设备给新设备签一个“同一个人”的声明，不另建账号。
- **有服务器的好友**：同时是 ADR-0050 的配对服务器。好友 ID 和他服务器的 endpoint ID 都记着：用插件走好友 ID，聊天走服务器联邦。

### 加好友

照 ADR-0050 的配对，一方出码、对方扫码、出码方点同意：

- 主人在 App 的“好友”页点“添加”，出一张码，10 分钟有效。码里是服务器的 endpoint ID、地址和一次性密钥。
- 朋友用 App 扫。他的 App 用好友身份经 `wonton/peer/0` 连过来，出示密钥，报上好友 ID、显示名、头像。
  他有自己的服务器时，再报服务器名和服务器的 endpoint ID。
- 主人在“Wonton”私聊里收到卡片“某某想加你为好友”，点“同意”才成立。
- 记在 `core/peers.json`，和 ADR-0050 的配对服务器同一份：
  - 每条是一个好友：好友 ID、显示名、备注、加的时间；
  - 有服务器时多带服务器名和服务器的 endpoint ID。
- 主人能把好友分组，如“打游戏的”，授权时按组选。组只在主人这边，好友看不到。
- 只有主人能加好友，好友不能把别人拉进来，也不能把授权转给别人。
- 删好友：连带收回他所有的插件授权；有服务器的，联邦配对一起删。

**反过来**，没有服务器的朋友也能出码：码里是他的好友 ID 和地址，主人扫了直接成立，主人扫码就是同意。

### 访客怎么连

- 好友的 App 用好友身份连主人的服务器，ALPN 是 `wonton/guest/0`。挂在同一个 endpoint 上，名单单独一份：
  只放行至少有一项有效授权的好友。设备名单和服务器名单都不放行这个 ALPN，反过来也一样（ADR-0050 的“名单分开”）。
- 流交给核心的网关，网关知道这是访客和他的好友 ID，不是设备，也不是主人。
- App 里，朋友在“好友分享给我的”看到每个主人开放给他的插件，点开是和插件页一样的 WebView（ADR-0033 的容器），本地代理改连主人的服务器。
  列表经 `GET /_wonton/guest/shares` 取，只列给他的。
- **没有服务器也能用 App**：引导里多一条“只用朋友分享的”。不配对服务器，直接进“好友”页，出码或扫码加好友。聊天、插件商店这些要服务器的页面不出现。

### 插件怎么知道是谁

- 沿用插件声明的登录方式，网关替访客填身份：
  - **`sso: proxy`**：`{user}` 是 `guest-<好友 ID 的前 10 位 base32>`。新加 `{display_name}` 和 `{role}`（`owner`、`member`、`guest`）两个模板变量。
    以 `guest-` 开头的用户名留给访客，人和 Bot 的用户名都不能用。
  - **`sso: oidc`**：Hydra 给访客发令牌，`sub` 同上，加声明 `wonton_role: guest` 和 `name`。
  - 插件自己登录（ADR-0022）：访客照样要过插件自己的登录，Wonton 不替他登录。
- 这个 ID 对同一个好友永远不变。多人游戏用它认玩家，用显示名显示。
- 插件清单新加 `webui.guests: true`，声明“这个插件给访客用过、知道访客是谁”。

### 授权和收回

- 授权是一条“插件 × 好友或组，可选到期时间”，记在 `core/shares.json`。
  在插件详情页“分享给好友”里设：选人或组，默认一直有效，也能选“1 小时”“今天”或者一个日期。
- 收回、到期、删好友、卸载插件以后：
  - 网关立即拒绝这个访客对这个插件的请求；
  - 网关记着每个访客在每个插件上开着的连接（包括 WebSocket），收回时当场断开；
  - 访客一项有效授权都不剩时，从访客名单里拿掉，iroh 连接用 403 关闭。
- 到期由核心按时钟判断，不靠好友的 App。

### 安全

访客能碰的只有被授权的插件的网页主机 `<slug>.<基础域名>`，以及这个插件网页自己的请求。别的一律 403 `share_required`：
- 核心的管理接口 `/_wonton/api/`（ADR-0017 的设备门只认设备，访客不是设备）；
- `matrix.<基础域名>`，访客没有 Matrix 账号；
- MCP 总线：它只在插件网络里，网关本来就不转；
- 文件服务、别的插件、核心的网页。

另外：
- 访客的请求不算“主人亲自操作”：确认卡片、放宽确认都和他无关。插件经总线调工具时，总线认的是插件，不是访客。
- 频率：每个访客每个插件有请求数和并发连接数上限，环境变量能改；超了 429。
- 插件在自己的应用里能做什么，由插件的用户权限管。主人分享一个没声明 `guests` 的插件时：
  - 确认页醒目写明“访客会以 `guest-…` 的身份登录这个应用，应用可能给他建账号、让他看到你的数据”；
  - 详情页给这个插件标“已分享给 N 个好友”。

### 失败即停

访客那边，各种情况分开显示：

| 情况 | 核心或 App 怎么知道 | 访客看到 |
| --- | --- | --- |
| 主人的服务器连不上 | iroh 连不上，或探活超时 | “某某的服务器连不上”，配重试 |
| 没有授权 | 网关 403 `share_required` | “某某没有把这个应用分享给你” |
| 授权已收回 | 网关 403 `share_revoked`（核心记着最近收回的） | “某某已停止分享这个应用” |
| 授权到期 | 网关 403 `share_expired` | “分享已到期” |
| 被删好友 | 访客名单里没有，iroh 用 403 关闭 | “你已不在某某的好友里” |
| 插件没在运行 | 现有的插件页状态（ADR-0033） | 同主人看到的状态，只是没有“启动”按钮 |

主人那边，“好友”页每个好友显示在线与否、最后一次用的时间、开放给他的插件。

## 和别的 ADR 的关系

- **ADR-0045（家人）**：家人有账号、能用所有对家人开放的插件、有私人 Bot。好友只有访客身份，只能用逐个授权的插件。
  一个人要从好友变成家人，走家人的邀请；两者不互相转换。
- **ADR-0050（跨服务器）**：配对服务器就是“有服务器的好友”。两者同一个好友列表、同一个出码扫码流程（`wonton/peer/0`）、同一份 `core/peers.json`。
  ADR-0050 设置首页的“其他服务器”改叫“好友”，`PeersViewModel` 的每项加一个“有没有服务器”。
- **ADR-0046（设备验证）**：那是同一个 Matrix 账号的设备之间确认，管的是聊天密钥。好友不进 Matrix，不用它。
  以后一人多台设备要合并时，可以借它“旧设备确认新设备”的做法。
- **ADR-0033（插件页）**：访客打开的插件页用同一个容器，桥照常给主题、语言。`ui/message`（切到聊天）对访客不可用：他在这台服务器上没有聊天。

## 理由

- 不建账号：身份是一把密钥，加好友是扫一次码，符合“服务器即账号”（ADR-0009），也不用为好友找回密码。
- 只多一个 ALPN、一份名单、网关里多一种身份。插件那边沿用 `sso: proxy` 和 OIDC，已有的插件不用改就能分清访客。
- 有服务器和没服务器的好友用同一套，免得出现“好友”和“其他服务器”两个列表、两套扫码。

## 没选的做法

- **给好友在主人的服务器上建一个受限账号**：账号要管密码或令牌、要清理，好友还会出现在 Matrix 里。这是家人的做法，好友不需要。
- **分享链接**（Nextcloud、Cloudflare Access 那种）：链接转发出去谁都能用，收回只能整条作废，分不清是谁。
- **好友身份复用连服务器的设备密钥**：一个好友 ID 就暴露了他连了哪些服务器，换服务器还会跟着变。
- **好友经主人的 Matrix 房间用插件**：插件网页不是聊天，硬塞进房间既慢又改了插件的用法。

## 代价与风险

- 访客的流量都经主人的服务器，多半走中继（ADR-0048），多人实时游戏的延迟取决于中继。
- 没声明 `guests` 的插件被分享后，插件里会出现 `guest-…` 用户，卸载授权不会替插件删掉它们。
- 好友身份在一台手机上，手机丢了、换了，主人那边要删掉旧的、加新的。
- 网关多一种身份，判断“这个请求能不能过”的地方都要认它。要写成测试：访客碰不到管理接口、Matrix、文件、别的插件、核心网页。

## 已定（主人 2026-11-06）

1. 没声明 `webui.guests` 的插件也能分享，确认页醒目提示。
2. App 开放“没有服务器、只用朋友分享的”这种用法。
3. 授权默认不到期，一直有效到主人收回；到期时间可以选。

## 验证

实现时写进这一节：
- 两台手机，一台配对了服务器、一台没有。加好友，分享一个多人插件，两个人同时玩，插件里认出两个不同的访客。
- 收回时访客的 WebSocket 当场断开，页面显示“已停止分享”。
- 访客用同一个连接访问管理接口、Matrix、文件、别的插件都是 403。
- 主人的服务器关掉，访客显示“连不上”，不是“没有授权”。
