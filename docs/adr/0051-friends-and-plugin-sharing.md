# ADR-0051 好友：云吞是标准的 Matrix 服务器，和整个生态互通，插件按人分享

- 状态：已接受（2026-11-08）：主人定了方向“完全 Matrix 那套，跟生态互通”，默认用我们送的名字，开工时间、迁移、花钱和推送见“已定”。
  2026-11-06 的版本（App 里一把好友密钥、访客通道 `wonton/guest/0`）和 2026-11-07 的两稿（好友在邀请人的服务器上开账号、好友只限配对过的服务器）都不要了

## 背景

主人想让朋友也用云吞，不管他有没有自己的服务器：

- 和自己、家人聊天，私聊、群聊都要，对方在哪台 Matrix 服务器上都行，包括 matrix.org。
- 用自己开放给他的插件，比如自己写的多人贪吃蛇，以自己的服务器当服务器，经 iroh 分发到每个人的 App 上。按插件、按人或按组授权，可以设到期，收回后立刻断开。
- 不是家人：家人有私人空间、私人 Bot、能用对家人开放的插件（ADR-0045）。好友只有聊天，加上逐个分享给他的插件。

主人的要求：
- “完全 Matrix 那套，跟生态互通”：一个人一个 Matrix 账号，好友是任何 Matrix 服务器上的人，加好友、聊天都用 Matrix 原生的做法。
- 加好友要对方同意（防骚扰、钓鱼）。
- 没服务器的人用生态里现成的账号（matrix.org 或别的公共服务器）。我们不运营公共账号服务，也不让人住在邀请人那里。
- 不造轮子：限制和防滥用先找现成的。

## 别人怎么做

调研笔记 chat-openid-probe、chat-identity-survey（2026-11-07，带出处）。

**一个 App 登录任意 Matrix 账号**：Element X、FluffyChat 这些客户端都是填服务器地址（或选 matrix.org）登录，账号在哪台服务器都一样用；
自家产品的功能（Element 的企业版管理、Beeper 的桥）只在自家服务器上有，换了服务器那些入口就不显示。

**把自家服务器接进公网 Matrix**：服务器名必须是真实域名，装好不能改（Synapse 文档原文，Tuwunel 实测拒绝启动）；
入口用 `.well-known` 委托到 443，家里不开端口时常见做法是小云服务器转发、Cloudflare Tunnel、Tailscale Funnel。
YunoHost、Sandstorm 给免费子域名但要求公网 IP；Home Assistant Cloud（Nabu Casa）给 `<随机>.ui.nabu.casa`，按月收费、中继只转密文。

**跨服务器认人**：Matrix 的 OpenID token。Element 的 widget、集成管理器、Element Call 的 `lk-jwt-service` 都这样用：
用户在自己的服务器上取一个一小时的 token 交给第三方，第三方去这台服务器的 `/_matrix/federation/v1/openid/userinfo` 换回用户 ID。
`lk-jwt-service` 2026-10 出过漏洞（GHSA-rq24-fh66-rq7x）：没核对换回来的用户 ID 是不是在它问的那台服务器上。规范因此写明调用方必须核对。

**挡垃圾**：
- MSC4155 邀请过滤：每个用户在账号数据里设“接受、忽略、拒绝谁的邀请”（按用户或服务器的通配），Tuwunel 1.9.4 已实现。
- Tuwunel 的配置：`forbidden_remote_server_names` 拉黑整台服务器，`block_non_admin_invites` 一刀切（连家人之间也拦），`forbidden_alias_names`、`forbidden_usernames`。
- Draupnir（AFL-3.0，独立运行的管理 Bot）：订阅社区共享的封禁名单，在主人管的群里自动封人、删垃圾。
- matrix.org 的做法：Synapse 模块、策略服务器（MSC4284，Tuwunel 部分实现）、专人审核。

**把应用开放给外人**（2026-11-06 查，出处见调研笔记 share-survey）：

| 产品 | 外人的身份 | 收回以后 |
| --- | --- | --- |
| Tailscale 节点分享 | 对方的 Tailscale 账号 | 移除设备立即断；只改 ACL 时，已建的 TCP 不断 |
| Plex Friends | 对方的 Plex 账号 | 删好友不收回库的访问；正在播的流播完为止 |
| Jellyfin、Home Assistant | 服务器上建本地用户 | 禁用或撤令牌时主动踢掉现有连接 |
| Nextcloud | 联邦共享认对方服务器上的账号 | 每个请求校验，下一个请求就失效 |

借鉴的几条：外人用他自己已有的账号，不在主人这里另开；收回要每个请求校验并主动拆掉长连接；跨服务器认人必须核对用户 ID 的服务器名。

## 用了哪些现成的

| 要的能力 | 用的现成的东西 |
| --- | --- |
| 账号、私聊、群聊、加密、多端同步、附件 | Matrix。云吞的 Tuwunel 和任何 Matrix 服务器联邦 |
| 加好友、同意、拒绝、屏蔽 | Matrix 的私聊邀请：接受、拒绝邀请；屏蔽用 MSC4155 和忽略名单 |
| 没服务器的人的账号 | 生态里现成的账号（matrix.org 等），App 用标准的 Matrix 登录（密码或服务器的 OIDC 登录） |
| 别家账号的推送 | 标准的 Matrix 推送网关接口，用 Sygnal（Apache-2.0，Element 官方的推送网关），接到我们已运营的推送中继（ADR-0003） |
| 服务器被外面找到 | `.well-known` 委托、ACME 证书；入口见“服务器名和入口” |
| 跨服务器认人 | Matrix OpenID token，实测 Tuwunel 按规范工作 |
| 挡垃圾 | MSC4155 邀请过滤、Tuwunel 的黑名单配置、Draupnir |
| 插件认人 | 现有的 OIDC（Hydra）和 `sso: proxy` 模板变量 |

**自己写的，以及现成的为什么不够：**
1. **核心替插件验别家的 OpenID token**：Tuwunel 只回答“这个 token 是不是我签的”，没有接口替我们去问别家（实测）。
2. **网关给本机的人补发邀请和发消息的限频**：Tuwunel 只有登录失败的限频（实测），MSC4155 只管收不管发。
3. **好友的 App 怎么找到主人的服务器**：一个 `.well-known/wonton` 文件写上服务器的 iroh endpoint ID（见“分享插件”）。iroh 是我们自己的隧道，Matrix 里没有对应的东西。

## 决策

### 云吞是标准的 Matrix 服务器

- 每台云吞的 Tuwunel 对整个 Matrix 开放联邦：任何 Matrix 服务器上的人都能和这台的人私聊、拉进群，这台的人也能加入别处的群。
- 前提是服务器名是一个真实域名、外面连得进来。默认用我们送的名字和入口（见“服务器名和入口”）。
- 配对过的云吞之间照旧走 iroh（ADR-0050）：配对过的服务器名在本机的地址映射里指向转发组件，不经公网。
- 加入别处的公开房间可以。本机建公开房间、发布到本机的房间目录第一版仍不放行（ADR-0045），会被搜到、被刷；以后要再开。

### 好友就是 Matrix 上的人，加好友用私聊邀请

- 好友是任何 Matrix 用户（`@bob:B`、`@xiaohong:matrix.org`）。主人的好友名单记在 `core/friends.json`：Matrix 用户 ID、显示名、主人给的分组、
  一个本机用户名（给插件用，见“分享插件”）。
- **加好友**：主人在 App 里点“加好友”，输入对方的 Matrix ID 或扫他的二维码（`https://matrix.to/#/@bob:B`）。App 发一个标准的私聊邀请
  （`is_direct`），房间里带一个状态事件 `app.wonton.friend`，标明“这是好友请求”。对方用任何 Matrix 客户端都看得到这个邀请。
- **同意**就是接受邀请：对方加入私聊，主人的 App 看到后把他记进好友名单。**拒绝**就是拒绝邀请。没理会，就一直是待处理的邀请。
- 反过来，别人发来的私聊邀请出现在云吞 App 的“请求”里（和服务器配对的请求放在一起的那一节，ADR-0050），不混在聊天列表里；
  带 `app.wonton.friend` 的标为“好友请求”。接受就成为好友。
- **屏蔽**：用 MSC4155 把这个人或整台服务器放进“拒绝”名单，之后他的邀请服务器直接拒；“请求”里留一节“已屏蔽”，能撤销。
- 好友只决定主人能把插件分享给谁。私聊本身照常，不是好友也能聊。
- **删好友**：从名单里拿掉，连带收回分享给他的所有插件；私聊留着，要退出自己点。

### 没服务器的人：用别家的账号登录云吞 App

- 云吞 App 能登录任意 Matrix 账号：添加服务器时多一个选项“用 Matrix 账号登录”，填服务器（默认 matrix.org），用那台服务器支持的方式登录（密码或它的 OIDC 登录）。
  一个账号一个槽位（ADR-0042），和自家服务器的槽位并列。
- 这样的槽位只有聊天，加上朋友分享给他的插件：

| | 自家云吞服务器 | 别家的 Matrix 账号 |
| --- | --- | --- |
| 私聊、群聊、跨服务器、加密、密钥备份 | 有 | 有 |
| 推送 | 经核心的推送代理 | 经我们的推送网关（Sygnal），只收事件 ID，App 自己取消息解密 |
| 好友、好友请求 | 有 | 有（请求就是私聊邀请） |
| 朋友分享的插件 | 有 | 有 |
| 自己的插件、商店、Agent、Bot、Wonton 私聊 | 有 | 没有 |
| 家人、私人空间、服务器设置 | 有 | 没有 |

- App 里别家账号的槽位：底栏只有“聊天”和“应用”（只列朋友分享的），设置里只有账号、设备、通知、语言，外加一条“有自己的云吞服务器？添加”。
  不显示灰掉的家人、Bot、商店入口。
- 推送：Matrix 服务器（比如 matrix.org）要一个公网能到的推送网关。我们在已运营的推送中继前加一个 Sygnal，按标准的 `/_matrix/push/v1/notify` 收；只收事件 ID，不收内容。
- 用 Element 这类别的客户端的人照样能和云吞的人聊天、当好友，只是打不开分享的插件（插件页要云吞 App 的隧道）。

### 分享插件

- 授权是一条“插件 × 好友或组，可选到期时间”，记在 `core/shares.json`，按 Matrix 用户 ID 记。
  在插件详情页“分享给好友”里设：选人或组，默认一直有效，也能选“1 小时”“今天”或者一个日期。
- **好友的 App 怎么找到主人的服务器**：每台云吞在公网入口上放一个 `https://<服务器名>/.well-known/wonton`，写着自己的 iroh endpoint ID 和中继地址。
  好友的 App 对每个带 `app.wonton.friend` 的私聊，取对方服务器的这个文件；有，就问这台“分享了什么给我”。只信经有效证书取到的 endpoint ID：
  OpenID token 不能交给冒充的 endpoint，否则它一小时内能拿去冒充好友。
- **好友怎么连过来**：App 直接拨主人的服务器，ALPN `wonton/share/0`，不经自己家的服务器转发。每次建连先在自己的服务器上取一个 OpenID token
  （`POST /_matrix/client/v3/user/{用户}/openid/request_token`）交给对方。
- **主人的服务器怎么认人**：
  1. 按 `matrix_server_name` 找到那台服务器：配对过的走 iroh（ADR-0050）；别的走标准的服务器发现（`.well-known/matrix/server`、SRV、8448），只认有效证书，
     不连内网地址、限超时和响应大小，发现结果缓存一小时。
  2. 去问 `GET /_matrix/federation/v1/openid/userinfo`，换回用户 ID。
  3. 用户 ID 的服务器名部分必须和 `matrix_server_name` 完全相等（端口、大小写归一后比），不是后缀匹配（GHSA-rq24-fh66-rq7x 的教训）。
  4. 查 `shares.json`，给这条连接一个会话，只能打开分享给他的插件。会话随连接结束；token 只用来建连，不当会话存。
- **插件怎么知道是谁**：和家人一样由网关填身份（ADR-0045 的“身份”）：
  - `sso: proxy`：`{user}` 是好友在主人这边的本机用户名，由核心按 ADR-0022 的规则生成，记在 `friends.json`，固定、不复用，不和本机账号重名。
    新加 `{role}`（`owner`、`member`、`friend`）模板变量，显示名用已有的 `{name}`。
  - `sso: oidc`：`sub`、`preferred_username` 是这个本机用户名，`groups` 是 `["friend"]`。
  - 插件自己登录（ADR-0022）：好友照样要过插件自己的登录。
  - 插件清单新加 `webui.friends: true`，声明“这个插件给好友用过、知道好友是谁”。
- **收回**（收回、到期、删好友、卸载插件以后）：网关立即拒绝这个好友对这个插件的请求；网关记着每个好友在每个插件上开着的连接（包括 WebSocket），收回时当场断开。
  好友的 App 下次问“分享了什么”时就没有了。
- 到期由核心按时钟判断，不靠好友的 App。
- 好友的请求不算“主人亲自操作”：确认卡片、放宽确认都和他无关。插件经总线调工具时，总线认的是插件，不是好友。
- 主人分享一个没声明 `webui.friends` 的插件时，确认页醒目写明“好友会以自己的用户名登录这个应用，应用可能给他建账号、让他看到你的数据”；
  详情页给这个插件标“已分享给 N 个好友”。

### 挡垃圾

开放联邦以后，家里这台成了公网上的一台小型 Matrix 服务器。先用现成的，网关只补缺口：

- **邀请**：本机每个人默认开 MSC4155，陌生人的邀请进“请求”，不直接出现在聊天列表；屏蔽的进“拒绝”名单。不用 `block_non_admin_invites`（会连家人之间也拦）。
- **整台服务器**：主人在设置里能拉黑一台服务器，写进 Tuwunel 的 `forbidden_remote_server_names`（可热加载）。
- **群里的垃圾**：主人管的群可以选装 Draupnir 插件（独立容器），订阅社区的共享封禁名单。和 Tuwunel 的配合没有实测，做插件时验证。
- **注册**：Tuwunel 照旧不开注册，账号只由核心建（ADR-0045）。
- **网关补的**：本机的人每分钟发邀请、发消息的上限（Tuwunel 没有）；好友的连接（`wonton/share/0`）每个 endpoint 的建连频率。上限由核心的环境变量改。
- **跟着漏洞升级**：Matrix 联邦近两年的严重漏洞（如 CVE-2025-30355、CVE-2024-31208）公告里都写着“封闭联邦不受影响”，开放后就受影响。
  Tuwunel 跟着官方版本走，核心升级时一起升（ADR-0025）；主人在设置里看得到 Tuwunel 的版本和有没有安全更新。

### 服务器名和入口：默认用我们送的名字（主人定）

服务器名装好就不能改（Tuwunel 实测改名后拒绝启动：数据库属于旧名字）。所以“和生态互通”的前提要在安装时定。主人定了：默认每台都用我们送的名字，自己的域名作高级选项。

**送的名字就是 ADR-0021 的家名**：注册时发的 `<家>`（8 位随机 base32，永不复用），服务器名是 `<家>.<域名>`，如 `k3f9qzab.<域名>`。
名字、入口、证书都照 ADR-0021 已定的做法，只多一条联邦的路：

- **入口**：ADR-0021 的中继（frps，按 SNI 转发、不解密）把 `<家>.<域名>:443` 转给这个家的连接器，再到家里的入口容器解开 TLS，交给核心网关。
  网关在这个名字上提供 `.well-known/matrix/server`（指向 `<家>.<域名>:443`）、`.well-known/matrix/client`、`.well-known/wonton`，把 `/_matrix/federation/`、`/_matrix/key/` 转给 Tuwunel。
  中继看得到哪台连哪台（SNI 和来源地址），看不到内容。
- **证书**：家里的服务器经 acme-dns 走 DNS-01 自己签 `<家>.<域名>` 和 `*.<家>.<域名>`，私钥只在家里；CAA 限定这个家的 ACME 账号（ADR-0021 的“家名服务和 DNS”）。
- **出站**：Tuwunel 直接从家里连别的服务器。配对过的云吞照旧经 iroh（ADR-0050），不经中继，省我们的带宽。
- **家里有公网 IP 的**：家名服务能把 `<家>.<域名>` 的记录指向这个家自己的地址，入口不经我们的中继，名字照旧是我们的。
- **安装时注册**：服务器名要在 Tuwunel 第一次启动前定，所以安装时就要连上家名服务注册。邀请制阶段（ADR-0021 的“防滥用和 PSL”）要邀请码；
  没有邀请码、不能联网，就只能用下面的高级选项。

**可配置、不捆绑**（同 ADR-0048 的中继）：家名服务和中继的地址由安装时的配置给（ADR-0021 的“入口的接口开放”），别人可以照同样的接口运营一套，或者主人自建一套。
但服务器名带着那套服务的域名：装好以后换一家运营的，就是换服务器名，等于重装聊天数据。入口（中继）可以换，名字不能换。

**安装界面如实写**（文字按 ADR-0043 放进本地化资源，大意）：“你的服务器会用云吞送的名字 `k3f9qzab.<域名>`，别人靠它找到你。
这个名字属于云吞：云吞停止这项服务，或者停用了你的名字，外面的人就联系不到你，账号也没法搬到别的名字上。你也可以用自己的域名（高级）。”

**滥用和投诉**：
- 家名服务能停用一个 `<家>`（ADR-0021 的 `Ping`、`NewUserConn` 钩子）：中继当场不再转发这个名字，联邦的人就连不进来；配对过的云吞经 iroh 不受影响。
- 限额照 ADR-0021：每个入口限速、每家并发连接和每月流量；联邦用这个家的一个入口，算在同一份配额里。
- 域名上公布投诉邮箱；安全浏览和证书透明日志监控照 ADR-0021。停用前先通知主人（核心每小时查一次家的状态），紧急的先停后通知。
- 我们只转发、不存内容，看不到消息；投诉能处理的只有“停用这个名字”。

**高级选项**：

| 选项 | 主人要准备 | 花费 | 代价 |
| --- | --- | --- | --- |
| 自己的域名 + Cloudflare Tunnel | 一个域名，DNS 托管在 Cloudflare | 一个域名的年费 | Cloudflare 解开 TLS，看得到谁和谁、什么时候（消息本身端到端加密）；单个请求最大 100 MB |
| 自己的域名 + 自己的小云服务器（自建 frps，ADR-0021 的“换成自己的域名”） | 一个域名，一台有公网 IP 的小云服务器 | 域名年费加小服务器的月费 | 要维护那台服务器 |
| 不要名字（随机的 `.wonton.internal`，只和配对过的云吞来往） | 什么都不用 | 无 | 加不了 matrix.org 上的人；和有名字的云吞也不通（对方要验证书，它只有自签证书）；以后要互通只能重装聊天数据、所有人换新账号 |

**我们要准备的**（邀请制开始前一周再买，见“已定（主人 2026-11-08）”；开发期间用测试域名和我们自己的机器）：

| 项 | 100 台 | 1000 台 |
| --- | --- | --- |
| 服务用的主域名（和产品官网分开，ADR-0021） | 一个域名的年费 | 同左 |
| DNS | 自建 PowerDNS 和 acme-dns（ADR-0021 的单机部署），不另花钱；或用带 API 的 DNS 服务商（Cloudflare 免费版、阿里云云解析免费版） | 公开注册前要两台以上权威 NS（ADR-0021 的“部署和被攻破的影响”），多一台小机器 |
| 入口机器的带宽 | 一台香港小机器跑全部（ADR-0021 邀请制阶段的做法）。联邦按每台每月 2–5 GB 估（聊天为主，附件被对方服务器拉一次），合计 0.2–0.5 TB | 合计 2–5 TB，上千条常驻连接；公开注册前要拆成中继、家名服务、两台 DNS（ADR-0021） |
| 每月大概 | 一台小机器加一个域名的月费 | 几台小机器加更多带宽的月费 |
| 别的 | — | Let's Encrypt 每个注册域名每周 50 张新证书，要申请提额或进 PSL；公开注册前要律师意见（ADR-0021） |

- 估算不含 ADR-0021 第三方 App 的流量（相册备份这类，每家每月上限 100 GB），那部分另算。
- 带宽按普通香港云服务器的行情估，线路好的（CN2 这类）贵几倍；真实流量取决于群里发多少图片和视频，上线后按中继的指标重估。

### 失败即停

好友那边，插件的情况分开显示：

| 情况 | 核心或 App 怎么知道 | 好友看到 |
| --- | --- | --- |
| 对方没有云吞，或没开分享 | 取不到 `.well-known/wonton` | 不显示，不算错 |
| 主人的服务器连不上 | `wonton/share/0` 连不上，或探活超时 | “连不上某某的服务器”，配重试 |
| 自己的服务器给不出 token | 取 token 失败 | 同连不上自己的服务器（槽位状态） |
| 认不出身份 | 网关 401 `share_identity`（token 失效、发现失败、用户 ID 对不上） | “某某的服务器认不出你”，详情里写原因 |
| 没有授权 | 网关 403 `share_required` | “某某没有把这个应用分享给你” |
| 授权已收回 | 网关 403 `share_revoked`（核心记着最近收回的） | “某某已停止分享这个应用” |
| 授权到期 | 网关 403 `share_expired` | “分享已到期” |
| 插件没在运行 | 现有的插件页状态（ADR-0033） | 同主人看到的状态，只是没有“启动”按钮 |

主人那边，“好友”页每个好友显示最后一次打开分享的时间、开放给他的插件。

## 和别的 ADR 的关系

- **ADR-0045（家人）**：家人照旧；家人也能加任何 Matrix 用户做聊天好友，分享插件只有主人能做。
- **ADR-0050（跨服务器）**：配对变成可选的快车道：配对过的云吞经 iroh 联邦，不经公网，也不用等对方有域名。没配对的 Matrix 服务器走公网联邦。
- **ADR-0042（多台服务器）**：槽位多一种别家的 Matrix 账号。
- **ADR-0033（插件页）**：好友打开的插件页用同一个容器，桥照常给主题、语言。

## 理由

- 主人要和生态互通：Matrix 的用户 ID 全网唯一，联邦本来就是“一个账号走到哪”，云吞做一台标准的 Matrix 服务器，聊天这边一行都不用另写。
- 没服务器的人用现成的公共服务器，我们不运营账号服务，不背审核、备案、停服的责任（调研笔记 chat-identity-survey 的“做法二”）。
- 加好友用私聊邀请，别的 Matrix 客户端也看得懂；屏蔽用 MSC4155，Tuwunel 已经实现。
- 跨服务器认人用 OpenID，是 widget、集成管理器、Element Call 都在用的标准，两边的服务器都已经实现。

## 没选的做法

- **我们运营一个公共账号服务**：本质是一台开放注册的公共 Matrix 服务器，大头成本是审核和合规（境内要 ICP、等保、实名），要运营主体；
  2025 年已有两台公共 Matrix 服务器扛不住而关停。生态里现成的公共服务器已经够用。
- **没服务器的人住在邀请人的服务器上**（本 ADR 2026-11-07 的第二稿）：账号归邀请人管，主人觉得不合理。
- **好友只限配对过的云吞**（同一稿）：加不了 matrix.org 上的人，不互通。
- **每个服务器给好友开一个账号**（第一稿）：一个人几个账号，不符合直觉。
- **好友的身份是 App 里的一把密钥，经访客通道用插件**（2026-11-06）：另成一套身份，聊不了天。
- **默认要求自己的域名**（自己的域名加 Cloudflare Tunnel，起初推荐的做法）：名字归主人自己，但装机前就要买域名、配 DNS；主人选了装机什么都不用准备的送名字。
- **自己做一套好友请求协议**：Matrix 的私聊邀请加 MSC4155 已经覆盖请求、同意、拒绝、屏蔽，别的客户端也认。
- **可搬家的身份**（Bluesky 的 DID、Nostr 的密钥、Matrix 的 MSC4014/4080/4243/4428/4430）：Matrix 的提案都没有实现，自己造就离开了生态。等 Matrix 的方案落地再接。

## 代价与风险

- 每台开了互通的云吞都是公网上的一台 Matrix 服务器：要跟着漏洞升级，会收到垃圾邀请，Cloudflare 或转发的机器挡不了联邦层的攻击。
- 默认的名字属于我们：家名服务停了或停用了某个家，那台服务器外面就联系不到，账号也搬不走（主人看过这条代价后选的）。我们要运营家名服务和中继、出带宽、处理投诉。
- 安装时要联网注册，邀请制阶段还要邀请码；不要名字的服务器以后改不了。
- 联邦流量多半经我们的中继，多一跳；配对过的云吞经 iroh 不受影响。
- 账号在别家服务器上的人，账号归那台服务器管（比如 matrix.org 能停用他），我们管不了。
- `.well-known/wonton` 和好友请求的状态事件是明文，好友所在的服务器看得到“谁加了谁做好友、谁有云吞”。
- OpenID token 一小时内能重复用，登出、停用都不撤销（实测）。好友的服务器停用了他，一小时内他还能连上主人的服务器；主人这边的收回不受影响。
- 推送多一个公网的 Sygnal，我们要运营它；它只看到事件 ID。
- 没声明 `webui.friends` 的插件被分享后，插件里会出现好友的用户，收回授权不会替插件删掉它们。

## 底座的问题

给上游 Tuwunel 提：
- 替调用方验别家 OpenID token 的接口（内部做发现和用户 ID 核对），核心这层就能删掉；
- 停用账号时删掉他的 OpenID token；`request_token` 按规范限速；
- 按用户的发邀请、发消息限额，网关这层可以挪回 Tuwunel；
- 没配 `[global.well_known]` 时默认回 404，端口一映射就要手写，建议自动生成。

## 已定（主人 2026-11-06）

1. 没声明 `webui.friends` 的插件也能分享，确认页醒目提示。
2. 授权默认不到期，一直有效到主人收回；到期时间可以选。

## 已定（主人 2026-11-07）

1. 完全用 Matrix 那套，和生态互通：好友是任何 Matrix 服务器上的人；没服务器的人用生态里现成的账号，我们不运营账号服务。
2. 加好友要对方同意。
3. 分享插件的流量直接连分享方的服务器，不经好友家转发。
4. 好友能自己建私聊、建群、拉人；Bot 默认不听好友的；好友数量不设上限。
5. 服务器名默认用我们送的名字（ADR-0021 的家名），入口是我们的中继；自己的域名和不要名字是高级选项。主人看过“名字属于我们，停了就失效，投诉归我们”的代价后选的；真正花钱前再确认。
6. 本机建公开房间、发布到房间目录，第一版不开。

## 已定（主人 2026-11-08）

1. 现在开工，第一个外人装上之前上线：名字装好改不了，先装的人以后要互通只能重装聊天数据。
2. 上线时主人自己的几台服务器把聊天部分清空重装，换成送的名字：聊天记录、主人和家人的聊天账号、Bot 的聊天账号、和别的云吞的配对都重来。
   插件和插件里的数据应当不受影响，上线前实测（见“验证”）。

   买了以后换配置，不改代码。
4. 用别家 Matrix 账号登录的人，推送由我们运营：Sygnal 和现有的推送中继（ADR-0003）放在一起。

## 验证

实现时写进这一节：
- 一台云吞用送的名字装好，`federationtester.matrix.org` 验过入口；停用这个家名后外面连不进来，配对过的云吞照旧能聊。
- 这台和 matrix.org 上的测试账号互加好友（邀请、接受、拒绝、屏蔽和撤销各走一遍）、私聊、建群；用 `federationtester.matrix.org` 验过入口。
- 用 matrix.org 的账号登录云吞 App：聊天和推送都通；底栏和设置里没有家人、Bot、商店；打开朋友分享的插件。
- 分享一个多人插件给配对过的云吞上的人和 matrix.org 上的人，两人同时玩，插件认出两个不同的好友；伪造 token、用户 ID 服务器名对不上、`.well-known/wonton` 证书无效都拒；
  收回时两人的 WebSocket 当场断开。
- 配对过的两台云吞照旧经 iroh 联邦，不经公网。
- 陌生人的邀请进“请求”；屏蔽的服务器的邀请被拒。
- 把一台装着插件、插件里有数据的服务器的聊天部分清空、换成送的名字：插件照常运行，插件里的数据还在，主人和家人重新登录后能打开插件。
