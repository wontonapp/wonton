# ADR-0057 可选权限：声明成默认关，主人自己打开

- 状态：已接受（2026-11-07）。方向由主人定（#36），细节由协调会话确认；补充 [ADR-0036](0036-plugin-privileges.md) 的“声明了就给”，不改它的分级、谁拿不到和卡片规则

## 背景

ADR-0036 的权限只有“声明了就在安装时给”，主人只能整装或不装。有的高权限对插件是加分项，很常见的环境里根本用不上，
或者主人暂时不想给：

| 插件 | 可选权限 | 关了会怎样 |
| --- | --- | --- |
| Beszel（ADR-0052 的设备状态面板） | `docker.socket` | 没有每个容器一格的 CPU 和内存；主机指标照常 |
| Jellyfin | `devices.gpu` | 转码走 CPU |
| Immich 的机器学习 | `devices.gpu` | 识别慢，或作者改用远端服务 |

主人 2026-11-07 定：Beszel 可以拿 Docker socket，但要做成可选的高权限，默认关；打开时醒目提示“这等于把主机的 root 交给插件”，
由主人自己决定，随时能关（#36、ADR-0052 的 Beszel 一节）。

现状只有两套“主人决定”的形状可以照：局域网网页的开关 `lan_webui`（ADR-0023，安装开关 + 详情页 PUT + 重建 + 存记录）和
设备级 `optional: true`（宿主缺这根串口时照常装）。ADR-0036 的三级提示、最高级单独确认、Bot 卡片规则都不够用：它们的默认值是“给”，
这里要多一个“不给”的默认。

## 决策

### 原则

- **可选只是默认值，不是更低的级别。** 权限的风险级别、提示文字、单独确认、Bot 的卡片规则一字不改；打开最高级仍然像安装时那样
  多点一步。
- **关着照常装、照常跑。** 可选权限不能变成“装不上”。关着的插件必须仍能用主要功能，作者逐项写明关着时少了什么。
- **默认关，选择必须显式。** 作者不能把可选项默认打开；请求里没带就是关，不看 `grant` 里有没有。
- **开关的状态、时间和发起人都留痕。** 主人和 Bot 都能开关，详情页要说清是哪一种。

### 允许可选的权限

`docker.socket`、`devices.gpu`、`devices.serial`、`devices.usb`。判据：关掉以后 compose 里能整段拿掉，插件还能运行。
`network.host`、`network.lan`、`cap.*`、`privileged` 决定网络形态或能否启动，暂不可选；`network.lan` 已经有 `lan_webui`。

### 写法

`x-wonton` 新增同级映射 `optional_permissions`，键是上面四项之一，值必须写 `off_loss`：一句给主人看的“关着时少了什么”，
和清单里其他文字一样按语言写（ADR-0043 的分工，核心给原文，App 只画）：

```yaml
permissions: [devices.gpu]          # 必需
optional_permissions:
  docker.socket:
    off_loss: { zh: 看不到每个容器的占用，主机指标照常, en: No per-container usage; host metrics still work }
```

- 同一项只能出现在一边，写成映射自然不重复。**`off_loss` 四种语言齐全**，和 `title`、`description` 一样；没写是清单错误，
  `plugin check --official` 也拦。
- 对应的 compose 字段照旧写在清单里，说的是“开着时谁拿到什么”（`docker.socket` 的卷、`gpu.services` 的服务名、
  `devices.serial` 的选设备块、`devices.usb` 的服务列表）；核心按开关决定渲染不渲染，**作者不用再写一遍映射**。可选和必需可以落在同一个
  服务上，拿掉按字段逐项做。
- `devices.gpu` 可选时不能再写 `requirements.gpu.need: required`（主人能关掉就不可能是必需）。

### 预览、请求、记录

- 预览的权限行加 `optional`、`enabled`、`off_loss`；可选项排在必需项后面，带原来的级别和提示，并逐个画开关，默认关。没有显卡
  这类情况只写 `notices`，不进 `blocked`。
- **必需项缺一不可，`grant` 多出的项必须是声明的可选项**：每一项必需权限都要在 `grant` 里，少一项拒；`grant` 可以带上可选项，
  但**它们不计为打开**；多出清单里没声明的项拒。可选项的选择只看请求的新字段 `enabled_permissions`，没带就是全关，
  值必须在声明的可选项里、不能重复、不能混必需项。
  - 老 App 不认识 `optional`，会把可选项一起放进 `grant`，也不带 `enabled_permissions`：按上面的规则接受，可选项全关，
    这是安全的方向。
- 安装记录新增 `enabled_permissions`（每项带打开的时间和发起人：主人，或带着 Bot 的 ID 和名字），`granted_permissions` 仍是必需项。
  渲染、健康检查、预览一律看两者的并集。
- 直接安装、升级和开关可选权限的 HTTP 接口只给主人；家人即使已有“能装插件”授权，也不能从这些入口改变权限。

### 装好以后

- 详情页每项可选权限显示现在开着还是关着、开着时是谁在什么时候打开的；开关走
  `PUT /_wonton/api/plugins/{id}/permissions/{permission}`，体 `{"enabled": bool}`。没声明成可选 → `invalid_input`；
  插件正在安装、卸载、重建 → `conflict`。
- 只重建**渲染结果真的变了**的服务：拿到或失去字段的，和引用了 `WONTON_PERMISSION_*`、环境变量跟着变的。其余服务不动，
  数据含在内照旧。只变变量而字段没变的也要重建：不重建它就一直拿着旧值，页面上的“容器明细已关闭”之类会撒谎。
- 失败时状态和容器都保持原样（关闭失败也如实显示仍开着，不假装关掉）。
- 打开最高级两步确认，第二步是“我知道这个插件能控制整台主机”；高级的 `devices.*` 一次展开提示即可。第二步由 App 画，接口不带标志。
- **Bot：打开要卡片，关闭是收权限。** 工具 `set_plugin_permission`：
  - `enabled: true`：每次都发确认卡片，最高级的卡片照最高级工具那样每行“以本机 root 身份”，不能被“始终允许”放宽
    （同 ADR-0036 最高级工具，审计 `basis` 是 `card`）。
  - `enabled: false`：按普通工具调用走 ADR-0024 的确认，可以放宽，不每次发卡。

### 插件怎么知道开没开

核心给**这个插件的所有服务**注入 `WONTON_PERMISSION_DOCKER_SOCKET=1`（另外三项同理 `_DEVICES_GPU`、`_DEVICES_SERIAL`、
`_DEVICES_USB`），关着时不注入。不只给拿到字段的服务：Beszel 的 Hub 网页不拿 socket，也要知道开没开，好显示“容器明细已关闭”。
值固定 `1`，`${VAR:+x}` 和 `[ -n "$VAR" ]` 都能判断；NVIDIA 显卡经 `DeviceRequests` 给，容器里没有节点可看，只有变量能覆盖四项。

### 列表

开着最高级可选权限的插件在已安装列表里带醒目标记（字段给列表项，不是只在详情页），主人不点进去也看得到哪个插件拿着 root。

### 升级

- 可选保留：沿用开关。
- 可选改成必需：**不自动生效**。之前开着的保持不变（现在算必需）；之前关着的当新加的必需项处理，标 `added`，必须确认，
  最高级照样两步。
- 可选去掉：记录清掉，字段不再渲染，预览提示。
- 新加可选：关。新加必需：标 `added`，必须确认。

### 边界

- **Agent 和 Bot 插件还是不能申请很高和最高级**，可选也不行。
- `plugin check` 校验：在名单里、`off_loss` 四语言齐全、字段落到位、不在两边重复、Agent 的级别限制不变。
- 官方索引审核：可选不放宽审核，最高级的“为什么要”照写；关着能用主要功能、`off_loss` 和 README 都对得上。

## 理由

- 和 ADR-0011“安全只做必要的”、ADR-0036“提示风险、主人决定”、ADR-0052 Beszel 的定位一致：能看主机状态本身不该以交出 root 为前提。
- 照 `lan_webui` 的形状走：安装预览开关、详情页 PUT、按记录重建、数据不动、失败回滚，都是现成路径，主人不用学新东西。
- 请求里单列 `enabled_permissions` 而不是“`grant` 里出现就算开”：老 App 会把可选项塞满 `grant`，混在一起就不再是显式选择；
  分开以后“没带 = 关”对任何客户端都成立。
- 关闭不每次发卡：关掉只减少权限，主人点一下就该生效；打开才需要重新确认。
- 变量注入所有服务而不是只看字段：状态要能被同插件的其他服务看到，否则只有容器内部知道。
- `off_loss` 进清单而不是审核文档：它是给主人看的，和别的说明文字一起走本地化，`plugin check` 能拦，预览和开关旁边直接用。

## 没选的做法

- **默认开、作者可改默认值。** 多一个字段，且和“主人自己决定”的初衷差不多。
- **`grant` 里出现即打开。** 老 App 会静默打开全部可选项。
- **安装时只提示、不记录开关，装完固定。** 主人想开还得重装，Docker socket 一旦给了就一直给。
- **任何权限都能标可选。** 要逐项想清楚关掉后的样子，先写死四项，以后按需扩。
- **把设备级 `optional` 合并成一种。** 那条轴说的是“宿主上可能没有”，和“主人给不给”不是一回事，合了就没法表达
  “必需权限、但设备可以不在”。
- **不加变量，只让插件看文件在不在。** NVIDIA 显卡在容器里没有节点，只看文件盖不住。
- **关掉的插件整个停掉。** 得维护服务级开关，作者也要写两套；启动一个空转的容器更省事。
- **Bot 关闭也发卡。** 收权限不值得每次都拦一下。
- **`off_loss` 只写在 README 或审核清单里。** 主人装的时候看不到，也没人校验。

## 代价与风险

- 又多一档主人要理解的权限状态；默认关的插件在预览里多一个开关和一句 `off_loss`。
- 关着能用的保证靠作者写清、审核把关；核心只做“字段拿掉”。
- 开关要重建容器，正在跑的任务断一次（同 `lan_webui`）；引用变量的服务都会被重建。
- 关闭失败时插件仍拿着 socket，界面必须说清，不能显示已关。
- 记录里多一份“谁在什么时候打开”的痕迹，Bot 打开过的能对上审计日志。

## 已定

负责人 2026-11-07 定：

1. 权限可以可选、默认关，方向照本篇。
2. `grant` 只放必需项，可选项走 `enabled_permissions`，没带就是全关；老 App 装出来的全关。
3. 可选改成必需不自动生效：之前关着的按新增必需项处理，之前开着的不变。
4. Bot 打开走卡片、不能放宽；Bot 关闭走普通确认。
5. `WONTON_PERMISSION_*` 注入所有服务，开关只重建渲染结果变了（字段或变量）的服务。
6. 详情页给出每项可选权限的状态和发起人；开着的最高级在列表上有醒目标记。
7. `plugin check --official` 要求每项可选权限有本地化的 `off_loss`，预览和开关旁边显示这句。
