# ADR-0122 一人一个主 Agent，多 profile 各是一个独立账号和私聊

- 状态：提议（2026-11-26 主人早会定 H3 方向，按 H3 起草；2026-11-26 主人拍板界面叫“分身”、主 Agent 的身份标签叫“主管”、名字由用户起；分身第一版都是私人的、像微信联系人，每个分身只在主人这里有一个私聊、不给家人用；主管和分身都能开辅助对话（私聊里的一个话题，同一套做法）；新建分身默认空白、可勾复制主管的技能和记忆；换主管后旧主管的辅助对话留在旧的那里、旧主管变成普通分身；删主管前必须指定继任；其余见“要主人拍板”）
- 补充：[ADR-0110](0110-one-hermes-container-per-person.md) 的 profile 模型，明确主 Agent、profile、会话三层，主 Agent 是第一个非默认 profile；不改运行组、一容器一人、加密设备唯一和四条 Bot 命令
- 关联：[ADR-0093](0093-side-chats.md)（辅助对话就是旁聊）、[ADR-0044](0044-bot-profile-and-status-avatars.md)（Bot 资料）、[ADR-0045](0045-family-members.md)（归属人）、[ADR-0088](0088-family-accounts.md)（角色与权限按 Bot）、[ADR-0108](0108-hermes-default-kernel.md)（默认内核）、[ADR-0123](0123-hubs-and-managed-devices.md)（运行位置与派活）

## 背景

主人 2026-11-26 早会定了 H3：

> 每人默认**一个主 Agent**——能开多个会话（一个主对话 + 随时开的辅助对话，比如聊 side project），背后都是同一个 Agent、共用记忆和技能。
> 同时支持用户自己再建多个 profile，每个 profile 是一个单独的 Matrix 账号 / 单独的私聊，各聊各的。
> 不同运行时、可能在别的机器上的 Agent，放到 host 层去管（更解耦，方便复用开源社区的设计）。Hermes 的 profile 本身是独立目录
> （配置、密钥、记忆、会话、技能、定时任务各是各的），但不是沙箱。

ADR-0110 已经定了“一个 Bot 就是一个具名 profile”、同一个人的多个 Bot 同容器、每个 Bot 独立账号和加密设备。H3 在这之上补两件：

- 一个人有且只有一个**默认**人格：日常聊天、派活、通知落款都落在它身上，多开的是它的会话，不是更多 Bot。
- 想要另一个身份时，用户自己建 profile：独立账号、独立私聊、独立目录，各聊各的；profile 不是会话，会话是 profile 里的时间线。

不补这两件会出两个问题：一是用户想“换个话题聊 side project”时被迫建一个新 Bot，账号和私聊列表越堆越多；二是分不清旁聊（ADR-0093）和 profile，把“另开一段对话”和“换一个身份”混成同一个动作。

## 决策

### 1. 主 Agent、profile、会话是三层

| 层 | 是什么 | Matrix 上是什么 | 共享什么 |
| --- | --- | --- | --- |
| 主 Agent | 一个人默认的那个 Agent，就是他的第一个私人 Bot | 一个 Matrix 账号、一个私聊 | 这个人对这个 Bot 的权限 |
| profile | 用户另外建的独立 Bot | 另一个 Matrix 账号、另一个私聊 | 同上，但身份、记忆、技能、定时任务各是各的 |
| 会话 | 主 Agent 或某个 profile 里的一条时间线 | 私聊里的主时间线，或一个话题（旁聊） | 同 profile 的记忆、技能、配置 |

- **主 Agent 不是默认 profile。** ADR-0110 的“默认 profile 只当宿主、不承载 Bot”照旧；主 Agent 是此人名下第一个非默认 profile。它的名字由用户在创建时自己起，核心生成唯一、不可改的 slug 作 Matrix localpart 和 profile 名；界面上它的身份标签是“主管”。默认 profile 永远只当宿主。
- **主 Agent 唯一。** 每人在自己的运行组里恰好一个；可以换（指定另一个 profile 当主 Agent）；角色不能空：停用主 Agent 前必须先设另一个 profile 为主 Agent，删主 Agent 之前同样先换。
- **辅助对话是会话，不是 profile。** 就是 ADR-0093 的旁聊：同一个私聊里的一个 Matrix 话题，新上下文、同一个人格、共享这个 profile 的记忆和技能，结束时在主对话里留一行结果；一次旁聊在 Matrix 上是一个话题，不是一个房间、更不是一个新账号。
- **分身第一版都是私人的，像微信联系人。** 每个分身只在主人这里有一个私聊，不给家人用；家人要用走共享 Bot 或群聊。共享 Bot 也是 Bot（profile），但它不是任何人的分身；分身只指私人 profile。
- **主管和分身都能开辅助对话。** 在各自私聊里开旁聊，做法和语义同第 1 条与 ADR-0093。
- **profile 是身份，不是会话。** 建 profile 就是建一个 Bot：新 Matrix 账号、新私聊、新 profile 目录，配置、密钥、记忆、会话、技能、定时任务各是各的。

### 2. 主 Agent 的职责

- 是这个人“找助手”的默认入口：新聊天、系统入口、快捷指令默认都落到主 Agent。
- 是这个人的通知落款：家里的提醒、派活结果、任务状态默认由主 Agent 发，不轮流由某个 profile 发。
- 是设备派活的默认发起方（第一版只有主 Agent 能派活，其他 profile 以后按需打开、默认关，见 ADR-0123）。
- 上面三项都不改变权限：主 Agent 和 profile 各算各的 Bot 权限（ADR-0088），主 Agent 不继承 profile，profile 也不继承主 Agent。

### 3. 用户怎么建、怎么切换

- 建 profile 在“我的 Agent”里：起显示名、选头像、写一句话介绍，核心给 slug 和 Matrix 账号；slug 此后不改，显示名和头像可改（ADR-0044）。界面里一律叫“分身”，不出现 profile 一词。
- 新建分身默认空白，可勾“复制主管的技能”“复制记忆”；复制是一次性的，之后各改各的。
- 主 Agent 和每个 profile 都是聊天列表里独立的一行；点谁进谁的私聊。没有“在同一个私聊里切 profile”的形态，Matrix 上本来就是两个账号。
- 分身出现在新建聊天列表，排在主管下面。
- 换主 Agent：在 profile 的资料页点“设为主 Agent”，核心把标记从旧的主 Agent 上挪走；旧的主 Agent 降为普通 profile，不删除。
- 把别的分身设为主管后，旧主管的辅助对话留在旧的那里，旧主管变成普通分身。
- profile 可以停用（ADR-0110 的停用标记）：停用后不回话、不出现在新聊天入口，数据还在。主 Agent 停用前必须先换（第 1 节），停用期间系统入口始终有落款。
- 一个人的 profile 个数只受内存约束：底价加每 Bot 增量，加之前核心按 ADR-0110 的口径核对主机内存，不够就如实报。

### 4. 记忆、技能和配置按 profile 隔离

- 同一个 profile 的所有会话（主对话和每个旁聊）共用这个 profile 的记忆、技能、模型配置、定时任务和凭据；这是“背后都是同一个 Agent”的落地。
- 跨 profile 不共享：主 Agent 的记忆不进 profile，profile 的技能不借给主 Agent。用户要复用，第一版先靠复制内容或导入导出，不自动同步；以后是否自动同步见“要主人拍板”。
- profile 不是沙箱：同一个人、同一个运行组、同一个容器，任何一个能读文件的 profile 都读得到同组其他 profile 的 `.env`、记忆和历史（ADR-0110 的风险原样）；要隔离的是身份和上下文，不是安全边界。
- 运行位置是另一层：profile 是身份单位，跑在哪台主机由 ADR-0123 的 host 层决定；搬 profile 时连同它的加密设备和目录整体搬，任何时候只有一个进程持有它（ADR-0110 第 2 节）。

### 5. 生命周期和兼容

- 建、删、停、恢复都走 ADR-0110 的四条 Bot 命令，不新增第五种机制；主 Agent 只是多一个标记。
- 注销/删除 profile：先停用，用户选保不保留数据，删账号前把主 Agent 标记挪走；删除主管前必须指定继任（另一个分身先设为主管）；被删的 slug 不再分配。
- 升级兼容：不写数据迁移（历史数据不回填），只做一次标记：存量安装里每个归属人的第一个私人 Bot 在第一次启动时标为主 Agent；插件级 `default` Bot 的归属人优先，其余没有私人 Bot 的归属人走“重建主 Agent”引导。新装引导先建这个人的第一个主 Agent（名字用户起），再允许建分身。绿地语义（AGENTS.md）。
- 通知和收件箱（ADR-0119）的条目带“来自哪个 profile”，主 Agent 的条目不带前缀；收件箱按人聚合，不按 profile 分页。

## 没选的做法

- **一人只有一个 profile**：用户想分开 work 和 side project 时只能新建 Bot，聊天列表和账号越堆越多，主 Agent 失去“默认”的含义。
- **旁聊用一个新房间**：房间要处理成员、邀请、通知、已读、离开，且 Matrix 上私聊本来就是一个房间；ADR-0093 已经用话题，不重复造。
- **换 profile 不换账号（同一个 Matrix 账号加前缀）**：两个身份能在同一个群里被分别 @、分别授权、分别有加密设备，共用账号做不到。
- **profile 当沙箱**：同容器同 PUID 才有热增删和共享底价；要安全隔离得开单独运行组，那是 ADR-0110 的“单独运行”，不是 profile 的默认语义。
- **主 Agent 可以没有或自动选**：系统入口、通知落款、派活发起方都指向一个固定身份，没有就要每次猜。
- **跨 profile 自动同步记忆**：第一版先让用户自己决定带哪段；自动同步会把 work 的上下文漏进 side project。

## 理由

- 一个默认人格降低日常摩擦：聊天、派活、通知都只有一条路，用户不用每次先想“用哪个 Bot”。
- profile 独立账号符合 Matrix 原生模型，也复用 ADR-0110 已有的创建、删除、停用和加密设备机制，核心不新增生命周期。
- 会话和身份分开后，旁聊（ADR-0093）不用改，只是主 Agent 或 profile 里的用法。

## 代价与风险

- 同容器同 PUID，profile 之间读得到彼此的凭据和历史（ADR-0110 已列）；要隔离只能让 profile 单独运行。
- 用户会混“旁聊”和“profile”：界面文案要把“在这段对话里聊”和“换一个身份”分开，文案待定（见“要主人拍板”）。
- 每个 profile 多付一份容器底价之外的少量增量；记忆和技能各一份，用户要自己维护重复内容。
- 主 Agent 被删时若用户没换好，系统入口和通知短暂没有落款，核心要拦在删除前。

## 待验证

1. Hermes 多路复用对每个 profile 的 `display_name`、头像、`ui_meta['hermes-bots']` 是否都按 profile 生效；换主 Agent 只改标记、不重建容器。
2. `hermes profile create/delete` 在热增删下的时延和失败语义（ADR-0110 验证过 `create` 5 秒内被服务，未验证主 Agent 标记的迁移）。
3. 旁聊和 profile 在同一个 App 会话列表里的排序、未读和推送是否互不串台。
4. 主 Agent 换人后，系统入口、通知落款、派活发起方三个读点是否都跟着换，旧主 Agent 的旁聊是否还在。
5. 停用主 Agent 前必须先换：换完再停用，标记是否跟着走，系统入口是否落到新主 Agent。
6. 一个人的 profile 数达到内存上限时，核心是否在创建前拒绝并给出可执行的下一步。

## 要主人拍板

1. **跨 profile 复用记忆和技能**：第一版靠复制或导入导出；以后要不要自动同步？同步哪些、单向还是双向？
2. **旁聊和分身的界面文案**：怎么把“在这段对话里换上下文”和“换一个身份”说清楚？
