# ADR-0123 一户一个枢纽、其他电脑是受管设备：主 Agent 派活，设备上的 herdr 执行，权限进收件箱

## 背景

- **一台设备只属于一个枢纽。** 第一版一台电脑只挂一个枢纽，不能同时注册两个；换枢纽就是迁移或重新入网，同一时刻只有一个守护进程实例和一把设备密钥（第 4 节）。

> M1 一户一个枢纽，可以是 Linux 服务器，也可以是装了自带虚拟机内核的 Mac 或 Windows；App 能连多个枢纽切换；其他机器作为受管设备挂在某个枢纽下。
> M2 主 Bot 决定把任务派到哪台机器，不每次问用户。M3 Agent 在机器上的权限挡位由那个 Agent 工具自己的设置决定，权限请求转到收件箱：
> 允许一次 / 总是允许 / 拒绝 / 拒绝并说明；总是允许按来源 + 会话 + 命令记住，超时自动拒。M4 不细控上下文，目标机上的 Agent 用自己的工作区。
> M5 目标机离线就排队、过期作废并通知。M6 监工和会话在枢纽上。M7 承载用 MCP 任务工具 + iroh 隧道 + 每台机器的 herdr
> （herdr 自带多机只靠 SSH，没有中继/打洞；我们像 Alma 的 herdr-remote 那样用自己的隧道接）。M8 参考 T3 Code 的多机设计，不直接用。
> H2 Hermes 访问的海外站点不通时静默降级，我们在设置里如实标出哪几项慢或不可用。

今天所有 Agent 都跑在枢纽的容器里（ADR-0110、ADR-0108）。手机、Mac、PC 只是客户端；用户电脑上已经装好、登录好的 Codex、Claude Code 用不上，家里的旧笔记本、台式机也帮不上忙。ADR-0081 设计过“用户电脑上的 Agent”，但只做了“一台电脑当一个远端 ACP 运行时”，没有枢纽、没有设备群、没有派活和收件箱。

T3 Code 把“运行环境（Environment）、访问端点（AccessEndpoint）、怎么启动（Launch）”拆开，值得学；Alma 的 `herdr-remote` 用自己打的隧道把远端 herdr 接进控制面，证明了 herdr 适合当执行器但不适合当控制面；herdr 自己的多机只走 SSH、没有中继和打洞，不能直接当我们的传输。

## 术语

| 词 | 含义 |
| --- | --- |
| 枢纽（hub） | 一户一台常开的服务器。Linux + Docker，或者 ADR-0062 的自带 Linux 虚拟机。跑核心、Tuwunel、调度器和监工；本身也是一台 `hub-local` 受管设备 |
| 受管设备（device） | 挂在某个枢纽下的一台电脑。跑守护进程和 herdr，在本地工作区执行任务；不是 Matrix 用户，不是 Wonton Bot |
| 设备守护进程（device daemon） | 我们发布和签名的小进程。只做设备侧的入网、任务拉起、权限转发、产物收集和心跳；没有 Matrix 令牌，没有住户密钥 |
| 派活（dispatch） | 主 Agent 经核心 MCP 工具把一个任务交给某台设备。派活本身不弹确认，设备授权是事先给的 |
| 任务（task） | 一次派活。有目标设备、工作区、交代、截止时间和权限挡位。任务记录、会话和审批都在枢纽上 |
| 工作区（workspace） | 设备上任务专用的目录，从仓库检出或直接指定；不属于任何 profile，第一版任务结束不自动清理、用户手动删 |
| 调度器（dispatcher） | 核心里的服务：设备注册表、任务表、路由、队列、产物核对、权限桥接 |
| 监工（supervisor） | 枢纽上的任务会话记录和状态机：进度、审批、追问、产物、结论；App 在这里看和接手 |

## 决策

### 1. 枢纽是常开的服务器，设备是挂在下面的执行面

- **一户一个枢纽**，默认就是家里的服务器；可以是 Linux 主机，也可以是 Mac、Windows 上的内置虚拟机（ADR-0062）。枢纽 7×24 在线，跑核心、Tuwunel、调度器、监工和收件箱；不允许进入睡眠模式才算合格，睡着了就按离线处理。
- 界面词：服务器一律叫“家里的服务器”，设备显示电脑自己的名字（如“某某的 MacBook”），界面不出现“枢纽”“受管设备”。
- **一台设备只属于一个枢纽。** 第一版一台电脑只挂一个枢纽，不能同时注册两个；换枢纽就是迁移或重新入网，同一时刻只有一个守护进程实例和一把设备密钥（第 4、5 节）。
- **枢纽自己也是一台设备**（`hub-local`），默认存在、默认执行器；没有额外电脑的家庭只用这一台也能派活。它和别的设备走同一套任务协议，核心不给自己开后门。
- 一个家庭只装一套核心：枢纽就是 ADR-0009 的“服务器”。设备是它下面的执行面，不跑核心、不跑 Tuwunel、不存住户身份。

### 2. 设备上跑什么

- 第一版设备只支持 macOS 和 Linux；Windows 下一期，不在第一版验收。枢纽本身仍照 ADR-0062 可以是 Mac、Windows 上的内置 Linux 虚拟机。

只跑三样：

1. **设备守护进程**：我们签名的 Rust 小程序。入网、拿任务、起停 herdr、转发权限、收产物、报心跳和负载；不开端口、不接管系统。
2. **herdr**：固定版本、按摘要安装（Apache-2.0）。一个任务一个 workspace、一个 tab、一个 pane；pane 里跑用户自己装的 Agent（Claude Code、Codex、omp 等），herdr 负责终端、会话、状态和断线保活。
3. **用户自己装的 Agent CLI**：用设备上的登录和配置，不经过 Wonton 的模型网关。守护进程不代理模型流量。

设备守护进程**不跑**：核心、Tuwunel、Matrix 客户端、profile 记忆。设备 Agent 用自己的工作区、自己的登录、自己的技能；邻居的 profile 和记忆留在枢纽（M4）。

和 [ADR-0081](0081-local-agent-host.md)、[ADR-0124](0124-client-react-pwa-electron.md) 的 Electron 三角色不是一回事：受管设备是枢纽下的执行面（守护进程 + herdr，执行派活），不是 Matrix 客户端；Electron 包是客户端、本机 Agent 主机、被控端三个角色，本机 Agent 主机是 Bot 的 ACP 运行身份，被控端是远程桌面。同一台电脑可以同时是受管设备又开着 Electron：设备守护进程用设备密钥，Agent 主机用主机身份，两把钥匙、两个开关，不复用；设备守护进程不跑 Matrix 客户端，Electron 的客户端和主机是另一组进程。本 ADR 与 #1084 都改 0081 和 ARCHITECTURE：先合一个、另一个 rebase，合完核对 `0081:3-4` 自洽。

### 3. 枢纽上跑什么

- 调度器、设备注册表、任务表、队列、监工、收件箱桥、产物核对和审计。
- 主 Agent（ADR-0122）经 MCP 工具发任务；这里只信主 Agent 和用户的身份，不信设备的结果。
- 监工持有任务会话：派给谁、为什么、进度、审批、产物、结论。App 在聊天里看到的是这条会话；设备只是把原始事件送上来。
- 用户随时能停整条任务（第 7 节）；停完保留记录，产物保留在设备或上传的产物里。

### 4. 设备加入、身份和信任

- **配对码来自枢纽**，格式照 ADR-0009 的 v=0 直接码（网页 relay 码是 v=2，见 ADR-0124），一次性、10 分钟、绑定一个住户；在已配对的设备上出码（住户自己的或管理员的）。设备守护进程装上后输码，生成设备密钥对（ed25519），把公钥和指纹交给枢纽。
- **住户批自己的电脑，管理员可批任何设备**：住户本人在已配对设备上核对指纹后批准；管理员可批准任何设备（含家人和别人的）。批准页列设备名、系统、架构、可用 Agent、工作区根、磁盘剩余；批准后设备才拿到任务。设备没有 Matrix 账号，进不了群、答不了卡片。
- **设备密钥即设备身份。** 枢纽按设备 ID 记录，密钥轮换 = 重新入网；吊销 = 枢纽删公钥并断开隧道，设备下一次心跳被拒。
- **设备默认不可信**：可能装了恶意 Agent、被拿走、连过不安全的网络。枢纽只信两件事——设备签名的心跳和产物哈希；设备说的“做完了”要核对（第 8 节）。
- **设备归属人**是批准它的住户（管理员代批时归设备使用者）；归属人管“谁能在这台设备上派活”和“能访问哪些目录”。默认只有归属人自己；归属人可在设备设置里打开“家人也能用”，打开后家人能往这台电脑派活，任务仍在电脑上登录的那一个用户下跑。

### 5. 设备控制面：守护进程 + iroh，不用 SSH

- 守护进程拨出到枢纽（ADR-0004 的 iroh 隧道），走中继或打洞，和手机、插件同一条隧道栈；连接由设备发起，枢纽不用有公网地址，设备也不开入站端口。
- **每台设备一条控制连接**，上面只跑我们的任务协议（第 6 节，QUIC 流 + 少量数据报用于取消和心跳）；herdr 的控制面在设备本机，由守护进程用它的 CLI 或本地 socket 驱动。
- **不用 `herdr --remote` 的 SSH 路径**：SSH 打不了洞、要端口和密钥管理，和 ADR-0009 的设备身份是两套。herdr 只当本机执行器；多机由我们的隧道承担（像 Alma 的 `herdr-remote`，只是隧道换成 iroh）。
- **控制面只依赖 herdr 的公开接口**：起 workspace/tab、往 pane 发送、读 pane 状态、结束 pane。herdr 升级只影响适配层，不影响任务协议（待验证：herdr 的 CLI 与 socket API 稳定性，见“待验证”）。
- ADR-0015 的检查单：

| 项 | 这里是什么 |
| --- | --- |
| 契约 | 第 6 节的任务协议 + MCP 工具 `wonton__dispatch_task` / `wonton__task_status` / `wonton__task_cancel`；设备控制面只认 herdr 公开接口 |
| 提供方 | 设备守护进程（参考实现随核心仓库发布）；herdr 是第一家执行器适配，适配层可换 |
| 消费方 | 核心调度器（第一个真实消费者）；主 Agent 只经 MCP 工具，不直连设备 |
| 契约测试 | `crates/wonton-core/src/device/tests/device_contract/`：一个假守护进程按协议跑通派活、权限、取消、产物、断线重连；另有一组 `#[ignore]` 的真 herdr 冒烟 |

### 6. MCP 任务工具的形状

派活是一个核心 MCP 工具，归在 `wonton__` 前缀下。新增权限项 `tasks`（进插件规范的权限表和安装预览），第一版只有主 Agent 能派活，其他 profile 以后按需打开、默认关（ADR-0122）。

```json
// wonton__dispatch_task
{
  "brief": "自包含的交代。目标机 Agent 看不到聊天，写清做什么、边界、怎么算做完",
  "device": "auto | <device-id> | hub-local",
  "workspace": { "kind": "repo", "remote": "…", "ref": "main" }
             | { "kind": "path", "path": "~/code/site" },
  "done_when": "跑通 pnpm build，提交到分支 fix/x，附 diff",
  "permission": "read_only | standard | trusted",
  "limits": { "timeout_s": 3600 },
  "deadline_at": "2026-11-26T18:00:00Z",
  "artifact": ["diff", "branch", "files", "log"],
  "origin": { "room_id": "…", "thread_root": "…" }
}
→ { "task_id": "…", "device": "…", "state": "queued", "why": "auto 选它的原因" }
```

`permission` 是给守护进程选 Agent 启动参数和提示的三档，不替代 Agent 原生审批（M3）；映射以适配层实测为准：

| 档 | 允许什么 | 示意映射 |
| --- | --- | --- |
| `read_only` | 读文件、跑只读命令，不写工作区 | Claude Code `--permission-mode plan`；Codex `--sandbox read-only` |
| `standard` | 工作区读写、装依赖、跑测试（默认） | Claude Code `--permission-mode default`；Codex `--sandbox workspace-write` |
| `trusted` | 任意命令、网络和包管理，按原生模式自动接受编辑/命令，仍受原生开关约束 | Claude Code `--permission-mode acceptEdits`；Codex `--sandbox danger-full-access` |

- `device: "auto"` 由调度器按第 7 节挑；挑不出来回 `no_device` 和候选原因（离线、没装这个 Agent、没有目录、负载高、没授权），不静默换到枢纽本地。
- 返回是异步的：工具立刻回 `task_id`，进度、审批、产物经 `wonton__task_status` 和收件箱回；主 Agent 不阻塞等结果。
- `wonton__task_status` 只读：状态、阶段、最后活动、待批项、产物引用；`wonton__task_cancel` 发取消，幂等。
- 同一个 `idempotency_key` 重复派活回同一个任务；设备离线时不重复投递（第 7 节）。
- 长任务的最后一步永远是“产物 + 结论”：设备把 diff、分支、文件、日志按协议上传到枢纽的产物区，超出大小走文件服务；枢纽核对哈希后交给主 Agent，主 Agent 再决定要不要合并、回复、转交。

### 7. 路由、队列、取消

- **路由由主 Agent 发起、调度器决定**（M2：不每次问用户）。输入：设备能力（系统、架构、装了什么 Agent）、存在与负载、工作区匹配（仓库在不在那台机器上）、住户授权、用户偏好（“这台机器只跑 Mac 的活”）。主 Agent 可以指定 `device`，也可以交给 `auto`。
- **决定要能解释**：任务卡写明“派到 <设备名>，因为它有仓库副本 / 因为 X 不可用”，用户能一键“换一台”“总用这台”“别用这台”。
- **主管派活不问，已授权的电脑直接派**：设备授权和 Agent 自己的权限挡位是事先给的（第 4 节、ADR-0024），第一次也不弹确认；真正要人拍的每一步由 Agent 自己的审批触发（第 8 节）。
- **排队只在枢纽**：设备离线、满负载、超过并发就排队，队列条目带截止时间。设备上线后按先来后到投递；同一住户的队列有上限。
- **不在任务中途换设备**：设备掉线先标 `offline`，宽限期后标 `uncertain`，不自动到另一台重跑（可能有半成品）；用户看到后手动“重派”或“继续等”。
- **过期作废并通知（M5）**：过了 `deadline_at` 或超过队列上限，任务标 `expired`，给发起人和设备归属人各一条收件箱 `notice`（warning），写清哪台设备、为什么没排上或过期、有没有留产物；主 Agent 收到 `recap`，可决定重派。不无限等，不自动重派。
- **取消随时有效**：`wonton__task_cancel`、任务卡的“停”、设备被吊销都走同一条路——枢纽停止投递，守护进程给 pane 发取消（herdr 的 Esc/Ctrl-C 或 ACP `session/cancel`），收部分产物，标 `cancelled`；取消不保证回滚已经落盘的文件，按“已发生的副作用”写清楚。

### 8. 权限：Agent 自己的挡位 + 收件箱

- **挡位由设备上的 Agent 工具自己决定**（M3）。Claude Code、Codex 的允许/拒绝规则、白名单、`settings.json` 都是它们的；我们不改、不复制，只在两边之间搬。
- 设备的 Agent 发出权限请求时，守护进程把它变成收件箱里的 `confirm`（ADR-0119）：`choices` 固定为 `approve`（允许一次）、`session`（本会话内同类允许）、`always`（总是允许）、`deny`（拒绝）；`deny` 可带 `comment`（拒绝并说明，≤200 字），发送方要求理由时 `requires_comment: true`，核心校验非空，不新增第五个 choice；`risk` 用 ADR-0036 的 `high`/`very_high`/`highest`。
- **“总是允许”的键是（设备、来源会话、命令签名）**：默认只在任务内有效，发送方可在条目里选 7 天；同一户、同一任务、同一条命令再来时自动答，改了命令就重新问。换工作区重新问，跨设备不继承。
- 超时默认 10 分钟自动拒绝（ADR-0119 的阻塞条目时限）；批完的条目留审计，App 能回看是设备、哪条命令、谁批的。
- 权限请求能在收件箱里批，也能在设备的终端里原生批；两边都行，以先进来的为准，另一边收到 settled 后撤卡。
- **设备 Agent 的“危险模式”照它的原生开关**（`--dangerously-skip-permissions`、YOLO 模式）：开了就少问，任务卡上标明“此类任务在这台设备上不再逐条问”；关着就逐条进收件箱。
- **住户权限不等于设备权限**：住户能在设备上派活，不代表设备 Agent 就能读住户的所有文件；设备 Agent 只看得到工作区根（第 9 节）。
- 主 Agent 的 Wonton MCP 工具（文件、插件、发消息）照旧走核心确认；设备 Agent 直接改的是设备本地文件，不经过核心，任务卡如实写“设备本地”。

### 9. 工作区、文件与隔离

- 每台设备有 **工作区根**（例：`~/wonton/work` 或 `/srv/wonton`），由归属人批准；任务只能写这棵树，守护进程按根做路径校验，越界拒绝。
- 一个任务一个目录：`<根>/<task_id>/`，从 git 检出或直接指目录。第一版产物不自动清理：设备工作区和枢纽产物区都留着，App 显示占用，用户手动删；磁盘满时如实报错。
- 设备上的 Agent 以**设备登录用户**身份运行，不建每人一个系统用户（第一版）；多住户共用一台设备时，住户之间靠工作区目录分开，不靠 OS 用户隔离，风险照实写。
- 设备 Agent 用电脑上自己登录的账号（GitHub、模型），不传住户的模型或仓库凭据；凭据只在设备上，由电脑主人自己登录。
- 产物只回上传：diff、分支名、文件、日志；设备上的工作区不反向同步到枢纽；要长期保存的任务显式上传产物。

### 10. 离线、断线、恢复

- **设备离线**：已在跑的任务继续在设备本地跑；枢纽标 `offline`，App 显示最后一次心跳；排队任务继续等，过期作废（第 7 节）。
- **断线重连**：守护进程按指数退避重拨；重连后先对账——哪些任务在跑、哪些在等审批、哪些已完成没上传；枢纽按设备报的进度校正，不重放已完成步骤。
- **设备掉电或崩溃**：任务标 `uncertain`；守护进程重启后扫描自己的任务目录，能接上的接上（herdr 的 pane 恢复不了就重开并附上“已中断”），接不上的标 `failed` 并附日志尾部。
- **枢纽离线**：设备继续跑当前任务，事件先写本地缓冲；超出任务截止时间就自行收尾并把结果留到重连，重连后补传。枢纽回来前 App 看不到进度，如实显示“枢纽离线”。
- **设备证书被吊销**：重连被拒，设备本地任务照常收尾但传不回来；App 标“设备已移除”，产物留在设备上直到重新入网。
- **不自动重试副作用**：下载、编译、改文件这类步骤不做幂等承诺；只有 Agent 自己说“可重试”时才重试，否则交给用户。

### 11. 多枢纽和 App

- App 用 ADR-0042 的服务器槽位保存多个枢纽，一次连一台，切换就是换槽位；每个枢纽有自己的设备列表、任务和收件箱。
- 一个设备只在一个枢纽下（第 1 节），第一版不能同时挂两个；跨枢纽派活第一版不做，靠“这台设备挂在哪个枢纽”决定。
- 同一台手机可以是自己家的主人、爸妈家的家人（ADR-0042 已有）；设备归属人按枢纽算，不跨枢纽合并。
- 跨枢纽的 Bot 通信仍走 Matrix 联邦（M3），不经过设备协议。

### 12. 网络现实与降级（H2）

- 设备上的 Agent 访问海外站点（模型 API、npm、GitHub）不通时，**不装作成功**：任务卡和收件箱写清是哪一步、哪一项慢或失败；能走设备自己的出网就走，走不了就报原因（设备借用枢纽出口代理是待验证项，ADR-0023）。
- 设置里有一页“网络”如实列出：本机到枢纽的路径（直连/中继）、枢纽到模型/仓库的探测结果、哪些功能因为网络暂不可用。不写“现在可用”这类会过时的句子，写状态和最后一次探测。
- 静默降级只允许发生在“有等价的本地方案”时：例如远程模型不通、但设备上有本地模型且用户开了；否则报错。
- n0 中继不可用、直连也打不通时，任务排队并标“隧道不可用”，不把“已派活”说成“设备已收到”。

### 13. 安全模型

| 威胁 | 约束 | 剩下的风险 |
| --- | --- | --- |
| 设备被拿走或被入侵 | 设备只有任务工作区和设备密钥；没有 Matrix 令牌、没有住户凭据；吊销即断 | 设备上有住户的项目代码和任务期间写入的秘密；拿到设备的人能读 |
| 设备伪造“做完了” | 枢纽核对产物：git 对象哈希、diff 可重放、日志校验；结论由主 Agent 复核 | 设备可以在工作区里写入恶意代码；合并前要人看 diff 或 CI |
| 恶意提示注入 | 设备 Agent 和工作区都当不可信输入；主 Agent 只信自己的结论和核对过的产物 | 模型被工作区里的说明文件带偏 |
| 住户 A 读住户 B 的活 | 工作区按任务分目录、路径校验；不共享 OS 用户 | 同一 OS 用户下能读 `~/` 其他目录；按根校验是尽力而为 |
| 设备被当作跳板进内网 | 设备本来就在家里网络里；出网走设备自己的网络或枢纽代理 | 设备能访问它所在的内网，和用户在这台电脑上手动做一样 |
| 派活被冒充 | 只有枢纽签发的设备密钥能连；派活只来自主 Agent 或有 `tasks` 权限的 profile | 主 Agent 自身被攻破时，等于住户被冒充 |

- 设备守护进程不开监听端口，只拨出；所有入站都经 iroh 流。
- 设备 Agent 的权限不用 ADR-0024 的“30 分钟内都允许”窗口（同 ADR-0081）：只有允许一次、本会话、总是允许、拒绝并说明；`session` 只放内存，会话结束、设备断线、吊销或核心重启就失效；超时 10 分钟自动拒。
- 设备被删时先撤任务、再删密钥；设备上的工作区由归属人决定清不清，枢纽不远程删设备文件。

### 14. 和 ADR-0110、ADR-0122 的关系

- ADR-0110 的容器、运行组、加密设备唯一不变：主 Agent 和 profile 仍是枢纽容器里的 Bot。
- 设备执行的是住户交代的任务，不把 profile 搬到设备上；profile 记忆、技能、定时任务都在枢纽（M4：不细控上下文）。
- 以后允许“整个 profile 跑在设备上”时，按 ADR-0015 另做运行时提供方，不在这一版混着做；那时设备要能跑 Hermes 容器/运行时，见“待验证”。

### 15. 不做

- 不用 SSH 当设备控制面（`herdr --remote` 只能本机装、要端口和密钥）；不把 herdr 的控制面暴露到公网。
- 不用 k8s、Nomad、云控制面；一台设备一个守护进程，直连枢纽。
- 不做远程桌面（ADR-0081 的另一半，另写）；设备只跑 Agent，不投屏。
- 不做每住户一个 OS 用户、不做设备上的多用户沙箱（第一版一个 OS 用户）。
- 不做跨枢纽派活、不做设备之间互派；由主 Agent 经枢纽转。
- 不让设备 Agent 直接拿 Wonton 的 Matrix 令牌或住户凭据。
- 不把 profile 记忆同步到设备；brief 是唯一上下文。

## 没选的做法

- **SSH + `herdr --remote`**：NAT 下要端口映射或跳板，设备身份和 ADR-0009 是两套，多机切换靠 SSH config；iroh 已经有打洞、中继和身份。
- **设备当 Wonton Bot、直接登 Matrix**：设备要存 Matrix 令牌和加密密钥，掉线、重装、吊销都要重做；而且设备 Agent 的发言会被当成 Bot，和主 Agent 的会话割裂。
- **把 profile 整个跑在设备上**：第一版设备只有 Agent CLI，没有 Hermes 运行时；先做“派活 + 产物”，再谈搬 profile。
- **枢纽下发记忆和技能到设备**：设备 Agent 的上下文会随枢纽变化漂移，且推送时机难；先只给 brief 和工作区。
- **每个任务新开一台一次性虚拟机**：干净但慢、贵，家里设备本来就长期在；第一版按任务目录而不是按机器隔离。
- **用 T3 Code 的代码**：它是 TypeScript 单体、自带服务端，我们已经有核心和隧道；只学它的执行环境 / 访问端点 / 启动三分。

## 理由

- 设备是家里已有的电脑，用户不用买新硬件；派活和工作区都在本地，项目代码不用上传。
- herdr 是现成的终端工作区管理器，有 pane 保活、Agent 状态、CLI 和 socket 控制，比自己写终端和会话便宜；它不是控制面，正好由我们的隧道和守护进程补上。
- 控制面、任务表、监工和收件箱全在枢纽，设备只做执行，掉线、换设备、审计都以枢纽为准。

## 代价与风险

- 设备是完整的电脑，权限面比容器大：它读得到自己用户的家目录、装得到全局软件、进得了所在内网；工作区根只是约定，不是沙箱（第 9 节）。
- herdr 是第三方、快速迭代的软件；控制面要跟它的公开接口，升级可能破坏适配（“待验证”第 1 条），我们得锁版本并在升级时跑冒烟。
- 设备的登录、模型配额、GitHub 权限都是设备用户的，住户之间共用一台设备时会互相影响额度；第一版不隔离。
- 设备不在线就是不在线：排队过期、重派、产物不全都会发生；主 Agent 要会解释“为什么没成”，App 要给人接手入口。
- 多设备意味着多份 Agent 配置、多套依赖和补丁，运维成本从一台枢纽扩散到每台设备；文档要给出“推荐怎么配一台设备”。

## 待验证

1. herdr 的 CLI/socket 控制面能稳定做到：起 workspace、起 pane 跑指定命令、读 blocked/working 状态、注入允许/拒绝、取消、收尾；锁版本后写进守护进程的适配层。
2. 权限请求从 Agent 原生界面到收件箱：优先 ACP；只能读屏幕的 Agent 用 pane 文本解析，解析失败的类别要能被收件箱原样展示而不是丢。
3. iroh 隧道在设备休眠、换网、NAT 漂移下的重连时延和失败原因；设备守护进程的退避与上限。
4. 产物核对：git 对象哈希、diff 重放的可行性和成本；大文件走文件服务的上限。
5. 设备上的 Agent 以非 root 用户运行、只写工作区根的系统级约束；macOS 的 TCC、Windows 的服务/计划任务和 Linux 的 systemd 各自要什么。
6. 换枢纽时迁移流程、密钥轮换和工作区搬移的边界；以后允许同时挂两个时两个守护进程并存的资源占用。
7. 住户之间共用一台设备时工作区目录的权限和串台（第一版不隔离，验证可接受）。
8. H2 的网络探测：哪些域名（模型、npm、GitHub）要探测、多久一次、探测结果的缓存和展示，不能把家里的网络打满。
