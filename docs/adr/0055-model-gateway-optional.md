# ADR-0055 模型网关可选：装 Agent 插件不再要求先有网关

- 状态：已接受（2026-11-07）；修订 [ADR-0008](0008-model-gateway-magpie.md) 里“声明 `models` 的插件必须先有网关”的部分

## 背景

很多用户习惯 Agent 官方的登录方式：Codex、Claude 直接登官方账号，ZCode、WorkBuddy 也有官方登录；有的
服务商额度只能在它自己官方的 Agent 里用。模型网关（magpie）只是为了统一管理 provider 和 key 的一个选择，
不能让用户只能这样用（主人 2026-11-06 定）。

此前的行为是硬依赖：声明了 `models` 权限的插件安装时，核心要求网关就绪，否则安装失败（`ModelsUnavailable`）；
网关就绪才签发凭据、注入 `WONTON_MODEL_*`。没有网关，Agent 插件一个都装不上。

## 决策

- **`models` 权限的意思改成“有网关就用”**：安装、升级不再要求网关就绪。没装、没就绪、或签发/验证失败，
  都照样装，`WONTON_MODEL_*` 照样定义、值为空字符串（compose 引用它们不会因为变量缺失而失败），插件用
  它自己的登录或 provider 设置。签发失败记日志，原因带进详情页的轻提示，不吞掉。
- **网关之后就绪**（装上、起来、恢复）：核心给没接上的使用方签发凭据，并按新变量重建运行中的容器，用现有的
  对账（`reconcile_models`）和重建路径。网关卸掉或坏了：使用方不动，详情页的提示变回“没接上”。
- **详情页一条轻提示，类别由核心给**（`PluginHintCategory::models_not_connected`），App 按类别本地化
  （ADR-0043 的分工）；“详情”原始值（如签发失败的原因）由核心按 App 的语言写。不是错误，不标红，状态照常。
- **不加“必需”档**：`models` 不分“必需/可选”，主人的原则是不能让用户只能用网关。
- 凭据和注入变量的记录（重建容器时用）存在使用方的凭据文件里；重建时网关不在也注入记下的值，网关回来对完账就接上。

## 理由

- 网关是加分项不是门槛：官方登录（`agent.login`，ADR-0034）和工作量最小的“填自己的 key”都该开箱可用。
- 空字符串而不是不定义：compose 的变量引用不会在安装时失败，插件按“有没有值”选路，规范里写清这个约定。
- 重建用现有路径（对账 + 按记录渲染重建）：网关回来时凭据值不变的使用方不用重建，只重建变量为空的。

## 没选的做法

- 给 `models` 加“必需”档：会让插件作者和主人都多一个要理解的开关，而且违背“不能让用户只能用网关”的原则。
- 网关不在时注入假地址或占位凭据：伪装成功，违背“失败即停”。

## 代价

- 没接网关时各 Agent 各管各的 key，主人要在多处配；接上网关想统一管理的，在“模型设置”里配好后插件重建即接上。
- 插件要自己处理“变量为空”：启动时按有无选路。官方插件逐个确认过（见各自仓库的 PR）；插件作者在规范的
  `WONTON_MODEL_*` 一节能看到约定。
- 核心要维护“记下的变量”这份状态（凭据文件里多两个字段）。

## 验证结果（2026-11-07，真实栈）

环境：magpie 0.1.1327、Hermes Agent v0.22.5、Tuwunel v1.9.4，`deploy/dev/core/dev.sh`（项目 `wonton-pmo`）。
复跑：起栈（`WONTON_DEV_DEFAULT_PLUGINS=` 空，不自动装 Hermes）→ `dev.sh uninstall ai.usemagpie.magpie --purge` →
`dev.sh install plugins/hermes --yes` → 重启核心（系统插件重装 = 装上网关）→ 拆栈。

- 没网关装 Hermes：装得上，状态 Running；详情页 `hints` 是 `[{"category": "models_not_connected", "detail": null}]`；
  运行容器里 `WONTON_MODEL_BASE_URL`、`WONTON_MODEL_API_KEY`、`WONTON_MODEL_DEFAULT` 都定义且为空字符串。
- 重启核心装上网关：日志「模型网关接上了，使用方已按新变量重建」，Hermes 容器按新变量重建，
  三个变量有值，签发的凭据请求 `GET <base>/models` 返回 200，详情页 `hints` 变空。
- 再卸掉网关：使用方不动、仍 Running，凭据值原样留在容器里，详情页提示变回「没接上」。
- 网关就绪时已接上的使用方不重建：假网关行为测试
  （`the_gateway_coming_back_again_leaves_connected_consumers_alone`）。真实栈里发现过对账把已接上的
  使用方也重建了一遍，已修：只有没接上的（没凭据或记着签发问题）才签发并重建。
