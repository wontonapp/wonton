# ADR-0070 版本号用 0.x，核心镜像只有 stable 一个渠道

- 状态：已接受（2026-11-08）；取代 ADR-0012 里“核心镜像分 stable、beta 两个渠道”一句

## 背景

ADR-0012 定了 stable、beta 两个渠道，1.0 之前只发预发布版本（`v0.1.0-beta.1` 到 `-beta.6`），所以 stable 从没推过，
安装脚本和插件开发环境默认都跟 beta。1.0 之前没有外部用户，两个渠道分不出谁该跟哪个，预发布后缀也只是重复了
“还没到 1.0”。

## 决策

- 版本号用 `v0.2.0`、`v0.3.0`……，不带预发布后缀。`release.yml` 只认 `vX.Y.Z`，每个版本都更新 stable。
- 核心镜像和 ACP bridge 镜像只有 `stable` 一个渠道，新装默认跟它（ADR-0025 的“默认渠道”）。
- 已经装好、`.env` 里跟着 `:beta` 的主机不迁移：要升到 0.x 就重装，或者把 `WONTON_CORE_SOURCE` 改成 `:stable` 后再
  执行一次 `install.sh`。

## 理由

- 只有一个渠道，安装脚本、插件开发环境和 App 的升级页都不用解释该跟哪个；以后要分渠道时再加，加一个 tag 不影响已有的。

## 代价

- 第一个 0.x 版本发出之前，`:stable` 在 GHCR 上不存在，默认值拉不到镜像。
- 已经发出去的服务器版本号还是 `0.1.0-beta.N`。协议里“这个接口要多新的服务器”按 semver 比，旧版本号照旧能比：
  `0.1.0-beta.6` 比 `0.2.0` 旧。
