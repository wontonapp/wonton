# ADR-0092 能力的四层中继：TCP 能力由核心按使用方转发，插件之间照旧隔离

- 状态：已接受（2026-11-12，主人定“MQTT 由核心按使用方做四层中继”）。验证结果待补

## 背景

ADR-0053 的能力经 `<名字>.wonton.internal` 由核心的网关转发，只支持 HTTP。MQTT 是 TCP 长连接：Zigbee2MQTT、
Node-RED、ESPHome 都要连一个 broker，Mosquitto 插件提供它，现在两边接不上。

别家都让使用方直连提供方：Home Assistant 的应用连 `core-mosquitto` 主机名，Umbrel 写死容器名。没有一家经平台转发 TCP。
直连在 Wonton 里等于把使用方接进提供方的插件网络，ADR-0053 已经否掉：插件之间不再隔离，核心也看不到谁连着谁、
换不了提供方。

核心已有的 ADR-0036 宿主网络中继是另一件事：它让核心连上宿主网络里的网页和 MCP 服务，是核心到插件的一段，
不认使用方、不看连接记录。按使用方转发、认来源、按记录放行和断开都是新的，所以单写一篇，当新组件估工作量和风险。

## 决策

### 哪些能力走四层

能力表（ADR-0053）每一项多写一个传输：`http`（默认，走网关）或 `tcp`（走本篇的中继），连同端口一起写进表里：

| 能力 | 传输 | 使用方连的地址 |
| --- | --- | --- |
| `mqtt` | `tcp` | `mqtt.wonton.internal:1883` |

- 传输和端口属于能力的接口约定，不属于提供方：提供方的 `provides.mqtt` 照旧只写 `{service, port}`，`port` 是它自己监听的端口，
  可以不是 1883。使用方看到的地址只由能力表决定，所以换提供方时使用方不用改。
- 只有核心定义的能力能是 `tcp`。第三方能力（`x-` 前缀）没有能力表，端口只能由提供方给，换提供方就会变，仍然只走 HTTP。
- 表里 `tcp` 能力的端口两两不同，也不和核心在插件网络里自己监听的端口重叠。写成测试。

### 地址和变量

使用方照 ADR-0053 拿到 `WONTON_<名字>_URL`，`tcp` 能力的 URL 是能力表写的协议名加地址，如 `mqtt://mqtt.wonton.internal:1883`。
很多上游要主机和端口分开填，`tcp` 能力另外注入 `WONTON_<名字>_HOST`（`mqtt.wonton.internal`）和 `WONTON_<名字>_PORT`（`1883`）。
没连上时三个变量一起留空，同 ADR-0053。

凭据照 ADR-0053：`mqtt` 的凭据是 Required，提供方按使用方签发。协议要用户名的，用户名是使用方插件 ID，就是已有的
`WONTON_APP_ID`；密码是 `WONTON_<名字>_KEY`。能力表的接口说明写明这一点。

### 认来源、放行和转发

- 核心本来就加入每个插件网络，在使用方的网络里带上 `<名字>.wonton.internal` 别名，和 HTTP 能力一样。
- 核心在能力表写的端口上收连接，按连接到达的**核心本端地址**属于哪个插件网络认出使用方。不看对端自报的任何东西，
  也不靠对端 IP 反查容器：一个插件网络只属于一个插件。
- 放行规则和 HTTP 相同：这个使用方没声明这个能力，或者“使用方—提供方—能力”没有确认记录（ADR-0053 的高权限能力），
  或者连接没签好凭据，核心收下连接后立刻关掉，不转发。TCP 没有状态码可带，原因写进核心日志，使用方插件的详情页按 ADR-0053
  的运行时规则显示（`requires` 的标异常、`wants` 的一条轻提示）。
- 放行的连接，核心连向这个使用方选用的提供方：提供方插件网络里那个服务的 `port`。提供方的服务在宿主网络里时，核心连
  提供方这一段经 ADR-0036 的 unix 套接字（同 ADR-0053 对 HTTP 的做法）；中继本身仍是本篇的组件。
- 转发是字节对拷，不解析 MQTT，不加 TLS（流量只在本机的插件网络里）。半关闭照传。
- 不设空闲超时：MQTT 自己有心跳，别的 TCP 协议也各有各的保活。
- 每个使用方每个能力同时最多 256 条连接，超了新连接直接关、记日志。这条防一个插件把核心的文件描述符用光，数值进常量，可调。

### 断开

连接记录变了，已经建立的连接要跟着变，否则使用方会一直连着旧提供方：

- 使用方换提供方、默认提供方变了、连接记录被删（卸载使用方或提供方、凭据轮换），核心关掉这一对上的全部现有连接。
  MQTT 客户端会自动重连，重连时按新记录转发。
- 提供方停了或异常：新连接立刻关；现有连接随提供方断开自然断开。
- 核心重启时所有连接都断，使用方自己重连。核心启动顺序照 ADR-0053：先恢复提供方，再开中继，再恢复使用方。

### 就绪

`tcp` 能力的提供方“就绪”是：容器健康（有 `healthcheck` 时）并且核心能连上它的 `port`。ADR-0053 里“等提供方就绪再装使用方”
用这个判定。

## 契约

| 新能力检查单 | 内容 |
| --- | --- |
| 契约 | MQTT 3.1.1（OASIS 标准，2014）和 MQTT 5.0（OASIS 标准，2019），TCP，地址 `mqtt.wonton.internal:1883`，用户名 `WONTON_APP_ID`、密码 `WONTON_MQTT_KEY`；不含 TLS 和 WebSocket |
| 提供方 | Mosquitto 插件（Eclipse Mosquitto，EPL-2.0/EDL-1.0，独立容器）。凭据命令：`mosquitto_passwd` 写密码文件再给 broker 发 SIGHUP，本地验过 |
| 消费方 | Zigbee2MQTT 插件（`ZIGBEE2MQTT_CONFIG_MQTT_SERVER`、`_USER`、`_PASSWORD` 直接引用注入变量）；之后 Node-RED、ESPHome |

契约测试照 [`model_gateway_contract`](../../crates/wonton-core/src/plugin/tests/model_gateway_contract/) 的样板：同一组使用方用例跑在
两个互不相干的提供方上，适配层只知道提供方怎么打包，用例只用注入的 `WONTON_MQTT_HOST/PORT/KEY` 和 `WONTON_APP_ID`。用例：

1. 两个使用方各自用自己的账号连上，一个订阅、一个发布，消息到达；
2. 用别的使用方的密码连，broker 拒绝（凭据确实按使用方隔离）；
3. 没声明 `mqtt` 的插件连 `mqtt.wonton.internal:1883`，连接被关；
4. 换提供方后，使用方的 compose 和变量值不变（`_KEY` 由新提供方重新签发），重连后用例 1 照样通过。

两个提供方是 Mosquitto 插件和另一个独立实现（NanoMQ 这类开源 broker 的插件，或只在测试里用的 broker）。要真 Docker 的标
`#[ignore = "需要 Docker，…"]`；中继本身的放行、断开和连接上限用假 Docker 加本机 TCP 监听写成默认就跑的行为测试。

## 理由

- 经核心转发，ADR-0053 的“插件之间隔离、核心按记录放行、能换提供方”对 TCP 能力也成立，不为 MQTT 开一个直连的口子。
- 按本端地址认来源：核心在每个插件网络里有自己的地址，连接到了哪个地址就是从哪个网络来的。不用在容器里放任何东西，
  也不用相信对端 IP。
- 中继放在核心进程里，不是每个使用方一个 socat 容器：放行要看连接记录，记录变了要断开现有连接，这两件只有核心能及时做；
  每对一个容器还会让容器数随使用方成倍增长。
- 端口在能力表里而不是提供方清单里：这是使用方能“写一次、换提供方不改”的前提。
- 不解析协议：中继只做 L4，以后别的 TCP 能力（数据库协议、SMTP 这类）进能力表时用同一个中继，不用为每个协议写代码。

## 代价与风险

- 核心多一个常驻的 TCP 转发组件，连接数和流量都过核心进程。家用规模（几十个设备、每秒几百条消息）不是问题，没压测过。
- 核心升级或重启时 MQTT 连接全断，设备消息在重连前那几秒会丢（QoS 0）或由客户端重发（QoS 1、2）。
- 中继不认 MQTT，主题权限只能由提供方管（Mosquitto 的 ACL）。默认的 Mosquitto 插件里每个使用方能读写所有主题：
  连上 broker 的插件能给 Zigbee2MQTT 发控制设备的消息。`mqtt` 按普通能力算，不是高权限，和 Home Assistant 一样。
- 第三方能力还是只能走 HTTP，社区插件要非 HTTP 的接口只能等能力进表。
- 使用方要支持断线自动重连，否则换提供方后会停在断开的状态。主流 MQTT 客户端都会重连，不会的算插件的问题。

## 没选的做法

- **使用方接进提供方的网络直连**（Home Assistant、Umbrel）：ADR-0053 已否，插件之间不再隔离，换提供方要重建网络。
- **按 IP 反查容器认来源**：容器重建后 IP 会被别的容器复用，有竞态；按本端地址认没有这个问题。
- **每对使用方—提供方一个 socat 容器**：见理由。
- **复用 ADR-0036 的宿主网络中继**：那是核心到一个插件的固定通道，不认使用方、没有放行和断开，改成这样等于重写。
- **中继里加 TLS**：流量不出本机，证书还要分发给每个使用方，换不来什么。

## 待验证
