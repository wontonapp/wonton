# ADR-0046 新设备由已有设备确认：登录后用 Matrix 的 SAS 自我验证

- 状态：已接受（2026-11-06），主人选“做，和恢复密钥并列”。补充 [ADR-0005](0005-native-clients-thick-core.md) 的聊天备份，不改那里的决定

## 背景

聊天备份默认开启，恢复密钥由主人自己保管（ADR-0005，主人 2026-11-05 选择）。新手机配对后是“未验证”，以前的消息
解不开，只能输入恢复密钥。主人手边有另一台已经能用的手机时，这一步可以由那台手机代劳（#274）。

和 2026-11-05 的选择的关系：那次在“核心保管恢复密钥”“旧手机转发”“主人自己保管”里选了自己保管，核心不碰密钥。这里
不改它：恢复密钥照样由主人保管、照样默认开备份，核心照样拿不到密钥。新加的是第二条取回的路，两条并列，主人用哪条都行：
手边有旧手机就让旧手机确认，没有就输入恢复密钥。手机全丢了仍然只能靠恢复密钥。

配对和 Matrix 历史的授权是两回事：核心能签主人的登录令牌，也知道配对码里的密钥，所以“已配对”说明不了这台设备
就是主人手里那台（ADR-0005 第 24 行的边界）。旧手机把交叉签名私钥和备份密钥交出去之前，必须有一个核心伪造不了的确认。

## 决策

- **方式**：新设备登录 Matrix 后，向自己账号的其他设备发自我验证请求，两台手机对照 SAS 的表情（对端不支持表情时是数字），
  主人在两边都点“相同”。matrix-sdk 0.19.1 完整支持：
  - 验证请求是 to-device 消息，只发给账号里已被交叉签名的设备。
  - 双方 MAC 校验通过后，新设备信任账号身份，自动用 `m.secret.request` 要交叉签名的三把私钥和备份密钥
    （`m.megolm_backup.v1`）。
  - 旧设备只回给同账号、已验证的设备，经 Olm 加密。
  - 新设备收到后启用备份，按需下载房间密钥，时间线原地解开。这一段和输入恢复密钥那条路共用。
- **入口**：聊天列表上现有的“输入恢复密钥”提醒，在账号里有别的已验证设备时（`can_verify_with_other_device`）点进去
  是两个并列的选项：“用另一台设备确认”和“输入恢复密钥”。主人在旧手机上点“添加设备”时，旧手机正开着、显示配对码，
  收到请求就在这一屏接着显示确认，不用另找入口。别的时候收到请求，旧手机在前台弹出。
- **旧手机要开着 App**。to-device 消息不进房间，Tuwunel 的推送只管房间事件，所以推送唤醒不了旧手机。新设备上写明
  “打开你另一台手机上的云吞”。Element 也要求已验证的设备开着 App。
- **核心不加接口**。只经 Matrix 客户端 API。客户端核心包装验证对象，给出验证流程的 ViewModel
  （`EncryptionStatus::verification_flow`，类型在 `wonton-protocol` 的 `verification` 模块）：
  - 状态：等对方、收到请求、对照、等对方确认、取回密钥、完成、没完成（原因分类）。
  - 操作：发起、接受、相同、不同、取消。
  - 表情给规范 SAS 表情表里的序号和表情本身，名字由壳按序号取本地化资源（ADR-0043）。新界面文字一律进本地化资源。
  - 验证完成后显示“正在取回密钥”，备份启用、本机拿齐私钥后才算完成。验证本身完成不等于历史可读。
- **不做的**：
  - 旧手机上“看设备名点允许”：交叉签名一台设备没有现场的公钥比对，核心能造一台同名设备骗过去。
  - 自动接受请求、自动点“相同”：理由同上。

## 理由

- 这是 Matrix 标准流程，SDK 已经写好密码学和秘密交换，我们只写流程和界面。别的 Matrix 客户端（Element X）登录的
  设备也能和云吞互相确认。
- SAS 挡得住核心作恶：核心换掉设备密钥或插进中间人，两台手机上的表情对不上。
- 配对给的权限和安全边界不变：拿不到旧手机现场确认，也没有恢复密钥，就解不开配对前的消息。

## 没选的

- **应用内扫码验证**（`m.qr_code.scan.v1`）：步数和 SAS 差不多，同样标准。但要开 SDK 的 `qrcode` feature，两端的
  扫码页都只读得出文字，读不出 Matrix 验证码的二进制载荷，要另做原生扫码。等 SAS 用起来以后再看要不要加。
- **MSC4108 扫码登录**（扫码同时登录并转交秘密）：要 Matrix 的 OAuth 登录、rendezvous 和网关放行 Tuwunel 的授权页。
  我们用 JWT 登录，Tuwunel 的 native OAuth 也不接受 JWT 建的账号，改动远大于收益。
- **把 Matrix 验证码塞进配对二维码**：配对码在新设备登录 Matrix 之前就扫了，那时新设备还没有 Matrix 设备密钥，
  得自定义协议。

## 代价与风险

- 旧手机必须在身边、开着 App；手机全丢了还是只能靠恢复密钥或重置（ADR-0005）。
- 只能解开旧设备手里有房间密钥、或者已经上传到备份的消息；从没有设备收到过的解不开。
- 两端各加约四屏状态的界面（新设备：发起和等待、对照；旧设备：请求、对照），外加 SAS 的 64 个表情名的四种语言。

## 待验证

调研只核对了 SDK 0.19.1 和 Tuwunel v1.9.4 的源码，并用 Tuwunel 做了 HTTP 探针，结论如下。

已证实：
- to-device 验证请求不触发推送。
- 重置身份时的 UIA 只接受 JWT，带新的登录令牌能过。

实现时要端到端测：
- iOS 和 Android 互相确认，以前的消息在时间线里原地解开。
- 重启后保持。
- 取消、超时、表情不同、两台旧手机同时收到。
- 旧手机自己缺私钥时如实报错。
