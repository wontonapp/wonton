## 背景与主人原话

多内核路线要求 Wonton 长期维护桥、运行时网关、各家登录与模式转换，还要解释这些差异。家庭产品的投入改为把同一个默认助手做可靠，保留标准接口和多个家人 Bot，而不是同时维护多套内核体验。OpenClaw 是替换备选，不是第二套并行建设的默认助手。

决策来源为 `tasks/decisions.md:916-925`，原文如下；资产边界依据 `research/agent-choice-1115/final.md` 第 6 章。两份来源是任务交接材料，以下完整保留主人第 1–7 条，避免依赖仓库外材料才能读懂决定。

```text
## 11-15 22:3x 主人拍板：Agent 内核（依据 research/agent-choice-1115/final.md）
1. 默认助手只用 Hermes；OpenClaw 只作替换备选，不同时养两套。
2. 放弃多内核路线：删 ACP 桥（crates/wonton-acp-bridge 等）和各家适配，停止第二批 Agent 接入；家人各自的多个 Bot 保留；Matrix、MCP 总线、确认、Bot 身份、模型网关、受控发消息等底座保留（见报告第 6 章表）。
3. 确认范围照旧：Wonton 受管资源必须核心确认；Agent 容器内自身工具按上游审批并写明风险；主人设的自动放行范围照旧。
4. 下一批做：任务（手上的活/等我的事）、透明记忆（看、改、删）、一句话订晨报和提醒；每个用真实输入、拒绝/取消、重启恢复验收。

## 11-15 22:5x 主人补充（Agent 内核）
5. 调别的 Agent（Codex、Claude Code 等）用 Hermes 自带的 ACP 委派（delegation 的 acp_command，见上游 website/docs/user-guide/features/delegation.md、tools/delegate_tool_config.py），不再自建 ACP 桥。
6. 模型接入只用 Hermes 自带的供应商接入（40 多个 provider、填 key 或登录订阅）；Magpie 只是一个普通插件，不再是 Agent 的模型入口，核心和默认装机不依赖它。
7. 要能方便跟随上游更新：用上游官方镜像原样跑，不改 Hermes 源码、不打补丁；Wonton 插件只做配置、compose、环境变量和最少的胶水；升级就是换版本号加冒烟。
```

## 决策

### 1. 单一默认内核不等于单一 Bot

默认助手只采用 Hermes 的原生 Matrix 路径。核心沿用普通默认插件的安装、健康检查和只装一次机制，不增加 Hermes 专用生命周期；主人卸载后不强装回来。Hermes 的安装、启动和 Matrix 私聊交接不再等待 Magpie 安装或模型网关凭据对账。

每个家人仍可有自己的私人 Bot，主人仍可建共享 Bot；Bot 的 Matrix 身份、归属、联系人、角色权限和文件授权不变（[ADR-0045](0045-family-members.md)、[ADR-0088](0088-family-accounts.md)）。一个内核可以驱动多个 Bot，不把家人合并到同一个进程或同一份数据里。私人 Bot 之间、私人与共享 Bot 之间保持独立容器及数据边界；Hermes profile 是配置单位，不把同一容器里的多个 profile 当作抵挡任意 shell 读取的安全隔离。

默认产品不再提供各家内核的比较、选择和逐家适配。替换能力来自 Matrix、MCP、Compose 等边界，不以继续维护第二套默认产品为前提；采用 OpenClaw 替换时仍须验证这些边界，不能把研究推荐当作替换已经验收。

### 2. Wonton 管资源与身份，Hermes 管 Agent

| 部件 | 职责与不变量 |
| --- | --- |
| Wonton 核心与客户端核心 | 插件生命周期、身份与角色、Matrix 接入、文件授权、MCP 总线、核心确认、受控发送、网关与隧道。核心不实现 Agent 循环、供应商适配或第二套任务与记忆引擎。 |
| Hermes | 模型与供应商接入、Agent 自身工具及上游审批、原生 ACP 委派、任务、记忆和定时能力；按上游提供的接口与配置使用。 |
| Hermes 插件 | Compose、清单、环境变量、配置及连接 Wonton 标准接口必需的最少胶水。使用固定版本和摘要的上游官方镜像，不修改源码、不打补丁、不维护分叉镜像。 |
| App 原生壳 | 沿用厚 Rust 核心、薄原生壳的职责边界。适配 Hermes 的既有能力，不另造简化内核；本篇不决定页面、导航、按钮、操作顺序或展示布局。 |

跟随上游升级以更新版本与镜像摘要、运行冒烟为边界，不依赖重放 Wonton 源码补丁。所需能力在选定官方版本中不存在或不可用时，明确报出缺失及影响，不用假数据、隐藏代理或另一套桥掩盖。

### 3. 原生 ACP 委派不是 Wonton ACP 桥

调用 Codex、Claude Code 等使用 Hermes 自带的 delegation/`acp_command` 路径。委派的启动、上下文、结果与取消归 Hermes 的上游实现，不重建 Matrix↔ACP 桥、`agent_acp` 网关、逐家模式转换和订阅登录适配器。

被委派程序不是因此自动注册成另一个 Wonton Bot，也不继承另一个 Bot 的身份或权限。需要访问 Wonton 受管资源时，仍须使用获授权的 Wonton MCP 入口；上游的允许回答不能代替核心确认。Hermes 内部委派和家人各自的多个 Bot 是不同层次的能力，不用前者冒充后者的隔离或身份。

上游 ACP 命令及依赖须按上游支持的方式提供；命令不存在、认证缺失、工具不可达或审批通道不可用时应明确失败，不能悄悄改成其他内核或模型。采用官方镜像不等于它已包含所有被委派 CLI，也不证明 Wonton 的真实委派链路已验收。

### 4. 模型只沿用 Hermes 自带接入

默认助手的主模型、辅助模型和子任务模型均沿用 Hermes 自带的供应商接入与配置能力。API key、订阅登录、本地或自定义服务只有在所选上游版本原生支持时才作为接法；不新增 Wonton 自己的 provider 目录、登录代理或供应商适配层。具体供应商与登录方式以该版本能力为准，不以原话中的数量代替兼容性验收。

Magpie 降为可装、可卸的普通插件，不再是 Agent 的模型入口；核心和默认装机、默认 Hermes 的运行不依赖它。保留通用模型网关能力及自愿使用它的插件的凭据签发、注入、吊销与失败边界，不把“保留模型网关”解释为保留 Magpie 的强制系统插件地位，也不删除仍有消费者的通用契约。

Hermes 的供应商密钥与登录态按上游支持方式保存在对应 Bot 的配置或数据中，不放进聊天、引导草稿或日志。原生工具能够读取容器内数据与凭据的风险须说明；不能继续声称“Agent 永远只拿受限网关凭据”。模型配置缺失、登录失效或上游失败均如实报告，安装成功、容器健康、打开过设置页面都不能冒充模型已可用。

| 旧规则 | 本决定的替代边界 |
| --- | --- |
| ADR-0008：Magpie 是不可卸载的系统插件，所有人共用其模型入口 | Magpie 是普通插件；通用模型网关合同保留，但不构成核心或默认助手的前置依赖。 |
| ADR-0055：官方订阅之外的 Agent 模型全部经 Magpie，禁止直接填 key 或地址 | 默认助手只使用 Hermes 自带供应商接入；不再施加这项强制网关规则。没有可用模型仍须报错，不做 Wonton 隐藏选路。 |
| ADR-0034：引导选内核、模型设置统一打开 Magpie 网页 | 默认只给 Hermes，模型配置归 Hermes 上游能力；撤销固定 Magpie 页面和侧栏入口的架构要求。引导仍须区分未配置、失败和可用，不在本篇指定新交互。 |
| ADR-0034 与 GOAL：经 ACP 桥登录各家订阅，单独承诺 Claude Code 经桥的公开版本路径 | 登录沿用 Hermes 所支持的上游流程，不再建设桥登录或逐家登录 UI。旧适配器的条款分析不能推及 Hermes 或所有订阅；是否支持、账号条款与风险按实际接法说明，不另造中转凭据的路径。 |

### 5. 确认边界不扩大，也不缩小

- **Wonton 受管资源**：安装、文件、设置、插件工具和对外发送等仍经核心授权与确认（[ADR-0016](0016-mcp-bus-and-confirmations.md)、[ADR-0024](0024-confirmation-scope.md)）。主人设定的自动放行范围照旧，不因原生委派或上游批准而扩大。
- **Agent 容器内自身工具**：终端、文件及被委派程序按上游审批，明确其可读取本 Bot 数据、历史和凭据的风险。不是所有容器内命令都转成核心确认卡片，也不能宣传“所有动作都由核心逐步审批”。
- **身份与来源**：核心核对实际 Bot、发起人及来源会话；来自文件、网页、其他 Bot 或工具的内容不是主人授权。认不清发起人时不能套用归属人的自动放行。
- **受控发送**：`wonton__send_message` 的收件人范围、收件人与全文确认、来源身份、主人已设的放宽范围和真实投递回报保留。Hermes 的普通回复或裸发送工具不能充当这条受控发送路径；取消、拒绝不发送，未获真实投递结果不报告送达。

### 6. 其他 Agent 插件（2026-11-19 补充）

- 官方维护的其他 Agent 插件下架并归档仓库：`wonton-agents` 合仓里的 Agent、ZCode、agent-orchestrator 和 OpenClaw，不再维护。
- 其他 Agent 由作者按插件规范做成插件，只走社区来源（[ADR-0031](0031-plugin-sources.md)），不进官方索引，不标“已审核”。核心对它们和 Hermes 用同一份合同。
- ACP 不再是组件之间的标准接口，只用于 Hermes 内部的委派（第 3 节、[ADR-0015](0015-small-components-standard-interfaces.md)）。

## 下一批能力的验收

投入任务、透明记忆、晨报与提醒，复用 Hermes 已有能力，不为展示再建第二份核心任务或记忆事实源。本篇只定能力、数据边界与验收，不规定 App 如何进入、编辑或展示。

| 能力 | 必须走通的真实闭环 |
| --- | --- |
| 任务：手上的活、等我的事 | 真实请求产生可辨认的工作与等待事项；拒绝和取消有真实效果；重启后恢复实际状态，不能把不确定或已经停止的任务显示为继续运行。 |
| 透明记忆：看、改、删 | 用真实对话形成记忆，归属人能查看、改正和删除，并观察后续回答的实际变化；拒绝或取消不产生修改，重启后仍符合保存结果。说明删除覆盖的是记忆、历史还是备份，不把删除摘要等同全部数据消失。 |
| 一句话订晨报和提醒 | 真实订阅按时触发并到达正确的人；拒绝或取消后不继续投递；重启后检查订阅和执行结果。主动发送继续受收件人、确认与自动放行边界约束，不以定时能力绕过它们。 |

三个闭环都按私人和共享 Bot 的授权范围消费数据，不把记忆透明化变成读取别人的记忆。原生能力不足、审批通道缺失或恢复结果不确定时如实报错，不补假状态。

## 理由与代价

- 选定一个默认内核，减少逐家登录、模式转换、前端和恢复特例的维护；不是根据代码榜或功能数量宣称 Hermes 已赢得所有家庭任务。
- Matrix、MCP、Compose 保留替换边界，Hermes 原生供应商接入与委派消除自建桥、模型入口和登录适配的重复职责。
- 官方镜像原样运行降低跟版负担，但升级仍可能改变工具、供应商、审批、附件或恢复行为；只改版本号不等于已通过冒烟。
- 多个独立 Bot 仍有进程、镜像和数据成本；容器内工具仍可读取本 Bot 凭据。单内核与 profile 均不能消除这些成本和风险。
- 放弃 Wonton 多前端、电脑 ACP 运行时和跨内核编排是明确的产品收缩；不以原生委派冒称这些旧能力仍获支持。

## 验证结果与待验证项

本篇记录方向，不改变运行实现，不执行旧代码、配置、插件或数据删除；文档接受不等于裁剪、跟版、手机交互或家庭闭环已验收。研究报告的资产分类以 Wonton `4fc2227d2d2cf742a6115be72291481ba520bbc1` 为依据，不能据此推算任意后续版本可直接删除的文件集合。

主人指定的原生委派依据固定到 Hermes `4c14d9df5be965bcb81f29725fad644d2376da47` 的 [`website/docs/user-guide/features/delegation.md`](https://github.com/NousResearch/hermes-agent/blob/4c14d9df5be965bcb81f29725fad644d2376da47/website/docs/user-guide/features/delegation.md) 与 [`tools/delegate_tool_config.py`](https://github.com/NousResearch/hermes-agent/blob/4c14d9df5be965bcb81f29725fad644d2376da47/tools/delegate_tool_config.py#L605-L684)。其中 `acp_command` 是上游运行时参数，配置键按所选上游版本核对，不新增同名 Wonton 清单合同。源码和文档用于定位能力，不替代所选官方镜像上的真实互操作验证。

实施验收须给出：

- 干净安装且不装 Magpie 时，Hermes 能通过其支持的供应商接模型；核心、默认安装、Bot 健康与私聊交接都不等待 Magpie。主、辅助和委派模型均核对真实路由，不把“配置写进去了”当模型调用成功。
- 使用所选官方镜像，走真实 Matrix 加密文字、图片、文件和 MCP 调用，核对启动前消息、附件分组、工具发现及容器重启后的行为；证明必要胶水可删才删。
- Hermes 原生 ACP 委派至少调用一个真实上游 Agent，核对结果、拒绝、取消、命令或认证缺失，以及重启后的明确状态；不借 Wonton ACP 桥完成冒烟。
