# ADR-0022 主人的身份：用户名固定，新插件默认用应用自带的登录

- 状态：已接受（2026-11-03），显示名和邮箱怎么配已被 ADR-0030 取代

## 背景

主人 2026-11-03 定了两件事：

1. 用户名 `WONTON_OWNER_NAME` 是固定 ID，像系统用户名一样，装好后不变。显示名和邮箱可以改。
2. 已经接好单点登录的插件保留。新插件默认 `sso: none`，用应用自带的登录：主人装好后第一次打开时，在应用里自己注册管理员（飞牛的做法）。

按 `70f523a` 的代码和 15 个官方插件 PR 的审查，和这两条不符的地方：

- 核心每次启动从环境变量读用户名，不记下来。主人的 Matrix 账号、OIDC 的 `sub`、Samba 建的 Linux 账号、插件在应用里建的账号都挂在它上面，换一个值就是换一个人。
- 规范写着“主人改了用户名要在每次启动时核对”，插件作者照着写出了对账代码。
- 用户名只在接 Matrix 时校验，允许 `/`、`+`、`=`。Samba 拿它建 Linux 账号时 busybox adduser 拒绝这些字符；和 `guest`、`nobody` 重名时，镜像脚本会去改那个系统用户。
- 没配邮箱时核心拼出 `{用户名}@{基础域名}`，插件里的 `${WONTON_OWNER_EMAIL:?}` 永远不报错，应用拿到的可能是收不到信的地址。
- 宿主的 `TZ` 原样注入。`:/etc/localtime`、`CST-8` 这类值让用严格时区库的插件起不来。
- 主人身份只注入给 `sso` 是 `oidc` 或 `proxy` 的插件。要用户名建账号的插件只能声明 `sso: proxy`，再凑一个应用不认的请求头，安装预览因此显示“自动登录”。
- `deploy/install/compose.yaml` 没把 `WONTON_OWNER_*` 传进核心容器，所以正式安装的主机都是 `owner` 和拼出来的邮箱，改 `.env` 也不起作用。

## 决策

### 用户名是固定 ID

- **规则：** `^[a-z][a-z0-9_-]{0,31}$`，不论接不接 Matrix 都校验。这是可移植的 POSIX 用户名，也是合法的 Matrix localpart。不能是常见的系统用户名（Debian、Alpine 基础镜像里 `/etc/passwd` 的名字，如 `root`、`nobody`、`guest`，和 `nogroup`），也不能是核心的 Matrix 管理账号或 Tuwunel 自己的服务器用户（`conduit`，v1.9.4 的默认值，核心不改它）：JWT 登录会进到那个账号。
- **记下来：** 核心第一次启动时把用户名写进 `<数据目录>/core/owner.json`，原子写入。这个文件跟数据目录一起备份和恢复。
- **对不上就退出：** 之后 `WONTON_OWNER_NAME` 和记下的值不一致时，核心报错退出，写明两个值、记录文件的路径和处理办法：改回记下的值或删掉这个变量；要换用户名只能用新的数据目录重新安装。
- **没写时：** 记录在，就用记下的值：没写不算冲突，`.env` 丢了或重写了也不至于起不来。没有记录时默认 `owner`。
- **保留名单只在第一次记下时查。** 系统用户名、核心的管理账号和 `conduit` 这些名单不可能列全，以后会加名字；加了只挡新装的主机，不让已有主机起不来，用户名又改不了。之后的启动只查字符规则。
- **记录文件坏了（读不了、格式不对、字符不合规则）：** 启动失败，不覆盖。
- **升级：** 新核心第一次启动时记下当时的值。这个值不合规则时启动失败，只能重新安装。正式安装的主机用的是 `owner` 或者过了这条规则的名字，规则收紧只影响手动改过配置的安装。
- **`sub` 就是用户名。** 应用按 `sub` 或 `preferred_username` 认人，不按邮箱认。

### 显示名和邮箱可以改

改 `.env` 后再执行一次 `install.sh`，或者 `docker compose up -d`：`docker restart` 和 `docker compose restart` 不重新读 `.env`。核心换上新值后，OIDC 声明和代登录的请求头马上跟着换；容器里的 `WONTON_OWNER_EMAIL` 是建容器时的快照，重建才换。应用里已有账号的资料不跟着变，主人在应用里改，插件不写对账代码。

正式安装里，`compose.yaml` 逐个传入 `WONTON_OWNER_NAME`、`WONTON_OWNER_DISPLAY_NAME`、`WONTON_OWNER_EMAIL` 和 `TZ`。用户名没写时留空（`${WONTON_OWNER_NAME:-}`），默认值只由核心给：写成 `:-owner` 时核心永远看不到“没写”，`.env` 丢了就和记下的值冲突。`install.sh` 把它们保留在 `.env` 里，第一次安装时可以在环境变量里给（`WONTON_OWNER_NAME=alice`）。一行命令装完的流程不提问，所以不给就是 `owner`。

校验只在 Rust 里写一处：`install.sh` 在启动容器前用新镜像跑 `wonton-core init`，由它校验这些值、核对记下的用户名，不对就当场报错，不用等健康检查超时。shell 里不抄字符规则，`TZ` 是不是合法的时区名 shell 也查不了。

`install.sh` 只做核心做不了的事：读宿主的时区（见下一节）。

### 邮箱和时区不兜底

- **没配邮箱时：** 不注入 `WONTON_OWNER_EMAIL`，OIDC 的 `email` 声明不给，`email_verified` 也不给。引用它又没写默认值的插件、代登录模板用了 `{email}` 的插件装不上，预览的 `blocked` 和安装的错误写明“主人还没配邮箱”和怎么配。这和“插件没申请 `owner.identity`”是两个错误，分开写：一个要主人去配，一个是插件写错了。配了的值要像个邮箱（一个 `@`、两边不空、没有空白和控制字符），不合规则时核心启动失败。
- **已装的插件遇到没邮箱时：** 升级的确认页在 `blocked` 里写同样的原因，旧版本继续跑，不算升级失败，也不回滚。重建容器（局域网地址变化）渲染不出来时，旧容器不动，插件标成异常（`Degraded`），原因同样写明。代登录用了 `{email}` 的，打开网页时报同样的原因。老主机的容器里是以前拼出来的邮箱，这个快照不动，到下次升级或重建才碰到这里。配好邮箱（改 `.env` 后再执行一次 `install.sh` 或 `docker compose up -d`，错误里写的也是这句）后可以重试。
- **`TZ` 只接受 IANA 时区名**（`Asia/Shanghai`、`UTC`），大小写要完全一致，核心启动时校验，不合规则时报错退出。没设时是 `UTC`。校验用 [jiff-tzdb](https://github.com/BurntSushi/jiff)（Unlicense 或 MIT）内嵌的时区库，不依赖镜像里有 `/usr/share/zoneinfo`。
- **正式安装没给 `TZ` 时，`install.sh` 读宿主的时区**（`timedatectl`、`/etc/timezone`），写进 `.env`，同样交给 `init` 校验，都读不到才是 `UTC`。`curl | sudo sh` 的环境里通常没有 `TZ`，不读的话插件显示的时间大多是错的。

### 主人身份和 sso 解耦

新权限 `owner.identity`：插件拿到 `WONTON_OWNER_NAME`，以及配了的话 `WONTON_OWNER_EMAIL`。不算高权限，安装页列出“知道你的用户名和邮箱”，Bot 也能装。

- `sso` 不带身份变量，只有写了 `owner.identity` 才注入。
- **预览按实际拿到的列，不只看权限。** 没申请 `owner.identity` 时，`sso: oidc`、或者代登录模板用了 `{user}`、`{name}`、`{email}` 的，应用登录时照样拿到身份，预览也列出“知道你的用户名和邮箱”。只用 `{secret:…}` 的 `proxy` 拿不到，不列。
- 新插件写 `spec: "0.3"`，要主人的身份就写 `owner.identity`。引用了身份变量又没申请的，错误写明“插件没申请 `owner.identity`”。
- `sso: proxy` 仍要写 `webui.proxy`，至少一项头或 Cookie。不带头的 `proxy` 和 `none` 加 `owner.identity` 没有区别，一件事只留一种写法。

规范版本加到 `0.3`。

### 新插件默认 `sso: none`

新插件默认用应用自带的登录。要声明 `oidc` 或 `proxy`，得满足插件规范“网页入口与单点登录”里的条件。

**网关这一层一直保留，不给插件开关。** 所有插件网页都先过主人的会话（局域网浏览器的插件会话，或经隧道的已配对设备），这是首次注册安全的前提：应用的注册页只有主人打得开。别的插件的页面借不了主人的登录（ADR-0011 的“浏览器里的隔离”），Bot 没有会话，插件容器之间不通。这些都写成测试。代价是局域网浏览器里要登两次：先核心，再应用。App 里只有应用这一次。

家人账号（M2）不能破坏这两条：应用的首次注册只有主人能做，主人放行之前插件网页只对主人开放，写了 `setup_done` 的还要它通过才放行；用户名永远不复用，删掉的也不再分配，不然 `sub` 相同，应用会把新人当成旧人。

### 和公网入口（ADR-0021）的关系

网关挡得住的只有插件网页这条路。主人打开局域网或公网入口以后，`app` 和 `credentials` 模式下未认证的请求能到插件。CT 日志能列出所有的家，标签是可读的，所以**没注册管理员的应用开到公网，别人可能抢先注册**。局域网入口一样，访客的手机和被攻破的设备都在同一个网段。

ADR-0021 已有的防线不够：

| 防线 | 缺口 |
| --- | --- |
| `credentials` 第一次 `issue` 成功之前不能开 | 只管 `credentials`，`app` 模式（Vaultwarden 这类）没有 |
| 声明 `network.clients` 的插件默认关掉自助注册 | 靠官方索引审核，社区插件没人审。第一个账号的注册往往关不掉 |
| `public.deny` 挡注册路径 | 只作用于公网入口，局域网不受限；按路径挡，走 WebSocket 事件的初始化挡不住（Uptime Kuma 2.x 的做法，写插件时核实） |

所以 **`clients.http.auth.app` 必须写 `setup_done`，首次注册没完成时入口打不开：**

```yaml
clients:
  http:
    service: vaultwarden
    port: 80
    auth:
      app:
        setup_done: [sh, /wonton/setup-done.sh]
```

- 约定同 `credentials`：核心在 `clients.http.service` 的容器里执行命令（argv，不经 shell），超时 30 秒。退出码 0 表示管理员已经有了，1 表示还没有。其他退出码和超时算状态不确定，也不开。
- 退出码 1 时，打开入口的接口回 409 `setup_pending`，App 写明先打开网页注册管理员。状态不确定时回 503 `plugin_unavailable`，附上标准错误输出：应用可能只是没就绪，主人早就注册过了，不能叫他去注册。
- 打开时查一次，插件每次启动后再查一次。启动后查到结果之前，入口暂停转发，App 显示“状态不确定”，不报已关闭也不报正常：刚启动的应用常常查不出结果（还在迁移数据库、没就绪、超时），这时关掉的话每次重启都要主人重新开，放行又可能把“还没有管理员”放出去。不确定时按间隔重试，直到有确定结果。
- 拿到 0 恢复转发。拿到 1 说明数据清空或恢复后变成了“还没有”，核心关掉这个插件的 HTTP 入口并通知主人，不留一个可以抢注的公网入口。
- 插件运行中数据被清空、又没有重启的窗口，接受，不定期查：应用自己的重置要管理员登录，能直接动数据的已经控制了主机。
- 插件里已经预建好账号、或者应用本来没有账号时，命令直接返回 0，官方索引收录时审核。
- `credentials` 不用它：`issue` 要账号已经存在才能成功，原有的规则挡住了同样的窗口。`gateway` 模式未认证的请求到不了插件。`clients.tcp` 不承载网页注册。
- 注册完成后的自助注册，仍按 ADR-0021 默认关掉。

`lan.ports`（ADR-0019）没有开关，装好就开，所以注册页只能在 `webui` 端口上，`lan.ports` 列出的端口不能提供未认证的管理员注册。官方索引收录时审核。`webui` 的端口列进 `lan.ports` 时例外：默认不开，主人打开开关 `lan_webui` 才开（ADR-0023）。

### 已有插件的判断标准

这篇不改任何已有插件。以后要改的时候，按插件规范“网页入口与单点登录”里声明 `oidc`、`proxy` 的条件：满足就保留，不满足就改成 `sso: none`。声明了 `sso: proxy` 但应用不认那个头、只为拿 `WONTON_OWNER_*` 的也算不满足，要身份的改写 `owner.identity`。

按 2026-11-03 各插件 PR 分支上的声明过一遍，明确属于这一种的是 Samba 和 Vane；其他插件要等写插件的人实测。

## 理由

- **用户名是别的东西的主键。** Matrix 的 localpart 不能改，换了就是新账号，房间和加密身份都不在了。固定下来，核心和所有插件都少一种要处理的状态。
- **`sub` 用用户名，不另起不透明 ID。** 用户名已经不变，也不会分给别人；已经接好 OIDC 的插件里，账号就是按它建的，换 ID 反而要迁移。家人账号（M2）按用户名区分。
- **新插件默认 `sso: none`。** 单点登录要插件替应用预建账号、补角色，11 个插件 PR 的审查都挑出了照规范写的对账代码（#122）。网关已经挡住了外人，应用自带的登录多一次输入，换来插件简单。
- **退出码，不看路径。** 核心不用认识每个应用怎么注册，符合 ADR-0015。

## 没选的做法

- **改用户名的流程或迁移工具。** 要改 Matrix（localpart 不能改，只能新建账号）、OIDC 的 `sub` 和每个插件里的账号，中途失败回不去，每个插件还要写对账代码。主人否掉了。
- **核心不校验，记下的值和环境变量不一致时用记下的。** 配置错了也没人知道。
- **把用户名写在 `.env` 或 `compose.yaml` 里当记录。** 它们由安装脚本和升级重写，又不随数据目录走：恢复数据到另一台机器时对不上。
- **`sub` 用不透明 ID。** 见“理由”。
- **`sso: proxy` 可以不写 `webui.proxy`（#123 最初的提法）。** 新插件就有了两种写法，见“主人身份和 sso 解耦”。
- **所有版本都只有写了 `owner.identity` 才注入。** 已有插件都要改，已经装着的插件重建容器时会失败。
- **所有版本都照旧隐式注入。** 已有插件不用改，但新插件也有两种写法，声明 `sso` 就多拿一份身份变量。
- **继续拼邮箱，或者插件自己拼。** 应用拿到收不到信的地址。
- **允许按插件关掉网关这一层。** 注册页就露给了局域网，第三方 App 另有 ADR-0021 的入口。
- **只靠 `public.deny` 和审核挡抢注。** 见上表。
- **主人手动确认“我已经注册”。** 核实不了，点错了就是公网抢注。
- **核心替主人预建管理员，密码放密钥库。** 要给每个应用写脚本，正是这篇想省掉的；主人还要去查密码。应用能用环境变量建管理员时，插件自己可以这样做（`owner.identity` 加 `secrets`）。
- **所有插件强制单点登录。** 见“理由”。

## 代价与风险

- **用错了用户名改不了。** 一行命令安装不提问，大多数主机上就是 `owner`，显示名才是主人看到的名字。
- **没配邮箱的主机上，要邮箱的插件装不上。** Immich、Paperless-ngx 的插件 PR 写了 `${WONTON_OWNER_EMAIL:?}`，正式安装默认没有邮箱，这两个插件要主人先配。这是如实失败，代价是多一步。
- **局域网浏览器里两次登录。** 见“新插件默认 `sso: none`”。
- **应用的登录归应用管。** 忘了密码按应用自己的办法找回；不删数据重装还是原来的账号，删了数据就要重新注册。
- **`setup_done` 要插件作者写对。** 永远返回 0 的脚本等于没有这道防线，社区插件没人审。打开开关时“这个应用会暴露到公网”的提示还在（ADR-0021）。
- **系统用户名的黑名单不可能列全。** 插件的镜像可能带自己的用户（`postgres`、`node`）。插件用这个名字建系统账号时要自己处理重名。
