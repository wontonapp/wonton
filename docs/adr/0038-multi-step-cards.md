# ADR-0038 多步卡片：一组问题一步一张，最后一起提交

- 状态：提议（2026-11-05 接受后重新打开）。主人决定 M1 不做 Agent 的问题卡片（见“问题卡片 M1 不做”）；其余取舍由主人确认（见“已定”）
- 补充：[ADR-0016](0016-mcp-bus-and-confirmations.md)（卡片和回答的接口）、[ADR-0034](0034-onboarding-and-help.md)（引导的外观）、[ADR-0035](0035-acp-bridge.md)（`elicitation/create`）、[ADR-0036](0036-plugin-privileges.md)（最高级“多点一步”的做法）

## 背景

主人 2026-11-05 定：“确认卡片这个，往往有时候要确认的问题就是不止一个。你像 Claude，它 App 端的逻辑就是几个卡片选完一个到下一个、选完之后再到下一个，最后一起 submit 提交这么一个逻辑。”要用在三处：Agent 问主人问题、一次操作有几项要确认、新用户引导。

这三处原来的做法：

- **Agent 问问题：** 只能在聊天里发文字。Hermes 自带 `clarify` 工具，它的 Matrix 适配器没有覆盖 `send_clarify`，退回成带编号的文字，主人回一条消息当答案。
- **一次操作几项确认：** 最高级插件的安装和更新连发两张卡片（`Bus::confirmed_twice`），各自有期限，第一张答了第二张才出现。
- **新用户引导：** 状态机在客户端核心（ADR-0034），每步一个 ViewModel。

### 现成的做法

| 做法 | 形状 | 能用的 | 不能直接用的原因 |
| --- | --- | --- | --- |
| Matrix 投票（[MSC3381](https://github.com/matrix-org/matrix-spec-proposals/blob/main/proposals/3381-polls.md)） | `m.poll.start` 一个事件一道题，`m.poll.response` 是房间事件 | 事件里带纯文本兜底，和卡片的 `body` 同一个想法 | 一个事件只有一道题，没有“一组题一起提交”；没有自由输入；回答是 Bot 要自己收的房间事件，工具调用等不到 |
| MCP elicitation（[2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation)） | 服务器发 `elicitation/create`，客户端问用户；扁平表单；`accept`、`decline`、`cancel` | 三种结果的词汇；规则：写明谁在问、能拒绝、表单不能要密码和 key，链接不可点 | 方向相反：Agent 是总线的客户端，只有服务器能发；也没有“步”的概念 |
| ACP elicitation（[RFD](https://agentclientprotocol.com/rfds/elicitation)，2026-07 定稿） | Agent 发给客户端，表单同 MCP | 桥是客户端，方向对：可以转成多步卡片 | 只有 ACP Agent 有；Hermes 不走 ACP |
| [AskUserQuestion](https://code.claude.com/docs/en/agent-sdk/user-input)、Hermes `clarify`（v0.22.5 源码） | `questions[]`，每题有选项和多选开关，界面自动加“其他” | 工具的形状和上限：模型已经写惯了。Claude 1–4 题、每题 2–4 项；Hermes 最多 5 题、每题最多 4 项，可以没有选项 | 是各自程序内部的工具，别的 Agent 用不了 |

所以：**工具的形状抄 AskUserQuestion 和 `clarify`，结果的词汇和规则抄 MCP elicitation，答案怎么交回沿用 ADR-0016。** 要自己设计的只有卡片上多出来的“步”，因为上面没有一个标准能在 Matrix 消息里表达“一组题一起提交”。

## 决策

### 问题卡片 M1 不做

**主人 2026-11-05 决定：Agent 发的问题卡片 M1 先不做。** Agent 要问主人时用文字：

- **Hermes：** 用它默认的 `clarify`，在 Matrix 上是带编号的文字，主人回一条消息当答案。
- **ACP 桥：** 表单模式的 `elicitation/create` 照旧回 `decline`，Agent 在聊天里打字问。
- **OpenClaw 这类改不了 Matrix 层的 Agent：** 用它自带的文字提问。

两个方案都没选：核心代发的明文卡片，主人不接受，因为题目和答案会以明文存在加密房间里；Agent 自己发加密卡片可行（见“验证结果”），但主人看过代价后选了 M1 不做。代价是每种自带 Matrix 层的 Agent 都要单独适配，核心没法审计和限流，Hermes 升级时插件可能要跟着改。

这篇里写 `question`、`wonton__ask_owner`、`/agent/questions` 和 Bot 聊天面板的部分，是明文方案的设计，没有实施。以后要做时，界面和 ViewModel 可以沿用，传输按“验证结果”里的加密方案重写。

这个决定只管 Agent 的问题。操作确认和新用户引导（`StepNav`）不受影响。

### 共用什么

三处共用**界面和 ViewModel 的形状**，不共用传输：

| | 内容由谁写 | 怎么到 App | 显示在哪 | 什么时候生效 |
| --- | --- | --- | --- | --- |
| Agent 问问题 | Agent 写题目 | 核心代 Bot 在 Bot 私聊里发一条消息 | Bot 聊天：一行记录，加输入框位置的面板 | 最后一起提交 |
| 一次操作几项确认 | 核心 | 核心的确认表（ADR-0016） | 发起的会话和“等你确认”列表 | 最后一起提交 |
| 新用户引导 | 客户端核心和官方索引 | `GET /_wonton/api/onboarding`，不发消息 | 全屏页 | 最后一页点完成，一起生效（见“新用户引导”） |

操作确认的权威只在核心：卡片不进房间，App 画的是核心给的那一份（ADR-0016），Bot 的房间里 Bot 什么都能发也伪造不了。

### 卡片：还是那张确认卡片，多一个 `flow`

单步卡片一个字段都不改。多步卡片是 `ConfirmationCard` 多一个可选的 `flow`，这样登记、更新、到期、推送和“一张卡片只能答一次”都不用另写一套。

```json
{
  "msgtype": "m.text",
  "body": "Hermes 问你\n1. 照片备份到哪块硬盘？\n……\n请在最新版的 Wonton App 里回答。",
  "app.wonton.step_card": {
    "id": "…",
    "state": { "type": "pending" },
    "title": "Hermes 问你",
    "lines": [],
    "choices": [
      { "answer": "approve", "label": "提交" },
      { "answer": "reject", "label": "不回答" }
    ],
    "expires_at_ms": 1,
    "flow": {
      "kind": "question",
      "steps": [
        {
          "id": "0",
          "title": "照片备份到哪块硬盘？",
          "lines": [],
          "skippable": true,
          "input": {
            "type": "pick",
            "multi": false,
            "other": true,
            "options": [
              { "id": "0", "label": "NAS", "description": "容量大，慢一些" },
              { "id": "1", "label": "主机自带的硬盘" }
            ]
          }
        }
      ],
      "submitted": []
    }
  }
}
```

- **`choices` 是最后的按钮。** 提交和拒绝沿用 `Answer` 的方向，文字由核心写（“安装”“不装”“提交”“不回答”）。拒绝每一步都能点，提交只在最后一步。
- **`kind`：** `question` 是 Agent 问的，`operation` 是核心要确认的。不认识的落到 `other`，按不能回答显示。
- **`input`：** `acknowledge` 是看过就下一步；`pick` 是选，`multi` 决定单选还是多选，`other` 决定有没有输入框；`text` 只有输入框。不认识的落到 `other`（见“旧 App”）。
- **`lines`：** 和单步卡片同一个 `CardLine`，`emphasis` 显示成醒目。Agent 写的题目不能带 `emphasis`。
- **`submitted`：** 提交后核心编辑消息时写入，每行是题目和答案的文字，给聊天记录和另一台设备用。

**谁发的才算卡片：** `operation` 只认核心账号。`question` 只认私聊里的对方，也就是 Bot 本人，主人自己发的不算。Agent 拿着自己的令牌也能发一条同样的 `question`：那只是它自己说的话，面板上的字本来就是它写的；答案发给核心，核心没有这个 ID 就 404，卡片显示已经失效。

### 问题卡片怎么进 Bot 私聊

> **没有采用。** 主人不接受这一节的明文方案，见“问题卡片 M1 不做”。

**核心用 Bot 的令牌，往 Bot 的主房间发一条不加密的 `m.room.message`，编辑同样。** 主人看到的是 Bot 发的一条消息。答案不进房间：走 `POST /_wonton/confirmations/{id}` 交给核心，核心作为工具结果还给 Agent。

```text
Agent ──tools/call──▶ 核心 ──Bot 的令牌，明文──▶ Bot 私聊 ──同步──▶ App
Agent ◀──工具结果─── 核心 ◀──经隧道 POST 答案──────────────────── App
```

- **不用改任何 Agent。** 会调 MCP 工具的 Agent 都能问，核心也不用认识它（ADR-0015）。
- **不会进 Agent 的输入。** Bot 自己发的消息，Agent 的 Matrix 层本来就跳过（Hermes 见 `_is_self_sender`，桥只收主人的消息）。题目 Agent 自己知道，答案在工具结果里。
- **推送和普通消息一样。** 编辑由 `.m.rule.suppress_edits` 挡住，不再响（ADR-0016）。
- **令牌。** Bot 的账号本来就是核心建的，核心一直能登录它（`Matrix::login`），不多给权力。
- **没有房间时如实报错。** 插件没有 Bot，或者主人退出了这个私聊，工具返回 `isError: true`，不发给没人看的房间。

**代价：题目和答案的文字是明文，存在 Matrix 服务器的数据库里，而这个房间其他消息是端到端加密的。** 这是这个方案唯一的降级。范围有限：

- 核心要把答案交给 Agent，本来就经手全部内容，加密只能防 Matrix 的数据库，而它和核心在同一台主机上（ADR-0016 对 Wonton 私聊是同一个取舍）。
- 这个房间其他消息不受影响，还是加密的（见“验证结果”）。
- 工具说明禁止要密码、key 和令牌。主人自己在输入框里写的，会进 `submitted`。
- App 不显示“这条没加密”。Element 这类其他客户端可能标出来。

### 显示在 Bot 聊天里

按主人给的 Claude App 截图：

**时间线里是一行记录，** 和消息一样留在历史里。等回答时显示状态点、“正在提问”和展开箭头；答完显示已回答，展开能看到每题的答案（`submitted`）；过期、不回答、作废都如实写。

**屏幕底部是面板，** 从下往上滑出。从上到下：

1. 题目，最多两行，右边圆形的 ×（整张“不回答”）。
2. 最多 4 行选项：粗体标题，下面一行灰色说明，细线分隔。
3. 输入框“输入您的回答…”。
4. 底部两个按钮：“跳过”（描边）和“提交”（实心）。

没有题号标签和说明。有多道题时只在题目上方显示“2/3”和上一题。深浅色都走令牌（ADR-0026）。

**面板打开时，它的输入框代替聊天的输入框。** 不留两个输入框。这期间 Agent 在等工具结果，往聊天里发的话要排到工具返回之后（Hermes 的 `busy_input_mode: queue`），可能等 10 分钟。主人要说别的，点 × 关掉问题，聊天的输入框就回来了。

**同时有几张卡片时，** 一次开一张，先发的先开，答完开下一张。

### 回答：还是那个接口，一次发完

```json
POST /_wonton/confirmations/{id}
{
  "answer": "approve",
  "steps": [
    { "step": "0", "selected": ["1"] },
    { "step": "1", "selected": [], "other": "放到移动硬盘" },
    { "step": "2", "skipped": true }
  ]
}
```

鉴权、一次性、409 都同 ADR-0016 第 3 步，Agent 没有隧道身份，答不了自己的问题。核心校验：每一步都有答案，不能跳过的没有跳过，选项和题目对得上，单选最多一项，有 `other` 的步才收文字，文字不超过上限。不对就 400 `invalid_input`，卡片还等着，不当成同意。`reject` 不带 `steps`。

走完每一步是 App 的事，核心只看最后这一个请求。这不是安全边界：能发这个请求的只有主人自己的设备和主人令牌。

### 和单步卡片并存，旧 App 怎么办

多步卡片放在**另一个字段** `app.wonton.step_card`，类型相同。旧 App 不读这个字段，把它当普通消息显示 `body`，里面写明题目和“请在最新版的 Wonton App 里回答”。其他 Matrix 客户端同样。

没有放在 `app.wonton.confirmation` 里加字段的原因：旧 App 会画出 `choices` 的“安装”按钮，却不知道有 `steps`，主人点了只会得到 400。

新 App 碰到更新的核心：

- 不认识的 `Answer` 按钮照旧不显示。
- 不认识的 `input`：这一步能跳过就自动跳过，不能跳过时不显示提交，提示要更新 App。拒绝还能点。

### 壳怎么画

状态都在客户端核心，壳只渲染，操作发回去（ADR-0005）。时间线多一种 `MessageContent::StepCard`，一个 `StepCardView`：

| 字段 | 内容 |
| --- | --- |
| `nav` | `StepNav`：第几步、共几步，上一步、跳过、下一步能不能点 |
| `step` | 当前这一步：题目、说明行、选项和各自的选中状态、输入框的内容 |
| `submitted` | 提交后的每一行 |
| `choices` | 现在显示的提交和拒绝按钮 |
| `sending`、`problem` | 同 `ConfirmationView` |

`TimelineUpdate` 多一个 `panel: Option<StepCardView>`：这个房间现在该开着面板的那张问题卡片，壳不用自己从条目里找。

操作只有一个 `Action::StepCard { id, op }`，`op` 是选、输入、上一步、下一步、跳过。最后的提交还是 `Action::AnswerConfirmation`，客户端核心带上草稿。

外观按 ADR-0026、ADR-0029：两端共用的自绘组件，只用现有令牌和 Phosphor 图标，不加新颜色。外框（`StepCardFrame`）和选项行（`StepOptionRow`）和引导共用，内容区是插槽，能放进面板、时间线和全屏页。步数只显示“2/3”，不加步骤名和说明。读屏读出第几步、共几步和选中状态。Agent 写的文字一律按纯文本显示，不解析 Markdown，链接不可点。

### 一步步走

- **单选：** 不是最后一题时，点了就到下一题。最后一题点了选中，再点“提交”。
- **多选和输入框：** 点“下一题”，最后一题点“提交”。在输入框里写了字，单选的选中就清掉，多选的还留着。
- **没有汇总页。** 答完最后一题就提交。
- **上一题：** 不发网络请求，已经选的都留着，能回去改。
- **跳过：** Agent 的问题每道都能跳过，Agent 设不了必答，要接得住 `skipped`。最后一题点跳过就提交。操作确认的每一步都不能跳过。
- **×（拒绝）：** 任何一步都能点，整张卡片结束，已选的不发出去。

操作确认没有面板，卡片在会话里的卡片行和“等你确认”列表里一步步翻（ADR-0016），最后一步的按钮来自 `choices`。

### 超时和中断

期限和单步卡片相同（`WONTON_CONFIRMATION_TTL_SECS`，默认 10 分钟），不分步计时。过期不提交已选的部分：主人没点提交，就是没答。

| 情况 | 结果 |
| --- | --- |
| App 退到后台又回来 | 草稿还在，它在客户端核心的内存里 |
| App 被杀 | 草稿没了，卡片还等着，从第一步重来。卡片最多活 10 分钟，不为它存盘 |
| 另一台设备 | 草稿不跨设备。先提交的算数，后提交的得到 409，卡片显示已经答过 |
| 提交时断网 | 按钮和草稿都在，可以再点。核心其实收到了的话，再点得到 409，等卡片更新 |
| 过期 | 卡片显示已过期，草稿丢弃。核心重启时同样靠期限（ADR-0016） |
| Agent 断开或取消 | `question`：卡片作废，写明“Agent 不再等这个回答了”，同 ADR-0035。`operation`：照 ADR-0016，确认照样有效 |

### Agent 问问题：`wonton__ask_owner`

核心自己的工具，有 `tools` 权限的插件都能调。

```json
{
  "questions": [
    {
      "question": "照片备份到哪块硬盘？",
      "options": [
        { "label": "NAS", "description": "容量大，慢一些" },
        { "label": "主机自带的硬盘" }
      ],
      "multi_select": false
    },
    { "question": "相册叫什么名字？" }
  ]
}
```

| 项 | 上限 |
| --- | --- |
| 题数 | 1–4 |
| 每题选项 | 2–4，或者不给（这题只有输入框） |
| 题目 | 200 字 |
| 选项的 `label` | 40 字 |
| 选项的 `description` | 100 字，可选 |
| 主人输入的文字 | 2000 字 |

- **输入框总有。** Agent 关不掉：主人可能想说它没想到的话。
- **超了不截断。** 返回 `isError: true`、`invalid_input`，写明哪里超了，Agent 自己改（“失败即停”）。
- **结果用题目和文字，不用编号，** 模型不用再对一遍：

  ```json
  {
    "action": "accept",
    "answers": [
      { "question": "照片备份到哪块硬盘？", "selected": ["NAS"] },
      { "question": "相册叫什么名字？", "skipped": true }
    ]
  }
  ```

  `action` 借 elicitation 的词：`accept`；`decline` 是主人点了 ×；另加 `expired`。这三种都是正常结果，不算 `isError`，Agent 接着干或者在聊天里再问。卡片发不出去、没有房间、等的太多（ADR-0016 的上限）是 `isError: true`。
- **只是问，不授权。** 工具不敏感（标 `readOnlyHint: true`），回答只回给调用的 Agent，核心不据此做任何事。敏感操作照旧发自己的确认卡片，主人回答“同意”不能代替它。放宽（ADR-0024）也不跳过问题：“一律允许”不会替主人回答。写成测试。
- **不收秘密。** 工具说明写明不能用它要密码、key、令牌，和 elicitation 表单同一条规则。要秘密的走官方登录链接（ADR-0035）。
- **防刷屏。** 和确认卡片共用每个插件 3 张的上限（ADR-0016）。
- **审计。** 写题目和结果（`accept`、`decline`、`expired`、作废），不写主人的答案。
- **怎么教给 Agent：** 写在工具说明里：有几件事要主人定时用它，一件简单的小事直接在聊天里问。

#### 其他 Agent 怎么接

- **Hermes：** 它的插件配置关掉 `clarify`，模型就只有这一种问法，不会一会儿卡片一会儿编号文字。
- **ACP Agent：** 桥说的不是 MCP，所以和 `/agent/permissions` 一样，给一个 `POST /agent/questions`，请求和结果与工具相同。桥把 ACP 表单模式的 `elicitation/create` 转过去，不再一律 `decline`：枚举是单选，枚举数组是多选，字符串是输入框，布尔是两个选项；转不了的回 `decline`。URL 模式照旧（ADR-0035）。
- **插件自己发 elicitation：** 不做。核心连插件时不声明这个能力，要做时映射规则同上。

### 一次操作几项确认

把两张连发的卡片合成一张，`kind: operation`，和单步卡片显示在同样的地方（ADR-0016）：第一步是权限和镜像，第二步是 ADR-0036 的最高级提示。声明了 `mcp` 的插件在第二步多一行“以后每次调用它的工具都会问”。`choices` 是“我知道这个插件能控制整台主机”和“不装”。只有一个期限，第一张答了第二张没答的中间状态也没有了。

没有“选怎么放行”这一步：ADR-0036 定了最高级不能放宽，没有东西可选。

| 流程 | 之后 |
| --- | --- |
| 最高级插件的安装和更新（`confirmed_twice` 的三处调用） | **合成一张多步卡片，删掉 `confirmed_twice`** |
| 很高和以下的安装、更新 | 不变，一张一步 |
| 工具调用（含最高级每次一张）、存文件、卸载、ACP 权限 | 不变，一张一步。一次一个决定，多点一步只是更烦 |
| App 安装页上最高级的“再弹一步” | 不变。它不是聊天里的卡片，不经 Matrix |

`scripts/dev.sh approve` 也要会答多步卡片（ADR-0024 的“开发环境”）：不能跳过的步选第一项。`GET /_wonton/api/confirmations` 同时列出问题卡片，脚本不答它们，要测的时候由测试自己答。

### 新用户引导

流程同 ADR-0034，页面用同一个卡片外框：一张卡片一步，有步数、上一步、跳过和下一步，最后一页列出所有选择。引导走 `OnboardingViewModel`，不走 `StepCardView`，两者只共用 `StepNav` 和壳的组件。

外框不假定内容和按钮：

- 内容区是插槽，能放进时间线上方，也能放进全屏页。选 Agent 和选需求用同样的选项行，资料和接模型（服务商、贴 key、测试）由壳另画，放在里面。
- 按钮的文字由壳按步骤给（下一步、完成、进入聊天），等结果时显示进行中。拒绝按钮可以没有：引导的跳过是“这一步不选，到下一步”，没有拒绝。
- 选项行能写明不能选的原因（`blocked`，不藏），行尾能放一个状态（已安装、安装中、失败）。

**不发 Matrix 消息，每一步只记下选择，最后一页点完成才一起生效。** 主人 2026-11-06 改的（原来是每步答完就生效）：试用时选一步就执行一步，装应用还要一个个点、一个个确认。

- **点完成之前没有副作用。** 选择记在客户端核心的内存里，不写 `core/onboarding.json`，也不发保存请求。中途关掉 App，下次从第一步开始，每一步预先填好家里服务器上现在的设置。
- **模型的 key 可以当场测。** 测试接口只测不存（ADR-0034 的 `test`），错了当场改；key 只在客户端核心的内存里，点完成时才保存。
- **最后一页列出资料、默认 Agent、模型和要装的应用，** 应用带着安装确认页同样的权限和说明（取安装预览）。点完成就算主人确认了这些权限，不再一个个弹确认页。有一项装不了、要先填资料或取预览失败时，完成不能点：回去改，或者不选它。
- **点完成后依次保存资料、模型、默认 Agent 和“走完了”，** 然后在后台装 Agent 和应用。每一项在这一页上显示排队、进行中、完成或失败；失败的写明类别，有重试，别的照常装。保存好之后就能进入聊天，不等下载（ADR-0034）。
- **重进引导不跳步。** 已经配好的步骤显示现在的选择（默认 Agent、已接的模型、已装的应用），可以改，也可以直接下一步。

key 仍然不进聊天记录；模型接上之前没有 Agent，配对刚结束时也不该先进聊天，所以引导还是原生页面，不发消息。

## 理由

- **卡片用同一个类型：** 发、改、到期、推送都已经做好测好，多步只多在“答之前”，而那部分全在客户端核心。
- **一个请求提交：** 核心不用存草稿，也就没有“答了一半”的状态；期限和一次性规则不变。
- **核心代 Bot 发：** 只有这样主人看到的是 Bot 聊天里的消息，同时所有 Agent 只要会调工具就能问（ADR-0015）。
- **工具形状抄现成的：** 主流模型已经会写，符合“能一次写对”。

## 没选的做法

- **Agent 的 Matrix 层自己发进加密房间。** 真正端到端加密，实测可行（见“验证结果”）。不用替换 Hermes 的适配器方法，工具也不再由核心提供。代价见“问题卡片 M1 不做”，主人选了 M1 不做。
- **核心带加密加入 Bot 私聊，或者给 Bot 多开一台带加密的设备代发。** 核心要跑带加密的 Matrix 客户端，存每个 Bot 的密钥（ADR-0016 否过）。第三个成员还会把私聊变成群聊。换来的只是 Matrix 数据库里看不到题目，而核心同一台主机上已经经手过了。
- **消息发在 Wonton 私聊，客户端把卡片放进 Bot 聊天。** 不降级加密，不用 Bot 的令牌。主人要的是记录留在 Bot 聊天里，换设备、翻历史都在。
- **不发消息，核心单独存问题，客户端自己轮询。** 也不降级，但没有推送，也不是消息。
- **用 MCP elicitation 让核心问 Agent。** 方向反了，问的是 Agent 不是主人。Hermes 收到后走它自己的确认，转不到 App。
- **工具参数直接用 elicitation 的 `requestedSchema`。** 标准，但模型要写 JSON Schema，容易错；对象的键也表达不了题目的顺序。
- **Matrix 投票一题一个事件。** 见“现成的做法”。
- **所有卡片都改成多步。** 单步卡片一次点完，改了只多一遍迁移。
- **草稿存在核心。** 可以换设备接着答，但核心要多一个接口和一种状态，卡片也才活 10 分钟。
- **一步一提交。** Agent 要等全部答完才能继续，一步一提交它也用不上；拒绝和过期时还要处理已经提交的部分。
- **汇总页。** 主人不要：答完最后一题就提交，要改就退回去。
- **Agent 能设必答。** 主人不想答时只能整张拒绝，反而丢了答过的。
- **面板和聊天输入框同时留着。** 两个输入框，往聊天里发的话还要排到工具返回之后。
- **引导也发消息。** 见“新用户引导”。
- **引导每步答完就生效。** 2026-11-05 选的，2026-11-06 主人试用后改掉：每步都有副作用，装应用要一个个确认，重进时已经配好的步骤还会被跳过。
- **引导的选择存在核心。** 换设备能接着走，但核心要多存一份草稿；引导几分钟就走完，关掉 App 从头走时每一步都已预先填好。

## 代价与风险

- **题目和答案在加密房间里是明文，** 见“问题卡片怎么进 Bot 私聊”。这是明文方案的代价，主人不接受，所以没有采用。
- **核心用 Bot 的令牌发消息。** 主人和 Agent 都看不出这条是核心发的还是 Agent 自己的 Matrix 层发的，这里两者同权。
- **等回答时 Bot 说不了话。** 和确认卡片一样（ADR-0016）：Agent 的调用一直等着。主人要说别的，先关掉问题。
- **旧 App 答不了多步卡片，** 只看到文字。最高级插件的卡片也是：这期间 Bot 装不了最高级插件，到期后 Agent 收到“主人没有确认”。
- **推送的正文可能很长。** 多道题的 `body` 比单步长，通知里只显示开头。
- **Agent 不一定会用它。** 模型可能还是在聊天里连问几句。靠工具说明，效果要实测。

## 已定

主人 2026-11-05 定：

1. **问题显示在哪：** “就在 Bot 聊天里，和消息一样”。还给了 Claude App 的截图，见“显示在 Bot 聊天里”。协调会话补充：要是 Hermes 的适配器发不了，就改适配器，或者让核心注入进房间，代价写进 ADR。这篇先选了注入，明文的代价主人没有接受，见第 8 条。
2. **引导：** “每步生效”。外观同卡片，每步能跳过。2026-11-06 主人改为最后一页点完成才一起生效，应用点完成后自动在后台装，见“新用户引导”。
3. **最高级安装：** “只要两步”。权限和 root 提示，加一行“以后每次调用它的工具都会问”。ADR-0036 不变。
4. **上限：** “4 题 × 4 个选项”，每题有输入框，超了报错不截断。
5. **汇总页：** “不要，答完最后一题就提交”。
6. **跳过：** “都能跳过”。Agent 的问题每道都能跳过，也能整张不回答；操作确认不能跳过。
7. **过期：** “10 分钟”，和确认卡片相同。
8. **问题卡片：** M1 先不做，Agent 用文字提问，见“问题卡片 M1 不做”。第 1、4、5、6 条里关于问题卡片的部分留到以后做时再用。

## 验证结果

2026-11-05 在开发机上实测，用 `wonton-client` 的集成测试环境（真实的 Tuwunel v1.9.4、真实的客户端核心，matrix-sdk 0.19.1，提交 `423fe9a1`）。Bot 账号建加密私聊，主人加入，房间确认是加密的。然后用 Bot 的令牌直接 `PUT /rooms/{id}/send/m.room.message/{txn}`：

| 做了什么 | 结果 |
| --- | --- |
| 发一条不加密的卡片 | 200，App 的时间线里显示成卡片，自定义字段读得到 |
| 明文编辑这张卡片（`m.replace`） | 200，App 上卡片状态更新 |
| 之后 Bot 经 SDK 发一条加密消息 | App 正常解密显示，房间不受影响 |

测试借用了现有的单步卡片解析（发件人写成核心账号），验证的是传输，不是 `app.wonton.step_card` 的解析。

**没测：** 明文消息的推送（默认规则按事件类型判定，这里是 `m.room.message`，应当和单步卡片相同）；真实 Hermes 容器（见“待验证”，只看了 v0.22.5 的源码 `_on_room_message` 先跳过自己的消息）；Element 怎么显示。

### Agent 自己发加密卡片

2026-11-05 在开发机上实测：Hermes v0.22.5 官方镜像（固定摘要，没改镜像）、Tuwunel v1.9.4，主人一侧是 `wonton-matrix` 的 matrix-sdk，模型是假的。测试代码没有进仓库。

| 步骤 | 结果 |
| --- | --- |
| `wonton/` 插件用 `ctx.register_platform_handler("matrix", factory)` 拿到 matrix client，`client.send_message_event` 发卡片 | 主人一侧解密后读到完整的 `app.wonton.step_card` |
| 主人 `room.send_raw("app.wonton.step_answer", …)` 发答案，插件 `client.add_event_handler` 收 | 插件收到解密后的答案，等着的工具调用继续，答案成为工具结果交给模型 |
| 插件加密编辑卡片为已回答 | 主人一侧卡片状态更新 |
| 看服务器上的事件 | 全是 `m.room.encrypted`，没有 `m.room.message`，查不到答案文字和字段名 |
| 答案事件的去向 | 不进 Hermes 的消息流程，也不出现在 App 时间线 |
| `agent.disabled_toolsets: [clarify]` | 模型的工具表里没有 `clarify` |
| 插件工具和 Hermes 默认的 `tool_search` | 工具不直接出现，模型经 `tool_call` 调用，这条路也跑通 |

**没测：** 真实模型会不会调它；`/stop` 打断；等回答时 Hermes 重启；推送；两台设备同时答；App 的界面。

**其他 Agent（只读了源码或搜索，没有运行）：**

- **ACP 桥：** 用的就是 `wonton-matrix`，把 `elicitation/create` 转成卡片估计约 1 天。`claude-agent-acp` 把 AskUserQuestion 转成 elicitation；`codex-acp` 没搜到相关代码，omp 没查到，要实测。
- **OpenClaw：** 有自己的 `ask_user` 工具，经 Matrix 插件发文字、主人打字回答。Matrix client 在内置插件里，没有给其他插件的接口。要出卡片得给上游提 PR，估计 2～3 天加等待时间。

**这样做时要改的：** 答案不走核心，所以 App 拿不到同步的结果，要等 Bot 编辑卡片，等不到就如实显示 Agent 没有回应。10 分钟的计时放到适配层，App 用 `expires_at_ms` 自己判断。Hermes 重启后等待就没了，卡片在到期前还能点，但不会有回应。

估算全部工作约 8.25 个工作日，明文方案约 7.25 个。两个数都是估计。
