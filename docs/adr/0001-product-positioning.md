# ADR-0001 产品定位、市场与命名

- 状态：已接受（2026-10-28）

## 背景

旧产品 Lucy 深度绑定端脑云：账号与设备绑定、模型、计费、OTA 都依赖它。新产品要完全独立，
形态参考“AI 以联系人身份住在 IM 里、能主动找你”的个人 Agent（如 MuseBot），以及飞牛这类
NAS 系统，但以 AI 原生为主。同类产品里，Olares 是最接近的 AI 原生个人云。

## 决策

- **形态**：Agent 为主的家庭服务器。对话是主入口：App 像 IM，Agent 是第一联系人，可以主动推送；
  NAS、相册、文件、Docker 应用都是插件，Agent 通过工具调用它们；有网页的插件在 App 里当小程序用。
- **用户**：公开发行给普通用户。
- **市场**：国内外同时；架构不锁区，provider、镜像、推送都按双区设计。
- **发行主体**：MVP 走 TestFlight 和直装 APK；公司主体、企业开发者账号、App 备案并行办理。
- **独立性**：不接入端脑云，不复用其代码。旧 Lucy 仓库留在 GitLab 原样不动，只作参考和回滚。
- **命名**：Wonton / 云吞。“云吞”倒过来读是“吞云”：把原本放在云上的 AI、相册和网盘吞回自己家。
  仓库名 `wonton`，插件扩展字段 `x-wonton`。

## 理由

- 对话入口让 Agent 成为主角，而不是 NAS 的附属功能；插件化让 NAS 能力和 AI 能力共用一套机制。
- 名字中西方都能立刻认出（同一种食物），中文字面双关自带故事，适合传播；查重时 GitHub 和中美
  App Store 没有同名的科技产品。

## 代价与风险

- 公开发行加双区意味着必须运营最小的云服务（推送中继、iroh 中继），并处理国内上架、备案和厂商推送对
  公司主体的要求。
- 名字是常用词，主域名已被注册，需要用变体（查询时 `wonton.chat`、`usewonton.com` 可注册）；
  上线前要做中美商标检索。
- 少数人可能把“吞云”联想到“吞云吐雾”，主联想仍是食物。

## 待定

核心开不开源、用什么许可证，在 M2 结束前定（主人 2026-11-04 定的期限）。
