# ADR-0042 一台手机连多台服务器：同一时间连一台，各自保留数据，每台都推送

- 状态：已接受（2026-11-06）。方向由主人确认（见“背景”）；修订 [ADR-0009](0009-identity-pairing-sso.md) 里“一个 App 可以连多台服务器”的做法和 [ADR-0003](0003-matrix-and-encrypted-push.md) 的推送内容

## 背景

ADR-0009 说一个 App 可以连多台服务器，但没定怎么做。代码里只有一个位置放连接信息：扫第二台的码会顶掉第一台，
聊天的本机数据（会话、加密密钥、房间缓存）、插件缓存、底栏和传输记录都跟着清掉，换回来要重新登录，
旧的加密消息要恢复密钥才能解开。

主人 2026-11-06 定的方向：

- 现在就做。同一时间只连一台，其他几台的数据各自留在手机上。每台都能收推送。在设置里添加、切换、移除。
- 不做同时连多台。
- 不写数据搬移：已经配对的手机升级后重新配对（绿地不兼容，见 AGENTS.md）。
- 重点验证两种情况：推送来自不是当前这台的服务器；切换时文件传到一半。

## 决策

### 本机存储按服务器分目录

客户端核心的数据目录分成两层：

```text
<数据目录>/
  device-key          本机的设备身份，所有服务器共用（每台服务器按它的 endpoint ID 登记这台手机）
  appearance.json     外观，按手机
  servers.json        配过的服务器：槽位、服务器 ID、自定义名字、编号、当前是哪台
  push-endpoint.json  平台给的推送地址，按手机
  servers/<槽位>/     一台服务器的一切：连接信息、Matrix 会话和 SQLite 库、引导、底栏、插件缓存、升级记录、
                      传输记录和下载的文件
```

服务器 ID 是它的隧道 endpoint ID，配对后不变。槽位名是本机生成的，和服务器 ID 无关：配对前还不知道 ID，
要先有地方存配对中的状态。同一台服务器再配一次，用新的槽位，配好后删掉旧槽位，沿用它的名字和编号。

扫描配对码的所有入口（包括已经配对时的重新配对、开发启动参数）都先校验，再在未配对的新槽位里交换；
不能在旧服务器的作用域里覆盖连接信息。显式“添加服务器”已经打开的空槽位直接复用。
服务器重装或重置后 endpoint ID 不同，即使地址、域名和名字相同，也是一台新服务器：保留旧槽位的数据，
新身份配好后切到它，不按地址或名字推断替换。只有 endpoint ID 相同才按上面的重新配对规则删除旧槽位。

连接旧 endpoint ID 失败只说明连不上它。隧道握手未认证出旧身份时，超时或连接错误不能证明同地址的服务器换了身份，
因此如实显示“连不上”，不声称“服务器身份变了”。配对新身份不依赖旧连接恢复。

底栏是否显示文字跟着底栏的其他设置存在每台服务器下，换服务器可能跟着变。
这样做是为了不把 `tabs.json` 拆成两半；如果主人在意，再把它挪到按手机的设置里。

### 切换就是换一套“连着一台服务器的核心”

一台服务器的连接、聊天、推送登记、插件、底栏、文件、引导和设置这些部件，合起来叫一个服务器作用域。
每个作用域有自己的 tokio 运行时。切换时整个停掉，后台任务一起结束，再按另一个槽位重新建一个。

壳拿到的订阅不跟着换：每种 ViewModel 的发送端由第一个作用域建好，之后的作用域接着用同一个，建起来时先发出自己的初始值。
壳不用重建界面，看到的就是所有 ViewModel 变成另一台服务器的。没选“由当前作用域转发到固定的发送端”：多一跳以后，
壳发出操作到订阅看到变化之间有了延迟，原来“操作成功时状态立即更新”的保证没了。共用发送端的代价是旧作用域要先停干净
再建新的（最多等一秒），不然它停下前最后的发送会盖掉新服务器的状态。
例外是时间线：它跟着打开的房间走，切换时结束（`next()` 返回空），壳退回会话列表。

为什么不同时连多台：每台都要一条隧道、一个 Sliding Sync、各自的插件轮询，手机的电量和流量吃不消。
另一台的新消息靠推送就能知道。

### 推送带上服务器 ID，不是当前这台的临时连一下

所有服务器共用平台给的同一个推送地址，推送加密不变（RFC 8291，ADR-0003）。推送内容加一个 `server` 字段，
写服务器自己的 endpoint ID。手机解开推送后：

- 是当前这台：照旧经当前的连接取回消息、在本机解密。
- 不是当前这台：在后台临时为那台服务器开一个只有连接、聊天和推送三个部件的作用域，取回、解密、给出通知，
  然后关掉。它用那台服务器自己槽位里的 Matrix 库，和当前作用域不冲突。同一台的几条推送共用一个临时作用域。
  切到那台、移除那台之前先关掉它：两个作用域不能同时用一个槽位的 Matrix 库。
- `server` 不在已配对的列表里（比如已经移除了那台）：如实显示一条“收到一台已移除的服务器的消息”，
  不伪装成消息内容。

通知带上服务器 ID。点开时先切到那台服务器，再进房间。

平台给了新的推送地址时，当前这台立刻重新登记。其他几台在后台逐台临时连上去登记，连不上的在下次切过去时补上。

### 切换时文件传到一半

传输记录在各自的槽位里。作用域停掉时，进行中的上传和下载停在原处，记录变成“已暂停”（重启 App 也是这样）。
切回那台服务器后自动接着传：上传用 tus 的断点续传，下载用 `Range`。

不在别的服务器上继续，也不标成失败：文件 ID 只在它自己那台服务器上有意义。

### 设置里的样子

“家里的服务器”这一页最上面是服务器列表，当前这台带勾。点另一台就切换。还有“添加服务器”（走扫码配对，配好后切过去），
每台可以改名、移除。

- 移除只删手机上的数据，不吊销设备。吊销在服务器那边做，和“添加设备”的反向一样，由主人在还连着的那台上操作。
- 移除当前这台时切到剩下的第一台。一台都不剩时回到配对页。
- 核心只存主人自己起的名字；没改名时给出配对成功时确定的编号，之后不变。壳按编号显示默认名，并随 App 语言变化（ADR-0043）。

## 代价

- 切换要重新建隧道、重新同步，有几秒的等待，界面上照实显示“正在连接”。
- 推送来自别的服务器时，要在后台多建一条隧道，比当前这台的推送慢。连不上就显示“取不到这条消息”和原因，
  和当前这台连不上时一样。
- 每台服务器各有一份 Matrix 库和插件图片缓存，手机上的占用跟着服务器数量涨。
