# ADR-0087 家人账号：独立账号、三级权限、私人和共享 Bot

- 状态：提议（2026-11-12）。方向由主人定：直接做完整版，每个家人一个独立账号，权限分管理员、家人、孩子三级，有私人 Bot 和共享 Bot；
  不等 M2 的其他项。几处取舍见“待主人定”。修订 [ADR-0045](0045-family-members.md)（角色从主人、家人两级改成三级，邀请加上
  两边同意，“给主人”的管理和卡片改成给管理员，OIDC 的 `groups`，谁能放宽）、[ADR-0007](0007-agents-and-bots.md)（家人不等 M2）。
  一个 Bot 里按人分档用 [ADR-0083](0083-bot-contacts-and-group-chat.md) 的档位和轮次报告，本篇只加按角色的上限

## 背景

ADR-0045 定了“每人一个账号、Bot 有归属人”，按 `96763a20` 的代码，核心已经有大半：`core/members.json`、绑定家人的配对码、
`GET /_wonton/api/me`、角色 `owner`／`member`／`friend`、插件的“家人能用”开关、私人 Bot 和共享 Bot、OIDC 的 `groups`、
总线带 `app.wonton/user`。缺的是：

- **两端 App 没有家人的入口**：客户端核心不调 `/_wonton/api/members`，设置里没有“家人”。家人只能用“添加设备”配对，登进来的是主人：
  聊天、笔记、AI 会话、模型设置全家共用，别人发的消息显示成“我”；孩子能装应用、改设置，能让主人的 Bot 删掉主人的笔记。
- **只有两级**：主人什么都能做，家人除了装插件外和主人一样指挥自己的 Bot。没有“孩子”：孩子的 Bot 调会改数据的工具时，卡片发给孩子自己点。
- **管理的人只有一个**：主人出差时，家里没有第二个人能批安装、管设备。

## 别人怎么做（2026-11-12 查）

| 项目 | 怎么分家里的人 | 借鉴什么 |
| --- | --- | --- |
| Matrix | 服务器级只有“是不是服务器管理员”（Synapse 的 admin API、Tuwunel 的管理房间）；房间里按权限等级（power level，默认 0、管理 50、管理员 100）定谁能踢人、撤回、改设置。规范里没有家长控制 | 每人一个账号；家庭群的管理用房间权限等级；服务器管理员不给人 |
| Home Assistant | 第一个用户是 owner，不能被删、不能降级；其余用户一个“管理员”开关，另可限“只能从局域网登录”。普通用户能控制所有设备，不按实体分权限（多年的功能请求，没做） | 主人加管理员开关的形态；粗粒度的角色比细粒度的授权好懂 |
| Nextcloud | `admin` 组；任意的组；组管理员（subadmin）管自己组的人；应用能“只给某些组用”；按用户限额 | 应用按组开放，就是插件的开放范围按角色 |
| Jellyfin | 每个用户一套策略：是否管理员、能看哪些媒体库、最高分级、屏蔽未分级和标签、能用的时段、能不能删媒体 | 家长控制做在应用里，平台只给角色；“能不能删”单列 |
| Immich | 每个用户一个管理员标志、自己的照片库和额度；伙伴共享、共享相册；OAuth 登录能从声明里读角色（`immich_role`）、存储标签和额度 | 多用户应用按 OIDC 的身份和角色自己分数据；有的应用读专门的声明，不读 `groups` |
| Apple 家人共享、Google Family Link | 组织者、家长、孩子；孩子买东西、装应用要家长批（“询问后购买”），请求推到家长的设备 | 孩子能发请求，由管理员批；不是一律不能 |

结论：**采用 Home Assistant 的“一个主人、管理员开关、普通用户”，加上家人共享的“孩子”一档和“孩子发请求、家长批”。**
细分（媒体分级、按人的库、额度）交给多用户的应用自己做，平台经标准的 OIDC 和 Matrix 告诉它“是谁、什么角色”。不自研权限系统：
不做按实体、按工具的授权表，不做自定义角色。

## 决策

### 1. 角色

| 角色 | 是谁 | 几个 |
| --- | --- | --- |
| 主人（`owner`） | 第一台配对设备的人（ADR-0009）。是管理员，另外不能被降级、移除；`sudo wonton pair` 找回的是他 | 一个 |
| 管理员（`admin`） | 主人或别的管理员设的家人 | 不限 |
| 家人（`member`） | 被邀请的大人 | 不限 |
| 孩子（`child`） | 被邀请的孩子。所有管理员都算他的家长 | 不限 |
| 好友（`friend`） | 不是家里人，照 ADR-0051 | — |

- 角色记在 `core/members.json` 每个人的记录上（主人照旧在 `core/owner.json`），邀请时选，管理员随时改（主人的不能改）。
  改角色立即生效：网关和总线每个请求按当前角色判断，插件、Bot 要重建的照 ADR-0045 重建。
- 下文“管理员”包括主人。ADR-0045 和别的 ADR 里“只给主人”的管理操作（服务器设置、家人、所有设备、共享 Bot、插件的开放范围）都改成只给管理员，
  例外只有上表主人那一格。

### 2. 邀请：出码、扫码、两边同意

沿用 ADR-0045 绑定家人的配对码，加上 ADR-0050 服务器配对的“扫码只是发请求，出码方同意才算”。不另造一套：

1. 管理员在“设置 → 家人”点“邀请”，填显示名、选角色（家人、孩子、管理员），选要不要建私人 Bot（同 ADR-0045）。
   核心记成“已邀请”，出一张绑定这个人的码：格式同 `wonton://pair`，24 小时有效，用一次（ADR-0045）。能当面扫，也能经系统分享发出去。
2. 被邀请的人装 App，扫码或打开链接。App 先给他看一页：加入谁家、什么角色、这个角色能做什么、管理员能看到什么（第 3 节表里“看谁的”那行），
   按钮“加入”和“不加入”。这是他这一边的同意。点了“加入”，App 经隧道交上码和这台设备的名字，核心记一条**加入请求**，回“等管理员同意”。
3. 管理员的 App 在“请求”里看到这一条（和服务器配对、好友请求放在一起的那一节，ADR-0050、ADR-0051）：邀请时填的名字、设备名、什么时候扫的，
   点“同意”或“拒绝”。新请求推送给所有管理员的设备，通知类别同确认卡片，谁先点算谁的。同意后设备登记在这个人名下，之后同 ADR-0045 的第 3、4 步。
4. 码用掉以后，再有人用同一张码只得到“码已用过”。被拒绝的请求连同码一起作废，管理员重发。

- 这一步补上 ADR-0045 的“分享出去的链接谁先用谁就是这个家人”：码转出去了，别人扫了也要管理员点同意，管理员看得到设备名和时间。
  ADR-0045“已定”第 7 条（24 小时、一次性、能分享）不变，多了同意这一步。
- 已配对的设备给自己加设备，照 ADR-0045 出归这个人的码，不用管理员同意：同一个人有了已登录的设备，就是他本人在操作。
- 被邀请的人已经有别的 Matrix 账号（matrix.org 上的好友）也照样走这条：家人要本机账号才有私人空间、私人 Bot（ADR-0045）；好友账号照旧是好友。

### 3. 各角色能做什么

| | 管理员 | 家人 | 孩子 |
| --- | --- | --- | --- |
| 装、删、升级应用 | 能，逐项确认权限（ADR-0036） | 管理员给了“能装应用”才能（ADR-0045，默认关）；没给时点“请管理员装”，卡片发给管理员 | 不能自己装；能点“请管理员装” |
| 看商店 | 能 | 能，只读加“请管理员装” | 同家人 |
| 改模型设置（接 provider、填 key、额度） | 能 | 不能，看得到自己 Bot 的用量 | 同家人 |
| 改服务器设置（升级核心、镜像加速、代理、局域网、第三方入口） | 能 | 不能 | 不能 |
| 用应用 | 全部 | 开放给家人的 | 开放给孩子的 |
| 定应用开放给谁 | 能 | 不能 | 不能 |
| 指挥 AI 动手 | 见第 4 节 | 见第 4 节 | 见第 4 节 |
| 看谁的聊天 | 只看自己在的房间 | 同左 | 同左 |
| 看谁的私人空间、Bot 记忆 | 只看自己的 | 同左 | 同左；管理员能不能看孩子的 AI 动手记录见“待主人定” |
| 管自己的设备、资料 | 能 | 能 | 能 |
| 管别人的设备，邀请、移除家人，改角色 | 能（主人除外） | 不能 | 不能 |
| 建、管共享 Bot | 能 | 不能 | 不能 |
| 加好友、接受好友请求（ADR-0051） | 能 | 能 | 见“待主人定” |
| 把应用分享给好友（ADR-0051） | 能 | 不能：应用全家一份 | 不能 |
| 把自己的 Bot 对群里的人打开（ADR-0083 的房间表） | 能 | 能 | 不能 |
| 开危险模式（第 7 节） | 能 | 不能 | 不能 |

- **管理接口分两层**照 ADR-0045，只是“只给主人”改成“只给管理员”，错误类别 `owner_only` 改名 `admin_only`。
- **请管理员装**：一张确认卡片（ADR-0016），发起者是这个人，接收的是所有管理员，谁先答算谁的，其余的设备撤下这张卡片。
  批了就照管理员自己装一样走权限确认，高风险照样多点一步（ADR-0036）。这和“家人的 Bot 要装、没授权时卡片发给主人”（ADR-0045）是同一条路。
- **插件的开放范围**：ADR-0045 的“家人能用”开关改成三选一：只给管理员（默认）、管理员和家人、全家（含孩子）。
  底栏、插件列表、网页、总线上的工具都按这一项过滤。

### 4. 指挥 AI 动手：按角色设上限

谁让 Bot 做的事，按谁的角色封顶。“谁让的”照 ADR-0083：私人 Bot 是归属人；共享 Bot 和群里，按桥报的进行中轮次里角色最低的人算；
认不清的按这个 Bot 在这个房间听的人里角色最低的算。档位（ADR-0083 第 5 节）再在这个上限之内取。

| 工具 | 管理员 | 家人 | 孩子 |
| --- | --- | --- | --- |
| 只读的（MCP 注解 `readOnlyHint: true`） | 直接用 | 直接用 | 直接用，只限开放给孩子的插件 |
| 会改数据、不删的（`destructiveHint: false`） | 卡片给本人，能放宽（ADR-0024） | 卡片给本人，能放宽自己的私人 Bot | 卡片给本人，不能放宽 |
| 会删、会覆盖的（`destructiveHint` 为 `true` 或没标，MCP 的默认就是 `true`） | 同上 | 同上 | 卡片给管理员，不能放宽 |
| 核心的安装、卸载 | 卡片给本人 | 有“能装应用”时给本人，否则给管理员 | 卡片给管理员 |
| 很高级插件的工具（ADR-0036） | 照 ADR-0024 | 插件开放给家人时才有，卡片给本人 | 工具列表里没有 |
| 最高级插件的工具（ADR-0036，每次都确认） | 卡片给本人 | 工具列表里没有 | 工具列表里没有 |
| 存进共享文件夹（`wonton__save_file`，ADR-0027） | 照 ADR-0027 | 照 ADR-0027 | 卡片给管理员 |
| Agent 自带的工具（shell、读写容器里的文件） | Agent 的模式由本人选（ADR-0035） | 同左 | 锁在最严的模式；碰得到的只有孩子自己的容器和私人空间 |

- **孩子的 AI 删不了别人的东西**，靠三层，不靠 Agent 守规矩：
  1. 碰不到：别人的私人空间不挂给孩子的 Bot（ADR-0045）；共享文件夹挂给孩子的私人 Bot 时一律只读；没开放给孩子的插件，工具不在列表里。
  2. 碰得到的会删、会覆盖的调用，卡片发给管理员，孩子自己点不了“同意”。
  3. 多用户的应用按工具调用里带的人（第 6 节）只给孩子自己的数据。
- 注解是插件声明的（ADR-0016），把删除工具标成只读的插件在审核目录时把关。没标 `destructiveHint` 的按会删算，宁严不松。
- “给管理员的卡片”和第 3 节一样，所有管理员都收得到，谁先答算谁的；卡片上写“替孩子某某”和 ADR-0083 的“哪条消息”。
- 放宽只属于自己的 Bot：家人放宽自己私人 Bot 的，管理员放宽共享 Bot 的和自己的；孩子不能放宽，管理员也不能替孩子的 Bot 放宽会删的那一行。
- 共享 Bot 可以设成“不听孩子”：不然家里有孩子、Agent 又报不了轮次时（ADR-0083“已定”第 11 条），共享 Bot 的每次调用都按孩子封顶。

### 5. 私人 Bot 和共享 Bot

照 ADR-0045，补上角色：

| | 私人 Bot | 共享 Bot |
| --- | --- | --- |
| 归谁 | 一个人，包括孩子 | 全家，管理员管 |
| 谁能用 | 归属人；他按 ADR-0083 在群里给别人开的档位 | 所有家人；管理员可以设“不听孩子” |
| 卡片给谁 | 归属人；孩子的会删类给管理员（第 4 节） | 管理员（ADR-0045 的“给主人”改成给管理员）；会删类按发起人封顶 |
| 会话上下文 | 一个房间一个会话（ADR-0083 第 7 节） | 同左：每个人和它的私聊、家庭群各是一个会话，互不带入 |
| 长期记忆 | 只有这一个人的 | 全 Bot 一份，全家共用 |
| 私人空间 | 挂归属人的 | 没有 |
| 插件里的数据 | 工具调用带归属人 | 认得出这一轮是谁的才带这个人，否则不带 |

- **共享 Bot 的长期记忆全家共用**：Agent 自己落盘的记忆文件、用户画像不按人分，这是 Agent 内部的事，核心管不到。
  家人第一次和共享 Bot 私聊时，App 在顶部提示一次“它记得的事全家都能问出来，私事找你自己的 Bot”。这是隐私提示，不算多余文字。
- **共享 Bot 按人带身份**：ADR-0045 写的是共享 Bot 的工具调用一律不带人。有了 ADR-0083 的轮次报告以后，核心认得出这一轮只有一个人时带上他，
  几个人的轮次同时进行时不带。不带人时，插件不能把它当成管理员，按“家里共用的数据”给或拒绝（插件规范写明）。

### 6. 身份：Matrix 账号、OIDC 和插件

**Matrix**

- 每人一个 Matrix 账号 `@<用户名>:<服务器名>`（ADR-0045），孩子也一样。用户名规则同 ADR-0022。
- **Tuwunel 的服务器管理员只有核心的管理账号**（ADR-0009），人一个都不是，管理员也不是：Tuwunel 的管理房间命令能绕过网关的房间规则。
  管理员的管理操作都经核心的接口。
- **家庭群用房间权限等级**：核心按角色同步，管理员 100，家人和孩子 0。踢人、撤回、改群名就是 Matrix 的原生规则，App 不另判断。
- 孩子能不能和外人聊天由“待主人定”第 1 条决定。要限时用 MSC4155 的邀请过滤（ADR-0051 已用）：核心在孩子账号的账号数据里写规则，
  网关拒绝孩子的设备改这一项。

**OIDC（Hydra）**

- 声明的形态不变（ADR-0009、ADR-0045）：`sub`、`preferred_username` 是这个人的用户名，`groups` 带角色。不加新的自定义声明：
  `groups` 是 Grafana、Nextcloud、Jellyfin 的 SSO 插件等认得的现成写法。早先的草稿用过 `wonton_role`，没有采用。
- `groups` 的取值：

| 角色 | `groups` |
| --- | --- |
| 主人 | `owner`、`admin`、`family`，加清单的 `admin_groups` |
| 管理员 | `admin`、`family`，加清单的 `admin_groups` |
| 家人 | `member`、`family` |
| 孩子 | `child`、`family` |
| 好友 | `friend`（ADR-0051） |

- 清单的 `webui.oidc.owner_groups` 改名 `admin_groups`：应用里的管理员身份给所有管理员，不只主人。`family` 给“家里人都能登录”这类配置用。
- 应用读专门声明的（Immich 的 `immich_role`）：清单里写一个映射 `webui.oidc.role_claim`（声明名，加管理员、家人、孩子各对应的值），
  核心按角色填。不写就没有这个声明。

**插件怎么认出是谁、什么角色**

| 入口 | 怎么带 |
| --- | --- |
| 网页经 OIDC 登录 | 上面的声明 |
| 网页经 `sso: proxy` | `{user}`、`{name}` 照旧，`{role}` 的取值加上 `admin`、`child` |
| 总线的 `tools/call` | `_meta` 的 `app.wonton/user`（ADR-0045）加 `app.wonton/role`；按第 5 节决定带不带 |
| ACP 运行时（ADR-0061） | `X-Wonton-User` 照旧，加 `X-Wonton-Role` |
| Bot 的容器 | 新变量 `WONTON_BOT_KEEPER_ROLE`：归属人的角色，共享 Bot 是 `household`。Agent 插件和桥凭它把孩子的 Bot 锁在最严的模式 |

**插件自己没有多用户时**

- 清单新加 `accounts: per_user`，声明“这个应用按登录的人分开数据”。没声明的按“全家共用一份”处理。
- 共用一份的插件也能开放给家人和孩子，开放时确认页醒目写明：“家里的人会共用这个应用里的数据和登录状态，他们的 AI 能改你在里面的东西”。
  选“全家（含孩子）”时再加一句孩子的。只给管理员的默认不变。
- 不为它按人装多份（ADR-0045 没选的做法照旧），也不替它做账号：要按人分，就换一个多用户的应用。

### 7. 危险模式：预留

主人要一个全自动的“危险模式”：给 Agent 宿主权限和 sudo，由用户自己打开。具体做法由后续 ADR 定，本篇只定边界：

- **只有管理员能开**，开在他自己的私人 Bot 上。家人、孩子的 Bot 和共享 Bot 不能开：它们听的人里有不是管理员的人，开了就等于把宿主交给他们。
- 开着的时候，这个 Bot 不能对任何别人打开（ADR-0083 的档位只能是“只聊天”），也不能做别的 Bot 的联系人：别人的话不能变成宿主上的命令。
- 每次打开都单独确认，写明“这个 Bot 能控制整台主机”，同 ADR-0036 最高级的提示；家里所有管理员的 App 都标出“某某的 Bot 开着危险模式”。
- ADR-0036 的“Agent 不能申请很高和最高级”、ADR-0011 的“Agent 拿不到宿主 shell”由那篇 ADR 修订，本篇不改。

### 8. 接口要什么

只写到字段和类别，具体类型留给接口 PR：

- 角色：`Role` 加 `Admin`、`Child`；邀请和家人设置带角色；`Me` 照旧带角色，壳不自己判断，设置条目由核心给（ADR-0045）。
- 加入请求：码、设备名、邀请时的名字和角色、时间；管理员的同意、拒绝；被邀请人那边的状态“等管理员同意”“被拒绝”“码已用过”。
- 插件的开放范围：三选一，认不出的按“只给管理员”。
- 确认卡片：接收人可以是“所有管理员”；发起者带“替谁”（ADR-0083）。
- 错误类别：`admin_only`（取代 `owner_only`）；孩子的请求被角色挡下时 `role_forbidden`，带被挡的动作。
- 清单：`webui.oidc.admin_groups`（取代 `owner_groups`）、`webui.oidc.role_claim`、`accounts`。
- 总线 `_meta` 的 `app.wonton/role`；运行时的 `X-Wonton-Role`；Bot 容器的 `WONTON_BOT_KEEPER_ROLE`。

实施见 issue。

## 理由

- **角色粗、应用细**：家里人一眼要能看懂“我能做什么”。按实体、按工具的授权表 Home Assistant 多年没做，Nextcloud 的组也只到“哪个应用给哪些组”；
  分级、按人的库这类细节，Jellyfin、Immich 自己就有，平台把角色递过去就够。
- **孩子按“发请求、家长批”**：一律不能，孩子就会去借大人的手机；家人共享的“询问后购买”是大家已经熟悉的做法。
- **删除类单列**：家里最怕的是 AI 替一个人删掉另一个人的东西。MCP 的 `destructiveHint` 是现成的标准注解，默认就当会删，不用核心判断语义。
- **请求和同意复用服务器配对**：同一节“请求”、同一种推送、同一个同意按钮，App 少一套界面，用户少学一样东西。
- **人不当 Tuwunel 管理员**：网关的房间规则（ADR-0045、ADR-0083）是安全边界，管理房间的命令能绕过它。

## 没选的做法

- **先做最小版（只开账号，不分级）**：主人定了直接做完整版。只开账号时孩子照样能装应用、让 AI 删东西。
- **自定义角色、按人按工具的授权表**：家里用不上这么细，界面讲不清楚；要细的应用自己有。
- **孩子的卡片全部给管理员**：孩子加一条笔记也要家长批，用不下去。只读的直接用、改的自己批、删的家长批。
- **管理员看所有人的聊天**：聊天端到端加密，核心看不到；要看只能把管理员的设备拉进每个房间，家人看得到成员列表，等于公开监控，也违背 ADR-0045“已定”第 2 条。
- **在 OIDC 里加一个 `wonton_role` 声明代替 `groups`**：应用得专门适配；`groups` 是现成的，专门读别的声明的应用用 `role_claim` 映射。
- **把家里的人做成 Tuwunel 的服务器管理员**：管理房间命令绕过网关。
- **单用户应用按人装多份**：内存翻倍，数据分散，ADR-0045 已否。

## 代价与风险

- 插件把删除工具标成只读、或者标 `destructiveHint: false`，孩子的 Bot 就能直接删或者自己批。靠目录审核，社区来源照样标“未审核”（ADR-0031）。
- 共享 Bot 的长期记忆全家共用，只能提示，挡不住。
- 共享 Bot 的上限按进行中轮次里角色最低的算：孩子和大人同时找它时，大人那一轮也按孩子封顶，几秒到几分钟。
- 报不了轮次的 Agent（ADR-0083“已定”第 11 条）在有孩子的家里当共享 Bot，每次都按孩子封顶，要管理员设“不听孩子”。
- 共用一份的应用开放给孩子后，孩子在网页里自己点删除，平台挡不住，只能开放时写清楚。
- 加入多一步管理员同意，家人当面扫码时也要管理员点一下。
- 管理员可以有多个：任何一个管理员都能改别人的角色、移除家人（主人除外）；家里谁当管理员要想清楚。

## 待主人定

1. **孩子能不能自己加好友、接受好友请求**
   - 甲：能发、能收，但要管理员批（同“请管理员装”，用 MSC4155 先挡住外面来的邀请，批了放行这一个人）。
   - 乙：不能，好友由管理员替他加。
   - 丙：和家人一样，不限。
   - 建议甲。家里人之间（家人、家庭群）不受限。
2. **管理员能不能看家人、孩子的聊天和 AI 记录**
   - 甲：都看不到（ADR-0045 已定的做法，家人和孩子一样）。
   - 乙：家人看不到；孩子的私人 Bot，管理员看得到它调了哪些工具、每天用了多少（审计记录和用量），看不到聊天内容。

   - 建议乙。

   - 甲：第 4 节的分法：只读直接用，改的自己批，删的管理员批。
   - 乙：只能用只读的，改的、删的都要管理员批。
   - 丙：只聊天，工具一个都不给。
   - 建议甲。

   - 乙：只给主人，别的管理员在应用里是普通用户。
