# ADR-0045 家人和多人：每人一个账号，Bot 有归属人，同机 Bot 经联系人互发消息

- 状态：已接受（2026-11-06），产品取舍由主人定（见“已定”）。修订 [ADR-0007](0007-agents-and-bots.md)（Bot 听谁的、Bot 之间的规则）、
  [ADR-0009](0009-identity-pairing-sso.md)（设备和配对码属于人）、[ADR-0010](0010-storage-and-nas.md)（私人空间）、
  [ADR-0016](0016-mcp-bus-and-confirmations.md)（总线按 Bot 授权、卡片发给谁）、[ADR-0020](0020-file-service.md)（访问范围、设备上传放哪）、
  [ADR-0024](0024-confirmation-scope.md)（谁能放宽）。好友和对整个 Matrix 开放联邦见 [ADR-0051](0051-friends-and-plugin-sharing.md)。
  主人以外的人按可配置的角色分权限，邀请加上管理员同意，“只给主人”的管理和卡片改成给管理员，“家人能用”开关和 OIDC 的 `groups` 由 [ADR-0088](0088-family-accounts.md) 修订

## 背景

GOAL 的 M2 第 4、6 项：主人邀请家人，每人有私人 Bot 和私人空间，主人可以建共享 Bot、拉进家庭群；同机的 Bot 之间能互发消息，
要有联系人审批、频率和转发跳数上限。主人还问过：人和人能不能聊天，能不能接别人家的 Agent、一起拉群。跨机的部分在 M3。

按 `2b84fdc2` 的代码，核心里没有“人”这一层：

- 任何已配对的设备都是主人（`gateway/mod.rs` 的 `device_user()`），登录令牌总是主人的 Matrix 账号，设备登记表没有用户字段。
- 已配对的设备都能进管理接口：装卸插件、改设置、回答确认卡片、改主人的资料，也都能出配对码。
- 一个插件一个 Bot（`plugin/bots.rs`），Bot 的主房间、`WONTON_MATRIX_OWNER`、Wonton 私聊、确认卡片都只对着主人。
- 总线和 Bot 的 Matrix 入口按来源地址认插件，认不出是插件里的哪个 Bot。
- 文件的访问者只有 `owner` 和 `bot:<名字>`，设备上传都进共享文件夹 `transfers`。
- OIDC 的 `groups` 默认只有 `owner`，清单可以给单个客户端加组（见插件规范的“OIDC”），代登录的 `{user}` 总是主人。
- 插件规范里有 `storage.home:*` 和 `bots`，核心没有兑现。

## 决策

### 人和 Bot

- **主人**：一台服务器一个，就是第一台配对设备的人（ADR-0009），管这台服务器。
- **家人**：主人邀请的人。每人有自己的 Matrix 账号 `@<用户名>:<server_name>`、自己的设备、私人空间、和核心的“Wonton”私聊，默认还有一个私人 Bot。
  用户名规则同 ADR-0022：固定、不复用，移除后也不再分配。邀请时主人填显示名，用户名默认由显示名生成（ASCII 的转成小写、
  去掉不合规则的字符；不是 ASCII 的用 `family<n>`），可以改。家人的显示名和邮箱由家人自己在 App 里填（同 ADR-0030）。
- **好友**：不是家人的朋友，就是任何 Matrix 服务器上的人，用他自己的账号；主人能把插件分享给他（ADR-0051）。
- **Bot 都有归属人。** 私人 Bot 归一个人，只听这个人的；共享 Bot 归全家，由主人管，听所有家人的。默认 Agent 的默认 Bot 是主人的私人 Bot。
  “听”的范围另加批准过的 Bot 联系人（见“Bot 之间互发消息”）。
- 核心记录：主人仍在 `core/owner.json`；家人在 `core/members.json`（用户名、显示名、邮箱、状态：已邀请、已加入、已移除，移除的留着防止复用）；
  Bot 记录加上归属人（用户名，或者 `household`）和 Bot 名，一个插件可以有多条。

### 谁能做什么

> 已被 [ADR-0088](0088-family-accounts.md) 第 1 至 5 节修订：主人以外的人能做什么由角色的权限项决定，“家人”是一个模板；AI 动手按角色封顶。

| | 主人 | 家人 | 私人 Bot | 共享 Bot |
| --- | --- | --- | --- | --- |
| 配对、吊销自己的设备 | 能 | 能 | — | — |
| 邀请、移除家人，给家人出配对码，建共享 Bot | 能 | 不能 | — | — |
| 装卸、升级插件 | 能 | 主人授权了才能 | 发卡片给归属人；归属人没授权时发给主人 | 发卡片给主人 |
| 查看、设置插件的 Bot 生效范围（包括商店详情，ADR-0066） | 能 | 不能 | — | — |
| 升级核心，改服务器设置（镜像加速、代理、局域网、第三方入口、模型） | 能 | 不能 | 不能 | 不能 |
| 打开插件网页（含每 Bot 网页） | 全部 | 同一个“家人能用”开关开放的插件 | 不能经网关打开 Bot 网页 | 同左 |
| 调插件的工具 | — | — | 归属人能用的插件 | 开放给家人的插件 |
| 共享文件夹 | 经插件 | 经开放给他的插件 | 经工具 | 经工具 |
| 私人空间 | 自己的 | 自己的 | 归属人的 | 没有 |
| 聊天 | 任何人、共享 Bot、自己的私人 Bot | 同左 | 归属人和联系人 | 家人和联系人 |
| 批准 Bot 联系人 | 自己的 Bot、共享 Bot | 自己的 Bot | 能发请求 | 能发请求 |

- 管理接口分两层：只给主人的（服务器设置、家人、所有设备），和每个人自己的（自己的设备、资料、卡片、引导进度）。装卸插件给主人和授权了的家人。
- **家人装插件要主人授权**：家人的设置里一个开关“能装插件”，默认关，主人随时开关。没授权的家人或他的 Bot 要装插件时，卡片发给主人批。
  授权了的家人装插件和主人一样：逐项确认权限，高风险权限照样醒目、单独确认（ADR-0036）；装好的插件全家一份，“家人能用”的开关仍由主人定。
  主人令牌是主人。网关先由隧道身份认出设备，再由设备认出人；认不出人的请求和现在一样拒绝。
- 审计（`core/audit.jsonl`）的 `acted_by` 加上人：`<用户名>/device:<id>`。

### 邀请和配对

> 第 1、2 步由 [ADR-0088](0088-family-accounts.md) 第 4 节修订：邀请时选角色，扫码后要管理员同意，不再是谁先用谁就是这个家人。

1. 主人在 App 的“设置 → 家人”里点“邀请”，填显示名，选要不要建私人 Bot（默认建；内存不够时如实说，可以只加人）。家人的数量不设上限。核心先查用户名没被占（已有的 Matrix 账号、
   已有的家人记录、核心的管理账号、Bot 用户名），记成“已邀请”。
2. 核心发一个**绑定这个家人的配对码**：格式同 ADR-0009 的 `wonton://pair`，码里不带用户名，归谁记在服务端。一次性，24 小时有效。
   有效期比 10 分钟长，所以服务端存的是密钥的哈希，随 `members.json` 落盘，核心重启后还在。主人可以随时作废、重发。
   App 画二维码让家人当面扫，也能经系统分享把链接发出去（ADR-0041 的链接能打开 App）。分享出去的链接谁先用谁就是这个家人，
   邀请页如实写这句话，家人配上后主人那边显示“已加入”。
3. 家人装 App，扫码或打开链接配对。手机已经连着别的服务器时走“添加服务器”（ADR-0042）。配对、隧道、推送和主人完全一样：
   iroh 经中继在任何网络下都连得上（ADR-0004），推送按设备登记（ADR-0003），推送里的 `server`（ADR-0042）照旧。设备登记在
   这个家人名下，`login-token` 回他的 `user_id`，App 用它登录，首次登录建号。
4. 第一台设备配上后，核心为他：建私人 Bot 并交出私聊（同 ADR-0007 的补充：装好、健康检查过了才交）；建他的 Wonton 私聊；拉他进家庭群；
   把状态改成“已加入”，在主人的 Wonton 私聊里说一声。
5. 引导（ADR-0034）：家人只走资料一步，选 Agent、接模型、选应用是主人的事。引导进度按人存。

- **加设备**：已配对的设备出的码归这台设备的人（`POST /_wonton/api/pairing-codes` 按隧道身份认人）。设备都丢了，主人在家人列表里给他出码；
  主人自己的找回仍是 `sudo wonton pair`。主人令牌、`wonton pair`、局域网状态页的首次配对码都属于主人。
- **移除家人**：主人在家人列表里移除。确认页写明后果：吊销他的所有设备、停用他的 Matrix 账号（退出所有房间，用户名不再分配），
  删掉他的私人 Bot（Bot 的数据可选保留），私人空间默认保留、可选删除（醒目“不可恢复”）。他在插件应用里的账号由应用自己管（ADR-0022）。
- **一台手机多个身份**：同一台手机可以是自己家的主人、爸妈家的家人。每台服务器各有一个槽位（ADR-0042）：用户 ID 照旧存在槽位目录的聊天会话里，角色记进槽位，按 `GET /_wonton/api/me` 更新。

### 私人空间和共享文件夹

- 私人空间在 `<数据目录>/homes/<用户名>/`，主人也有一个，加人时建。
- **设备上传改放上传者的私人空间** `homes/<用户名>/transfers`，共享文件夹 `transfers` 去掉。共享文件夹全家可见：上传留在那里，
  谁传的文件都会被开放给别人的 Samba、文件搜索看到。要让 Samba 这类应用看到上传，用下面的 `storage.homes`。
- **共享文件夹**（照片、音乐、文档等）全家共用，不按人授权：一家人，按人分文件夹的需求由私人空间满足。家人经开放给他的插件用它们。
- **`storage.home:read` / `:write`** 只能用在 `bots.services` 里，挂这个 Bot 归属人的私人空间；共享 Bot 没有私人空间，声明了它的 Bot 不能建成共享 Bot。
- **新权限 `storage.homes:read` / `:write`（高）**：挂所有人私人空间的根 `homes/`，给自己有账号体系的应用（Samba、Syncthing、文件管理器）
  按用户名分开。安装确认写明“能看到所有人的私人空间，靠应用自己的账号分开”。核心注入用户名单 `WONTON_USERS`（逗号分隔），名单变了重建插件。
- **文件服务的访问范围**（ADR-0020）：`owner` 换成用户名（`user:<用户名>`），设备只能取范围里有自己这个人的文件。设备上传的起始范围是上传者。
  私人 Bot 分享给归属人不用确认；分享给别人（`to`）算对外发送，归属人确认。共享 Bot 只碰得到共享文件夹和插件里的文件，分享给房间里的人不用确认。
  “发到另一台设备”发进这个人自己的 Wonton 私聊。
- **`wonton__save_file`**（ADR-0027）：私人 Bot 能存进归属人的私人空间和授权的共享文件夹；共享 Bot 只能存共享文件夹。Bot 的 outbox
  改到每个 Bot 自己的 `${WONTON_BOT_DATA}/outbox`：现在整个插件一份，同一个插件里不同人的 Bot 能读到彼此要存的文件。
- **主人看不到家人的私人空间和 Bot 记忆**：App 里不提供。如实写在邀请页：能登录服务器的人能直接读磁盘；聊天端到端加密，服务器上读不到。

### 插件、网页和工具

- 插件全家一份，由主人（和授权了的家人）装。每个插件有一个开关“家人能用”，默认关，安装页和插件设置里都能开；应用是否按人隔离由上游自己的账号模型决定。只有一个管理员账号或共用会话凭据时，开关旁明确提醒主人家人会共用该登录状态。家人的插件列表和底栏只有开放给他的插件，看不到商店。
- **网页**：每 Bot 网页复用插件现有的同一个“家人能用”开关（记录字段 `family`，`family_enabled` 读取），默认关，
  即默认只给主人；打开后家人能访问这个插件各 Bot 的网页。私人 Bot 的归属人、共享 Bot 的聊天参与者不另获权限，
  不增加 Bot 专用开关。好友只在核心支持既有插件分享时按同一授权开放，不在 Bot 网页里另建分享规则。
  家人未获准沿用 403 `not_shared`，不是另一套 Bot 权限错误。
  开关开放的是同一个 Bot 的应用及登录入口，家人可能看到或修改同一份应用状态，不承诺按人隔离；也不把支持
  多用户的应用一概描述为共用一个登录。
- **每 Bot 一页**：清单不变，`webui.service` 在 `bots.services` 时每个 Bot 一份 UI，路由到自己的容器。
  默认 Bot 沿用插件 slug 的 origin；非默认 Bot 用 `bot--<Bot 名>-<截短的插件 slug>-<8 位摘要>` 标签。
  标签最多 63 字节，只截插件 slug，保留完整 Bot 名；摘要是 `SHA256(plugin_id UTF-8 + 一个 NUL 字节 + Bot 名 UTF-8)`
  的小写十六进制前 8 位。登记撞名回 409 `conflict`，不改名、不回退默认 Bot，不能拆 URL 推算身份。
  查同标签占用者和预留须在现有分配锁下原子完成，并先于创建 Matrix 身份、凭据、数据目录或容器；
  409 冲突不得留下这些部分副作用。相同 Bot 重复登记不算冲突；崩溃恢复和重试留给运行时实现，不承诺跨系统回滚。
  精确截断算法见[插件规范的每 Bot 网页约定](https://github.com/wontonapp/wonton-docs/blob/main/plugin-spec.md#每个-bot-的网页)。
  仅 origin 分开，入口仍原样追加 `webui.path`；插件级入口使用默认 Bot，也经过同一权限检查。
- **登录边界**：Bot 名由已有 `WONTON_BOT_NAME` 传入容器；Bot 服务的 `WONTON_APP_URL` 指向自己的 origin，
  全插件一份的服务沿用插件／默认 Bot origin。OIDC 回调和登出回跳按对应 origin 登记，会话 Cookie 精确绑定主机，
  不设父域 `Domain`。家人登录前须看到“服务器主人可以查看、管理这里的登录状态”，不得承诺对主人保密；
  提示须由 iOS、Android 壳的简体中文、繁體中文、English、日本語四种资源提供（ADR-0043）。
- **网关边界**：Agent、Bot 和其他插件的插件网络来源打开 Bot 网页时先回 403 `permission_denied`，
  再考虑普通插件网页的 `self_request` 例外，带人的凭据也不能绕过。同插件网络容器仍能直连彼此端口，
  网关不能阻止，不把独立 origin 称为容器间沙箱。不新增局域网端口、宿主权限，既有 Agent／Bot 禁令不变。
  默认和非默认 Bot 的 origin 主机名都须在自己的插件网络作为核心网关的 DNS 别名；取消的只是自请求豁免。
  Bot 容器内 `curl "$WONTON_APP_URL"` 的目标行为因此改为网关的 403 `permission_denied`，不是 DNS 失败。
- **网页接口**：网页类型由 [`bot_web`](../../crates/wonton-protocol/src/bot_web.rs) 定义，
  撞名契约见 [`bot_web_registration`](../../crates/wonton-protocol/src/bot_web_registration.rs)；
  `GET /_wonton/api/bots/{plugin_id}/{bot}/webui` 的元数据按请求者权限给出 `BotWebView`。
  就绪时 `BotWebPage` 带完整 `BotRef`、URL、显示方式和跨源隔离要求；页面身份专用
  `TabRef::Bot { bot: BotRef, path: Option<String> }`，不存 URL，不借 `TabRef::Plugin` 或 `TabRef::Url`。
  `path: None` 打开同一个 `BotRef` 的 `BotView.web` 在 `Ready` 时给出的 `page.url`；`Some(path)` 只允许该
  origin 内的路径，可含查询和片段。选择／打开沿用 `Action::SelectTab`，固定沿用 `PinTab`、`PinCurrentPage`
  和 `Panel`；`PlacedTab` 保留相同的 Bot 身份和路径。桥、媒体、`--wonton-*` 走既有 `TabRef`／`PlacedTab`
  和页面容器，不另建壳层 WebView，也不省略桥。
  实现时把聊天已有的 `BotView` watch 通道传给 `TabsLink`，Bot 网页状态变化时重算 `TabsViewModel` 的
  `TabPage`，桥和媒体使用它的精确页面 URL／origin。URL 只来自该 `BotRef` 的 `BotView.web.Ready.page.url`，
  不读 `plugin.web_url`。`BotView.web: None` 表示没有验证可用的 URL，包括断连或身份变化；未知、缺失或错误时
  不给页面 URL，断连或身份变化时清空，不猜 URL、不回退默认 Bot。运行事实只带 Bot 身份和运行计数，不混入访问授权。
  Bot 不存在为 404 `not_found`，未认证为 401 `unauthenticated`，服务未就绪为 503 `not_ready`，
  无网页为 404 `no_webui`。这些是接口和目标行为约定，不是网关路由、App 打开行为或端到端验证结论；
  接口阶段不暴露运行时入口，客户端对不支持的 Bot 页面明确拒绝，不能转开其他页面。
- **身份**（`groups` 改成按能力给、`owner_groups` 改名 `admin_groups`、`{role}` 的取值，由 [ADR-0088](0088-family-accounts.md) 第 8 节修订）：OIDC 的 `sub`、`preferred_username` 是当前这个人的用户名，`groups` 主人默认是 `["owner"]`、家人是 `["member"]`；代登录的
  `{user}`、`{name}`、`{email}` 也是当前这个人。`owner.identity` 不变，注入的是主人（服务器管理员）；在 `bots.services` 里注入的是这个 Bot 的归属人，
  共享 Bot 是主人。
- **工具带上替谁办事**：总线给插件的 `tools/call` 在 `_meta` 里带 `app.wonton/user`：私人 Bot 是归属人的用户名，共享 Bot 不带。
  多用户的应用（比如 Immich 的 MCP 适配器）按它切到这个人的数据；不认它的插件对所有人给同样的数据，主人把它开放给家人，就等于家人的 Bot 能看到它的工具看得到的东西，
  开关旁边写明。

### 总线按 Bot 认调用方

- 每个 Bot 一个总线令牌，放在 `WONTON_MCP_URL` 的路径里（`/mcp/<令牌>`），Agent 的配置不用改：每个 MCP 客户端都支持 URL，请求头不一定。
  来源地址的检查照旧，令牌和来源插件对不上就拒绝。核心记日志时去掉令牌。
- Bot 的 Matrix 入口（`matrix.wonton.internal`）按访问令牌认 Bot（`whoami`，按令牌的哈希缓存），只放行这个插件自己的 Bot：现在插件拿任何令牌都能转发。
- 工具列表按 Bot：核心工具，加归属人能用（共享 Bot：开放给家人）的插件的工具。
- 核心工具里按“调用方”找 Bot 记录的（如 ADR-0044 的 `wonton__set_profile`），改成按令牌认出的这个 Bot。
- **Bot 的资料**（ADR-0044）：私人 Bot 由归属人改，共享 Bot 由主人改；`PUT /_wonton/api/bots/{插件}/profile` 按设备的人核对，
  名字不能和归属人的名字重名。
- **卡片发给归属人**：敏感调用的卡片给归属人（推送、列表、会话里显示都只对他，ADR-0016），共享 Bot 的给主人。核心不知道是谁让共享 Bot 办的事：消息是加密的。
  只有这个人的设备能回答（`POST /_wonton/confirmations/{id}` 核对设备的人），主人令牌只答主人的卡片。待回答的列表只列自己的。
  发给家人的卡片没有“N 分钟内都允许”（ADR-0024 的放行时段）：时段按插件记、不分 Bot，家人打开的时段会连同一插件里主人的 Bot 一起放行。
- **放宽**（ADR-0024）：家人能放宽自己的私人 Bot 调开放给他的插件；共享 Bot 的放宽由主人定。“我来操作”按人：主人在插件网页里操作时停住的是所有 Bot，
  家人操作时只停住他自己的私人 Bot。有 Bot 联系人的 Bot 不适用放宽，见“不可信输入”。
- **模型**：所有 Bot 用主人在模型设置里配的 provider，每个 Bot 一个网关凭据（插件规范已有 `<插件 id>/<Bot 名>`），用量按 Bot 记，默认不限额。
  留好限额的接口：主人以后在家人的设置里给他的 Bot 设额度，核心经模型网关按凭据的额度设（magpie 已支持），换模型网关时由它声明的命令实现，同 ADR-0034 的 key 测试。

### Matrix 怎么落地

- **账号**：家人第一次登录时由 JWT 建号，同主人。Bot 分配用户名时也跳过已邀请还没登录的家人（现在只跳过已有的账号）。
- **私人 Bot**：在默认 Agent 插件里按 `bots` 新建一个 Bot（插件规范“一个插件多个 Bot”，每个 Bot 一组容器），Bot 名是归属人的用户名，
  Matrix 用户名 `<插件 id 最后一段>-<Bot 名>`（如 `hermes-alice`）。主房间建法、交接同现在，交给归属人：核心临时代他登录一台设备加入，再退出。
  Agent 插件没有声明 `bots` 时建不了，邀请页如实写，可以只加人。
- **Wonton 私聊**：每个人一个（ADR-0016 的房间），核心发给这个人的通知、文件链接都在这里；确认卡片不在这里（ADR-0016 第 6 条）。
- **家庭群**：第一个家人加入时，核心用自己的账号建一个加密房间，带状态事件 `app.wonton.family`，主人和核心都是管理员。家人加入、移除时核心邀请、
  代他加入（同主房间的交接），或者随账号停用退出。主人建的共享 Bot 默认拉进来，它的主房间就是家庭群。核心没有加密设备，在群里不说话，
  不影响家人之间的加密：房间密钥只发给有设备的成员。其他群聊家人在 App 里自己建，是普通 Matrix 房间。
- **共享 Bot**：主人在 App 里“新建共享 Bot”，选 Agent 插件和名字，同样按 `bots` 新建，归属 `household`。
- **加密**：私聊、家庭群都端到端加密；Wonton 私聊照旧不加密（ADR-0016）。
- **Bot 听谁的**：`WONTON_MATRIX_OWNER` 改成 `WONTON_MATRIX_ALLOWED_USERS`，逗号分隔：私人 Bot 是归属人加联系人，共享 Bot 是所有家人加联系人。
  名单变了，核心重建这个 Bot 的服务，沿用设备和令牌（插件规范的“重建容器时沿用设备和令牌”）。Hermes 的 `MATRIX_ALLOWED_USERS` 同时管邀请和消息，直接接上。
- **用户目录**：Tuwunel 默认只搜得到有共同房间的人（`show_all_local_users_in_user_directory = false`）。家庭群让家人彼此看得到，Bot 不在共同房间里就搜不到。
- **网关管房间规则。** 所有客户端接口都经核心网关（设备经 `matrix.<基础域名>`，Bot 经 `matrix.wonton.internal`），Tuwunel 没有邀请策略的扩展点
  （`block_non_admin_invites` 是一刀切）。网关只看请求路径和请求体里的用户 ID，不看消息内容：
  - 邀请 Bot（`POST /rooms/{房间}/invite`、`createRoom` 的 `invite`）：私人 Bot 只能由归属人和它的联系人邀请，共享 Bot 由家人和联系人邀请。
  - Bot 邀请别人：只能邀请它听的人（归属人或家人）和联系人。
  - 人邀请人不限，只限频（ADR-0051 的“挡垃圾”）。
  - 不放行公开房间：`createRoom` 的 `public_chat`、`visibility: public`，把 `join_rules` 改成 `public`。公开房间会被搜到、被刷，第一版不开（ADR-0051）。
  - 不合规则回 403 `M_FORBIDDEN`，`X-Wonton-Error` 是 `contact_required` 或 `public_room`。
  - 设备用的访问令牌必须是这台设备的人的（`whoami` 对得上），Bot 同理。

### Bot 之间互发消息（同机）

**联系人**

- 两个 Bot 结成一对，双向。归属人在 App 的 Bot 资料页“加联系人”，或者 Bot 调核心工具 `wonton__request_contact`（不敏感，只是发请求）。
- 两个 Bot 的归属人都同意才成立：发起的人算同意了自己那一方，另一方收到一条请求；两个 Bot 归同一个人时只有一条；共享 Bot 一方由主人批。
  请求上写明：“对方 Bot 的话，你的 Bot 会当作给它的话处理”。
- 请求存在核心里、不过期，不用确认卡片（卡片背后是一次等着的调用，会过期，核心重启就没了；请求可能隔几天才处理）。
  归属人在 Bot 的“联系人”页或“等你确认”列表（ADR-0016）里同意或拒绝；新请求推送到归属人的设备，通知类别同确认卡片，
  不往“Wonton”私聊发提醒（主人 2026-11-11 定）。跨机的请求也一样（ADR-0050）。
- 成立后：网关放行两者互相邀请、建私聊；双方的 `WONTON_MATRIX_ALLOWED_USERS` 加上对方（重建）。记在 `core/contacts.json`。
- 任何一方的归属人随时能删：名单里去掉、网关不再放行邀请；已有的房间留着，对方的消息 Bot 不再处理。
- Bot 用 `wonton__list_contacts` 看自己的联系人：用户 ID、显示名、归属人的显示名。

**不可信输入**

来自 Bot 的消息是不可信输入（ADR-0007、ADR-0011）。Agent 分不清名单里谁是人、谁是 Bot：Hermes 只有一张白名单。所以靠总线兜底：
有 Bot 联系人的 Bot，ADR-0024 的放宽对它不生效，敏感工具每次都要归属人确认：核心分不出一次调用是不是 Bot 的话引起的。
代价是以前放宽过的插件，加了 Bot 联系人以后又要逐次确认，联系人请求上写明这一点。

**频率和跳数**

网关按 Matrix 的发送接口数，不看内容（房间是加密的，核心本来就看不到），只读明文的 `m.relates_to` 认编辑。只数 Bot 的 `PUT /rooms/{房间}/send/{类型}/{txn}`，类型是
`m.room.message`、`m.room.encrypted`、`m.sticker`；状态事件、回执、输入状态、to-device 消息不算。

- **频率**：每个 Bot 在每个房间每分钟最多 20 条，可以突发 10 条。超了回 429 `M_LIMIT_EXCEEDED` 带 `retry_after_ms`，SDK 自己会等。
  所有 Bot 都适用：人和 Bot 聊天到不了这个量。
- **跳数**：每个房间数“人上一次在这里说话之后，不同 Bot 之间来回了几跳”。一条 Bot 消息的发送者和这个房间上一条 Bot 消息的发送者不同，
  才算一跳；同一个 Bot 连着发（Agent 的进度、分段回复）不算。编辑（`m.relates_to.rel_type` 是 `m.replace`，加密消息里这一项也是明文）
  既不算一跳，也不改“上一条是谁发的”。人（经隧道的设备）在这个房间发一条就清零，房间里 1 小时没有消息也清零。
  到了 20 跳，再换一个 Bot 说话回 403，`errcode` 是 `APP.WONTON.HOP_LIMIT`（Bot 的 Matrix SDK 读不到响应头，`M_FORBIDDEN` 的其余字段也会丢，
  只有自定义的 `errcode` 能让 Bot 认出类别），`X-Wonton-Error: hop_limit`，SDK 不重试；上一条那个 Bot 接着说照样放行。
  核心给双方归属人各发一张卡片（ADR-0016，显示在这个房间）“A、B 来回说了 20 次，已停下”：两个 Bot 归同一个人时一张，共享 Bot 一方由主人批；
  一个回合只发一轮。按钮“继续”和“先停着”，所有卡片都选“继续”才清零，任何一方选“先停着”或没回答，房间就停着（一方同意就放行，等于替另一方的
  Bot 决定接着说）。“删除联系人”按钮等 Bot 联系人上线再加。人说话清零后卡片照样留着，再选“继续”无害。
  被拒收的消息停在 Bot 的发送队列里，桥在清零之后重发（有人说话，或者 Bot 又有新消息要发时试一次，不定时重试），补发完在房间里说明有几条被停下过。
- 为什么这样就够：没有人参与、停不下来的 Bot 对话，要在有限个房间里轮流发无限条消息，总有一个房间的来回超过上限；跨房间转发（A→B→C）每个房间各算，
  绕回同一个房间就累计。有人说话就清零，所以人和 Bot 一起的群聊不受影响。
- 几个数字（20 跳、1 小时、每分钟 20 条）由核心的环境变量改。

### 跨机（M3）留的位置

这次不做，只保证以后接得上：

- **核心按 Matrix 用户 ID 认人和 Bot**，联系人、邀请规则、频率和跳数都不关心对方在哪台机器上。跨机的对象接进来以后也是一个 Matrix 用户 ID。
- **两种接法**：
  1. Matrix 联邦走 iroh：Tuwunel 打开联邦，只对配对过的服务器（`allowed_remote_server_names_experimental`），联邦流量经一个说 iroh 的转发组件。
     人和人、人和 Bot、跨机拉群都能做。前提是每台的 `server_name` 唯一、永远不变，已经改成第一次安装时随机生成（ADR-0009 的“补充：Matrix 的服务器名”）。
     两台配对时交换服务器名和 endpoint ID，转发组件按它连，不查 DNS。
  2. A2A 桥插件：远端的 Agent 在本机表现成桥插件的 Bot 账号（`bots`），只能 Bot 对 Bot，拉不了远端的人进群。
- **服务器配对**：两台的主人互相扫码，用另一个 ALPN（`wonton/peer/0`），记在 `core/peers.json`。跨机的联系人两边的归属人都批。
- **跳数**：经联邦来的消息不经网关，频率和跳数只在本机 Bot 发送时数；远端的人说话不清零。双方各自限住自己的 Bot，环路照样停得下来。

### 客户端

- `GET /_wonton/api/me` 返回自己的用户 ID、角色（`owner`、`member`，认不出的落到 `Other`）、显示名和邮箱，取代 `owner-profile` 的读；写资料的接口按人。
  `login-token` 的 `user_id` 是这台设备的人。
- 设置首页（`SettingsViewModel`）按角色出条目：家人看不到服务器管理的几项；主人多一项“家人”（列表、邀请、出码、移除、建共享 Bot）。
  条目由核心给，壳不判断角色。
- Bot 资料页加联系人（和 ADR-0044 的改名、头像放在一页）。家庭群在聊天列表里是一个普通房间，带家庭的标记。
- 界面文字按 ADR-0043 放进本地化资源。

## 已定（主人 2026-11-06）

1. 家人默认不能装插件，主人可以给某个家人授权，随时能关；没授权时，家人或他的 Bot 要装，卡片发给主人批。授权了的家人装高风险插件照样走确认。
2. 主人在 App 里看不到家人的数据，邀请页如实写磁盘层面的事实。
3. 插件默认对家人关，每个插件一个开关。
4. 家人数量不设上限，邀请时默认建私人 Bot，内存不够如实说。
5. 有 Bot 联系人的 Bot，放宽确认不生效，敏感工具每次都确认。
6. Matrix 服务器名现在就改成每台唯一，单独先做（ADR-0009 的补充）。已装的服务器重装 Matrix 的数据，主人重新配对，不写迁移。
7. 邀请码 24 小时、一次性、能分享。
8. 家人的 Bot 用主人的模型额度，默认不限额，限额的接口留好。

## 理由

- **一人一个 Matrix 账号**：私聊、群聊、多端同步、推送、加密都是 Matrix 现成的，人和人聊天不用另做。
- **插件全家一份**：相册、音乐、文档这些应用本来就是多用户的，按人各装一份内存翻倍，数据还分散。
- **规则放在网关**：网关已经是 Tuwunel 客户端接口的唯一入口，按用户 ID 和接口判断，不依赖某个 Agent 照规矩办事（ADR-0015），也不改 Tuwunel。
- **跳数按房间数、只数换人**：看不到内容也能执行，有上限的证明简单。环路至少要两个 Bot 轮流说，一个 Bot 自己连着说不会因为别的 Bot 的话停不下来；
  只数总条数会把忙着干活的单个 Agent 也停下（进度、编辑都是消息）。

## 没选的做法

- **家人共用主人的账号**：没有隐私，Bot 分不出谁在说话。
- **每个家人一套核心或插件**：重，插件不共用；一台手机多台服务器（ADR-0042）已经能接“各自一台”的情况。
- **让 Agent 自己在消息里带跳数**：靠每个 Agent 都照做；核心看不到加密的内容，核对不了。
- **按严格的转发链数跳数**：核心看不到内容，不知道哪条消息是因为哪条发的。
- **按每个 Bot 各自连着发的条数数**：一个 Bot 自己连着说本来停得下来，只会误伤长活。
- **在 Tuwunel 里管邀请和频率**：没有扩展点，改上游源码违背“不改源码”。
- **家庭群由主人的 App 建**：成员跟着家人名单走，放在客户端就要主人的每台设备来对账。
- **共享 Bot 的卡片发给提问的人**：核心不知道是谁让它办的事。
- **总线令牌放请求头**：不是每个 MCP 客户端都能配请求头，放 URL 里 Agent 配置不用改。

## 代价与风险

- 每个家人的私人 Bot 一组容器，资源少的主机（4 GB 的 Pi）带不了几个人。
- 网关要解析 `createRoom`、`invite`、`state` 的请求体，Matrix 接口变了要跟着改，契约测试兜住。
- 名单变了要重建 Bot 的容器，Bot 会断开十几秒。
- 跳数是近似：间隔超过 1 小时的慢环路拦不住，靠频率和用量额度兜底。两个各忙各的 Agent 在同一个房间里交替发进度，也会被算成来回，
  到顶时主人在卡片上选“继续”。
- 不认 `app.wonton/user` 的插件对所有人给同样的数据，靠主人开放时看清提示。
- 停用 Matrix 账号不可恢复，误删家人只能重新邀请，用户名不能再用。
