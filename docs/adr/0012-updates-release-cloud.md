# ADR-0012 更新、发布与云服务

- 状态：已接受（2026-10-28）

## 背景

旧链路用约 4.6 万行 shell/mjs 自建签名 OTA、installer 快照和多 mirror 事务提交，manifest 过期、
bot 读不到包等发布事故反复出现；发布要走 test、canary、prod 多个分支。

## 决策

- **核心升级**：核心镜像分 stable、beta 两个渠道。App 里一键升级：核心拉起一次性的升级器容器，
  拉新镜像、重建核心容器、做健康检查，失败就回滚到旧镜像。
- **插件升级**：按商店目录里的版本升级，可以设为自动。
- **镜像分发**：同时发布到 GHCR 和国内镜像仓库，安装脚本按网络自动选择；以镜像 digest 作为版本身份。
- **我们运营的云服务**只有四类：iroh 中继与发现、推送中继、插件目录与节点列表（签名静态文件）、
  国内镜像。没有用户账号，也不存业务数据。
- **节点**：MVP 部署香港和海外各一个节点；主体和备案办好后增加内地节点。
- **App 分发**：MVP 走 TestFlight 和直装 APK；应用商店上架在 M3。
- **CI**：GitHub Actions；发布由 tag 触发。

## 理由

容器镜像和 digest 已经提供了不可变制品和回滚，不需要自建 OTA 体系。

## 代价与风险

- 需要选择并维护国内镜像仓库和两地节点。
- 推送中继需要防滥用：家里服务器注册身份、请求签名、限速。
