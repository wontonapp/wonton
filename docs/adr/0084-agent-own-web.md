# ADR-0084 Agent 自带网页做插件：网页就是插件的 webui，访问控制用核心现有的那套

- 状态：已接受（2026-11-12）；应用访问授权由 [ADR-0088](0088-family-accounts.md) 修订
- 修订 [ADR-0061](0061-agent-runtime-and-frontends.md)：Agent 自带的网页是运行时本身，不是前端

## 背景

主人（2026-11-12）：dsh 这类自带官方网页的 Agent 做成插件，用户在它的网页里用，体验像自带的 Agent，也能用我们的其他插件。
又说：不是所有插件的网页都需要 SSO，dsh 用官方登录或 API key 都行，不要过度设计。

## 决策

- **Agent 自带网页 = 插件的 `webui`，`sso: none`，访问控制用核心现有的那套，不另设机制。** 谁能打开照核心网关的规矩：
  主人不受限制，其余人按角色的 `open_apps`（ADR-0088）。Agent 自己的登录（官方账号或 API key）照原样用。
- 网页自带的启动令牌（如 dsh 每次启动随机生成的）由插件自己处理：Agent 允许就关掉（核心网关已经管住谁能进），
  不允许就在插件的数据卷或配置里固定下来，由 `webui` 地址或同容器里的一层小包装带上；核心不为它加机制，也不做核对请求头的入口。
- 这个网页是**运行时本身**，不是 `agent_acp` 的前端，不经 ACP 网关，ADR-0061 第 2、3、10 节不管它。Agent 自己的审批留在它的网页里；
  经 Wonton MCP 调别的插件仍走确认卡片（ADR-0016）。打开网页的人拿到这个 Bot 的全部能力，私人 Bot 也一样。
- 同一个插件照常带桥（ADR-0035），这个 Bot 也在聊天里；手机以聊天为主，网页是从插件页打开的入口。
- **唯一的硬要求**：dsh 网页用的配置里关掉 `session-log-deepseek`（它会把会话日志随官方 API 请求上传）。
- 顺手能做就做、不挡上线：我们的设置放单独的 `--patch` 层，不改用户的 profile；启动时确认 `session-log-deepseek` 已关、
  Wonton MCP 能连上，否则如实报错；启动令牌不进日志。

## 已知限制

dsh 0.2.2-rc.1、测试替身模型、开发主机上的真实栈（2026-11-12）实测：

- 网页和聊天共用同一个会话库，互相看得见；网页不按人或浏览器分会话。
- Agent 自己的审批在浏览器关掉后一直挂着，不超时、不推送；长任务从聊天发起。
- 运行中总线令牌失效，Wonton 的工具悄悄消失，网页和日志都没有提示。

## 考虑过的做法

- **`sso: proxy` 加同网络命名空间的入口，核对核心注入的密钥头再换 Agent 的启动令牌**：能挡同插件容器直连网页，主人定不做，过度设计。
- **按 Bot 另设网页权限**：复用插件级的访问授权，不另加 Bot 专用开关。
