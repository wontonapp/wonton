# ADR-0084 Agent 自带网页做插件：网页就是 Agent 自己的界面，入口核对核心注入的密钥头才换登录令牌

- 状态：已接受（2026-11-12，谁能打开由主人定，见第 3 节）
- 修订 [ADR-0045](0045-family-members.md)（Agent 自带网页随“家人能用”开关的后果）、
  [ADR-0061](0061-agent-runtime-and-frontends.md)（Agent 自带网页不是前端），改动见“对其他 ADR 的修改”。
  [ADR-0081](0081-local-agent-host.md) 里 dsh 沙箱的说法一并更正

## 背景

主人（2026-11-12）：dsh 这类自带官方网页的 Agent 做成插件，用户在它的网页里用，体验像自带的 Agent，也能用我们的其他插件。

先例是 Hermes：官方 dashboard 只听回环，插件里一个 nginx 和它共用网络命名空间，插件网页指向这个 nginx
（[wonton-plugin-hermes `docker-compose.yml`](https://github.com/geraldpeng6/wonton-plugin-hermes/blob/e98910f/docker-compose.yml#L184-L190)）。

dsh（[deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)，MIT）有 `dsh web`，只有一个主人。
它的登录和 Hermes 不同，照搬接不上：

- 启动令牌每个进程随机生成，不能配置，只打印在输出里（带 `?token=` 的地址）；
- 浏览器拿令牌换一个 dsh 签名的 cookie，cookie 绑定请求的 `Host`；dsh 不认任何请求头，也不支持 OIDC。

核心的 `sso: proxy` 只能注入固定值，替代不了这个 cookie；`sso: none` 的入口在插件网络里谁都连得到，同一插件里能跑 shell 的
别的 Bot 容器 curl 一下就能拿到令牌（插件网络按插件分，ADR-0011）。

## 决策

### 1. Agent 自带的网页就是插件的网页，它是运行时本身

- 自带网页的 Agent 打包成插件，插件网页（`webui`）指向这个 Agent 自己的界面。我们不改它的界面，不在里面加我们的东西。
- 这个网页是**运行时本身**，不是 `agent_acp` 的前端（ADR-0061）：它不经 ACP 网关，ADR-0061 第 2 节的规矩（丢掉前端的 `mcpServers`、
  权限请求由网关回答、只许一个工作模式、会话按前端归属）不管它。和 Hermes 一样，Agent 自己的审批留在它的网页里；
  经 Wonton MCP 调别的插件仍走确认卡片（ADR-0016），卡片在 App 里，网页里只显示“调用中”。
- 同一个插件照常带桥（ADR-0035），这个 Bot 也在聊天里。**手机以聊天为主**：推送、端到端加密、确认卡片和离线显示都在聊天里；
  网页是从插件页打开的高级入口。
- dsh 网页只跑 dsh 自己的 agent loop，不是各家 Agent 的通用网页。

### 2. 登录：Agent 只听回环，入口核对密钥头后才换令牌

拿 dsh 实测走通（见“验证结果”）。插件里两个服务，都写进 `bots.services`（这样才拿得到 `WONTON_MCP_URL`，每个 Bot 一份，ADR-0045“每 Bot 一页”）：

- **Agent 的网页服务**：`dsh web` 只听 `127.0.0.1`（默认就是，不传 `--host`）。输出整体重定向进一个 0600 的文件，入口从中取出令牌。
- **入口**：nginx，`network_mode: service:<网页服务>`，和它共用网络命名空间。
  - 清单：`webui: {service: <入口>, port: 8080, sso: proxy, proxy: {headers: {X-Wonton-Web-Entry: "{secret:web_entry}"}}}`，
    `secrets.web_entry` 由核心生成（32 字节，十六进制）。核心网关只给已认证的人的请求注入这个头。
  - 入口用等长比较（逐字节异或，不提前返回）核对这个头，对不上一律 403。对上了才在不带 dsh cookie 的 `GET /` 上内部改写成
    `/?token=<令牌>`，由 dsh 写下 cookie。
  - 转发时 `Host`、`Origin` 改成回环地址，dsh 的 cookie 因此和浏览器用的域名无关。
- **谁进不来**：同插件的其他服务直连入口没有头；伪造的头对不上；别的插件经核心网关没有会话，核心先挡（401）；
  同插件的容器经核心网关，核心剥掉代登录头（ADR-0063），入口再挡；回环上的 Agent 端口在插件网络里连不上。

这个入口是只给“自带网页、令牌只打印出来”的 Agent 用的胶水。上游支持把令牌写进文件或认请求头时，入口跟着变薄。

### 3. 谁能打开：照“家人能用”开关，开关处醒目提示

- 照 ADR-0045 的“家人能用”开关：开关关着只有主人能打开；开着，家人能打开这个插件每个 Bot 的网页。**不另做按 Bot 的网页权限**（主人定）。
- **后果**：打开网页的人拿到这个 Bot 的全部能力，等于容器的操作者——批准它的命令、看它所有的会话（包括别人和它在聊天里的会话，见第 5 节）、
  从网页的插件页装任意 npm 或 Git 代码、加 stdio MCP 跑命令、读到它的总线令牌和模型凭据。私人 Bot 的工具按归属人开放的插件执行，
  所以开关一开，家人在网页里用的是主人私人 Bot 的权限；ADR-0061 第 3、10 节“家人不能借主人的私人 Bot”管不到这条路。
- 开关处醒目提示上面这段，文字按 ADR-0043 放进各平台的本地化资源。

### 4. 配置守则

- **我们管的设置单独一层**：模型网关、Wonton MCP（`streamable-http`，指向 `WONTON_MCP_URL`）、关掉 `session-log-deepseek`，
  由入口在启动时写进一个单独的文件，`dsh --profile web --patch <文件>` 叠加。**不改用户的 profile**（dsh“设置”页写的
  `profiles/<profile>/cordis.patch.yml`），不然要么我们冲掉用户的设置，要么用户删掉我们的。
- **没生效就不启动**：启动前跑 `dsh --profile web --dump-config --patch <文件>`，三项都确认生效才启动，否则如实报出是哪一项。
  `session-log-deepseek` 默认会把会话日志随官方 API 请求上传，关不掉就拒绝启动。dsh 各预发布版之间配置条目的写法会变
  （0.2.2-rc.1 的 web profile 没有 `mcp-manager`，要插 `dsh-mcp-client`），这道检查也挡住这种变化。
- **启动令牌不进任何日志**：Agent 的输出只进 0600 文件；放令牌的卷只挂给网页服务（读写）和入口（只读），桥和 Agent 服务不挂；
  入口关掉访问日志。共享卷的两个服务要用同一个 `user`，核心才让挂。入口的健康检查是“令牌文件非空”。
- **总线令牌先探活**：入口启动时对 `WONTON_MCP_URL` 发一次 MCP `initialize`，不是 2xx 就拒绝启动，报“总线令牌无效”。
  运行中失效见第 5 节。

### 5. 已知限制和我们的做法

| 限制（实测） | 我们的做法 |
| --- | --- |
| 网页和聊天共用 Agent 的同一个会话库，互相看得见；网页没有按人或按浏览器分的会话 | 写进插件说明和第 3 节的开关提示 |
| Agent 自己的审批在浏览器关掉后一直挂着，不超时、不推送；重新打开网页还能接着批 | 写进插件说明：长任务从聊天发起（有推送和卡片），网页当高级入口。把它的审批也报给核心（`POST /agent/permissions`）是以后可能的一步，没定 |
| 运行中总线令牌失效，Wonton 的工具悄悄消失，网页和日志都没有提示 | 启动时探活（第 4 节）；运行中发现不了，写进插件说明 |
| 网页插件页装的 npm、Git 代码留在数据目录，不受我们的版本固定和冒烟管 | 升级说明里提醒；冒烟用不带用户插件的配置跑 |

原来 Agent 服务上贴 API key 的登录页不再是插件网页；没接模型网关的用户走聊天里的登录命令，不为它开第二个网页。

### 6. 升级和夜跑

- dsh 不在 ACP 官方注册表里，ADR-0079 第 3 节的机器人管不到。用 Renovate 的 npm 数据源提升级 PR，冒烟通过才合；不自己写机器人。
- 夜跑用测试替身模型，不花钱。

### 7. 放在哪

插件来源能带子目录（ADR-0079 第 2 节）以后，dsh 按 ADR-0079 第 4 节搬进 `wontonapp/wonton-agents` 的 `agents/dsh/`，网页在那里加，
不在旧仓库里做。

## 验证结果

2026-11-12，一次性实验，没有合并：dsh 0.2.2-rc.1（插件镜像 `ghcr.io/geraldpeng6/wonton-plugin-dsh:0.1.2` 固定的版本），
一台开发主机上的真实 Wonton 栈，测试替身模型（说 Messages API，假 key），只测了默认 Bot。

| 项 | 结果 |
| --- | --- |
| 主人从核心网关打开网页 | 通过：核心注入密钥头，入口核对，令牌换 cookie，dsh 网页完整加载 |
| 同插件容器直连入口，不带头、带伪造的头 | 都是 403 |
| 同插件容器直连 dsh 的端口 | 连不上（只听回环） |
| 别的插件的容器经核心网关 | 401 |
| 同插件容器经核心网关 | 403（核心剥掉代登录头，入口拒） |
| 网页里用 Wonton 的插件 | 模型拿到 16 个总线工具；只读工具直接返回；非只读工具出确认卡片，拒绝后结果回到网页 |
| 会话隔离 | 没有：聊天（ACP）建的会话和网页的在同一目录，网页列表跟着变；两个浏览器看到同一份列表 |
| 浏览器关掉后遇到审批 | 5 分钟后仍在等，没超时、没推送；重新打开后能批，任务接着跑 |
| 总线令牌换成失效的 | 模型的工具从 51 个变成 35 个，Wonton 的全部消失；网页和进程输出都没有错误 |
| 第 4 节的守则 | 都做到：独立的 `--patch` 层；把关日志的条目故意写错时入口拒绝启动；各容器和核心的日志里没有 `token=` |

没验的：家人开着开关时打开网页（要第二个家人账号）；经真实 Matrix 聊天建会话（用 ACP socket 直接建，存储效果相同）；App 推送；
模型网关是否说 Messages API；升级后配置条目的变化。

## 考虑过的做法

- **把网页做成通用的 `agent_acp` 前端**：dsh 网页只跑 dsh 自己，别家 Agent 只能当它的子 Agent。要通用网页就是 ADR-0061 第 8 节的“简单对话 UI”。
- **社区的多 Agent 网页**（如 [AionUi](https://github.com/iOfficeAI/AionUi)）给 Codex、Claude Code 当网页入口：都自己起 Agent 子进程，
  做不做等主人定。
- **按 Bot 的网页权限**（入口再按 `{role}`、`{user}` 只放这个 Bot 听的人）：主人定照家人开关，一个开关，该放开就放开，提示写清。
- **照 Hermes 用 `sso: none`、不核对头**：入口在插件网络里谁都连得到，同插件能跑 shell 的容器就能拿到令牌。
- **`dsh web --host <容器 IP>`**：同上，Agent 端口本身也暴露在插件网络里。
- **写一个 dsh 认证插件**：挂在上游写明未稳定的内部接口上；dsh 也不支持 OIDC。
- **沿用 ACP 服务的网关钩子，整份重写 profile**：和用户在“设置”页的改动互相覆盖。
- **现在就把 dsh 的审批转成卡片**：要写一个 dsh 插件挂在未稳定的接口上；先写明限制，见第 5 节。

## 代价与待验证项

- 入口是逐家的胶水，挂在“令牌打印在输出里”这种人读的格式上；dsh 改输出格式就要跟着改。可以向上游提把令牌写进文件。
- 开关一开，家人拿到 Bot 的全部能力；只靠提示，没有技术上的拦法。
- 网页里只看得到 Wonton 卡片“调用中”，要拿起手机答；网页打开时在 WebView 上方弹原生确认，另行立项（判断归哪个插件放在 Rust 客户端核心）。
- 待实测：家人开着开关时的访问；每个非默认 Bot 的网页；经隧道打开时 cookie 和 WebSocket 是否正常。
