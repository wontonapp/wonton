# ADR-0039 代理插件：没有自己代理的主人，装一个插件就能让出网插件走代理

- 状态：已接受（2026-11-06）。方向由主人确认（见“已定”）

## 背景

[ADR-0023](0023-egress-proxy.md) 让出网插件经出口容器 `wonton-egress`（gost）走主人的代理。前提是主人已经有一个 Docker 网段连得上的代理，比如宿主上开了 Allow LAN 的 Clash，或者别的机器上的代理。没有的主人只能自己去装、去配，插件要下的模型和依赖照样下不来。比如 Immich 按内容搜照片要从 huggingface.co 下载识别模型，直连不通时这一项就用不了。

主人 2026-11-06 定的方向：

- 用开源项目做一个代理插件：mihomo 的上游镜像，加上它的网页面板，手机上能切节点、看流量和连接。插件只是中间层，保留上游的原生体验。
- 订阅链接在插件里填，按密钥保存。
- 代理端口只在 Wonton 内部的网络上，不占宿主端口。给家里其他设备用是一个默认关的开关。
- 插件在清单里声明“提供出网代理”。核心的出网代理设置里，除了手填地址，再加“使用已安装的代理插件”。核心只认这个声明，不认具体是哪个插件（[ADR-0015](0015-small-components-standard-interfaces.md)）。
- 安装时写明代理插件能看到所有插件访问了哪些网站。Bot 来装时走确认卡片。
- 装代理插件本身不能依赖代理。
- 代理插件停了或坏了，出网如实报“代理不可用”，不悄悄改成直连。

## 决策

### 清单：`provides.egress_proxy`

```yaml
x-wonton:
  kind: app
  provides:
    egress_proxy:
      service: proxy
      port: 7890
  permissions:
    - network.egress
    - egress.proxy
```

| 字段 | 说明 |
| --- | --- |
| `service` | 提供代理的服务，要在 `services` 里，不能写 `network_mode`，不能是 Bot 服务。 |
| `port` | HTTP 代理端口，要支持 `CONNECT`。 |

- **新权限 `egress.proxy`，风险级别高。** 和 `provides.egress_proxy` 成对出现，规则同 [ADR-0036](0036-plugin-privileges.md) 的高权限。确认页写：“选它做出网代理后，所有出网插件的请求都经过它：它能看到这些插件访问了哪些网站，也能改写不加密的内容。”Bot 装高风险插件本来就走确认卡片，不用另加规则。
- **必须同时申请 `network.egress`。** 代理插件自己要出网。
- **不限 `kind: system`。** `provides.models` 只给系统插件，因为网关是预装的，看得到全部模型请求和服务商的 key。代理插件是主人自己挑的，同类项目很多，风险由确认页写明、主人决定，和 ADR-0036 “声明了就给”一致。
- **同一台服务器只能装一个。** 装第二个时安装失败（`conflict`），同 `provides.models`。只有一个就不用选，设置里也不用列表。

### 核心怎么接上它

`wonton-egress` 本来就接在每个出网插件的网络上。代理插件也是出网插件，所以 gost 和它已经在同一个网络里。选了代理插件时：

- **gost 的上游写成代理服务的容器名**：`http://wonton-<slug>--<服务名>:<port>`，有实例名时按插件规范的命名多一段。容器名在一台 Docker 上唯一，经内置 DNS 解析，只有接在这个网络上的容器解析得到。
- **核心自己的路径**（GitHub、官方索引、推送）也连这个地址：核心接在所有插件网络上。
- **查原因的一次性容器接在代理插件的网络上**，不接 `wonton-egress`：上游只在那个网络上。判断和提示同 ADR-0023 的“代理连不上时怎么报错”。
- **代理插件自己不写代理变量。** 它的流量直连，不经 gost，否则请求会绕回它自己。
- **装、升级、重装代理插件都不检查出网代理。** ADR-0023 在代理不通时挡出网插件的安装；代理插件坏了的时候正要重装它，不能被自己挡住。拉镜像由 Docker 守护进程做，本来就不经 gost。

### 设置：来源多一个 `plugin`

- `EgressProxySource` 加 `plugin`：使用已安装的代理插件。`EgressProxySettings.provider` 给出装着的代理插件（ID 和名字），没装时为空。来源是 `plugin` 时 `url` 为空：主人不需要知道容器名。
- `EgressProxyUpdate` 加 `use_plugin`。为 `true` 时 `url` 必须为空，否则 400 `invalid_input`；没装代理插件时 404 `not_installed`。设了 `WONTON_EGRESS_PROXY` 的主机照旧 409 `conflict`。
- **重启的规则不变。** 从没有代理切到代理插件，或者反过来，出网插件的环境变量要变，按 ADR-0023 先列出要重启的插件，主人确认。在手填地址和代理插件之间切换时，插件的变量不变（都是 `http://egress.wonton.internal:3128`），只重建 gost。
- **装上不自动选它。** 选它要重启出网插件，要主人看过列表再确认。代理插件装好后，详情页提示“在出网代理设置里选它”。

### 代理插件不可用时

- **没在运行、没就绪或者容器被删了：** gost 连不上上游，插件得到 503，和主人的代理连不上时一样。设置页的插件路径报 `proxy_unreachable`，提示写“代理插件没在运行”，带上它的状态。不改成直连。
- **出网插件的安装照旧被挡**，原因写代理插件不可用。代理插件自己除外，见上。
- **卸载正在用的代理插件：** 409 `conflict`，提示先在出网代理设置里换掉。直接卸载会让所有出网插件出不去，主人未必想到这一层。
- **代理插件里一个节点都没有**（订阅没填、拉不下来）：CONNECT 连得上，到不了外网，探测是 `upstream_failed`，按 ADR-0023 只提示、不挡安装。

### 给家里其他设备用

不用新机制。插件按插件规范用 `lan.ports` 加 `lan.client` 开局域网端口：写了 `lan.client` 时 `lan.ports` 全部受开关 `lan_webui` 管，默认关；打开后详情页显示地址、用户名和核心生成的密码，代理插件用它们开鉴权。要 `network.lan` 权限，确认页照常写谁能连上来。

### 第一个代理插件

插件仓库的事，这里只记和底座有关的约束，其余写在插件仓库的 README：

- mihomo（GPL-3.0）加网页面板 zashboard（MIT）。都是独立容器，只拉上游官方镜像，不链接进 Wonton，符合 AGENTS.md 的许可证规则。
- **插件名不带 mihomo。** mihomo 的 README 要求与 MetaCubeX 无关的下游项目名字里不出现 mihomo，所以插件叫“代理”（`app.wonton.proxy`），上游名字只出现在镜像、来源和说明里。
- **管理接口要设密钥。** 名单只比对字面写法（ADR-0023 的“它不是安全边界”），别的出网插件可以把目标写成代理插件的容器名，经 gost 和代理本身到达它的管理接口。密钥用 `secrets.generate`。
- **订阅链接只存在插件的数据目录里，文件权限 0600。** 用户在插件的页面里填。不用 `secrets.collect`：核心保管的那份不会注入回插件，重装时帮不上；保留数据重装时文件本来就在。订阅链接不出现在日志、页面和 MCP 里。
- **面板不让主人再填一次密钥。** 网关按 `sso: proxy` 用 `{secret:…}` 替面板带上管理接口的密钥，响应里出现的密钥由网关去掉。
- **镜像要直连拉得到。** 装代理插件时还没有代理。

## 已定

- **做成插件，不做成核心组件。** 核心保持薄，代理方案很多，主人可以换。没选：核心内置 mihomo，那就要跟着上游的规则格式和订阅协议走。
- **核心只认声明。** 不认镜像，也不认插件 ID。别的代理插件（sing-box、Xray）按同样的声明就能接上。

## 没选的做法

- **装上就自动选为出网代理：** 省一步，但会在主人没看到重启列表时重启出网插件。
- **代理插件单独一条路，不经 gost：** 要另一套拒绝名单和探测。经 gost 时，ADR-0023 的名单、探测、重启规则都能直接用。
- **gost 的上游写代理容器的 IP：** 容器重建后 IP 会变，要再加一层同步。用别名的话要 `.wonton.internal` 后缀，那是核心的入口。
- **可以装几个、在设置里选：** 一台家庭服务器同时跑两个代理插件的情况少，列表和选择都是额外的界面。要时再加。
- **只有 `kind: system` 能声明：** 那就只有官方预装的才行，主人换不了自己喜欢的代理方案。

## 代价与风险

- 被选中的代理插件看得到所有出网插件访问的网站，能改写不加密的内容。由确认页写明，主人决定。
- 代理插件坏了时核心自己的路径也不通。要从官方索引重装它，得先在设置里取消代理，取消要重启出网插件。重启代理插件就能好的情况不受影响。
- 代理插件升级时容器重建，那几秒里出网插件得到 503。

## 验证结果

2026-11-06，Docker Engine 29.7.2、x86_64，gost 3.3.3（摘要由核心固定），BusyBox 1.37：

- 独立实例中启动真实核心容器，经主人令牌调用管理接口：安装代理插件和出网插件后选择代理，返回 `source: plugin`、`url: null` 和提供方；无令牌访问返回 401。
- 同时指定插件和地址返回 400；第二个代理插件和卸载在用的代理插件返回 409。切换到手填的另一代理再切回时，只更换 gost，代理插件和出网插件的容器 ID 不变。
- 重启核心后保留插件选择，出网插件不重建。停止代理服务后，安装出网插件返回 `egress_proxy_unavailable / proxy_unreachable`，已装出网插件的请求收到 503，不直连。
- 自动化 Docker 场景在 `crates/wonton-core/src/plugin/tests/egress_plugin_docker.rs`：目标只在上游代理的另一个网络中，出网插件经核心注入的变量、gost 和提供方容器名取得预期内容；删除代理容器后探测为 `proxy_unreachable`、请求返回 503。容器和网络在成功及断言失败后都清理。

原生壳的选择控件不在这次验证范围。Rust 客户端的重启确认、手填与插件切换、探测刷新由客户端行为测试覆盖。
