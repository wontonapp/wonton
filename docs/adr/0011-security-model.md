# ADR-0011 安全模型

- 状态：已接受（2026-10-28）。“插件权限”和“网络暴露”已被 [ADR-0036](0036-plugin-privileges.md) 取代；“已定”里“永远不给 Bot 宿主的 shell”已被 [ADR-0091](0091-danger-mode.md) 取代（主人 2026-11-12）

## 背景

旧部署实测发现：Hermes 和 Edge 同属一个用户，能读到设备身份私钥；有的机器上 Hermes 带 docker、
sudo 组且审批关闭，一次提示注入就能控制整台机器；本地 API 绑在 `0.0.0.0`。

## 决策

- **安全只做必要的**（主人 2026-11-03 定）：不把使用搞得麻烦，否则大家只会一直开着“一律允许”（Claude Code 有 auto 模式之前就是这样）。确实有风险、拦了又伤体验的，做成开关，默认关，旁边写明风险，主人自己打开。
- **Agent 是不可信执行者**：在独立容器里运行，只看得到自己的工作区和被授权的文件夹，没有 Docker
  socket，也没有宿主 root。
- **改变系统状态的操作走核心**：装卸插件、删文件、改设置、对外发送都通过核心 MCP 工具执行。
  敏感操作由核心在聊天里给主人发确认按钮，主人点了才执行，并写审计日志。主人可以放宽插件工具的确认（ADR-0024）。
- **插件权限**：写在清单里，安装时展示确认。高权限按风险分三级提示，声明了就给，由主人决定；Agent 和 Bot 插件自己拿不到
  Docker socket、特权模式和宿主 shell（ADR-0036），Bot 碰宿主只经最高级插件的工具，平时每次确认，危险模式下免确认（[ADR-0091](0091-danger-mode.md)）；这里的宿主指服务器，用户自己电脑上的 Agent 见 [ADR-0081](0081-local-agent-host.md)。插件不声明的能力一律不给。
- **Docker socket**：核心容器挂载，以及升级器和 `install.sh` 里跑 compose 的一次性容器（ADR-0025）；插件只有声明了 `docker.socket`、主人单独确认后才有（ADR-0036）。宿主的 `/dev` 也只读挂进核心容器，用来检测显卡和设备所属的组（ADR-0018）；
  设备 cgroup 没放行，核心开不了这些设备。
- **密钥**：provider key 等密钥只存在核心密钥库和 magpie；插件拿到的是只属于自己的受限令牌。第三方 App 入口的密钥由核心保管，运行时
  只挂进各自的容器（ADR-0021）：frp 令牌给连接器，acme-dns 凭据和 ACME 账号钥匙给 lego，证书私钥给入口容器。
- **不可信输入**：来自其他 Bot、网页、文件的内容都视为不可信，防止提示注入触发敏感操作。
- **网络暴露**：插件不直接向宿主或外网暴露端口；所有访问经核心网关鉴权。例外都要清单声明：局域网端口
  （ADR-0019）；宿主网络（ADR-0036）；第三方 App 的入口（ADR-0021），主人打开后未认证的请求能到应用自己的登录，面向公网的 TLS 解析放在
  没有 Docker socket 的容器里；访客链接（ADR-0090），拿着有效链接的人是这个应用的匿名用户，到期或收回即失效。公网入口有一个总开关。

## 插件隔离的约束

权限确认只展示清单声明的权限，下面的约束保证没有声明权限的插件越不过隔离（#20）。

- **默认加固**：插件容器一律带 `no-new-privileges:true`，插件进程不能经自己的操作拿到新特权（setuid
  位、文件能力）。依赖 setuid 的镜像（容器里用 sudo 的）写 `security_opt: [no-new-privileges:false]`
  退回 Docker 默认，这一项不算权限、不要求声明（ADR-0036 的“默认加固”）。`cap_drop` 只减不加，也不需要权限。
- **绑定挂载**：Docker 每次启动容器都会跟随软链接重新解析挂载源，所以任何容器能改写的目录都不能出现在
  挂载源的路径上：
  - 宿主路径只能是插件自己的应用数据目录（或其子目录），以及已授权共享文件夹的根目录。
  - 同一插件的挂载源不能嵌套，同一个目录可以挂进多个服务。否则能写外层目录的容器可以把内层的源换成
    指向 `/` 的软链接，容器重启后就挂上了宿主根目录。
  - 共享文件夹只能整个挂载，不能挂子路径：它由多个插件共用，任何有写权限的插件都能把子目录换成软链接。
    确需子路径时改用 Docker 卷的 subpath（moby 用 safepath 防止逃逸），M0 不支持。
  - 核心创建挂载源目录并交给 `PUID:PGID` 时，从应用数据目录或共享文件夹开始逐级 lstat，不跟随软链接：
    路径上有软链接（比如上次安装留下的）或不是目录就拒绝安装，改属主用 lchown。
  - `read_only` 服务的 `configs` 是核心自己管理的挂载源（`configs_store`）：文件放在核心数据目录的
    `<数据目录>/core/configs/<实例>/<插件>/<服务>/<编号>`，只读挂给容器。那里插件容器写不到（它们能写
    的只有应用数据目录和共享文件夹），路径上不会有能换成软链接的目录，所以不用逐级检查。属主和权限由
    Docker daemon 按归档记录写（daemon 是 root，和普通服务的归档交付是同一个组件），核心保持非 root 也能
    声明任意的 `uid`/`gid`；覆盖写会换 inode，所以内容更新在重建容器后可见，安装和升级本来就会重建。

  前三条保证运行中的插件改不了任何挂载源路径上的目录，所以核心只需在安装时检查一次。
- **资源名**：插件的容器和命名卷叫 `wonton-<slug>--<服务名或卷名>`，网络叫 `wonton-<slug>`。slug 不含 `--`，
  不同插件的资源不会重名，一个插件不能靠重名占掉另一个插件的资源。不同 ID 可能得到同一个 slug
  （`app.foo-bar` 和 `app.foo.bar`），核心不允许它们同时安装；卸载时保留的卷按 `wonton.plugin` 标签校验
  归属，同 slug 的另一个插件挂不上。
- **几套核心共用一台 Docker**（插件开发环境，ADR-0017）：设了实例名（`WONTON_INSTANCE`）的核心在资源名的 `wonton-`
  后加一段 `<实例名>--`，再给资源打上 `wonton.instance` 标签。实例名只有小写字母和数字，slug 都含连字符，所以不同
  实例、实例和正式安装的资源不会重名。卸载时核心按 `wonton.plugin` 标签找资源，只删实例标签和自己一致的（正式安装
  只删没有实例标签的），删不到别的核心里同一个插件的容器和数据。这只是让几套核心互不干扰，不是隔离：每套核心都挂着
  Docker socket，能管这台主机上的一切，所以只在开发者自己的主机上这样用。
- **浏览器里的隔离**：插件子域名彼此同站，也和核心同站，`SameSite=Lax` 拦不住一个插件的页面让浏览器带着
  Cookie 向别的插件或核心发请求；经隧道时，设备身份同样随每个请求带上。所以网关（`gateway/isolation.rs`）：
  - 插件子域名上，Cookie 会话、隧道身份和 `sso: proxy` 代加的凭据只给这些请求：`Sec-Fetch-Site`
    为 `same-origin` 或 `none`；导航（`Sec-Fetch-Mode: navigate`，方法为 `GET` 或 `HEAD`，`<object>`、
    `<embed>` 的加载不算）；没有 `Sec-Fetch-Site` 时，没有 `Origin` 或者 `Origin` 就是插件地址。其余请求按
    未登录处理，到不了插件，也不跳去核心换会话。
  - 核心域名上改状态的请求（`POST`、`DELETE` 等）只接受同源：`Sec-Fetch-Site` 为 `same-origin` 或 `none`；
    没有它时，`Origin` 要么没有、要么是核心地址；否则回 403 `cross_site`。插件页面因此不能替主人退出登录。
    管理 API 另外要 `Authorization: Bearer`，浏览器不会自动带上它；插件管理接口还接受已配对设备，但不接受网页发起的
    请求（ADR-0017）。
  - 插件响应里的 `Set-Cookie` 去掉 `Domain` 属性，只对插件自己的子域名有效；名字以 `wonton_` 开头的整条
    丢弃，转发给插件的请求里也去掉这些 Cookie。插件页面的脚本仍能用 `document.cookie` 给父域写 Cookie，
    所以网关按字节解析 `Cookie` 头，同名的会话 Cookie 逐个试：别处写进来的 Cookie 冒充不了会话，也挤不掉
    真正的会话。
  - `sso: proxy` 的插件：网关代加的请求头和 Cookie 先删掉客户端发来的同名项；响应里设置这些 Cookie 的
    `Set-Cookie`，以及值里带着代加密钥原文的响应头，都不交给浏览器（插件规范“网关代登录”）。

  这几条的边界：
  - 浏览器只对 https 和 `localhost` 发 Fetch Metadata，其余 http 地址上只剩 `Origin`：跨站的表单 POST、
    `fetch` 和 WebSocket 都带 `Origin`，挡得住；`<img>`、`<script>` 这类 GET 不带它，仍会带着登录状态到达
    插件，所以插件的 `GET` 不能改状态。隧道内不另加 HTTPS（ADR-0009），这条边界一直存在。
  - iframe 也是导航：别的插件能把这个插件嵌进 iframe，读不到内容，但可能诱导主人点击。防点击劫持靠插件
    自己的 `X-Frame-Options` 或 CSP `frame-ancestors`。
  - 应用的 OIDC 回调要用默认的 `query` 响应模式：`form_post` 是从 `auth.<base>` 发来的跨站 POST，会被当成
    未登录。
