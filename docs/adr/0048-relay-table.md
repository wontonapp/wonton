# ADR-0048 中继表：从配置来，分档自动选优，准入只认 endpoint ID

- 状态：已接受（2026-11-06）

## 背景

隧道打洞失败时经中继转发（ADR-0004）。核心和 App 一直用 iroh 内置的 n0 公共中继：

- n0 的条款写明只适合开发和个人使用，没有 SLA，限速数值不公开。2026-11-06 在广州电信晚高峰实测，单条连接约 20 KB/s。
- 大陆的 IPv4 对称 NAT、CGNAT 和移动网络的 UDP 限速都很常见，按推算约 10–35% 的流量要走中继。

自建中继是 GOAL 的 M2 第 11 项。主人的要求：

- 不捆绑：中继地址像环境变量一样好改，自部署的人可以换成自己的，也可以用公共的。
- 预置能用的公共中继。
- 自动挑延迟低、速度快的，用户也能设优先级。
- 收费以后要能按用户限权限、按用户算配额，现在就留好接口。

核实到的上游情况（iroh 和 iroh-relay 1.4.1）：

- `RelayConfig` 只有地址、QUIC 端口和准入令牌三个字段，没有权重，表里的顺序也不起作用。
- 家中继由 iroh 按近 5 分钟的探测延迟自己挑，新中继要快约 1.5 倍才会换过去。
- 中继的准入有 `everyone`、名单、`shared_token`、`http` 回调几种。endpoint ID 在回调之前已经过握手认证，可信；回调只能答“放”或“不放”。
- 中继没有按 endpoint 计量或限速：metrics 是整个进程的累计数，限速是每条连接一个令牌桶，全服务一个值。
- 除 n0 外没有承诺对外开放的公共 iroh 中继。Tailscale 的 DERP 和 iroh 的中继协议不通。

## 决策

### 中继表

核心有一张中继表，每项是地址、可选的准入令牌和档位（数字小的优先）。三个来源，后面的盖过前面同一地址的项：

1. **内置**：n0 的公共中继，放在最后一档。什么都不配也能用。
2. **签名列表**（可选）：核心配置里写列表的地址，核心下载 `relays.json` 和它的 minisign 签名，用内置的公钥验签，验不过就不用，并照实报错。列表里不放令牌。我们运营的中继经它发布。
3. **主人配置**：核心的环境变量 `WONTON_RELAYS`，可以加中继、设档位、填令牌，也能去掉内置的 n0。

App 不另存一份配置：核心把整张表（连同令牌）放进配对码和 `/_wonton/api/tunnel`，App 用它建自己那一侧的 iroh 中继表，连接信息里服务器的中继地址也取自它。主人只改核心一个地方，手机上的 App 在下次连上时跟着变。App 内置的 n0 只在连接信息里一个中继都没有时用。

### 分档自动选优

- 两侧都只把最优先一档的中继交给 iroh，档内由 iroh 按延迟自动挑。我们不另写测速。
- 整档的中继都连不上，并且持续超过阈值时，才把下一档加进去；上一档恢复后撤掉下一档。阈值和理由写在代码旁边。
- “优先级”就是档位：同档谁快用谁，跨档按顺序用。iroh 没有软权重，不在同一档里排先后。

### 准入和配额

- 协议和核心只认 endpoint ID 和每个中继的令牌。
- 内测用 iroh-relay 的 `shared_token`。
- 收费以后，中继改成 `http` 回调：账号和套餐服务按 endpoint ID 答“放”或“不放”。核心、App 和协议都不用改。
- 按户计量、限速和超额断开做在中继一侧，到时再定是给 iroh-relay 提上游 PR，还是先维护一个补丁版。和核心无关。
- 中继拒绝时不带原因，App 只能如实显示“中继连不上”，分不出是配额用完还是中继挂了。要区分，得等账号服务有自己的查询接口。

### 部署

自建中继和发现节点只要求一台 Linux 加 Docker 的主机，不绑定云厂商：

- 用官方 `iroh-relay`、`iroh-dns-server` 镜像，按摘要固定版本。
- 开 TCP 443 和 UDP 7842（QAD）。
- 一个子域，A/AAAA 记录直接指向主机，不开 CDN 代理。
- 证书和 pkarr 数据放在持久卷里。

换主机只要改 DNS 和搬数据卷，客户端不用动。

## 理由

- 地址从配置来，内置 n0 兜底：自部署的人不配也能用，想换只改一处，不依赖我们运营的任何服务。
- 令牌随连接信息下发：App 能用主人自己的、有准入的中继，不用在手机上另外配置。
- 分档而不是权重：iroh 没有权重。排在前面的不会被优先用，写了等于骗人。
- 准入只认 endpoint ID：它已经过握手认证。收费时只换中继一侧的准入方式，协议不变。

## 代价与风险

- 令牌跟着配对码和连接信息走，泄露后别人也能用这个中继。内测的 `shared_token` 接受这个风险，收费以后改用按 endpoint 的回调。
- 回调服务不可用时，中继拒绝所有连接，所以账号服务要做高可用。
- 档位回退靠持续观察 `home_relay_status`，切档前会有一段连接变慢甚至连不上。

## 没选的

- **只用 n0 的付费托管中继**（Pro 每月 19 美元，独享一个区域在 Pro 之上每月加 199 美元）：捆绑一家服务，也不解决自部署的人用什么。可以作为表里的一项，主人自己配。
- **App 自己下载签名列表**：手机只认核心给的表，两边不会不一致。中继换主机时 DNS 跟着改，地址不变。
- **改 iroh 加权重**：改动大，上游也没有这个方向。分档已经够用。
