# ADR-0048 中继表：从配置来，分档自动选优，准入只认 endpoint ID

- 状态：已接受（2026-11-06）

## 背景

隧道打洞失败时经中继转发（ADR-0004）。核心和 App 一直用 iroh 内置的 n0 公共中继：

- n0 的条款写明只适合开发和个人使用，没有 SLA，限速数值不公开。2026-11-06 在广州电信晚高峰实测，单条连接约 20 KB/s。
- 大陆的 IPv4 对称 NAT、CGNAT 和移动网络的 UDP 限速都很常见，按推算约 10–35% 的流量要走中继。

自建中继是 GOAL 的 M2 第 11 项。主人的要求：

- 不捆绑：中继地址像环境变量一样好改，自部署的人可以换成自己的，也可以用公共的。
- 什么都不配也能用（只预置 n0 公共中继）。我们自己的中继不烘进公开构建、不进公开文档：地址和令牌从部署配置来，令牌只放在 0600 文件或环境变量里。
- 自动挑延迟低、速度快的，用户也能设优先级。
- 收费以后要能按用户限权限、按用户算配额，现在就留好接口。

核实到的上游情况（iroh 和 iroh-relay 1.4.1）：

- `RelayConfig` 只有地址、QUIC 端口和准入令牌三个字段，没有权重，表里的顺序也不起作用。
- 家中继由 iroh 按近 5 分钟的探测延迟自己挑，新中继要快约 1.5 倍才会换过去。
- 中继的准入有 `everyone`、名单、`shared_token`、`http` 回调几种。endpoint ID 在回调之前已经过握手认证，可信；回调只能答“放”或“不放”。
- 中继没有按 endpoint 计量或限速：metrics 是整个进程的累计数，限速是每条连接一个令牌桶，全服务一个值。
- 除 n0 外没有承诺对外开放的公共 iroh 中继。Tailscale 的 DERP 和 iroh 的中继协议不通。

## 决策

### 中继表

核心有一张中继表，每项是地址、可选的准入令牌和档位（数字小的优先）。中继域名统一不带 FQDN 尾点；
内置地址、配置、配对码和连接信息在入口规范化，使配对码、中继表和连接状态使用同一个地址 key。
三个来源，后面的盖过前面同一地址的项：

1. **内置**：n0 的公共中继，放在最后一档。什么都不配也能用。公开构建只预置 n0，我们的地址和令牌不进公开构建和公开文档；要在某个构建里预置别的，给构建参数 `WONTON_BUILTIN_RELAYS`。
2. **签名列表**（可选）：核心配置里写列表的地址，核心下载 `relays.json` 和它的 minisign 签名，用内置的公钥验签，验不过就不用，并照实报错。列表里不放令牌。要对外发布中继地址时用这种方式，公钥和列表地址同样是配置项。
3. **主人配置**：环境变量 `WONTON_RELAYS` 和数据目录里的 `relays.json`（权限 0600，设置页写它），两处都要求已配对才能读到。可以加中继、设档位、填令牌，也能去掉内置的 n0。环境变量设了就只认它，设置页只读；令牌只从这两处读，不进仓库、不进日志。

n0 兜底是一个开关：开着时 n0 那一组总在最后一档。逐台删 n0 也记进主人配置、删掉的不会再被自动补回；
整组都删光（表里一条 n0 都没有）当作「就要 n0 兜底」，不记删除，所以把开关关掉再打开能整组回来。

App 不另存一份配置：核心把整张表（连同令牌）放进配对码和 `/_wonton/api/tunnel`，App 用它建自己那一侧的 iroh 中继表，连接信息里服务器的中继地址也取自它。主人只改核心一个地方，手机上的 App 在下次连上时跟着变。App 内置的 n0 只在连接信息里一个中继都没有时用。

### 分档自动选优

- 两侧都只把最优先一档的中继交给 iroh，档内由 iroh 按延迟自动挑。我们不另写测速。
- 整档的中继都连不上，并且持续超过阈值时，才把下一档加进去；上一档恢复后撤掉下一档。阈值和理由写在代码旁边。
- 中继拒绝令牌和连不上算同一种失败：按指数退避重连，间隔封顶 16 秒。被撤的每台中继单独养一个只装它的
  探针 endpoint，不按轮询周期改中继表（每次改都会让 iroh 跑一遍完整 net_report）。理由写在 `relays/fallback.rs` 的注释里。
- “优先级”就是档位：同档谁快用谁，跨档按顺序用。iroh 没有软权重，不在同一档里排先后。

### 准入和配额

- 协议和核心只认 endpoint ID 和每个中继的令牌。
- 内测用 iroh-relay 的 `shared_token`。
- 收费以后，中继改成 `http` 回调：账号和套餐服务按 endpoint ID 答“放”或“不放”。核心、App 和协议都不用改。
- 按户计量、限速和超额断开做在中继一侧，到时再定是给 iroh-relay 提上游 PR，还是先维护一个补丁版。和核心无关。
- 中继的准入拒绝带一句原因（iroh-relay 的 `ServerDeniedAuth`），iroh 从 1.4.1 起在 `RelayStatus::auth_denied_reason()` 里给出来。客户端据此把“令牌被拒”单独成一类，不再笼统说“连不上”；配额用完和中继挂了仍然分不出，要等账号服务有自己的查询接口。

### 令牌下发（2026-11-27）

主人的要求：令牌从家里服务器的配置到 App，不写进 App 包、不进日志、不进 URL；令牌错或缺时客户端如实报“中继拒绝：令牌无效”，不静默改走别的路。链路和约束：

1. 核心配置 `WONTON_RELAYS` 里的 `https://TOKEN@relay.example.org` 解析成内部中继表，令牌从地址里去掉，单独存成 `RelayToken`。
2. `Tunnel::relays()` 把表转成下发写法 `RelayView { url, token?, tier }`：地址永远不带 userinfo，令牌只在 `token` 字段。配对码和 `/_wonton/api/tunnel` 用同一份。
3. 两个通道都只给已认证的一方：配对码在主人扫码时给出；`/_wonton/api/tunnel` 要主人令牌或这条隧道上的已配对设备，插件网页的跨站请求被拒。
4. App 的隧道客户端把表存进连接信息（App 私有目录），逐项校验（https、不带 userinfo、令牌非空）；坏了一项就整份不用、留旧表并按取地址失败重试。建 iroh 的中继表时把令牌放进 `RelayConfig::with_auth_token`。
5. 日志：`RelayToken` 的 `Debug` 打印 `<redacted>`，配对码的 `Debug` 也不打印令牌；连接信息的 JSON 只落磁盘，不进日志。
6. 出错：客户端看到 `RelayStatus::auth_denied_reason()` 就把中继一行归成“被拒绝”，断开时提示“中继拒绝了这台手机的令牌”，重试按钮照常转圈。n0 兜底档仍在 30 秒后按 ADR-0048 加入，不因为令牌错就停掉；但界面不会再把它笼统说成“连不上中继”。
7. 轮换：令牌换了以后，App 下一次取 `/_wonton/api/tunnel` 存下新值；跑着的 endpoint 不会热换（iroh#4642），重连或重启 App 时生效。旧令牌在换掉之前一直有效。

约束：

- 令牌是共享的，拿到配对码或已配对设备就能读出来。内测接受（ADR-0048 已写），泄露就轮换。
- 令牌不进 URL 的路径、查询和片段，也不进 App 包。二维码里放的是下发写法的 JSON，和 `/_wonton/api/tunnel` 的 `relays` 相同。
- 核心报来的表只认 https、不带 userinfo；客户端不猜、不修。

### 部署

自建中继和发现节点只要求一台 Linux 加 Docker 的主机，不绑定云厂商：

- 用官方 `iroh-relay`、`iroh-dns-server` 镜像，按摘要固定版本。
- 开 TCP 443 和 UDP 7842（QAD）。
- 一个子域，A/AAAA 记录直接指向主机，不开 CDN 代理。
- 证书和 pkarr 数据放在持久卷里。

换主机只要改 DNS 和搬数据卷，客户端不用动。

## 理由

- 地址从配置来，内置 n0 兜底：自部署的人不配也能用，想换只改一处，不依赖我们运营的任何服务。我们自己的中继也只算一项配置，公开构建里看不出我们的部署。
- 令牌随连接信息下发：App 能用主人自己的、有准入的中继，不用在手机上另外配置。
- 分档而不是权重：iroh 没有权重。排在前面的不会被优先用，写了等于骗人。
- 准入只认 endpoint ID：它已经过握手认证。收费时只换中继一侧的准入方式，协议不变。

## 代价与风险

- 令牌跟着配对码和连接信息走，泄露后别人也能用这个中继。内测的 `shared_token` 接受这个风险，收费以后改用按 endpoint 的回调。
- 回调服务不可用时，中继拒绝所有连接，所以账号服务要做高可用。
- 档位回退靠持续观察 `home_relay_status`，切档前会有一段连接变慢甚至连不上。

## 没选的

- **只用 n0 的付费托管中继**：按月付费，独享一个区域还要加钱；捆绑一家服务，也不解决自部署的人用什么。可以作为表里的一项，主人自己配。
- **App 自己下载签名列表**：手机只认核心给的表，两边不会不一致。中继换主机时 DNS 跟着改，地址不变。
- **改 iroh 加权重**：改动大，上游也没有这个方向。分档已经够用。

## 验证结果（第二阶段，2026-11-26）

主人 11-26 补充：自建中继只给我们自己用，不做公共中继。公开构建和公开文档里不预置我们的地址和令牌；默认表只有 n0（或空表跟着 iroh 默认），我们的中继靠环境变量或 0600 的 `relays.json` 加进来，令牌从这两处读，随配对票据只发给已配对设备。

已跑：

- `cargo test -p wonton-tunnel --lib`：99 通过。覆盖 `#端口`、`!URL` 删除标记、`n0` 关键字和 `no-n0`、n0 自动放最后一档、QUIC 端口进 `RelayConfig`。
- `cargo test -p wonton-core --lib relay_settings::tests`：12 通过。覆盖内置→签名→主人配置逐层覆盖、同地址后面的盖过前面的、配置文件 0600 往返、环境变量锁定时拒绝保存、坏文件写清路径和原因、默认表正好是 n0 那一组、删掉的 n0 地址重启后不再回来、n0 关掉再打开整组回来。
- `cargo test -p wonton-core --lib gateway::relays_api_tests`：7 通过。GET 要主人令牌，保存回整张表（令牌照给已配对设备），http 地址和重复地址 400，请求体不是 JSON 400 且文案已本地化，环境变量固定时 PUT 409，删掉的内置项不再出现。
- `cargo test -p wonton-client --lib`：全量通过，其中 `home::relays::tests` 19 条。设置页草稿的加、删、挪档、重复、锁定和 Discard；URL 规范化（含 FQDN 尾点、`#端口`）、空串清令牌、0 清端口；服务器拒绝的原文。
- `cargo fmt --all -- --check`、`cargo clippy -p wonton-tunnel -p wonton-core -p wonton-client --all-targets -- -D warnings`、`python3 scripts/check-ui-text.py`、`bash scripts/check-file-size.sh`：通过。

没跑：真实 `iroh-relay` 的端到端（`relay-deploy` 的主机还没上线，新增的 `relays.json.minisig` 用本地夹具验签和篡改）。`WONTON_BUILTIN_RELAYS` 已经作为构建参数进了 `deploy/dev/core/Dockerfile`，公开镜像仍然留空。
