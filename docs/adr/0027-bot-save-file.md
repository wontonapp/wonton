# ADR-0027 Bot 把文件存进共享文件夹：按路径授权

- 状态：已接受（2026-11-04），取舍由主人确认。取代 ADR-0024 判定的第 1 步（见“和 ADR-0024 的关系”），补充 ADR-0020。“其余核心敏感工具每次发卡片”已被 [ADR-0033](0033-plugin-tabs.md) 改动

## 背景

主人让 Hermes 下载一首歌放进 Navidrome，下载到了也放不进去（#252）。写共享文件夹的权限只有插件级的 `storage.share.<名称>:write`：装插件时批准一次，容器里读写挂载整个文件夹，之后每次写都不经过主人。Hermes 没有挂载任何共享文件夹（ADR-0020），上传接口只接受经隧道的已配对设备，所以 Bot 手里的文件出不了自己的容器。

主人 2026-11-04 定了方向：走确认卡片，但不能老问。第一稿有“这一次”“30 分钟内”“一直”三档和“所有共享文件夹”总开关，主人看过后说“不用那么复杂，就授权路径就行了”。

## 别人怎么做

2026-11-04 核对的公开文档。iOS 相册的访问级别和 Android 的“所有文件访问”没有在文档页上核对到，按已知的 API 写。

| 产品 | 这一次 | 这段时间 | 一直 | 范围 | 全部放开 | 查看和撤销 |
| --- | --- | --- | --- | --- | --- | --- |
| Claude Code | Yes | 改文件的 “don't ask again” 到会话结束 | 权限规则写进设置 | 路径规则 `Edit(/src/**)` | `acceptEdits`、`bypassPermissions` 模式 | `/permissions` 列出全部规则 |
| Chrome 文件访问（122 起） | Allow this time | 无 | Allow on every visit | 用户选的文件夹 | 无 | 站点设置逐项列出，能单独删 |
| macOS | 无 | 无 | 问一次，一直有效 | 每个 App 对桌面、文稿、下载分开 | “完全磁盘访问”单独一个列表 | 系统设置的“文件和文件夹”里逐项开关 |
| iOS 相册 | 无 | 无 | 问一次，一直有效 | 仅添加（`addOnly`）、选中的照片（`limited`）、全部 | 全部 | 系统设置 |
| Android 文件框架 | 到设备重启 | 无 | `takePersistableUriPermission` | 用户选的目录树；存储根目录和 `Download` 不给选 | “所有文件访问”单独一项 | 系统设置 |

用上的两条：一直有效的授权按文件夹给，包含子文件夹；能存不等于能看，同名不覆盖（iOS 的“仅添加”、Android 的 `ACTION_CREATE_DOCUMENT`）。

## 决策

### 工具

核心新增两个工具，所有申请了 `tools` 的插件都能调，核心不为某个 Agent 特殊处理（ADR-0015）。

| 工具 | 敏感 | 参数 | 说明 |
| --- | --- | --- | --- |
| `wonton__list_shares` | 否 | 无 | 列出共享文件夹的名字。 |
| `wonton__save_file` | 是 | `files`（1 到 100 个 outbox 里的相对路径）、`share`、`dir`（可选的子目录） | 把文件存进共享文件夹，返回每个文件最后的路径（同名时加了序号）。 |

Bot 不需要任何 `storage.share.*` 权限，也不会因此能读、列出或删除文件夹里的东西。授权只管“能往里加”。

### 文件怎么过来

插件把 `${WONTON_APP_DATA}/outbox` 挂进容器（Hermes 挂到 `/opt/data/outbox`），Bot 把要存的文件放进去；这个目录和别的绑定挂载一样由核心预先建好。没挂的插件调用时报错。调用方按来源地址认，路径只在它自己的 outbox 里解析。

只认 outbox 是因为 Agent 的数据目录里有密钥，这是 ADR-0020 把“登记 Bot 自己的文件”往后放的原因。

### 一次保存的步骤

1. **检查。** 共享文件夹必须已经存在，Bot 建不了新的共享文件夹。路径不能是绝对路径，不能含 `.`、`..` 或空段，逐级 `openat`（`O_NOFOLLOW`）打开，只接受普通文件。任何一级的名字以 `.` 开头都拒绝，已授权也一样：这些名字常常是应用的配置（Syncthing 的 `.stignore`、`.stfolder`）。
2. **暂存。** 复制到核心私有的暂存目录。之后 Bot 再改 outbox，也影响不到确认的内容。放不下返回 `storage_full`（留 5% 空闲，同 ADR-0020）。已授权时也暂存，只有一条路。
3. **判定。** 目标在这个 Bot 已授权的路径里就放行，否则发卡片。
4. **放文件。** 复用 `place_upload` 的做法：`linkat` 不覆盖，同名加序号，子目录逐级建，属主 `PUID:PGID`，`.wonton-` 开头的名字保留。
5. **收尾。** 写审计，删掉暂存和 outbox 里的原文件。拒绝或过期时只删暂存，原文件留给 Bot 处理。一个文件放不下时停下，前面放好的不撤回，结果里写明。原文件在暂存之后又被改过就不删。核心启动时清掉暂存目录的残留。

### 卡片和授权

卡片写明谁要存、每个文件的名字和实际大小、总大小、存到哪里，来源标“Bot 提供，内容未审核”。文件多时列前 10 个，写明还有几个。一次调用带多个文件只发一张卡片。

| 回答 | 按钮（目标是 `music/周杰伦`） | 效果 |
| --- | --- | --- |
| `approve` | 允许存进 music/周杰伦 | 这次放行，以后这个路径不再问 |
| `approve_wider` | 允许存进 music | 同上，范围是整个共享文件夹；目标就是共享文件夹本身时没有这个按钮 |
| `reject` | 拒绝 | 工具返回错误，说明原因 |

路径由核心按卡片记着，回答里不带路径：`approve_wider` 只是多一个枚举值，壳照常把按钮的回答发回去。别的卡片没有 `approve_wider`，回答它得到 400 `invalid_input`。

- 一条授权是（Bot，路径）。覆盖这个文件夹和它下面已有的、以后才有的子文件夹。按路径分段比较，`music/a` 不覆盖 `music/ab`。
- 授权跟着 Bot：新装的 Bot 不继承，Bot 或插件被删、被卸载（保留数据也算）时一起清掉，升级时保留。
- 授权按名字记。主人把文件夹改名或删了，授权不跟着走；Bot 再存时按子目录的规则建回来。
- 已授权也改变不了的：只新增，不覆盖；Bot 没有删除、移动和读取的工具；`.` 开头的名字一律拒绝。

### 主人在哪里看和撤销

Bot 所在插件的详情页列出已授权的路径，能撤销。撤销只拦后面的调用，已经开始放的文件不撤回。

| 接口 | 作用 |
| --- | --- |
| `GET /_wonton/api/plugins/{id}` | `PluginDetail` 多一个 `save_grants`：已授权的路径 |
| `DELETE /_wonton/api/plugins/{id}/save-grants?folder=` | 撤销一条授权 |
| `POST /_wonton/confirmations/{id}` | 多接受 `approve_wider` |

撤销和回答卡片都和管理接口（ADR-0017）是同一道门，Agent 和插件都做不到。授权按插件存在核心的数据目录里（权限 0600，插件访问不到），读不出来时当作没有授权，回到发卡片，写明错误日志，不覆盖这个文件。

### 审计

每次保存写一行：调用方、目标、每个文件的名字、大小和 SHA-256；经卡片批准的同时写下给了哪个路径，已授权的写下命中的路径。撤销也写一行。

### 和 ADR-0024 的关系

取代 ADR-0024 判定的第 1 步“核心自己的工具，敏感的每次发卡片”。改成：`wonton__save_file` 先看已授权的路径，没命中才发卡片；其余核心敏感工具（安装、卸载）每次发卡片（Bot 更新自己写的插件、权限没变宽时不发，见 ADR-0033）。卡片上没有“30 分钟内都允许”。

“一律允许”“始终允许”和“标成只读”对这个工具不适用，设置接口照旧拒绝核心工具。

### 接口和落地

`Answer` 多 `approve_wider`，`PluginDetail` 多 `save_grants`，这是跨端接口，先单独提接口的 PR（AGENTS.md）。旧 App 不认识的按钮不显示（ADR-0016），`approve` 照常能用。

## 理由

- 授权都在核心判定，确认由核心发、核心验证。提示注入能让 Bot 发起保存，打开不了授权。
- 授权只能添加，所以一直有效的代价有上限：最坏是文件夹里多了不想要的文件，原有的文件不会丢。
- 只有一种授权，卡片协议只多一个枚举值，壳不用改，主人也不用选“多久”。

## 没选的做法

- **给 Hermes 挂 `:write`。** 不用改核心，但没有卡片，Bot 能随时改删整个文件夹。
- **文件搜索插件加写工具。** 卡片现成，但字节过不去：Hermes 容器里的文件到不了插件容器。让它自己下载，就要同时有全部文件夹的读写和 `network.egress`，能把文件往外发。
- **单独的下载插件。** 只能抓能直链下载的 URL，Bot 处理过的文件存不了，写权限也是装插件时一次给。
- **Bot 经 HTTP 上传（复用 tus）。** 要给插件网络开上传接口，Agent 还要带客户端。两边在同一台机器上，用不着续传。
- **核心按 URL 下载。** 核心不该替插件访问任意地址，也带不了登录态和 yt-dlp 这类工具。
- **“存这一次”“30 分钟内都允许”“所有共享文件夹”。** 第一稿有，主人看过后去掉了：路径授权够用，选项多了反而麻烦。
- **“一律允许”也包含存文件。** 同上，只有一种授权。
- **存完登记成文件编号，Bot 接着分享。** 要核对来源插件的授权（ADR-0020），Bot 没有这种授权，单为它开一条路不值。文件搜索插件能找到它。
- **卡片上做目录选择器。** 要在卡片里列目录，壳要多一套界面。两个按钮够用。
- **按文件类型授权**（`music` 只收音频）。扩展名能造假，核心不判断内容。
- **授权后每次存都发通知。** 主人要的就是不被打扰。
- **给每条授权设配额。** 只靠 5% 空闲保底。先看实际有没有这个问题。

## 代价与风险

- 授权后，提示注入能让 Bot 不经确认往这个路径里放文件。路径连着自动处理的插件时风险更大：Syncthing 会同步到别的设备，Paperless 这类插件可能自动导入。
- 只有 5% 空闲保底，Bot 能把磁盘写到那条线。
- 大文件要复制进暂存再放：等确认期间占双份空间，跨卷时再复制一次。
- 授权后主人看不到每个文件，只有审计文件，App 里没有审计页面（同 ADR-0024）。
- Bot 怎么拿到文件（下载、转码）在它自己的容器里，不经核心，也不进审计（#193）。卡片和审计只看存进去的结果。

## 实测

2026-11-04，核心 feat/save-file-core，真实模型，`deploy/dev/core/smoke.sh`：

- Navidrome 0.64.2 约 15 秒发现核心放进 `music` 的文件，不用开定时扫描。
- Hermes v0.22.5 在 `/opt/data` 下再挂一层 outbox 能正常读写。Hermes 下载一首真实的歌，存进 `music/冒烟`，Navidrome 搜得到。
- 批准一次后子文件夹不再问；撤销后重新发卡片；选“整个共享文件夹”后授权变成 `music`。
