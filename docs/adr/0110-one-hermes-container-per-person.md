# ADR-0110 一人一个 Hermes 容器：同一个人的多个 Bot 是容器里的 profile，由核心的 Bot 管理增删

- 状态：提议（2026-11-20）。方向“一人一容器多 Bot”由主人定，未决问题见文末
- 修订：[ADR-0108](0108-hermes-default-kernel.md) 第 1 节“私人 Bot 之间保持独立容器”；[ADR-0045](0045-family-members.md) 的“每个 Bot 一组容器”、
  私人 Bot 的命名、“名单变了核心重建这个 Bot 的服务”和 `WONTON_MATRIX_ALLOWED_USERS` 的注入方式；[ADR-0044](0044-bot-profile-and-status-avatars.md)
  按插件改资料的接口（改成按 Bot），资料加简介和角色两项

## 背景

主人要每个人能有好几个私人 Bot（管家、记账、健身教练……），每个 Bot 有自己的 Matrix 账号、名字、头像、简介和角色，
权限按 Bot 给；同一个人的这些 Bot 放在他自己的一个 Hermes 容器里，一个进程跑多个 profile；家人之间仍然分容器。

ADR-0108 让每个私人 Bot 独占一组容器（插件规范 `bots.services`：每个 Bot 一组 init、gateway、web）。一组的底价约 450 MiB，
一个人开五个 Bot 就是五份底价。

上游 Hermes v0.22.7 自带多路复用网关（`gateway.multiplex_profiles`，上游默认打开）：一个 gateway 进程服务默认 profile
和 `profiles/` 下的每个 profile，每个 profile 有自己的 `.env`（凭据范围）、平台适配器、会话、记忆和 SOUL，增删 profile
经控制套接字热加载（上游文档 `website/docs/user-guide/multi-profile-gateways.md`）。上游 Bot Mode 里“一个 Bot 就是一个
profile”，名字、标题和头像存在 profile 的 `profile.yaml`（`display_name`、`description`、`ui_meta['hermes-bots']`），
人设在 `SOUL.md`（`bot-mode.md`、`which-file-does-what.md`）。

2026-11-19 在真实栈上测过这条路（见“验证结果”）。能用，但有几处硬约束：

- 同一个 Bot 账号只能有一个加密客户端。Bot 自己的容器先登录过、上传过设备密钥，多路复用器再为它建客户端，消息就解不开。
- 核心给每个 Bot 起独立容器的流程、改插件访问开关后整插件重建，都会把 Bot 自己的容器再拉起来，和多路复用器抢同一个账号。
- 核心注入容器进程环境的 `MATRIX_ALLOWED_USERS` 压过 profile `.env` 里的同名项，profile 自己的名单不生效。
- 核心按插件找“默认 Bot”回答身份工具（`bot_profile.rs` 的 `profile_bot`），同一插件里所有 Bot 读写的是同一份资料。

## 决策

### 1. 容器按归属人分

- 一个 Agent 插件里，**每个归属人一组容器**：主人、每个家人各一组，装他自己的全部私人 Bot；共享 Bot（归属 `household`）另一组。
  不同的人永远不在同一组。
- 一组里一个 Hermes 多路复用进程。**一个 Bot 就是一个具名 profile**，profile 名就是核心的 Bot 名（核心的 Bot 名规则是
  Hermes profile 名规则的子集）。
- **默认 profile 只当宿主，不承载 Bot**：没有 Matrix 账号，不收消息。这样每个 Bot 都能同样地增删，容器的进程环境里也没有任何
  一个 Bot 的值（第 5 节）。
- 插件规范删掉“每个 Bot 一组容器”。插件的 `bots` 改为“每个归属人一组服务，加三条 Bot 命令”（第 2 节）。
- profile 不是安全隔离（ADR-0108 第 1 节照旧）：一组容器里的数据都属于同一个人，信任边界是归属人，不是 Bot。

### 2. Bot 的增删改由核心发起，插件在容器里执行

核心管 Bot 的记录、Matrix 账号、令牌和权限；Hermes 的文件只由插件写。两者之间是插件声明的三条命令，形状同模型网关的凭据命令：
核心经 Docker exec 在这个归属人的容器里执行，参数里只有 Bot 名，变量和身份以 JSON 走标准输入，退出码 0 才算成功，
其余如实报“上游出错”并带标准错误。

| 命令 | 核心什么时候调 | 插件做什么（Hermes 插件） |
| --- | --- | --- |
| 加 Bot | 新建 Bot；容器每次启动后对每条 Bot 记录重放一次 | `hermes profile create <名> --clone --no-alias`；写 `profiles/<名>/.env`；写身份（第 4 节）和工具集（第 6 节）。已存在时只覆盖这些，不报错 |
| 改 Bot | 这个 Bot 的变量、身份或 AI 动手级别变了 | 改写上面这些，只让这一个 profile 重新加载（先解挂再重扫），别的 profile 和容器不动 |
| 删 Bot | 删除 Bot | `hermes profile delete <名> --yes`：停掉它的适配器、删掉它的数据 |

**新建一个 Bot：**

1. 核心查权限和上限（未决问题 2），在 ADR-0045 的分配锁里定 Bot 名和 Matrix 用户名，建 Matrix 账号，写初始资料（第 4 节）。
2. 核心为它签发**唯一的**访问令牌（第 3 节），生成总线令牌，存进 Bot 记录。
3. 这个归属人没有容器组时，核心按安装的路径建好并启动（只带归属人级的变量）。
4. 核心调“加 Bot”。Hermes 热加载这个 profile，多路复用器为它建 Matrix 客户端。
5. 核心等它就绪（第 7 节），照 ADR-0045 交出主房间。

哪一步失败就报哪一步和类别（权限缺失、超出上限、插件未就绪、上游出错、输入非法），不显示成已建好；已建的 Matrix 账号和记录
按 ADR-0045 的规则保留或清理。

**删除一个 Bot：** 核心先调“删 Bot”，等它的适配器停下，再吊销它的访问令牌、总线令牌和模型凭据；不保留数据时停用 Matrix 账号。
先停后吊销，适配器不会拿着失效令牌一直重试。别的 Bot 不断线，容器不重启。归属人的最后一个 Bot 删掉后，核心删掉这组容器。
“保留数据”怎么做见未决问题 5。

**容器重建**（插件升级、改插件设置、核心按 ADR-0105 恢复）会让这个人的所有 Bot 一起断开再重连。重启后核心对每条记录重放
“加 Bot”，所以 profile 目录丢了 `.env`、记录有而 profile 没有，都在这一步补齐；profile 有而记录没有的不服务，如实报出。

### 3. Matrix 账号和唯一的加密设备

- **账号由核心建、核心持有记录**，用户名规则同 ADR-0045。Bot 名由核心生成，在插件里唯一、建后不改（未决问题 7）；人看到的是资料里的名字。
- **每个 Bot 只有一个加密设备，它的密钥第一次、也是唯一一次由多路复用器上传。** 核心代登录签发一个访问令牌（得到设备 D，
  核心自己不上传任何密钥），只写进这个 Bot 的 profile；没有别的进程拿到它。核心为写资料、交房间临时登录的设备不上传密钥，
  用完立刻退出（ADR-0044 的做法）。
- **网关兜住这条约束**：Bot 经 `matrix.wonton.internal` 上传设备密钥（`/keys/upload`）时，只放行 Bot 记录里那台设备，
  别的设备回 403。“每个 Bot 一个容器”删掉后不会再有第二个客户端，这一条防的是实现走样。

### 4. 身份：单一来源是 Bot 的 Matrix 资料

| 项 | 存在哪 |
| --- | --- |
| 名字 | `displayname`（ADR-0044） |
| 头像 | `avatar_url`；状态头像 `app.wonton.avatars`（ADR-0044） |
| 简介 | MSC4133 扩展资料字段 `app.wonton.bio` |
| 角色 | MSC4133 扩展资料字段 `app.wonton.role`：这个 Bot 管什么，一句话（如“记账”）。和 ADR-0088 分给人的角色不是一回事 |

- 写入口有三个：App 经核心的按 Bot 资料接口；Agent 经 `wonton__set_profile`；Bot 用自己的令牌直接写 Matrix（ADR-0044 允许）。
  前两个经核心，第三个经核心的 Matrix 网关。任何一次写成功后，核心调“改 Bot”，把新身份交给插件。
- 方向只有一个：Matrix 资料 → Hermes profile。Hermes 插件把名字写进 `profile.yaml` 的 `display_name`，简介写 `description`，
  角色写 `ui_meta['hermes-bots'].title`，头像写 profile 的头像资产，并更新 `SOUL.md` 里的身份（怎么写不覆盖用户自己的人设，
  见未决问题 4）。在 Hermes 自己的网页里改这几项，下一次同步会被覆盖，插件说明写明。
- Matrix 写成功、同步到 Hermes 失败时，Bot 显示“资料没同步到 Bot”并能重试，不当成已改好。

### 5. 每个 Bot 的变量只进它自己的 profile

- **容器进程环境只放归属人级的值**：归属人、AI 动手上限（`WONTON_BOT_AI_LEVEL`）、私人空间和共享文件夹的挂载、主人身份、语言。
  不放任何 `WONTON_MATRIX_*`、`WONTON_MCP_URL` 和模型凭据。
- **每个 Bot 的值只经“加 Bot”“改 Bot”写进它的 `.env`**：主服务器、用户 ID、访问令牌、听谁的名单（`MATRIX_ALLOWED_USERS`）、
  主房间、总线地址（带它自己的总线令牌）、模型凭据。进程环境里没有同名变量，上游按“profile 的 `.env` → 它的 `config.yaml`
  → 适配器默认值”取，名单按 profile 生效（待验证 7）。
- 名单的内容照 ADR-0045、ADR-0083（归属人、联系人、房间表）。名单变了核心调“改 Bot”，只重新加载这一个 profile，不重建服务。

### 6. 权限按 Bot

- **总线**：每个 Bot 一个总线令牌（ADR-0045）。所有“调用方自己”的核心工具（`wonton__get_profile`、`wonton__set_profile` 等）
  **按令牌认出的 Bot 取**，不再取插件的默认 Bot。
- **插件访问开关、ADR-0024 的始终允许、一律允许、放行时段，ADR-0091 的危险模式**都按 Bot 记。改它们只改核心的判定和这个 Bot 的
  工具列表（通知它重新取），**不重建、不重启任何容器**。
- **Agent 自带的工具**：每个 Bot 一个 AI 动手级别，不高于归属人角色的上限（ADR-0088 第 5 节），经“加 Bot”“改 Bot”交给插件。
  Hermes 插件把它落到这个 profile 的 `platform_toolsets`：级别不给的工具集不装配，模型看不到这个工具。更细的工具集在 Hermes
  自己的网页里按 profile 改。
- 同一个容器里的 Bot 互相读得到对方的文件和令牌，按 Bot 给的高权限对同组的其他 Bot 并不封闭，见未决问题 1。

### 7. 就绪和状态

- **一个 Bot 就绪** = “加 Bot”退出码 0，且核心的 Matrix 网关看到这个 Bot 的令牌在 `/sync`。判据只看 Matrix，不看插件内部。
- **容器健康** = 多路复用进程活着，不再看某一个 Bot 的 Matrix 连接。
- Bot 的状态如实给：建中、就绪、断开、资料没同步、删除中；ADR-0044 的运行状态照旧按 Bot 算。

### 8. 不在本篇

- 同一容器的 Bot 经上游 Bot Chat、`message_agent` 直接互发，以及“讨论模式”：不开放，另写 ADR。Bot 之间经 Matrix 互发照旧走
  ADR-0045 的联系人、频率和跳数。插件不建名为“Bot Chat”的会话。
- 模型接入照 ADR-0108：新 Bot 从同一容器的宿主 profile 复制模型配置，之后各自可改。

## 理由

- **省内存**：底价按人算，不按 Bot 算。实测多挂两个空闲 profile 只多约 10 MiB。
- **上游原生**：多路复用是上游默认的形态，“Bot 就是 profile”是上游自己的概念，不打补丁，符合 ADR-0108 第 7 条。
- **边界和信任一致**：profile 不隔离，所以只让同一个人的 Bot 同住；不同人之间仍是容器边界，ADR-0088 第 7 节“谁的都看不到”不受影响。
- **核心不知道 Hermes 的文件**：核心只调插件声明的三条命令（ADR-0015），换一个支持多 Bot 的 Agent 插件，核心不用改。
  三条命令沿用模型网关凭据命令的形状：结果同步回来，失败就能如实报，不需要容器里再常驻一个同步进程。
- **身份以 Matrix 为源**：所有客户端看到的就是 Matrix 资料，Agent 也能用自己的令牌写（ADR-0044）；核心本来就经网关看得到每一次写。

## 没选的做法

- **每个 Bot 一组容器（ADR-0108 的原样）**：底价乘以 Bot 数；还要保证 Bot 自己的容器和任何其他客户端永远不碰同一个账号。
- **一个容器装全家**：任何一个能用终端的 Bot 都读得到别人的令牌、记忆和聊天记录，违反 ADR-0088 第 7 节；每个人的私人空间、
  只读挂载和 AI 动手上限不同，放不进同一组挂载；一次重启全家的 Bot 都断。
- **核心直接写 Hermes 的文件**（`.env`、`profile.yaml`、`SOUL.md`）：核心为 Hermes 做特殊处理，上游改目录结构就坏。
- **容器里常驻一个进程盯着核心写的目录**：结果是异步的，要另造状态回报，还多一个进程。
- **进程环境注入、profile `.env` 覆盖**：实测 `.env` 压不过进程环境里的同名变量。
- **身份以核心记录或 Hermes profile 为源**：以核心为源要把 Matrix 上的改动反向同步回来；以 Hermes 为源要核心去读 Hermes 的文件。

## 代价与风险

- 一个人的 Bot 同进同出：容器重建或进程崩溃，他的所有 Bot 一起断开重连（实测重启 13 秒）。
- 同组的 Bot 之间没有隔离：能用终端或文件工具的 Bot 读得到同组其他 Bot 的 `.env`（含访问令牌和总线令牌）、记忆和历史。
- 内存共用一个容器上限：实测跑一轮后内存不回收，一个忙的 Bot 能把容器挤到上限，连累同组的 Bot。
- 热增删依赖上游的控制套接字和重扫行为。实测挪走 profile 目录会被重扫重建、并丢掉 `.env`；升级上游要重跑这部分冒烟。
- 每 Bot 网页（ADR-0045）打开的是这组容器的 Hermes 网页，里面是这个人的全部 profile；能打开其中一个 Bot 网页的人，可能看到同组的其他 Bot（待验证 10）。

## 要改的组件

**核心**

- 身份工具按令牌取 Bot：先行修复，单独一个小 PR 先合。
- Bot 的部署按归属人分容器组；删掉每个 Bot 一组容器的部署，以及名单变化时重建 Bot 服务的路径。
- Bot 管理接口：列出某人的 Bot、建私人 Bot、删 Bot、按 Bot 改资料；谁能做照 ADR-0088。
- 执行插件声明的三条 Bot 命令，容器每次启动后重放“加 Bot”。
- Matrix 网关：只放行记录设备上传密钥；以 `/sync` 判就绪；资料写成功后触发同步。
- 插件访问开关等策略改动不碰容器：查清实测里改开关后整插件重建的来源并去掉。
- 容器进程环境只放归属人级的变量。

**协议**（`wonton-protocol`）

- 资料加简介、角色；资料接口改成按 Bot（带 Bot 名）。
- 建、删 Bot 的请求和响应，错误类别（权限缺失、超出上限、插件不支持多 Bot、插件未就绪、上游出错）。
- Bot 的视图带第 7 节的状态和 AI 动手级别。

**插件规范**（wonton-docs）

- `bots` 改成“每个归属人一组服务”加三条 Bot 命令：参数、标准输入的字段、退出码、“加 Bot”必须幂等；删掉每个 Bot 一组服务。
- 扩展资料字段 `app.wonton.bio`、`app.wonton.role`；收存密钥、outbox 和 ADR-0054 命令表按 Bot 的位置。

**Hermes 插件**

- compose 改成一个多路复用 gateway，默认 profile 只当宿主；gateway 服务的环境里去掉 `MATRIX_*` 和 `WONTON_MCP_URL`；健康检查改看进程。
- 三条命令的胶水：建删 profile、写 `.env`、把身份写进 `profile.yaml`、`ui_meta`、头像和 `SOUL.md`、按级别写 `platform_toolsets`、只重新加载一个 profile。
- 恢复密钥、outbox、ADR-0054 的命令表按 profile 分开写。

**App**

- Bot 管理：我的 Bot 列表、新建（名字、头像、简介、角色）、删除（写明后果）、改资料、按 Bot 的插件访问和 AI 动手级别。
- 状态如实显示第 7 节那几种，失败给重试；界面走 ADR-0026。

## 验证结果（2026-11-19，194 号机，Tuwunel 2.0.0，`nousresearch/hermes-agent:v0.22.7` 按摘要固定，未改上游）

| 项 | 结果 |
| --- | --- |
| 每个 profile 用自己 `.env` 的总线令牌 | 是：B 的真实 Matrix 轮次 41 次请求全部带 B 的令牌，0 次带 A 的 |
| 身份工具按令牌取 Bot | 否：A、B、C 的 `wonton__get_profile` 都返回默认 Bot（`profile_bot` 固定取默认 Bot） |
| 按 profile 限工具 | 是：B 的 `platform_toolsets.matrix` 去掉 `terminal`、`file` 后，B 的轮次里没有这些工具；同进程的 A 照常执行 `ls /` |
| 插件访问开关按 Bot 生效 | 是：关掉后只有这个 Bot 的工具列表变；但改开关后核心重建了整个插件，把各 Bot 的独立容器又拉了起来 |
| 内存 | 3 个空闲 profile 451.8 MiB；跑一轮（容器里的 `hermes -z` 子进程）后 585–641 MiB，卸掉 profile 不回落 |
| 热增删 | `hermes profile create` 不到 5 秒被服务；`hermes profile delete` 不到 5 秒下线；期间其他 Bot 不断线 |
| 重启 | `docker restart` 到健康 13 秒，所有 Bot 断开重连；没有 profile 目录的 Bot 重启后丢失 |
| 挪走 profile 目录 | 不算删：重扫会重建目录，且重建出的 profile 没有 `.env` |
| 设备密钥 | Bot 先由自己的容器登录过，多路复用器再建客户端后，新消息解不开；记录指向多路复用器那台设备并新建房间后正常 |
| `MATRIX_ALLOWED_USERS` | profile `.env` 里的值不生效，进程环境里核心注入的同名变量优先 |
| `message_agent`、bot-chat 定时投递 | 无头下可用，输出落在目标 profile，不串号（本篇不开放，见第 8 节） |

## 待验证

1. 一个人建三个 Bot：只有一组容器，三个 profile 都被服务；建第二、三个时，第一个不断线，容器启动时间不变。
2. 每个 Bot 账号里有设备密钥的设备只有一台，等于记录的设备；主人 App 和每个 Bot 加密收发正常；别的设备上传密钥被网关 403。
3. 删掉一个 Bot：5 秒内不再被服务，它的令牌失效，其他 Bot 照常收发，容器不重启。

## 未决问题

1. **同组 Bot 不隔离，按 Bot 给的高权限怎么办。** 能用终端的 Bot 读得到同组 Bot 的总线令牌，冒用它的危险模式、一律允许或
   别人给它的档位。A：照“安全别过度”，开这些时醒目写明“同一个人的其他 Bot 也能借用”；B：开危险模式或给别人用（ADR-0083
   高于“只聊天”）的 Bot 单独一组容器，其余按 A；C：同组里只要有一个 Bot 开了这些，其余 Bot 的 AI 动手级别不给终端和文件。推荐 B。
2. **一个人能开几个 Bot，容器内存上限多少。** 依据：底价约 450 MiB 按容器算；空闲 profile 每个几 MiB；跑一轮涨 130–190 MiB
   且不回收（子进程的数字，进程内待测）。A：角色加权限项“私人 Bot 个数”，主人不限，模板默认给个小数；B：核心按主机可用内存算，
   每组容器底价加每 Bot 预留，不够就如实拒；C：不限个数，只按 Bot 数加大容器上限。推荐 A 加 B，具体数字等进程内实测后定。
3. **身份同步失败时 App 显示哪一边。** A：显示 Matrix 资料（来源），另标“没同步到 Bot”；B：显示 Bot 实际在用的。推荐 A。
4. **`SOUL.md` 怎么写。** A：核心身份里加“人设”全文，整个文件按身份重写；B：只在建 Bot 时写一次，之后由插件每轮把身份注入提示；
   C：文件开头一段由插件管理（标记包住），其余留给用户和 Hermes。推荐 C。
5. **删 Bot 时“保留数据”。** A：不提供，删就删 profile（Matrix 账号可留）；B：用上游的停服标记让 profile 留在磁盘、不被服务，
