# ADR-0110 同一个人的多个 Bot 默认共用他的一个 Hermes 容器，也可单独运行；Bot 由核心统一管理

- 状态：已接受（主人 2026-11-20 定运行方式和个数，其余按推荐批），取舍见“已定”；2026-11-26 部分修订（[ADR-0122](0122-primary-agent-and-profiles.md)）：主 Agent、profile 与辅助对话的身份模型，运行方式和容器边界不变
- 修订：[ADR-0108](0108-hermes-default-kernel.md) 第 1 节“私人 Bot 之间保持独立容器”；[ADR-0045](0045-family-members.md) 的“每个 Bot 一组容器”、
  私人 Bot 的命名、“名单变了核心重建这个 Bot 的服务”和 `WONTON_MATRIX_ALLOWED_USERS` 的注入方式；[ADR-0044](0044-bot-profile-and-status-avatars.md)
  按插件改资料的接口（改成按 Bot），资料加简介和角色两项

## 背景

主人要每个人能有好几个私人 Bot（管家、记账、健身教练……），每个 Bot 有自己的 Matrix 账号、名字、头像、简介和角色，
权限按 Bot 给；同一个人的这些 Bot 放在他自己的一个 Hermes 容器里，一个进程跑多个 profile；家人之间仍然分容器。

ADR-0108 让每个私人 Bot 独占一组容器（插件规范 `bots.services`：每个 Bot 一组 init、gateway、web）。一组容器有约 620 MiB
的固定底价（见“验证结果”），一个人开五个 Bot 就是五份底价。

上游 Hermes v0.22.7 自带多路复用网关（`gateway.multiplex_profiles`，上游默认打开）：一个 gateway 进程服务默认 profile
和 `profiles/` 下的每个 profile，每个 profile 有自己的 `.env`（凭据范围）、平台适配器、会话、记忆和 SOUL，增删 profile
经控制套接字热加载（上游文档 `website/docs/user-guide/multi-profile-gateways.md`）。上游 Bot Mode 里“一个 Bot 就是一个
profile”，名字、标题和头像存在 profile 的 `profile.yaml`（`display_name`、`description`、`ui_meta['hermes-bots']`），
人设在 `SOUL.md`（`bot-mode.md`、`which-file-does-what.md`）。

2026-11-19 在真实栈上测过这条路（见“验证结果”）。能用，但有几处硬约束：

- 同一个 Bot 账号只能有一个加密客户端。Bot 自己的容器先登录过、上传过设备密钥，多路复用器再为它建客户端，消息就解不开。
- 核心给每个 Bot 起独立容器的流程、改插件访问开关后整插件重建，都会把 Bot 自己的容器再拉起来，和多路复用器抢同一个账号。
- 核心注入容器进程环境的 `MATRIX_ALLOWED_USERS` 压过 profile `.env` 里的同名项，profile 自己的名单不生效。
- 核心按插件找“默认 Bot”回答身份工具（`bot_profile.rs` 的 `profile_bot`），同一插件里所有 Bot 读写的是同一份资料。

## 决策

### 1. 运行组：每人一个共用组，加上若干单独运行的组

- 一个 Agent 插件里，Bot 按**运行组**部署，一组是一组容器、一个 Hermes 多路复用进程。每个归属人有一个**共用组**，
  他选“和我的其他 Bot 一起运行”的 Bot 都在里面；选“单独运行”的 Bot 各占一个**单独组**。共享 Bot（归属 `household`）
  同样有自己的共用组和单独组。不同归属人的 Bot 永远不在同一组。
- 建 Bot 和改 Bot 时都能选这两种，默认“和我的其他 Bot 一起运行”。改选项就是第 2 节的“换组”。
- **一个 Bot 就是一个具名 profile**，profile 名就是核心的 Bot 名（核心的 Bot 名规则是 Hermes profile 名规则的子集）。
- **默认 profile 只当宿主，不承载 Bot**：没有 Matrix 账号，不收消息。每个 Bot 都能同样地增删、换组，容器的进程环境里也没有任何
  一个 Bot 的值（第 5 节）。
- 主 Agent 是这个人的第一个非默认 profile；默认 profile 仍只当宿主（ADR-0122）。
- 插件规范删掉“每个 Bot 一组容器”。插件的 `bots` 改为“每个运行组一组服务，加四条 Bot 命令”（第 2 节）。
- profile 不是安全隔离（ADR-0108 第 1 节照旧）：同组的数据都属于同一个人，信任边界是归属人；想让某个 Bot 和自己的其他 Bot 隔开，
  就让它单独运行（第 6 节）。
- **内存上限是固定底价加每 Bot 少量**：一组容器的内存上限 = 插件声明的底价 + 每个 Bot 的增量 × 组里的 Bot 数。实测一组的
  占用约 620 MiB，几乎全是底价（网关进程约 370 MiB，同容器的 Hermes 网页进程约 190 MiB），每多一个 Bot、每多跑几轮只多几 MiB；
  上限低于底价时网关起不来（见“验证结果”）。两个值写在插件清单里，按实测定。
- **单独运行的每一组都要付一份底价**。用户选“单独运行”时，核心给出这一组要多占的内存，作为提示的依据（文字在壳里）。
- Bot 数不设上限，也没有“私人 Bot 个数”这项权限。加 Bot 前核心按 ADR-0045 的“内存不够时如实说”核对主机内存，不够就报
  “主机内存不够”，不建，不压低别的组的上限，也不把 Bot 塞进已满的组。

### 2. Bot 的增删改由核心发起，插件在容器里执行

核心管 Bot 的记录、Matrix 账号、令牌和权限；Hermes 的文件只由插件写。两者之间是插件声明的四条命令，形状同模型网关的凭据命令：
核心经 Docker exec 在 Bot 所在组的容器里执行，参数里只有 Bot 名，变量和身份以 JSON 走标准输入，退出码 0 才算成功，
其余如实报“上游出错”并带标准错误。

| 命令 | 核心什么时候调 | 插件做什么（Hermes 插件） |
| --- | --- | --- |
| 加 Bot | 新建 Bot；换组时在新组；恢复停用的 Bot；容器每次启动后对组里每条没停用的记录重放一次 | `hermes profile create <名> --clone --no-alias`（目录已在时跳过）；写 `profiles/<名>/.env`；写身份（第 4 节）和工具集（第 6 节）；有停用标记就删掉，再热服务（`serve-profile`）。已存在时只覆盖这些，不报错 |
| 改 Bot | 这个 Bot 的变量、身份或 AI 动手级别变了 | 改写上面这些，只让这一个 profile 重新加载（先解挂再重扫），别的 profile 和容器不动 |
| 停 Bot | 换组前；删 Bot 且保留数据 | 写停用标记 `profiles/<名>/gateway.parked`，再解挂（`unserve-profile`）：适配器停下，重扫和重启都不再拉起，目录留在磁盘。不用 `hermes -p <名> gateway stop`：在多路复用器里它停的是整个网关 |
| 删 Bot | 删 Bot 且不留数据；换组时在旧组 | `hermes profile delete <名> --yes`：停掉它的适配器、删掉它的数据 |

只解挂不写标记不算停用：上游的目录监视 19–35 秒后会把它重新拉起。

插件还在清单里声明一个 Bot 的数据在组数据目录下的位置（Hermes 是 `profiles/{bot}`），核心换组时整个搬，不看里面的内容。
同一个插件的所有组用同一个容器用户（`PUID`、`PGID`）：搬过去的文件属主不对，上游镜像的入口直接退出。

**新建一个 Bot：**

1. 核心查权限，在 ADR-0045 的分配锁里定 Bot 名和 Matrix 用户名，建 Matrix 账号，写初始资料（第 4 节）。
2. 核心为它签发**唯一的**访问令牌（第 3 节），生成总线令牌，存进 Bot 记录。
3. 目标组（共用组或新的单独组）没有容器时，核心按安装的路径建好并启动，只带归属人级的变量；有容器时核对主机内存后在线调高
   它的内存上限，不重启。
4. 核心调“加 Bot”。Hermes 热加载这个 profile，多路复用器为它建 Matrix 客户端。
5. 核心等它就绪（第 7 节），照 ADR-0045 交出主房间。

哪一步失败就报哪一步和类别（权限缺失、主机内存不够、插件未就绪、上游出错、输入非法），不显示成已建好；已建的 Matrix 账号和记录
按 ADR-0045 的规则保留或清理。

**删除一个 Bot：** 核心先调“删 Bot”（不留数据）或“停 Bot”（保留数据），等它的适配器停下，再吊销它的访问令牌、总线令牌和
模型凭据；不留数据时停用 Matrix 账号。先停后吊销，适配器不会拿着失效令牌一直重试。别的 Bot 不断线，容器不重启，内存上限
在线调低。一组的最后一个 Bot 删掉后，核心删掉这组容器；只剩停用 Bot 的组照样删容器，数据目录留着。

**换组**（一起运行 ↔ 单独运行）：同一台设备、同一份加密存储整个搬过去，不是新的登录：

1. 核心把 Bot 标成“换组中”，在旧组调“停 Bot”，直到核心的 Matrix 网关看不到这个令牌的 `/sync`。
2. 核心把插件声明的这个 Bot 的数据目录（含 Matrix 的加密存储和停用标记）复制两份：一份进新组，带着停用标记，新组不会抢先服务它；
   一份是回滚用的副本，放在任何一组的 `profiles/` 之外。新组没有容器就先建（同新建第 3 步）。
3. 核心在旧组调“删 Bot”。重扫只加不删，目录没了旧组也不会再把它建出来。
4. 核心在新组调“加 Bot”，删掉停用标记，多路复用器用原来的设备和密钥恢复客户端；等它就绪，删掉回滚副本，两组的内存上限各自在线调整。
5. 第 4 步失败时，核心删掉新组里的目录，用回滚副本放回旧组、在旧组调“加 Bot”，Bot 回到原组并如实报出换组失败。

任何时候 `profiles/` 下只有一份这个 Bot 的目录：留在 `profiles/` 下的备份会被当成另一个 profile 拉起，和正式的那个抢同一个账号。

**容器重建**（插件升级、改插件设置、核心按 ADR-0105 恢复）会让这一组的所有 Bot 一起断开再重连，别的组不受影响。重启后核心对
组里每条记录重放“加 Bot”（停用的除外），所以 profile 目录丢了 `.env`、记录有而 profile 没有，都在这一步补齐；
profile 有而记录没有的不服务，如实报出。

### 3. Matrix 账号和唯一的加密设备

- **账号由核心建、核心持有记录**，用户名规则同 ADR-0045。Bot 名由核心生成：归属人的用户名，第二个起加序号（`alice`、`alice-2`），
  在插件里唯一、建后不改，Matrix 用户名照旧是 `<插件 id 最后一段>-<Bot 名>`。人看到的是资料里的名字。
- **每个 Bot 只有一个加密设备，它的密钥第一次、也是唯一一次由多路复用器上传。** 核心代登录签发一个访问令牌（得到设备 D，
  核心自己不上传任何密钥），只写进这个 Bot 的 profile；没有别的进程拿到它。核心为写资料、交房间临时登录的设备不上传密钥，
  用完立刻退出（ADR-0044 的做法）。换组搬的是同一台设备和它的加密存储，不产生新设备。
- **网关兜住这条约束**：Bot 经 `matrix.wonton.internal` 上传设备密钥（`/keys/upload`）时，只放行 Bot 记录里那台设备，
  别的设备回 403。

### 4. 身份：单一来源是 Bot 的 Matrix 资料

| 项 | 存在哪 |
| --- | --- |
| 名字 | `displayname`（ADR-0044） |
| 头像 | `avatar_url`；状态头像 `app.wonton.avatars`（ADR-0044） |
| 简介 | MSC4133 扩展资料字段 `app.wonton.bio` |
| 角色 | MSC4133 扩展资料字段 `app.wonton.role`：这个 Bot 管什么，一句话（如“记账”）。和 ADR-0088 分给人的角色不是一回事 |

- 写入口有三个：App 经核心的按 Bot 资料接口；Agent 经 `wonton__set_profile`；Bot 用自己的令牌直接写 Matrix（ADR-0044 允许）。
  前两个经核心，第三个经核心的 Matrix 网关。任何一次写成功后，核心调“改 Bot”，把新身份交给插件。
- 方向只有一个：Matrix 资料 → Hermes profile。Hermes 插件把名字写进 `profile.yaml` 的 `display_name`，简介写 `description`，
  角色写 `ui_meta['hermes-bots'].title`，头像写 profile 的头像资产。在 Hermes 自己的网页里改这几项，下一次同步会被覆盖，插件说明写明。
- **`SOUL.md` 插件只管文件顶部带标记的那一段**（名字、角色、简介），每次同步整段替换；标记外的内容属于用户和 Hermes，插件不读不改。
  标记段不在顶部或被删掉时，插件在顶部重新插入，不动其余内容。
- Matrix 写成功、同步到 Hermes 失败时，App 显示 Matrix 资料，并标“没同步到 Bot”，能重试，不当成已改好。

### 5. 每个 Bot 的变量只进它自己的 profile

- **容器进程环境只放归属人级的值**：归属人、AI 动手上限（`WONTON_BOT_AI_LEVEL`）、私人空间和共享文件夹的挂载、主人身份、语言。
  不放任何 `WONTON_MATRIX_*`、`WONTON_MCP_URL` 和模型凭据。
- **每个 Bot 的值只经“加 Bot”“改 Bot”写进它的 `.env`**：主服务器、用户 ID、访问令牌、听谁的名单（`MATRIX_ALLOWED_USERS`）、
  主房间、总线地址（带它自己的总线令牌）、模型凭据。进程环境里没有同名变量，上游按“profile 的 `.env` → 它的 `config.yaml`
  → 适配器默认值”取，名单按 profile 生效（待验证 7）。
- 名单的内容照 ADR-0045、ADR-0083（归属人、联系人、房间表）。名单变了核心调“改 Bot”，只重新加载这一个 profile，不重建服务。

### 6. 权限按 Bot

- **总线**：每个 Bot 一个总线令牌（ADR-0045）。所有“调用方自己”的核心工具（`wonton__get_profile`、`wonton__set_profile` 等）
  **按令牌认出的 Bot 取**，不再取插件的默认 Bot。
- **插件访问开关、ADR-0024 的始终允许、一律允许、放行时段，ADR-0091 的危险模式**都按 Bot 记。改它们只改核心的判定和这个 Bot 的
  工具列表（通知它重新取），**不重建、不重启任何容器**。
- **Agent 自带的工具**：每个 Bot 一个 AI 动手级别，不高于归属人角色的上限（ADR-0088 第 5 节），经“加 Bot”“改 Bot”交给插件。
  Hermes 插件把它落到这个 profile 的 `platform_toolsets`：级别不给的工具集不装配，模型看不到这个工具。更细的工具集在 Hermes
  自己的网页里按 profile 改。
- **同组不隔离，醒目写明，不强制**：Bot 和别的 Bot 一起运行时，打开危险模式、或按 ADR-0083 分享给别人且档位高于“只聊天”，
  核心在这一步给醒目提示“同组的其他 Bot 的令牌、记忆和记录它都读得到”，附“改成单独运行”的入口；用户可以照旧一起运行。
  提示由核心按 Bot 的运行方式和权限给出，壳不自己判断。

### 7. 就绪和状态

- **一个 Bot 就绪** = “加 Bot”退出码 0，且核心的 Matrix 网关看到这个 Bot 的令牌在 `/sync`。判据只看 Matrix，不看插件内部。
- **容器健康** = 多路复用进程活着，不再看某一个 Bot 的 Matrix 连接（只当宿主的默认 profile 没有 Matrix，按 Matrix 判就永远不健康）。
- **内存不够要认出来**：上限不够时容器一直是 running，网关进程被杀、被容器里的 s6 拉起、再被杀，Bot 只来得及放一个 👀，不回话、
  不报错。核心按容器的 OOM 事实（Docker 的 `oom` 事件、`OOMKilled`）认出这种循环，把这一组的 Bot 都标成“内存不够”，
  如实告诉归属人和主人，不自动调上限、不当成断线。
- **停用的 Bot 不会回应**：发给它的消息没有任何反应。核心在它的 Bot 视图给“已停用”，App 在和它的聊天、群成员里如实显示，
  不让人以为它在想。
- Bot 的状态如实给：建中、就绪、断开、资料没同步、换组中、已停用、内存不够、删除中；ADR-0044 的运行状态照旧按 Bot 算。

### 8. 不在本篇

- 同一容器的 Bot 经上游 Bot Chat、`message_agent` 直接互发，以及“讨论模式”：不开放，另写 ADR。Bot 之间经 Matrix 互发照旧走
  ADR-0045 的联系人、频率和跳数。插件不建名为“Bot Chat”的会话。
- 模型接入照 ADR-0108：新 Bot 从所在组的宿主 profile 复制模型配置，之后各自可改。
- 主 Agent、profile 与旁聊（辅助对话）的区别、profile 的创建和切换见 [ADR-0122](0122-primary-agent-and-profiles.md)。

## 理由

- **省内存**：一组约 620 MiB 几乎全是底价，多一个 Bot 只多几 MiB；一起运行的 Bot 只付一份底价。
- **上游原生**：多路复用是上游默认的形态，“Bot 就是 profile”是上游自己的概念，不打补丁，符合 ADR-0108 第 7 条。
- **边界和信任一致**：profile 不隔离，所以只让同一个人的 Bot 同住；不同人之间仍是容器边界，ADR-0088 第 7 节“谁的都看不到”不受影响。
  同一个人的 Bot 之间要不要隔开，由他自己按 Bot 选。
- **核心不知道 Hermes 的文件**：核心只调插件声明的命令、搬插件声明的目录（ADR-0015），换一个支持多 Bot 的 Agent 插件，核心不用改。
  命令沿用模型网关凭据命令的形状：结果同步回来，失败就能如实报，不需要容器里再常驻一个同步进程。
- **身份以 Matrix 为源**：所有客户端看到的就是 Matrix 资料，Agent 也能用自己的令牌写（ADR-0044）；核心本来就经网关看得到每一次写。

## 没选的做法

- **每个 Bot 一组容器（ADR-0108 的原样）**：底价乘以 Bot 数。需要隔离的 Bot 可以单独运行，不必让所有 Bot 都付这份钱。
- **一个容器装全家**：任何一个能用终端的 Bot 都读得到别人的令牌、记忆和聊天记录，违反 ADR-0088 第 7 节；每个人的私人空间、
  只读挂载和 AI 动手上限不同，放不进同一组挂载；一次重启全家的 Bot 都断。
- **高权限的 Bot 强制单独运行**：多数家庭里同一个人的 Bot 之间互相读得到无关紧要，强制分组只多占内存；写明风险、给出入口，由用户自己定。
- **限制每人的 Bot 个数**：真正的约束是主机内存，按内存核对、如实报错就够了，个数上限只是间接的估计。
- **核心直接写 Hermes 的文件**（`.env`、`profile.yaml`、`SOUL.md`）：核心为 Hermes 做特殊处理，上游改目录结构就坏。
- **容器里常驻一个进程盯着核心写的目录**：结果是异步的，要另造状态回报，还多一个进程。
- **进程环境注入、profile `.env` 覆盖**：实测 `.env` 压不过进程环境里的同名变量。
- **身份以核心记录或 Hermes profile 为源**：以核心为源要把 Matrix 上的改动反向同步回来；以 Hermes 为源要核心去读 Hermes 的文件。

## 代价与风险

- 同组的 Bot 同进同出：容器重建或进程崩溃，组里所有 Bot 一起断开重连（实测重启 13 秒）。
- 同组的 Bot 之间没有隔离：能用终端或文件工具的 Bot 读得到同组其他 Bot 的 `.env`（含访问令牌和总线令牌）、记忆和历史，
  也就能借用它们按 Bot 拿到的高权限。只有提示，没有强制。
- 内存共用一个容器上限：上限不够时整组的 Bot 一起反复被杀，不只是那个忙的 Bot。
- 单独运行的 Bot 每个都多付一份约 620 MiB 的底价。
- 换组要停这个 Bot 一会儿，搬加密存储出错会让它解不开消息；第 2 节的步骤保证任何时候只有一个组服务它。
- 停用的 Bot 不回应：不经 App 的 Matrix 客户端看不到“已停用”，只看到消息没人理。
- 热增删、停用依赖上游的控制套接字、目录监视和停用标记的行为。实测挪走 profile 目录会被重扫重建、并丢掉 `.env`；
  升级上游要重跑这部分冒烟。
- 每 Bot 网页（ADR-0045）打开的是这组容器的 Hermes 网页，里面是这组的全部 profile；能打开其中一个 Bot 网页的人，可能看到同组的其他 Bot（待验证 10）。

## 要改的组件

**核心**

- 身份工具按令牌取 Bot：先行修复，单独一个小 PR 先合。
- Bot 的部署按运行组分容器；删掉每个 Bot 一组容器的部署，以及名单变化时重建 Bot 服务的路径。
- Bot 管理接口：列出某人的 Bot、建私人 Bot、删 Bot（保留或不留数据）、按 Bot 改资料、改运行方式；谁能做照 ADR-0088。
- 执行插件声明的四条 Bot 命令，容器每次启动后重放“加 Bot”；换组的五步。
- 组的内存上限按“底价 + 每 Bot 增量”在线调整，加 Bot 前核对主机内存；选单独运行时给出要多占的底价。
- 认出组容器的 OOM 循环（`oom` 事件、`OOMKilled`），把这组的 Bot 标成“内存不够”并告诉归属人和主人。
- 换组的回滚副本放在所有组的 `profiles/` 之外；同一插件的各组用同一个 `PUID`、`PGID`。
- Matrix 网关：只放行记录设备上传密钥；以 `/sync` 判就绪和停下；资料写成功后触发同步。
- 插件访问开关等策略改动不碰容器：查清实测里改开关后整插件重建的来源并去掉。
- 容器进程环境只放归属人级的变量。
- 一起运行的 Bot 开危险模式或高档分享时给出第 6 节的提示。

**协议**（`wonton-protocol`）

- 资料加简介、角色；资料接口改成按 Bot（带 Bot 名）。
- 建、删 Bot 和改运行方式的请求和响应，错误类别（权限缺失、主机内存不够、插件不支持多 Bot、插件未就绪、上游出错）。
- Bot 的视图带运行方式、第 7 节的状态（含“已停用”“内存不够”）、AI 动手级别、第 6 节的提示和单独运行要多占的内存。

**插件规范**（wonton-docs）

- `bots` 改成“每个运行组一组服务”加四条 Bot 命令：参数、标准输入的字段、退出码、“加 Bot”必须幂等；Bot 数据目录的位置；
  底价和每个 Bot 的内存增量；“停 Bot”必须持久（重扫、重启都不拉起），“加 Bot”要能恢复停用的 Bot；删掉每个 Bot 一组服务。
- 扩展资料字段 `app.wonton.bio`、`app.wonton.role`；收存密钥、outbox 和 ADR-0054 命令表按 Bot 的位置。

**Hermes 插件**

- compose 改成一个多路复用 gateway，默认 profile 只当宿主；gateway 服务的环境里去掉 `MATRIX_*` 和 `WONTON_MCP_URL`；健康检查改看进程。
- 四条命令的胶水：建、删 profile，停用落到写 `gateway.parked` 再解挂、恢复落到删标记再热服务（不调 `gateway stop`），写 `.env`，把身份写进 `profile.yaml`、`ui_meta`、头像和 `SOUL.md` 顶部的标记段，
  按级别写 `platform_toolsets`，只重新加载一个 profile。
- 恢复密钥、outbox、ADR-0054 的命令表按 profile 分开写。

**App**

- Bot 管理：我的 Bot 列表、新建（名字、头像、简介、角色、运行方式）、删除（写明后果，选保不保留数据）、改资料、改运行方式、
  按 Bot 的插件访问和 AI 动手级别。
- 第 6 节的提示、第 7 节的状态如实显示，失败给重试；“没同步到 Bot”标在资料旁；停用的 Bot 在聊天和群成员里标出；
  选单独运行时按核心给的数字说明要多占的内存；界面走 ADR-0026。

## 验证结果（2026-11-19，194 号机，Tuwunel 2.0.0，`nousresearch/hermes-agent:v0.22.7` 按摘要固定，未改上游，`docker stats` 取数）

| 项 | 结果 |
| --- | --- |
| 每个 profile 用自己 `.env` 的总线令牌 | 是：B 的真实 Matrix 轮次 41 次请求全部带 B 的令牌，0 次带 A 的 |
| 身份工具按令牌取 Bot | 否：A、B、C 的 `wonton__get_profile` 都返回默认 Bot（`profile_bot` 固定取默认 Bot） |
| 按 profile 限工具 | 是：B 的 `platform_toolsets.matrix` 去掉 `terminal`、`file` 后，B 的轮次里没有这些工具；同进程的 A 照常执行 `ls /` |
| 插件访问开关按 Bot 生效 | 是：关掉后只有这个 Bot 的工具列表变；但改开关后核心重建了整个插件，把各 Bot 的独立容器又拉了起来 |
| 网关容器内存（不设上限，3 个 profile 内服务 1、2、3 个，每轮一句提问、多数带一次工具调用） | 服务起来后稳定在 615–630 MiB；1、2、3 个 profile 空闲时 624、620、625 MiB；每轮增量 <5 MiB；空闲 10 分钟不涨。其中网关进程约 370 MiB，Hermes 网页进程约 190 MiB，和轮次无关 |
| 内存上限偏低 | 220 MiB：网关被 OOM 杀掉、s6 拉起、再被杀，循环中容器一直 running，Bot 全部不可用；450 MiB：能起来但常驻 96–99%，跑一轮时只放了一个 👀 就被杀，房间里没有任何报错 |
| 热增删 | `hermes profile create` 不到 5 秒被服务；`hermes profile delete` 不到 5 秒下线；期间其他 Bot 不断线 |
| 解挂 | `request_unserve_profile` 后 `served_profiles` 去掉该 profile |
| 重启 | `docker restart` 到健康 13 秒，所有 Bot 断开重连；没有 profile 目录的 Bot 重启后丢失 |
| 停用 | `hermes -p b gateway stop` 停掉整个网关、不写标记；只 `unserve-profile` 19–35 秒后被目录监视拉回；写 `profiles/b/gateway.parked` 再解挂后，重扫和 `docker restart` 都不再服务 b；停用期间发给 b 的消息没有任何回应 |
| 换组 | 连同 `platforms/matrix/store` 复制到另一组后设备 ID 不变，旧房间和新建房间都能解密回答；旧组删掉目录后重扫不拉回（重扫只加不删）；目标组要用同一个 `PUID`、`PGID`；留在 `profiles/` 下的同凭据备份目录被当成另一个 profile 拉起，并报凭据重复 |
| 只当宿主的默认 profile | 没有 Matrix 令牌时只剩 API 平台，按 Matrix 连接判健康会一直不健康 |
| 挪走 profile 目录 | 不算删：重扫会重建目录，且重建出的 profile 没有 `.env` |
| 设备密钥 | Bot 先由自己的容器登录过，多路复用器再建客户端后，新消息解不开；记录指向多路复用器那台设备并新建房间后正常 |
| `MATRIX_ALLOWED_USERS` | profile `.env` 里的值不生效，进程环境里核心注入的同名变量优先 |
| `message_agent`、bot-chat 定时投递 | 无头下可用，输出落在目标 profile，不串号（本篇不开放，见第 8 节） |

## 已定

1. **同组不隔离时，由用户按 Bot 选一起运行还是单独运行，默认一起运行；高权限的情形只提示不强制。** 高权限需要隔离时总要分组，
   与其由核心按规则强制，不如让用户自己选；危险模式和高档分享时给出醒目提示和“改成单独运行”的入口。
2. **Bot 个数不设上限；一组的内存上限是固定底价加每 Bot 少量；主机内存真不够时如实报错。** 实测一组约 620 MiB 几乎全是底价，
   多一个 Bot 只多几 MiB，所以约束来自组数和主机内存，不是 Bot 个数；单独运行的每组都付一份底价，用户选时要知道。
   开不起来、反复被 OOM 杀掉都失败即停、如实报出，不压低别的组、不静默降级。
3. **身份同步失败时显示 Matrix 资料，标“没同步到 Bot”。** Matrix 资料是唯一来源，所有客户端看到的都是它；标出没同步，
   不把没生效的改动当成已生效。
4. **`SOUL.md` 插件只管顶部带标记的那一段。** 身份变了 Bot 要知道，用户自己写的人设也不能被覆盖；整段替换比逐行合并简单可靠。
5. **删 Bot 时保留数据用上游的停用标记：写 `gateway.parked` 再解挂。** 实测重扫和重启都不会拉起带标记的 profile，数据原样留在磁盘、
   能恢复；只解挂会被目录监视拉回，`gateway stop` 会停掉整个网关，都不能用。
6. **核心代为登录签发访问令牌，令牌只交给多路复用器。** 沿用核心建账号、只给令牌不给密码的做法；设备的密钥第一次也唯一一次由
   多路复用器上传，满足加密设备只有一个的约束。
7. **Bot 名用归属人用户名加序号（`alice`、`alice-2`）。** 人看到的是资料里的名字，Bot 名只出现在 Matrix 用户 ID 和 profile 名里，
   不用让人再起一个英文名。
8. **默认 profile 只当宿主，不承载 Bot。** 上游的默认 profile 删不掉、解挂不了；不放 Bot，每个 Bot 都能同样地增删、换组，
   进程环境里也没有任何一个 Bot 的值。
