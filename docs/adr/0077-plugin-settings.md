# ADR-0077 插件设置：清单带 JSON Schema，核心校验并存进记录，改了就只重建用到的服务

- 状态：已接受（2026-11-11，主人定了方向：Schema、核心校验、按渲染漂移只重建用到的服务、敏感项走输入密钥、App 按 Schema 生成设置页）

## 背景

不少插件在装完以后有普通设置：Actual 选哪个预算、Vane 用自己的出口地址、SearXNG 的搜索实例。现在这些只能进插件
自己的网页，或者照着说明改清单；`x-wonton.settings` 只是“插件包里有这个文件”，核心从来不解析、不存值、不注入
（#16）。

`settings` 已经写在规范里当预留，App 侧的“按 Schema 原生渲染”也一直在等一个能用的合同。没有合同就没法做界面：
值存哪、谁校验、改了什么时候生效、敏感项怎么办，每一件都决定另一边怎么写。

核心已有的两套做法可以对照：

- **输入密钥**（ADR-0064）：清单声明，装时在原生表单填，核心保管，不回显，改了重建用过它的服务。
- **渲染漂移**：容器的 `wonton.render` 摘要和这次渲染对不上就重建，卷和数据目录不动。

设置和输入密钥正好相反：值要读出来、要能反复改、不是凭据。所以照输入密钥的表单和“只重建用到的服务”，照渲染漂移
的“用摘要判断”，但值明文存进插件记录、随详情返回。

## 决策

### 清单和文件

`x-wonton.settings` 照旧是插件包里的文件路径，内容是这份设置的 JSON Schema（Draft 2020-12）。文件随插件包固定、
进插件包摘要，最外层照插件包现有规则不超过 2 MiB。

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "additionalProperties": false,
  "x-wonton-order": ["budget", "months"],
  "properties": {
    "budget": {
      "type": "string",
      "enum": ["household", "personal"],
      "x-wonton-title": { "zh": "预算", "en": "Budget" },
      "x-wonton-enum-titles": {
        "household": { "zh": "家庭", "en": "Household" },
        "personal": { "zh": "个人", "en": "Personal" }
      }
    },
    "months": {
      "type": "integer",
      "minimum": 1,
      "maximum": 12,
      "default": 3,
      "x-wonton-title": { "zh": "显示几个月", "en": "Months shown" }
    }
  }
}
```

- 属性名是小写字母、数字和下划线，`^[a-z][a-z0-9_]*$`，最长 64；一份 Schema 最多 64 项。
- `x-wonton-title` 必填，多语言；`x-wonton-description` 可选。显示顺序按 `x-wonton-order`，没列的按属性名排在后面。
- 只支持根上的 `properties`：不支持嵌套对象、`oneOf`/`anyOf`/`allOf`、`const`，这些属性照常校验，App 显示为
  JSON 文本。`$ref` 只认同一个文件里的 `$defs`，远程 `$ref` 拒绝。敏感标记要写在属性上——被 `$ref` 的 `$defs` 里
  写了也一样要在属性上再写一遍。
- 支持给 App 生成控件的类型只有：`boolean`、`integer`、`number`、`string`、字符串的 `enum`，以及
  `array` + `items.enum` 的多选。长度、范围和模式照常被校验，控件只是尽量照着长。
- 敏感项不留在设置里：属性带 `writeOnly: true`、`format: "password"` 或 `x-wonton-secret: true` 时算错误（见
  “敏感项”）。
- 使用 `settings` 的清单至少写 `spec: "0.12"`。

### 校验和库

Schema 自己在校验值之前先校验一遍：能解析、是 Draft 2020-12、根是 `type: object` + `additionalProperties: false`、
每个属性有标题、没有敏感标记、默认值自己过得了 Schema、枚举非空不重复、上下限不颠倒。不合格时安装和升级在动资源
之前就返回 400 `settings_schema_invalid`，带每一项的问题和位置。

值用 [`jsonschema`](https://crates.io/crates/jsonschema) 0.61（MIT，最低 Rust 1.85，支持 Draft 2020-12，关掉
`resolve-http`/`resolve-file`，Schema 就是包里的一个文件）。不自研：关键字解析和格式校验的边角太多，自己写只会越来
越像一份残的 JSON Schema。

校验时机：

- 安装、升级请求在拉镜像、建网络之前按新 Schema 校验整份生效值。不通过返回 400 `settings_invalid`，带每个字段的
  路径、类别和一句人话，什么都不改。
- 安装请求只带主人新填的值，默认值由核心按 Schema 的 `default` 补。必填项（在 `required` 里）没有值、也没有默认值时
  不能提交。
- 升级预览把装着版本的值填进新 Schema 的表单。新 Schema 下已经不合法、或新 Schema 删掉了的属性：删掉的属性连值一起
  丢掉；不合法的留在表单里，带问题说明，主人改好才能确认升级。
- 装好以后写设置，只校验新值叠在当前值上的结果；不通过时原值不动、不重建。
- `additionalProperties` 只能写 `false`。请求里带 Schema 没有的属性也是 `settings_invalid`。

### 存哪

值存进插件记录（`InstalledRecord.settings`），一个属性一项，另记最后修改时间。记录本来就在核心数据目录、权限 0600。
值不是凭据，明文存、随读接口原样返回。

卸载时和记录里的其他东西一起按“保留数据”处理。可选项被清空时删掉这一项，注入空串。

### 怎么交给插件

核心把生效值渲染成环境变量 `WONTON_SETTING_<属性名大写>` 注入。字符串原样；布尔是 `true`/`false`；整数和数字是十进制；
数组是 JSON 数组文本；JSON 兜底类型的值是 JSON 文本。没有值、也没有默认值时可选项注入空串（数组是 `[]`，对象是 `{}`，
布尔是 `false`），插件按变量非空选路。

值只进渲染结果，不进配置文件的源码；配置里照常写 `${WONTON_SETTING_xxx}`，同一个值就进了这份配置。

**改了设置，只重建渲染结果里出现这个变量的服务。** 没有服务用它，就只存值，下次启动生效。判断和重建走输入密钥那套
（渲染出全部容器、按变量筛服务、只替换这些），容器上的 `wonton.render` 摘要跟着渲染结果变，和渲染漂移同一条路。
重建失败时把值退回原样、按旧值再渲染一次，错误照原类别返回；退回也失败就把插件标成异常。

### 敏感项

敏感项留在输入密钥（ADR-0064）：值不回显，走系统密码框。设置和密钥不重叠：Schema 里出现敏感标记就拒绝，而不是
让作者自己判断“这里大概是秘密”。

理由：Secret 走的是另一条存储和注入路径（`WONTON_SECRET_*`、不回显、改完必重建），如果设置也能存秘密，App 得按字段
逐项猜哪条路径、详情页要不要打码，值也可能被日志和调试接口带出去。

### 接口

设置页是原生页，形状由核心按 Schema 给：字段、标题、说明、类型、范围、枚举、当前值、默认值、用到它的服务，以及校验
问题。壳只画控件、收值、提交，不认识的新类型画成 JSON 文本编辑器。插件包只给字段的标题和说明，页面标题、保存、
校验类别的文字在各平台的本地化资源里（ADR-0043）。

- `GET /_wonton/api/plugins/{id}/settings` → `PluginSettingsView`。插件没有 `settings` 时 404 `not_found`。
- `POST /_wonton/api/plugins/{id}/settings/preview`：请求体是写请求的体，只校验、不保存，返回填上值的视图。
- `PUT /_wonton/api/plugins/{id}/settings`：`PluginSettingsUpdate`，保存并重建，返回重建后的视图。
- 视图和写请求都带 `schema_digest`（设置文件的 sha256）。插件在中间升级换了文件时对不上，返回 409 `changed`，App
  重新读。
- 安装预览的 `settings` 带表单和默认值；安装、升级请求和确认卡片的回答用 `settings` 带值。Bot 经 MCP 装插件时，
  主人在确认卡片里用同一套原生表单填，值不进 Matrix。
- 只有主人能读写，路由按 `owner_only`（同 ADR-0045）。

接口只有值和字段形状，不回显 Schema 原文。

### 错误类别

| HTTP | `kind` | 情况 |
| --- | --- | --- |
| 400 | `settings_schema_invalid` | 包的 Schema 自己不合格，`problems` 带位置、类别和说明 |
| 400 | `settings_invalid` | 值过不了 Schema，`fields` 带字段、类别和说明 |
| 409 | `changed` | `schema_digest` 对不上 |
| 409 | `conflict` | 插件正在装、卸、重建 |
| 404 | `not_found` | 没有这个插件或它没有设置 |

## 理由

- **Schema 在包里**：设置是插件能力的一部分，跟版本走、进摘要，预览和升级能对出差异。让用户在插件网页里填、核心不
  认识，就还是今天的样子：没有原生页、升级丢了也不知道。
- **核心校验**：值最终要进容器，核心是渲染的人；把校验留给插件，装错的值会以“容器起不来”的样子出现，看不出是哪个
  字段。
- **只重建用到的服务**：改一个预算不该把整个 Compose 项目重启。渲染结果已经知道哪个服务引用了哪个变量，和输入密钥
  共用筛选，不用另写一套依赖分析。
- **存记录**：设置属于这个插件实例，和权限、局域网开关一样，卸载时跟着走。单独目录只有一份文件，没多出任何隔离。
- **敏感项走密钥**：见上，走已经定好的路径，App 只需按两种来源分别渲染。
- **未知类型落到 JSON 文本**：核心先认、App 后跟。新核心加一个类型，旧 App 至少能编辑，不至于整页打不开。

## 代价与风险

- 值明文可读，进日志和调试接口；放进去的就不该是凭据。
- 一份设置全插件共用，Bot 服务也一样。每个 Bot 一套设置这次不做。
- 设置页的能力取决于 App 认得的类型；`array`、`object` 这类只能是 JSON 文本，写错了要靠核心的报错才看得出来。
- 改设置会重启用到的服务，正在进行的任务会断。
- 校验库带来一棵依赖树；关掉远程取 Schema 后，`$ref` 只能用同一个文件里的 `$defs`，跨文件的要自己展开。
- 升级时删掉的属性丢值，降级回去只能重填。

## 没选的做法

- **核心不解释，交给插件命令校验**：每条设置都要插件实现一个命令和输出格式，核心拿不到字段的形状，App 也就画不出
  原生表单。
- **值放 `configs` 的配置文件**：改一次就要重写配置、重启全部挂它的服务；一份设置被几个服务用时还会各存一份。
- **敏感项也允许写在设置里**：多一条回显、多一套打码规则，详情页要按字段区分，存错位置的值会以明文露出来。
- **通用 JSON 编辑器一把梭**：能跑，但没有开关、下拉和数字范围，普通用户对着大括号填设置。
- **只有插件网页，没有原生页**：就是现状；装的时候还要先起容器再碰网页，Bot 装的时候更没法填。
- **每改一项就重建全部服务**：简单，但一个预算选择会断掉目录同步和网页。
