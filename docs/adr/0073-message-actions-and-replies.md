# ADR-0073 消息菜单和回复：菜单项由核心按消息给，回复、转发、撤回都用 Matrix 的标准做法

- 状态：已接受（2026-11-08）；第 3 节和第 2 节最后一条已被 [ADR-0109](0109-chat-like-telegram.md) 取代：改成左滑回复，点引用能跳到原消息

## 背景

#745 要长按消息的菜单里有复制、回复、转发、删除，并且能右滑回复。协议里的菜单项原本只有复制。哪条消息能回复、能撤回，取决于
发送状态、消息类型和本账号在房间里的权限，这些只有核心知道。

## 决策

### 1. 菜单项由核心按消息给

`TimelineMessage::actions` 按菜单顺序列出这条消息能做的事：`Copy`、`Reply`、`Forward`、`Redact`。壳照平台习惯画（iOS 长按出系统
上下文菜单，Android 单击出自绘菜单，见 ADR-0109），不认识的菜单项不显示。核心的规则：

- 回复：已经发出（有事件 ID），不是已撤回的、不是确认卡片。
- 转发：已经发出的文字和图片。
- 撤回：自己发出的；或者本账号在这个房间的权限能撤回别人的消息（Matrix 的 power level）。已撤回的没有。
- 没发出去的消息照旧用“重发”“取消发送”，不进这个菜单。

### 2. 回复用 Matrix 的 `m.in_reply_to`

- 发送时由壳显式给出回复的是哪条（`SendText`、`SendImage` 的 `reply_to`），核心不存“当前在回复谁”的隐式状态：壳显示的引用就是发出去的引用。
- 引用由核心给（`ReplyQuote`、`QuotedMessage`）：文字摘要、图片缩略图、已撤回、解不开等类别，壳按类别画，不自己摘要原消息。
  原消息不在本地时核心经 matrix-sdk 向服务器取，先给 `Loading`，取不到给 `Unavailable`，不伪装成已取到。
- 菜单里的 `Reply` 自带引用，壳进入回复状态时直接画它。
- 回复对象和正文一起进草稿（matrix-sdk 的 `ComposerDraftType::Reply`），换房间、杀 App 再进还在，发送成功后清掉。
- ~~点引用跳到原消息依赖 ADR-0071 的时间线定位，不在这次。~~ 已由 [ADR-0109](0109-chat-like-telegram.md) 第 4 节做：点引用跳到原消息，“向下”按钮先回到跳之前的位置。

### 3. 滑动回复

> 已被 [ADR-0109](0109-chat-like-telegram.md) 第 5 节取代：照 Telegram 改成左滑回复。

消息有 `Reply` 时才能滑，没有 `Reply` 的消息滑不动。

### 4. 转发是照原样再发一条

Matrix 没有标准的“转发”关系，各客户端都是把内容重新发一遍。核心照原样发到目标房间：文字带格式，图片复用原来的媒体地址和加密信息，
不重新上传；不加“转发自”标记。核心的一次转发只到一个房间。iOS 的转发面板能选几个会话（[ADR-0109](0109-chat-like-telegram.md) 第 9 节）：只选一个时壳随后打开目标房间，进展看那里的本地回显和发送状态；选了几个就对每个房间各转发一次，留在原来的房间。目标是房间的主时间线，不往旁聊里转发。

转发可以带一条附言，放在动作的 `comment` 里，核心不猜；壳只派发这一个转发动作，不另发一条文字。附言首尾的空白由核心去掉，只含空白的附言当作没有附言。一次选几个会话，就每个房间各派发一次，各带一份附言：每个房间各有一条自己的附言，不是只发一份。有附言时先在同一个目标房间发附言，服务器确认后才发转发：附言和转发走同一条
房间发送队列，顺序和失败都只有一个来源。附言发不出去（连发送队列都进不去，或服务器不可恢复地拒绝）就不转发，原因进 `problem`；不带附言时直接转发。附言确认之前目标房间只有
附言的本地回显，转发本身要晚一步才出现。附言失败后的转发不自动重试，主人重新转发一次就是新的动作；被拒的附言卡在队首，挡着这个房间后面的发送，要先重发或取消那一条，新的转发才有结果。两端都只派发这一个动作，壳不另发文字。ui-fake 和真核心都实现了附言，走查别把两边当成一致。

### 5. 撤回是 Matrix 的 redaction

对所有人生效，所有设备上都变成“已撤回”。壳在发出前请主人确认。Matrix 没有“只在自己这里删除”，不做。

## 考虑过的做法

- **核心记住“正在回复谁”，发送时自动带上**：壳少传一个参数，但壳显示的引用和实际发出的可能不一致（比如设置回复的操作失败了），
  发送时显式给出更可靠。
- **转发时带“转发自某某”**：没有标准字段，别的 Matrix 客户端看不懂，只能写进正文，会污染原文。
- **编辑消息一起做**：输入框要多一种“编辑中”状态，和回复、草稿互相影响，单独做。

## 代价与待验证项

- 把加密房间里的图片转发到不加密的房间，图片的解密信息会随消息进入那个房间，等于把图片发到了那里；这和主人手动重发一样，不另外提示。
- 回复别的客户端发来的旧格式回复（带回退正文）时，正文里的回退部分要由核心去掉，实现时用真实的 Element 消息验证。
