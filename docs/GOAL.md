# 目标与里程碑

## 总目标

做出一个能公开发行给普通用户、国内外都能用的 AI 原生家庭服务器 Wonton / 云吞。

用户在任意一台 Linux + Docker 主机上一行命令装好，用手机扫码配对后，就拥有一个住在自己家里、
随时能找到、能主动找你的私人 Agent。相册、文件、音乐、本地模型和任意 Docker 应用都以插件形式接入：
Agent 能调用它们，有网页的插件在 App 里像小程序一样使用。

以 M3（1.0 公开发布）为“完成”。每个里程碑都以下面的验收标准为准，没达到就不算完成。

## M0 技术验证

目的：在写大量功能之前，先证明主干链路在真实网络和真实手机上可行。每一项都要产出一个可复跑的
最小程序或脚本，以及一段结论（写进对应 ADR 的“验证结果”一节）。

1. **iroh 隧道**：基于 iroh 1.x 的 HTTP 隧道（参考 dumbpipe）。服务端只接受已配对设备的
   endpoint ID；手机在蜂窝网络下经隧道访问家里服务器的 HTTP 服务；记录直连与中继的比例和延迟。
2. **Matrix 主干**：Tuwunel 跑在 Docker 里；客户端用 matrix-rust-sdk 经隧道登录、用 Sliding Sync
   同步、收发消息和附件；验证用 Tuwunel 的 JWT 登录能力给设备和 Bot 签发登录。
3. **加密推送**：Tuwunel pusher → 核心推送代理（用设备公钥加密）→ gorush 中继 → APNs / FCM →
   iOS 通知扩展、Android 本地解密并显示；中继日志里不出现明文。M0 先在 Android 上验证（手机有谷歌
   服务走 FCM，没有就用 UnifiedPush 自建 ntfy），gorush 跑在本机或局域网；iOS 推送需要付费的 Apple
   开发者账号，有账号后补做。
4. **默认 Bot**：Hermes 通过它的 Matrix 平台以 bot 身份接入 Tuwunel，模型请求经 magpie 网关；
   在手机上完成一次对话。
5. **厚核心骨架**：Rust 客户端核心经 UniFFI 导出“操作进、ViewModel 出”的接口，SwiftUI 和
   Compose 各渲染一个会话列表；核心行为测试在 CI 里运行。
6. **插件安装与小程序**：核心经 Docker API 安装一个带 `x-wonton` 的 compose 插件，网关按清单
   路由它的网页；App 在 WebView 里经隧道打开，并通过 OIDC 自动登录一个支持 OIDC 的应用。
7. **云端节点**（推迟到 M2）：在一台海外主机和一台香港主机上部署 iroh-relay、iroh-dns-server
   （共享令牌加限速），客户端从签名的节点列表里获取中继地址。开发和内测期先用 n0 的公共中继
   （免费、限速、没有可用性保证），配对二维码带直连地址；内测中经公共中继体验差再提前部署。
   推送中继的公网部署归到 M2 的系统推送（第 12 项）。

完成标准：第 1–6 项都有结论（第 3 项的 iOS 部分等有 Apple 开发者账号后补做），第 7 项推迟到 M2；
遇到阻断的项有替代方案，并写进 ADR。

## M1 MVP 内测

按用户路径验收，通过 TestFlight 和直装 APK 分发：

1. 在干净的 Debian 或 Ubuntu + Docker 主机上（amd64 和 arm64 各一台）执行一行安装命令，10 分钟内
   装完；浏览器打开局域网页面，能看到配对二维码和运行状态。
2. iOS / Android App 扫码配对成为主人；手机切到蜂窝网络后仍可正常使用。
3. 在“模型设置”小程序（magpie）里填入任意 provider 的 key 后，默认 Bot 能收发文字、图片和文件。
4. 插件商店：官方目录至少包含 Immich、Navidrome、Paperless-ngx、Ollama、Syncthing、Samba，并能
   导入 CasaOS 应用；安装前展示并确认权限；插件网页在 App 内打开，支持 OIDC 的应用自动登录。
5. 对 Bot 说“帮我装某个应用”，Bot 在聊天里发确认按钮，主人确认后完成安装并回报结果。
6. Bot 能在已授权的文件夹里查找文件，并通过 MCP 在 Immich 里按内容搜照片。
7. 核心在 App 里一键升级；健康检查失败时自动回滚到旧版本。
8. 工程：CI 门禁全绿；核心行为测试覆盖配对、聊天、推送、插件安装的主流程；端到端冒烟脚本能在
   真实主机上复跑。

MVP 只做主干。M2 的能力在架构上预留接口，MVP 期间就可以由多个 Agent 在各自的 worktree 里
并行开发，测完提 PR 合并。

## M2 第一个大版本

1. **实时通话**：和 Bot 语音通话，App 在后台也不断线；通话中可以把屏幕共享给 Agent。先做云端
   实时模型直连，再做家里 LiveKit 的隐私模式。
2. **Subsonic 原生音乐页**：对接 Navidrome 等 Subsonic 服务，支持锁屏控制、无缝播放、离线缓存。
3. **桌面端**：Compose Multiplatform，覆盖 Windows、macOS、Linux。
4. **家人邀请**：每人有私人 Bot 和私人空间；主人可以建共享 Bot，拉进家庭群。
5. **ACP 桥**：可以把 Codex、Claude Code 等装成新的 Bot。
6. **Bot 之间互发消息（同机）**：联系人审批，频率和转发跳数限制。
7. **第三方 IM 渠道插件**：Telegram、飞书、企业微信等。
8. **文件语义检索插件、U 盘自动导入插件**：优先选现成开源方案。
9. **国内 Android 厂商推送**：依赖公司主体和商店上架。
10. **小程序 JS SDK**：原生播放、文件选择、分享、发到聊天。
11. **自建中继与发现节点**（原 M0 第 7 项）：香港、海外各一台主机部署 iroh-relay、iroh-dns-server，
    客户端从签名的节点列表获取地址；内测中经公共中继体验差就提前做。
12. **系统推送**（原 M1 第 4 项）：App 被杀或锁屏时，Bot 的回复和插件通知以系统推送弹出（iOS 走
    APNs，海外 Android 走 FCM，国内 Android 用可选的“保持连接”模式）；推送中继看不到明文，部署在我们的
    一台公网主机上。推送的接口保留，M1 不以它验收。

## M3 公开发布 1.0

1. 国内外应用商店上架：公司主体、App 备案、商标检索与注册、隐私政策。
2. 备案完成后增加内地中继与推送节点。
3. 插件规范 1.0 和插件开发文档公开。
4. Web 端：同一套 Compose UI 编译到 Web，核心在服务器上运行，浏览器经 WebSocket 连接。
5. 跨机 Bot 通信插件（Matrix 联邦走 iroh，或 A2A）。
6. 安全审查：Agent 权限、插件权限、配对与推送链路。
